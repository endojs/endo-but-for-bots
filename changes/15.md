### @jfparadis — CHANGES_REQUESTED — 2020-02-13T16:06:14Z

I think that the CI should do what the developer does, not something different. 
- This give consistent output
- There is no separate tool to update and debug. 
- This list of packages is redundant with `packages.json`

It's dangerous here to skip packages. Instead, let's make the automation as light as possible, so it cannot introduce failures.

A few things:
1. Lerna is much more mature that yarn at managing monorepos.  Lerna and yarn workspaces are not redundant. Lerna is not just a command runner. It's possible can get by with clever tricks like this, but we lose something we get for free with Lerna. Check `lerna` documentation:
- https://github.com/lerna/lerna
-`lerna -h` or `./node_modules/.bin/lerna -h` if it's not installed as a global.
2. Yes, the `--no-bail` option is exactly about continuing execution:
> "Continue running script despite non-zero exit in a given package"
https://github.com/lerna/lerna/blob/62901748f818516d58efdfd955eacb447e270351/commands/run/command.js#L40
3. There is a `--no-sort` command option to run things alphabetically, but I suggest we don't use that and let lerna execute by dependency order:
> "Do not sort packages topologically (dependencies before dependents)."
https://github.com/lerna/lerna/blob/2c487fe5f612739970eb08026b2bf7da82a32b66/core/global-options/index.js#L34
