## Summary

- **What:** Tightens `ses` `overrideTaming: 'moderate'` enablements list to specific properties instead of `'*'` wildcards.
- **Why:** Reduces inspector noise and avoids stepping into accessor getters during VS Code debugging; tested against LavaMoat for compatibility.
- **Themes:** ses-lockdown, ecosystem-compat
- **Status:** merged

## Description

This is technically a breaking change that is not supposed to break anything in practice. But we need testing, for example with @kumavis 's LavaMoat, to see if that's really true.

@kumavis even though I seem unable to list you as a reviewer, could you test out these tighter settings against LavaMoat and let me know if I need to add more enablements? Even if so, I'd rather keep adding them specifically and permanently retire the old `'*'` logic. Among other things, it was creating an unpleasant debugging experience in two ways:
   * VSCode debugger's object inspector shows inherited accessor, overwhelming the properties of interest with noise
   * Single stepping over any enabled property takes us into the getter for that property.
