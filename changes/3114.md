## Description

This PR significantly enhances debug logging for libp2p network connectivity, specifically targeting issues with internet hole-punching and cross-computer connections. The goal is to provide clear, attempt-scoped tracing of an Endo-initiated connection from the daemon's address selection down to libp2p's internal dial and DHT operations.

Key changes include:
-   **`packages/daemon/src/networks/libp2p.js`**: Added targeted diagnostics for the full lifecycle of an Endo outbound connection attempt, including dial queue snapshots, peer store state, detailed dial progress events (via `onProgress` callbacks for `dial-queue:*`, `transport-manager:selected-transport`, `upgrader:*`), and critical DHT query events (`kad-dht:query:*`). Also improved logging for address hint publication and made verbose libp2p component logging configurable via `ENDO_LIBP2P_VERBOSE_COMPONENTS`.
-   **`packages/daemon/src/daemon.js`**: Added daemon-level logs within `makePeer` to trace address evaluation, network support, and the start/success/failure of dial attempts. Expanded `addPeerInfo` logging to show actual address sets.

These changes allow for end-to-end tracing of a single connection attempt, making it possible to diagnose why internet connections fail by observing DHT lookup paths, dialed addresses, transport choices, and specific failure points.

### Security Considerations

This change introduces no new security assumptions or dependencies. It only enhances debug logging.

### Scaling Considerations

Increased logging verbosity is primarily for debug environments. The new `ENDO_LIBP2P_VERBOSE_COMPONENTS` environment variable allows control over libp2p's internal component logging, preventing excessive noise in production. No significant impact on CPU, RAM, or other scarce resources is expected in normal operation.

### Documentation Considerations

Users troubleshooting connectivity issues will need to be aware of the new `ENDO_LIBP2P_VERBOSE_COMPONENTS` environment variable to enable more granular libp2p logging. No backwards compatibility issues or upgrade instructions for existing data are necessary.

### Testing Considerations

This PR is focused on improving observability for network debugging rather than introducing new features. While no new unit tests are included, the enhanced logging will be crucial for diagnosing and testing real-world network connectivity scenarios, especially across different NAT configurations.

### Compatibility Considerations

This change introduces no breaking changes to prior usage patterns. It enhances the ability to debug existing patterns.

### Upgrade Considerations

No specific upgrade steps are required for live production systems. The logging enhancements are opt-in or for debugging purposes.
