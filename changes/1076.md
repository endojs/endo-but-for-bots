## Summary

- **What:** Removes superfluous `.d.ts` files that were shadowing JSDoc-typed implementations and silently downgrading types to `any`; widens `cjs-module-analyzer` TS inputs and adds a `bundle-source` jsconfig.
- **Why:** A `.d.ts` next to a `.js` replaces the implementation in TS's type lookup, creating cycles that erase types for downstream consumers.
- **Themes:** types, bundle-source, compartment-mapper
- **Status:** merged

## Description

Evidently, a type definition file replaces the implementation JavaScript file in the types space, so any reference to the implementation is a cycle, and any value participating in that cycle silently degrades to the any type. Consequently, the type information disappears for any external dependency.

In this change, I’ve deleted superfluous type definition files that I had previously thought necessary to expressly export types from JSDoc modules.
