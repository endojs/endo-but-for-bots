## Summary

- Enables the `exactOptionalPropertyTypes` TypeScript compiler option, which distinguishes between "property is absent" (`{}`) and "property is explicitly `undefined`" (`{ foo: undefined }`)
- Bumps yarn to 4.13
- Fixes all resulting type errors across 19 files in 10 packages

## Approach

Two strategies depending on the kind of type:

**Option bag types** (parameters where callers destructure and re-spread): add `| undefined` to optional properties in type definitions. This is the pragmatic fix because the pattern of `const { policy } = options; fn({ policy })` is pervasive, and `policy` is `T | undefined` after destructuring.

**Data structures and return types** (`LocalModuleSource`, `MethodGuardPayload`, `GrantDetails`, archive return values, etc.): use conditional spreading at creation sites, e.g. `...(sha512 !== undefined && { sha512 })`. This keeps the types precise — consumers don't have to handle an `undefined` that would never actually be present.

Other targeted fixes:
- `ReadNowPowers` uses `NonNullable` in its mapped type because `Required<Pick<T, K>>` strips `?` but preserves `| undefined`
- Iterator `done` normalized with `!!done`
- Fixed stale import of `MakeModuleMapHookOptions` → `MapNodeModulesHookOptions`
