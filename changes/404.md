## Summary

- **What:** Adds a `parsers` field in `package.json` that overrides `type` for `endo`, e.g. `"parsers": {"js": "mjs"}` to opt `node -r esm`-style packages into ESM parsing without breaking native Node.js consumers.
- **Themes:** compartment-mapper, ecosystem-compat
- **Status:** merged

## Description

This change introduces a `parsers` field that will override `type` on Endo, creating an escape hatch for packages that currently use `esm` with `node -r esm`. These packages use `js` files for ECMAScript module sources, which `esm` translates to CommonJS, so setting `"type": "module"` in these packages confuses Node.js. Adding `"parsers": {"js": "mjs"}` to these packages will inform Endo that the sources are in fact ECMAScript modules, allowing applications to consume both packages targeting Node.js and `esm`.
