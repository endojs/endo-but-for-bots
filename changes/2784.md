## Summary

- **What:** Deprecates `@endo/marshal`'s `trivialComparator` in favor of a type-specific `compareNumerics` (with NaN support), uses it in `compareRank`, and avoids redundant `harden` work in `sortByRank`.
- **Why:** Discourages UTF-16 code-unit comparison of strings via relational operators (refs #2113).
- **Themes:** marshal, performance, chore
- **Status:** merged

Ref #2113

## Description

We want to discourage comparison of strings by UTF-16 code unit as implemented by relational operators.
