## Summary

- **What:** Adds a `hostEvaluators` lockdown option (`_legacy`, `all`, `none`, `no-direct`) to `ses`, refactors `assertDirectEvalAvailable` into `probeHostEvaluators`, disables `compartment.evaluate` when direct eval is unavailable, and turns on the Hermes VM in CI.
- **Why:** Closes #1891 — Hermes lacks direct eval and `with`, so `ses` needs a configurable initialization path that fails fast on incompatible lockdown options instead of crashing later.
- **Themes:** ses-lockdown, compartments, ecosystem-compat, ci
- **Status:** merged

Hermes eval behaviour on `bin/hermesc` (standalone compiler) and `bin/hermes` (vm, eshost)

```js
// Hermes direct eval cannot access or modify variables within its closure scope (sloppy and indirect)

eval = globalThis.eval; // remains direct eval, compiler: "error: invalid assignment left-hand side"

// calling globalThis.eval(...) uses indirect eval

// calling eval on Hermes VM emits: "warning: Direct call to eval(), but lexical scope is not supported."

print(eval(1 + 1));
print(eval("1 + 1"));

function a(eval, TEST) {
  // compiler: "error: cannot declare 'eval'"
  eval("TEST=true");
  return TEST;
}
print(a(eval, false)); // vm: false

function b(eval) {
  // compiler: "error: cannot declare 'eval'"
  var TEST = false;
  eval("TEST=true");
  return TEST;
}
print(b(eval)); // vm: false

function c() {
  var TEST = false;
  eval("TEST=true");
  return TEST;
}
print(c()); // vm: false

function d() {
  var TEST2 = 42;
  return eval("TEST2");
}
print(d()); // ReferenceError: Property 'TEST2' doesn't exist

// Note: eshost only runs bin/hermes (vm), not bin/hermesc (compiler)
```
