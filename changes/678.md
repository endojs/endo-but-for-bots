## Summary

- **What:** Moves `StaticModuleRecord` out of `ses` into the `transform-module` (later `static-module-record`) package, flattens the `ses/lockdown` and `ses` entry points back into a single `ses`, and updates `@endo/compartment-mapper` atomically.
- **Why:** SES no longer entrains Babel anywhere; the parser dependency follows `StaticModuleRecord` into a separate shim package.
- **Themes:** ses-lockdown, compartments, compartment-mapper
- **Status:** merged

## Description

This change makes the end-to-end changes necessary to move StaticModuleRecord from SES to the transform-module package.

This afforded an opportunity to wake up the transform-module tests. These have been dead code since before my time at Agoric and, with SES Compartment implemented, could be restored using that instead of the simple evaluator prototype. Some tests are not working and have been explicitly skipped. The transform appears to be failing to rename certain hoisted local names. cc @michaelfig

This also afforded the opportunity to flatten `ses/lockdown` and `ses` into just `ses`, back to the simpler state of affairs. SES no longer entrains Babel in any layer. That dependency shifts to the StaticModuleRecord shim (née transform-module).

It is necessary to update `compartment-mapper` in an atomic change, since it depends on `StaticModuleRecord`.

This renames `@agoric/transform-module` to `@endo/static-module-record` and leaves moving the directory to a future change to keep the diff clean. This also leaves `make-simple-evaluate` and `make-importer` as dead code to be removed in a future change. The next work toward #673 is to introduce a pre-compiled module type to the compartment-module and front-load the conversion, using `StaticModuleRecord`, when loading any ESM, instead of writing ESM to archives.
