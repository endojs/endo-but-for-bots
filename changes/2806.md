## Summary

- **What:** Treats packages named in `peerDependenciesMeta` (without a corresponding `peerDependencies` entry) as dependencies in `@endo/compartment-mapper` so a `CompartmentDescriptor` still gets generated, and trims the unused per-dep spec storage in `graphPackage`.
- **Why:** Some real-world `package.json` files declare `peerDependenciesMeta` solo (legacy npm 6 idiom); compartment mapper was dropping them entirely.
- **Themes:** compartment-mapper, ecosystem-compat
- **Status:** merged

## Description

## Description

_May be controversial!_

This adds dependency names found in `peerDependenciesMeta` which are otherwise unspecified in other dependency fields to the list of all dependencies so that a `CompartmentDescriptor` will be created if the package exists.

### @boneskull (MEMBER) — 2025-05-17T00:08:25Z

I should mention why this pattern exists:

npm (post-wide-usage) and pre-v6.x did not install `peerDependencies` by default.  npm v7 introduced `peerDependenciesMeta` and also introduced the behavior of automatically installing `peerDependencies`.  While it's pointless to add `peerDependenciesMeta` (maybe it works in yarn or smth) _without_ `peerDependencies`, there's no notion of an _optional_ peer dep prior to npm v7, so adding anything to `peerDependencies` just makes extra work for the consumer who must manually install it (which is likely why the behavior changed).  

nvm v6 was shipped w/ Node.js v10.x thru v14.x and npm v8+ in LTS versions thereafter.
