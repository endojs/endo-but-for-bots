## Summary

- **What:** Adds GitHub-URL `title` attributes to relative-path Markdown hyperlinks across docs so a future `vitepress` link-transformer can swap relative `.md` links for the GitHub URL while keeping IDE navigation working.
- **Themes:** docs, tooling

## Description


## Description

As part of keeping the [docs site up-to-date with API docs](https://docs.google.com/document/d/1h-wQzmGVtHVPGp8fNsSYormZQoRFRDMRNZksm37Nwm8/edit?usp=sharing) initiative, there are certain instances of hyperlinks in a few md files that generate deadlinks and are hence flagged by `vitepress`.  Since we use relative paths to reference md files within the same repo to make them [navigable in external IDEs](https://github.com/endojs/endo/pull/1269), simply replacing them with their github url would be a downgrade in terms of experience. 

This PR proposes that we add a **_title_** against each href which necessarily just equals the github url of that file. This helps us with two things:
 - maintain IDE navigation
 - do pre-processing on such links to replace href with the title for docs site

Currently, the plan is to use a `linkTransformer` of sorts to achieve this. On the docs site, these links will get replaced by their github URL thereby circumventing the 404s they would have led to (if we ignored the dead link warnings). Here's an initial version of code that I have tested to make it happen:

```js
export default (md) => {
    md.renderer.rules.link_open = (tokens, idx, options, _, self) => {
      const token = tokens[idx];
      const hrefIndex = token.attrIndex('href');
      const titleIndex = token.attrIndex('title');
  
      if (hrefIndex >= 0 && titleIndex >= 0) {
        const href = token.attrs[hrefIndex][1];
        const title = token.attrs[titleIndex][1];
  
        if (href.endsWith('.md') && title.startsWith('http')) {

          token.attrs[hrefIndex][1] = title;
          token.attrs.splice(titleIndex, 1);
        }
      }
  
      return self.renderToken(tokens, idx, options);
    };
  };
```
