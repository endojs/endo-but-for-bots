## Summary

- **What:** Adds source-comment URLs at error throw-sites that have SES error codes (e.g. `SES_NO_EVAL`) so developers following stack-trace locations land near a link to the explanation page; mitigates #1429.
- **Themes:** errors, docs
- **Status:** merged

## Description

Mitigates https://github.com/endojs/endo/issues/1429

When seeing an error with an error code, it can be hard to find the page explaining that error code. As #1429 documents, Google searching on the error code is not helpful. However, @turadg noticed that he often uses the stack trace locations to look at the code that raised this error. This PR adds comments to the source code locations that raise errors we have already given error codes to, where these comments contain the URL of the error code explanation page we want the developer to discover.

Since the files are in the same package, I thought a relative link might work, but I couldn't get VS Code to make it navigable.

This Markdown comment will render as clickable on hover, but that doesn't help with the problem at hand.
```
/** [SES_NO_EVAL](../error-codes/SES_NO_EVAL.md) */
```
This would be a little more JSDoc style and concise, but even less clickable:
```
/** {@link ../error-codes/SES_NO_EVAL.md} *
```

I expect we'll have a better way eventually. E.g. https://github.com/microsoft/TypeScript/issues/47718 . Or a little web build like https://endojs.github.io/errors/SES_NO_EVAL 

But this is already an improvement to discovery and all the above would be incremental improvements. So 👍 to merge.
