- **Themes:** chore, ses-lockdown

## Description

None of our own package.json files state any dependency on `"acorn"` other than `"^8.0.1"`. Nevertheless, somehow acorn v7 links end up in our `yarn.lock`.  I have no idea what the proper way is to ensure that no acorn 7s get linked into our system, but we need to because acorn 7 has a bug that interferes with SES fixed in acorn 8. So I'm making this draft until either
   * we determine that it is ok to force version linkage in this manner, or
   * we do this whatever the proper way to do this is.

Please don't manually munge the `yarn.lock`.  Nobody knows what invariants you're violating.

We find the individual packages that depend on old acorns, and upgrade each one of them.  I think the main culprit is rollup, but I've been hesitant to upgrade it (and its dependent plugins) because there was some instability in the versions I tried circa 6 months ago.

The other (better?) way is to use `patch-package` to patch the acorn 7 package and work around the problem.
