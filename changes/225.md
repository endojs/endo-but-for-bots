### @warner (CONTRIBUTOR) — 2020-03-16T19:08:30Z

Splitting `compartment-shim` into its own package would work for me too. The motivation is that `ses-adapter` wants to provide a `Compartment` in case it's not already available on the global. If it *is* available on the global, that means we're in a SES-shimmed world, or in a newer JS environment that includes the real (standardized) Compartment. If it isn't on the global, `ses-adapter` wants to provide something that works well enough for libraries to run their unit tests.

Oh, to be clear, I should mention that splitting `compartment-shim` into its own package is fine, as long as it won't cause problems to *import* (but not use) `Compartment` from `compartment-shim` inside a SES environment. We'll be using static import syntax, so the import will happen before we discover whether `Compartment` is available on the global.
