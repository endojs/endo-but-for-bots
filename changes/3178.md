## Summary

- **What:** Replaces the stream-formula/promise-chain message protocol on the `llm` daemon branch with a three-verb design — `send` (create message), `act` (ephemeral status), `edit` (append-only update ledger) — making streaming an emergent property of sequential edits.
- **Why:** Simplifies the daemon message graph and aligns with how AI agents emit interleaved thinking/tool-call/answer status updates.
- **Themes:** daemon, familiar, ocapn
- **Status:** open / under review

## Description

Replace the stream-formula/promise-chain approach with a simpler three-verb model: send creates messages, act broadcasts ephemeral status indicators, and edit revises existing messages via an append-only update ledger. Streaming becomes emergent from sequential edits rather than a first-class protocol concept.

### @jcorbin (NONE) — 2026-04-16T15:55:27Z


So the `MessagedEdit` looks good, no notes ( other than my own iceberg of confusion around "why do messages have a strings list? what even are edge names?" &C )

But the `Action` is triggering various shades of "aint-it-chief":
1. actions need be full blown free form messages, like an ephemeral sub-reply
2. a pending message needs to be able to have multiple statuses, and each status needs to be able to be dismissed, and then maybe later re-added
3. from a presentation stand point "badges" aint it, they are ephemeral small messages like:
  - "thinking..."
  - maybe "thinking: okay, so here, is my actual train of thought, when you opt in to seeing it, should appear to 'stream', but then collapse or dismiss once the next round kicks, or at least dismiss once final response settles, or collapse, or ..."
  - "Calling file read <path> tool..."
  - "Calling file read <path> tool... done." ( maybe with result dump opt-in for debugging )
  - "Calling sub-agent <name>..."

So on balance, how about we nix actions as a separate thing, and just use message edits instead:
- what if `Package` and `MessageUpdate` both had an additional `status: Array<string>` field
- to motivate perhaps, here is a decently representative "Must Be This Tall To Provide Insight" scenario:
  1. `status: ["thinking..."]`
  2. `status: ["thinking: okay so maybe I need to use Tool A? or Tool Z? Let's see..."]`
  3. `status: ["Calling tool A...", "Calling tool B...", "Calling tool C..."]`
  4. `status: ["Calling tool A...", "Called tool B: result note", "Calling tool B..."]`
  5. `status: ["thinking: darn those tool calls did not work, and I keep making this error, let's Try Harder :tm:"]`
  6. `status: ["Calling tool python with shell script omg so much code"]`
  7. `status: ["thinking: wow that worked, I'm so good at writing code, now what should I tell the user? Let me see..."]`
  8. `strings: ["Okay, so I tried so hard, and got so far, and in the end I wrote a 30 line python script, and won this prize: 42"], status: ["typing..."]`
