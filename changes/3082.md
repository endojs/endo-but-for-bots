### @boneskull (MEMBER) — 2026-02-19T01:15:03Z

I note that the resulting `CHANGELOG.md` format (which Changesets are going to generate) could be better:

- No date information is appended to the release header.  The `CHANGELOG.md` files do not have this information, but `NEWS.md` does.
- No "diff"/"compare" link is generated, like in the current `CHANGELOG.md` files generated by Lerna. So we're losing something there.

It is straightforward to provide Changesets a custom `CHANGELOG.md` formatter; this could just be a module; e.g., `.changeset/endo-changelog-formatter.js` based on the [GitHub formatter](https://github.com/changesets/changesets/blob/e07fd62e8c1ebad39eeeb9833cd5c31336323bb1/packages/changelog-github/src/index.ts).

If we're fussy about this, I can implement a custom formatter now. Otherwise in a subsequent PR.

**UPDATE**: Because the CHANGELOG.md is created in a Release PR, any hypothetical date would be the date the Release PR was updated--_not_ the date on which the PR was merged.  Still, it's better than no date at all.
