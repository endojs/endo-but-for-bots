I agree that the `M.null()` divergence feels like a bug (now #1601), but that's a behavioral change so I'd like to fix it in a followup and keep this PR limited to docs and tests.

As for fast-check, property-based testing was in the back of my mind here... a lot of it seems manual, but we could definitely assert agreement such as `kindOf` response values over arbitrary Passables corresponding with the same-named `M` method to the exclusion of all other type-based `M` methods (possibly with predictable error messages, which are in general the biggest hurdle), and also trivial properties like `M.any()` and `M.and()` and `M.or(self, arbitrary)` always matching any Passable.
