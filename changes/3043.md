## Description

This PR addresses a believed test flake in `packages/daemon/test/endo.test.js` → `endo › lifecycle`, which manifests as a `RemoteError: "Unexpected dangling message at offset 4"` from the netstring reader.

The primary hypothesis is that an over-aggressive worker shutdown mechanism can force-kill a worker even when it's already terminating cleanly, leading to truncated netstring messages.

**Proposed Fix:**
The worker graceful cancellation logic in `packages/daemon/src/daemon.js` has been adjusted. It now only escalates to a forced cancellation if the grace period *actually* elapses, rather than also escalating when the worker terminates within the grace period.

**Debugging Enhancements:**
1.  Added opt-in debug logging (`ENDO_FLAKE_DEBUG=1`) in `packages/daemon/src/daemon.js` to trace worker lifecycle events.
2.  Passed a meaningful `name` to `makeNetstringReader` in `packages/daemon/src/connection.js` to provide clearer error messages in future failures.

**CI Changes (for reproduction and verification):**
1.  A new workflow `.github/workflows/flake-daemon-lifecycle.yml` has been added. This workflow runs *only* the flaky `daemon › lifecycle` test 100 times (fail-fast) on Node 22 (ubuntu) with `ENDO_FLAKE_DEBUG=1` enabled.
2.  Other PR workflows (`ci.yml`, `browser-test.yml`, `depcheck.yml`) have had their `pull_request` triggers changed to `workflow_dispatch` to prevent them from running on this investigative PR.

The most critical files to review are:
*   `packages/daemon/src/daemon.js` (worker cancellation logic and debug logging)
*   `packages/daemon/src/connection.js` (netstring reader naming)
*   `.github/workflows/flake-daemon-lifecycle.yml` (new CI workflow)
