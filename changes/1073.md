## Summary

- **What:** Wraps CJS `module.exports` in a Proxy in `@endo/compartment-mapper` so live binding/late property additions visible to ESM consumers behave correctly.
- **Why:** Closes #885 — CJS modules expect `exports` to be a plain object with prototype methods; a proxy preserves that while letting ESM consumers see the right shape.
- **Themes:** compartment-mapper, ecosystem-compat
- **Status:** merged

## Description

Fix #885 

I don't yet know if it's ok to leave Object as the target for the proxy and return its prototype methods when requested.   
CommonJS lets modules depend on `exports` being an object with the default prototype, so it needs to be there. Maybe hardened or petrified? 

I had this code for a few days now, but wanted to see if I can use the proxy to fix `import * from cjs`. Turns out it has nothing to do with parse-cjs so this can land separately.
