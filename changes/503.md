### @kriskowal (MEMBER) — 2020-10-24T02:14:37Z

I believe that freezing is a better default than harden here, but I defer to @erights. I don’t have strong arguments either way either.

Freezing is sufficient to get Agoric SDK’s bundler to pass the existing tests. It is a likely best practice to harden the `globals` on the way in (Compartment “endowments”).

One advantage of leaving the choice to `harden` to the user is that we don’t need to expose any API to disable the default hardening. We _will_ need to have an API to disable the `freeze`, for packages that depend on mutability of their compartment-isolated globals. Unfortunately, there’s no way to freeze the `globalThis` for every subcontained compartment from the outside—expressing that override in `package.json`s is the way to go.

### @kriskowal (MEMBER) — 2020-10-27T17:24:10Z

We’ve resolved that freeze is a strange middle ground between doing nothing and hardening. Hardening creates complications because it requires lockdown, and lockdown implies realm control, the archiver should not have realm control, and the archiver runs this code. So, for now, the simplest way forward is to do nothing and relax the tests in Agoric SDK, at least specifically for the compartment map bundle.
