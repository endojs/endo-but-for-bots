## Description

Add an experimental Tor netlayer implementation for `@endo/ocapn` with Goblins/Guile-compatible onion transport conventions.

### What changed

- Added `packages/ocapn/src/netlayers/tor.js` with:
  - Tor control socket integration (`AUTHENTICATE`, `ADD_ONION`)
  - Ephemeral and restored onion identity support (`privateKey` + `serviceId`)
  - OCapN location emission as `transport: 'onion'`, `designator: <service-id>`, `hints: false`
  - SOCKS5 onion dialing to `<designator>.onion:9045`
  - Connection reuse and shutdown/resource cleanup
  - Exported helper functions for command/reply parsing and SOCKS frame handling
- Added focused tests in `packages/ocapn/test/tor-netlayer.test.js` for:
  - Tor control command construction
  - `ADD_ONION` reply parsing
  - SOCKS5 request/reply framing and error handling
- Updated API-surface walk entry points to include `TorNetLayer` in `packages/ocapn/test/api-surface.test.js`.
- Added Tor netlayer usage/setup/interoperability notes to `packages/ocapn/README.md`.
- Follow-up lint/type cleanup commit for the new Tor files.

### Security Considerations

- The netlayer talks to Tor over local unix sockets and does not spawn Tor itself.
- `privateKey` support is opt-in for stable identities; this value should be handled as sensitive material by callers.

### Scaling Considerations

- No meaningful change in asymptotic behavior versus existing netlayer patterns.
- One local unix listener socket and one Tor control socket per netlayer instance.

### Documentation Considerations

- README now documents expected Tor daemon setup, defaults, and Goblins-compatible behavior.

### Testing Considerations

- `yarn lint` in `packages/ocapn` passes.
- `yarn test test/tor-netlayer.test.js` in `packages/ocapn` passes.

### Compatibility Considerations

- Keeps existing netlayers unchanged.
- Tor defaults intentionally align with Goblins conventions (`onion`, service-id designator, port `9045`).

### Upgrade Considerations

- Additive change only; no migration required.
