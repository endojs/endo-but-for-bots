## Description

Moves the Signal integration out of `@endo/fae` and into a dedicated
package: `@endo/daemon-signal`.

This package provides a standalone Signal bridge for controlling Endo daemon
agents over Signal messages via `signal-cli`.

Critical files to review:
- `packages/daemon-signal/src/signal-bridge.js`
- `packages/daemon-signal/src/signal-policy.js`
- `packages/daemon-signal/src/signal-command.js`
- `packages/daemon-signal/src/signal-cli.js`
- `packages/daemon-signal/tools/signal-bridge.js`
- `packages/daemon-signal/setup-tools.js`

Structure added:
- New package `packages/daemon-signal/` with:
  - package metadata/scripts (`package.json`, `tsconfig.json`)
  - public entry points (`index.js`, `bridge.js`, `transport.js`)
  - setup script (`setup-tools.js`)
  - tool caplets (`tools/signal-cli.js`, `tools/signal-bridge.js`)
  - runtime modules (`src/signal-*.js`)
  - unit tests (`test/signal-command.test.js`, `test/signal-policy.test.js`)

Behavior implemented:
- `signal-cli` transport wrapper (`receive`, `sendDirect`, `sendGroup`)
- inbound policy gates:
  - ignore senders without configured daemon agent
  - in group chats, ignore messages unless they start with configured account
    mention prefix
- slash command parsing and execution:
  - `/help`, `/enter`, `/exit`, `/who`, `/inventory`, `/show`, `/send`
- conversation state keyed by (agent, thread)
- plain text forwarding to active conversation target
- `@petname` token extraction for outbound object references
- inventory metadata rendering using identifier + locator-derived formula type

Migration cleanup:
- removed all Signal-specific files/scripts from `packages/fae`
- updated `packages/fae/README.md` to point Signal users to
  `packages/daemon-signal/README.md`

### Security Considerations

Introduces authority to call local `signal-cli` from unconfined tooling, and to
forward message content into daemon mail APIs.

Mitigations in this change:
- sender->agent mapping is explicit (`agentForSender`) and required for ingress
- group ingress requires explicit leading mention prefix
- no implicit execution of arbitrary shell from Signal payloads
- forwarding path uses existing host mail interfaces and petname resolution

Residual risk:
- any configured sender can ask the mapped agent to forward messages and object
  refs; this depends on mapping hygiene and Signal account trust boundaries.

### Scaling Considerations

Polling uses bounded `signal-cli receive --timeout` windows and processes each
batch sequentially.

Potential cost drivers are message volume and inventory listing depth for
`/inventory` commands.

### Documentation Considerations

New package docs at `packages/daemon-signal/README.md` cover setup, config,
commands, and policy behavior.

`packages/fae/README.md` now points to daemon-signal for Signal integration.

No daemon data migration is introduced.

### Testing Considerations

Added unit tests in daemon-signal:
- `packages/daemon-signal/test/signal-command.test.js`
- `packages/daemon-signal/test/signal-policy.test.js`

Executed in this branch:
- `npx corepack yarn workspace @endo/daemon-signal lint`
- `npx corepack yarn workspace @endo/daemon-signal test`

(Only warning-level lint findings remain for safe-await-separator patterns.)

### Compatibility Considerations

This is additive via a new package and a relocation of Signal integration code.

`@endo/fae` retains its existing agent/tool behavior; only Signal-specific
files/scripts were removed from that package.

### Upgrade Considerations

Users should run Signal setup from `packages/daemon-signal`:
- `SIGNAL_ACCOUNT=... yarn setup-tools`

No breaking protocol/data migration changes introduced.
