## Description

This PR implements Yarn's catalog feature to centralize the management of testing dependencies across the monorepo, eliminating the manual effort required to keep versions in sync.

## Changes Made

**Updated Yarn to 4.10.3** as specified in the issue to access the catalog feature.

**Created a testing catalog** in `.yarnrc.yml` that defines centralized versions for commonly used testing dependencies:

```yaml
catalogs:
  testing:
    ava: ^6.4.1
    c8: ^7.14.0
    tsd: ^0.32.0
```

**Updated all package.json files** to reference the catalog instead of hardcoded versions. For example:

```json
"devDependencies": {
  "ava": "catalog:testing",
  "c8": "catalog:testing", 
  "tsd": "catalog:testing"
}
```

## Impact

- **39 packages** now reference `ava` through the catalog (previously all using `^6.4.1`)
- **32 packages** now reference `c8` through the catalog (previously all using `^7.14.0`)
- **13 packages** now reference `tsd` through the catalog (previously all using `^0.32.0`)
- **84 total dependency references** now centrally managed

## Benefits

- **Single source of truth**: Testing dependency versions are now defined in one location
- **Reduced maintenance**: Future updates require changes in only `.yarnrc.yml` instead of across multiple packages
- **Consistency guarantee**: Eliminates version drift between packages
- **Simplified updates**: Dependencies can be updated project-wide with a single change

TypeScript was initially considered for the catalog but excluded due to resolver compatibility issues with the current Yarn version. The catalog successfully addresses the core issue for the primary testing dependencies that required manual synchronization.

All tests pass and builds work correctly with the new catalog-based dependency management.

Fixes #2965.
