## Summary

- **What:** Major upgrade to `package.json` `browser` field handling in `@endo/compartment-mapper`: replaces the `exports` graph node with `externalAliases`/`internalAliases`, makes `inferExports` return relative paths, threads `tags` through `ArchiveOptions`, and supports `false` ignores plus dependency-to-dependency rewrites.
- **Why:** Bundlers targeting browsers rely on these `browser` field semantics, and metamask-extension exposed many gaps.
- **Themes:** compartment-mapper, bundle-source, ecosystem-compat
- **Status:** merged

## Description

Significantly improves support for `browser` field resolution, used by bundlers to resolve alternate modules when targeting builds for the browser environment.

 :sparkles: commits are intended to be individually reviewable :sparkles: 

**changes summary:**
- `importHook` will return a redirect and update the `compartmentMap` if a candidate is present in its `moduleDescriptors`
- replace `exports` with `externalAliases` (like `exports` field) and `internalAliases` (like `imports` field?). `browser` field can affect both
- changes result of `inferExports` to be relative, allowing the aliases to be mounted on different base names (as in browser field induced package aliases)
- adds `tags` field to `ArchiveOptions` and allows passing tags through from bundler
- various readability improvements and guards with informative error messages
- expands compatibility with `browser` field of `package.json`, see "features" section below

**feature:**
- browser field can override the main field
- browser field as an object can include `false` values implying "ignore"
- browser field as an object can replace:
  - local modules with other local modules
  - dependencies with other local modules
  - dependencies with other dependencies
