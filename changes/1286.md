## Summary

- **What:** Draft test demonstrating that `Error` is not extensible inside a Compartment under `errorTaming: 'unsafe'`, so `Error.prepareStackTrace = …` and `Error.captureStackTrace` are unavailable.
- **Why:** LavaMoat needs the V8 Error API to function inside Compartments for packages like `depd` that set stack-trace formatters.
- **Themes:** ses-lockdown, compartments, errors, ecosystem-compat, tests
- **Status:** closed-unmerged

## Description

A basic test showing that Error is no longer extensible even if lockdown did leave it at that with errorTaming: 'unsafe'

Test fails with 
```
  TypeError {
    message: 'Cannot add property prepareStackTrace, object is not extensible',
  }
```

Am I missing something obvious? If I am, LavaMoat is also missing it ;)

### @naugtur (MEMBER) — 2022-09-14T08:43:53Z

@kriskowal yes, this test should be the full extent.
`depd` package is the most elaborate example of common usage pattern. (and not the best one because we're hoping to get it to switch to a bundler mode where it won't make any stacktraces, but I digress)

Setting `Error.stackTraceLimit`and calling `Error.captureStackTrace(obj);` is the most common (simpler) way of using this. This is the absolute minimum we need

Providing a prepareStackTrace `Error.prepareStackTrace = prepareObjectStackTrace;` is more elaborate, because the second argument to the function is an object model of the stack trace and whatever the function returns is then stored on Error.stack for errors thrown in that Realm. In our case that'd be the Compartment instead. If we can emulate that behavior under unsafe error taming, it'd be a great boost to debugability.

Addressing the question from @erights 
- writing to Error.prepareStackTrace throws `'Cannot add property prepareStackTrace, object is not extensible',` inside a compartment, but not outside a compartment. This test was added to a file that already tests the same bit of code and there it works under lockdown.
We have a difference in behavior between just lockdown and lockdown+compartment
- `Error.captureStackTrace is not a function` is thrown if I remove the lines attempting to assign prepareStackTrace
