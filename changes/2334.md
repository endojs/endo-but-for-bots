## Summary

- **What:** Adapts the `ses` shim so it compiles cleanly under Hermes (the React Native compiler) by feature-detecting and dropping async generators / async-function arrows from `permits.js`, `get-anonymous-intrinsics`, and `module-load.js` (refs #1891, fixes #2474).
- **Why:** Hermes parses but cannot codegen `async function*`/async arrows, causing `react-native bundle-android --mode=release` to crash with `StackOverflowError`; this lets RN release builds use SES.
- **Themes:** ses-lockdown, ecosystem-compat, performance
- **Status:** merged

<s>Add lockdown shim compatible with Hermes</s>
Make current shim compatible with Hermes compiler
for building React Native (RN) prod apps with SES

Generating the release AAB ([Android App Bundle](https://reactnative.dev/docs/signed-apk-android#generating-the-release-aab))
i.e. `npx react-native build-android --mode=release` via RN CLI
calls Gradle's `bundleRelease` task under the hood (`bundle` build task on `release` variant)
which calls RNGP ([React Native Gradle Plugin](https://reactnative.dev/docs/react-native-gradle-plugin)) React task [`createBundleReleaseJsAndAssets`](https://github.com/facebook/react-native/blob/3af01a8a44853246d3deb957c4a1c65e43848bb5/packages/gradle-plugin/react-native-gradle-plugin/src/main/kotlin/com/facebook/react/TaskConfiguration.kt#L58) and fails
after Metro [finishes](https://github.com/facebook/react-native/blob/c25246044f51b770ff1e090d6b4ec78d41ec917f/packages/community-cli-plugin/src/commands/bundle/saveAssets.js#L109) writing the release bundle (bundle, sourcemaps, assets)

Gradle emits these Hermes errors
- [`async functions are unsupported`](https://github.com/facebook/hermes/blob/main/lib/IRGen/ESTreeIRGen-func.cpp#L213-L217)
  - https://github.com/facebook/hermes/issues/1395
- [`async generators are unsupported`](https://github.com/facebook/hermes/blob/main/lib/AST/SemanticValidator.cpp#L798-L800)

(at runtime we can see both are [`SyntaxError`](https://github.com/facebook/hermes/blob/main/tools/hermes-parser/js/hermes-parser/src/utils/createSyntaxError.js)s)
Resulting in vague `java.lang.StackOverflowError (no error message)`

The try/catch approach testing language ft support via a new fn works
since RNGP no longer emits the Hermes errors in the task after Metro bundles
and we're conditionally using parts of SES compatible with the Hermes engine

The initial approach involved building a new shim via an env var
which involved a lot of duplicates `/src` files

Nb: clean before bundling to see changes reflected (avoid cache)
i.e. `./gradlew clean :app:bundleRelease`

Nb: `async function* a() {};` alone won't emit an error
but using/referencing it and beyond `const b = a;` will

Nb: eventually we hit RNGP [BundleHermesCTask.kt](https://github.com/facebook/react-native/blob/00d4d9c63204a786680059c25a0a0cb9753d1cdc/packages/gradle-plugin/react-native-gradle-plugin/src/main/kotlin/com/facebook/react/tasks/BundleHermesCTask.kt#L93) > run > detectedHermesCommand > detectOSAwareHermesCommand from [PathUtils.kt](https://github.com/facebook/react-native/blob/00d4d9c63204a786680059c25a0a0cb9753d1cdc/packages/gradle-plugin/react-native-gradle-plugin/src/main/kotlin/com/facebook/react/utils/PathUtils.kt#L114-L161), which calls the Hermes compiler default command `hermesc` - the path of the binary file, to create the optimised bytecode bundle to load/exec at runtime
