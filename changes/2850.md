## Summary

- **What:** Lets `@endo/pass-style` and `@endo/patterns` types accept a nominal `RemotableBrand` anywhere a structural `RemotableObject` is accepted, deprecates `RemotableObject`, and corrects misused `Remotable` annotations.
- **Why:** Brand-tagging existing types is structurally compatible while `RemotableObject` propagates structurally and breaks call sites; agoric-sdk's typing migration drove this.
- **Themes:** pass-style, patterns, types
- **Status:** merged

## Description

Refs: https://github.com/Agoric/agoric-sdk/pull/11454

## Description

In some cases, a remotable object may have a `RemotableBrand` type but not a `RemotableObject` type. This is because the former can easily be "tagged" onto an existing type (as a nominal type without public properties), but the latter would cause type checking issues (as a structural type).

This change enables pass-style and pattern types to accept `RemotableBrand` wherever a `RemotableObject` is accepted as a remotable passable cap.

Based on feedback, this also marks `RemotableObject` as deprecated, and fixes a few mistaken usages of `Remotable` instead of `RemotableObject`.
