## Description

## exploring endo daemon ui
building on top of `preact` rewrite of @kriskowal's initial ui https://github.com/endojs/endo/pull/1876

### demo features:
- profile switching
- basic inventory
- chat with sending object references
- adopting objects
- adopting/installing apps (re-formulated with own powers)
- opening installed apps in new tab
- 1kce game prototype included

based on this presentation by Spritely Institute https://youtu.be/T8uqHCo10I8

### Changes to Daemon required:
- [x] expose formula `type` to subscribers. primarily for customizing ui interactions (eg "adopt object" vs "install app")
  - [x] https://github.com/endojs/endo/pull/1997
- [x] expose formula `id` (?) to subscribers for comparing values in messages (packages) to own petnamed values. primarily for reverse lookup of names in packages messages
  - Get rid of notion of "id" and just use identity `number` instead.
  - `number` will be made unforgeable.
  - [x] https://github.com/endojs/endo/pull/1997
- [ ] implement `adoptApp` feature
  - [ ] instead we should send the app bundle, available via `INFO.cat.bundle` per https://github.com/endojs/endo/pull/1916
  - [ ] implement `adoptBundle` or something does something like ( adopt bundle, store bundle, importBundleAndEndow )
- [x] implement `query` + `followQuery` in petStore ( or just handle the usecase of filtering by type, or kick down the road since we'll have types on client side ) [skipped]
- [x] add sent mail to own inbox (track message `dest`, in `send(...)` call own `receive(...)`, and expose `dest` and `formulaIdentifiers` in `dubMessage`)
  - We are going to drop `dubMessage`, but @kriskowal will do it.
  - [x]  https://github.com/endojs/endo/pull/2004
- [x] eval evade for web bundle
  - [x] https://github.com/endojs/endo/pull/2003
  - [x] or  #2007

### TODO/improvements:
