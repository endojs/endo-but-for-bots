## Summary

- **What:** Fixes `@endo/ses` so that when module A re-exports name X from module B and module C imports X from A, executing C no longer throws `SyntaxError` at the recognition check in `module-instance.js`; encountered against `terser`.
- **Themes:** ses-lockdown, ecosystem-compat
- **Status:** merged

## Description

## Description

This fixes a situation in which module _A_ re-exports name _X_ from module _B_, and then imports module _C_, which in turn imports _X_ from _A_.

Prior to this change, the named export _X_ would not be recognized as being exported by _A_ when executing _C_; a `SyntaxError` would be thrown:

https://github.com/endojs/endo/blob/e7f0f29bcffd5be97f0316a69656d8958b904b85/packages/ses/src/module-instance.js#L387-L389

Originally encountered in the source code for `terser`.

**This change needs a close reading,** as I'm not confident in its correctness.

### Example

```js
// a.js
export { x } from './b.js';
import './c.js';
```

```js
// b.js
export const x = 'x';
```

```js
// c.js
import { x } from './a.js';
```
