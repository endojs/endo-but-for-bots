## Summary

- **What:** Builds `ses`'s safe `Function` constructor by chaining two calls to the original unsafe `Function` to dodge the `new Function('/*', '*/) {')` validation bypass (tc39/ecma262#2374).
- **Why:** Workaround for XS still being vulnerable to the comment-injection trick.
- **Themes:** ses-lockdown, security
- **Status:** merged

## Description

It seems that XS may still be vulnerable to the attack explained at https://github.com/tc39/ecma262/pull/2374#issuecomment-813769710 where `new Function('/*', '*/ ) {')` would incorrectly validate.

With this PR, SES builds a correct safe `Function` constructor by composing two calls to an original unsafe `Function` constructor that may suffer from this bug but is otherwise correctly validating. This assumption seems to be true of all major JavaScript engines including XS.

Mysteriously, at
https://github.com/endojs/endo/blob/e9199f41c511b5df10593d931febdd90693b011a/packages/ses/test/test-break-function-eval.js#L69
we already test that this case is properly rejected. If XS has this bug, then prior to this PR this test should have failed on XS. It would be good to resolve this mystery before merging this PR. Attn @dckc @phoddie

(Later)
@dckc reports that this case is currently failing under XS. Mystery solved. Merging.

Fixes https://github.com/endojs/endo/issues/665
