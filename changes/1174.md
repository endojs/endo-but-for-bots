## Summary

- **What:** Garbage-collects unused compartments out of `@endo/compartment-mapper` archive output so unused-package versions/positions don't perturb the bundle hash, plus drive-by absolute-export and redundant-relativize fixes.
- **Why:** Reduce hash drift between `yarn install` and `yarn install --production`, which differ in dev-only packages.
- **Themes:** compartment-mapper, bundle-source, performance
- **Status:** merged

## Description

This change causes archives and bundles to have smaller compartment maps and to
create fewer compartments at runtime.
The motivation for this change is to reduce the probability that a vagary of
`yarn`, like the difference in behavior between `yarn install` and `yarn
install --production` on the hash of resulting bundles, by making the versions
and positions of of unused packages irrelevant.

- fix(compartment-mapper): Package exports may be absolute
- refactor(compartment-mapper): Avoid redundant relativize
- test(compartment-mapper): Test compartment map retention
- feat(compartment-mapper): Archives retain compartments only for retained modules
- docs(compartment-mapper): Update news for archive compartment retention
