## Description

This is a stack of changes to improve the experience of using the `bundle-source` command.

* Increases the sensitivity of the cache key: any deviation from the last known mtime (even in regress) as well as a change in size will cause a bundle to be regenerated.
* Replaces the lockfile mechanism with atomic renames. POSIX systems guarantee that `rename` is atomic if the file remains on the same volume and we can guarantee that the file remains on the same volume by keeping it in the same directory. So we create a scratch file including the PID of the writing process (and a consistent extension so they’re easy to delete if the bundler exits prematurely.) Then, we capture the mtime and size of the scratch and rename the extension off. This ensures that we capture the mtime and size of the file we wrote, even if there are concurrent processes generating the same bundle. The new failure mode is duplication of effort. Stray scratch files do not interfere with progress on subsequent runs.
* The bundler only loads the dependencies necessary for the requested formats. So, if you only generate Endo Zip Base 64 bundles, we no longer import Rollup. Likewise, if you only generate Get Exports or Nested Evaluate, you do not import the Compartment Mapper.
* Debug logs will appear only if the `DEBUG` environment variable is a comma separated list including `bundle-source`.
* Factors out `transform.js` and `fs.js` in expectation that these will be the bases of new packages. The evasive transforms are useful for other bundling mechanisms like WebPack and the file system module is a good place to start for a hardened file system for the Pet Daemon.

### Security Considerations

No known implications

### Scaling Considerations

This should improve performance of the bundler.

### Documentation Considerations

Usage of the bundler does not change, but the `DEBUG=bundle-source` directive may be useful to end users in the event that the bundler misbehaves.

### Testing Considerations

I’ve manually tested the bundler tool on `demo/circular/a.js` and `demo/circular/b.js`, inducing cache misses by touching or adding newlines to these files, and manually invalidating the `meta` file. In all cases, the tool converged on cache hits.
