## Description

This PR introduces the ability to disable formula garbage collection in the Endo daemon at startup. This is primarily a debugging aid, allowing operators to diagnose GC-related issues without rebuilding the daemon from source.

**Key changes include:**

*   **`packages/daemon/src/daemon.js`**: `makeDaemonCore` now accepts a `gcEnabled` option (default `true`) to control formula collection. A log message is emitted when GC is explicitly disabled. This option is threaded through `provideEndoBootstrap` and `makeDaemon`.
*   **`packages/daemon/src/daemon-node.js`**: Reads the `ENDO_GC` environment variable (`'0'` to disable) and passes the resulting `gcEnabled` flag to `makeDaemon`.
*   **`packages/daemon/index.js`**: The public `start()` and `restart()` functions now accept a `gcEnabled: false` option, which sets `ENDO_GC=0` in the child process environment.

## Security Considerations

This change introduces a debugging option to disable garbage collection. While disabling GC could lead to increased memory consumption, it is an explicit opt-in for debugging purposes and does not introduce new attack surfaces or authorities.

## Scaling Considerations

Disabling garbage collection will prevent the reclamation of memory used by formulas, leading to increased RAM consumption over time. This is an intentional consequence when the `gcEnabled` option is set to `false` (or `ENDO_GC=0`), used specifically for debugging and not intended for production use without careful consideration.

## Documentation Considerations

Users should be informed about:
*   The `ENDO_GC` environment variable (set to `0` to disable GC).
*   The `gcEnabled: false` option for the `start()` and `restart()` functions in `packages/daemon/index.js`.
No backwards compatibility issues or data migration steps are required.

## Testing Considerations

Existing unit tests should continue to pass. Additional manual testing is needed to verify the acceptance criteria:
1.  `ENDO_GC=0 endo start` produces a log line confirming GC is disabled.
2.  `ENDO_GC=0 endo restart` also disables GC.
3.  Omitting `ENDO_GC` or setting `ENDO_GC=1` (or `gcEnabled: true`) maintains existing GC behavior.
4.  The public `start()` API's `gcEnabled: false` option works as expected.

## Compatibility Considerations

This change is additive. It introduces new options (`ENDO_GC` environment variable and `gcEnabled` API option) and does not break any prior usage patterns.

## Upgrade Considerations

No specific upgrade steps are required. This is an opt-in debugging feature that does not affect existing deployments unless explicitly configured.
