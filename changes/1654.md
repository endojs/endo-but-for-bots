### @mhofman (CONTRIBUTOR) — 2023-06-27T04:01:55Z

> Either the object always has the same identity for all `fn(arg)` calls, as with reproducibility, or it has a fresh identity per call, as with fresh allocation by the call. This weaker guarantee is "determinism", which we define to allow such always-fresh but otherwise equivalent.

> But even meeting all these requirements, the
resulting memoization is observable because it turns observably distinct identities into observably shared identities.

Oh this is a good call. I hadn't though about the memoization being observable if the return value is equivalent but newly allocated every time. That seem to indicate that a generic memoization feature would not only need to prevent side effects of the memoized function, but also capture which allocations are observable in the results, and replicate those for every cached result.

One tempting naive approach to accomplish this replication in our environment might be to marshal encode then decode the result for every memoized call, however because of promises you effectively have to apply a membrane-like transform to any promises within the result.
