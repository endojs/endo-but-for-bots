## Summary

- **What:** Adds an `errorTrapping` lockdown option to `ses` that traps `uncaughtException`/`unhandledRejection` (and the web equivalents) and routes errors to the tamed console so stacks are revealed instead of being printed as `{}`; supports `report`, `exit`, `abort`, `platform`, `none` modes.
- **Why:** Fixes #769 — Node and the web censor stacks on uncaught errors so users only saw `{}`; reviewers required parameterizing the policy so unprivileged code cannot force `process.exit`.
- **Themes:** ses-lockdown, errors, security
- **Status:** merged

## Description

Errors are reported as `{}` when they are caught by Node.js or the web runtime because their stacks are censored. They must be caught with a platform hook and passed to the tamed console to reveal their stack. 

- test(ses): Test error output on Node.js (a failing test)
- fix(ses): Trap and report errors (fixes failing test)

Must be merged to keep the left traversal on git bisectable with passing tests.

### @kriskowal (MEMBER) — 2021-06-08T21:35:43Z

Summarizing out-of-band conversation with @erights and @dckc:

We’ve decided that the behavior for uncaught errors needs to be parameterized on lockdown options and default to platform-emulation, with the right reserved to change the behavior. The behaviors may be `report`, `reload`, `exit`, `abort`, or `platform`.

- `report` *just* report the error to the virtualized console, revealing the stack trace to the underlying platform console, whatever was present when the shim was initialized.
- `reload` reboots, restarts, or reloads. (aspirational goal)
- `exit` report and exit with an exit code, -1 if no exit code was previously supplied. On the web, this amounts to hitting a breakpoint if the debugger is open and navigating away.
- `abort` report and exit with a core dump or navigate away. In Node.js, `process.abort()`.
- `platform` is consistent with the underlying behavior when an exception is not caught. On the web, this is an error report and resume. On Node.js, it’s an error report and exit. This will be the provisional default.

I’ve implemented an `errorTrapping` option for `lockdown`, as described in my comment about intent.

I was flummoxed by a failing integration test for a while. The problem was that Parcel saw the `process` free variable and tried a little too hard to be helpful. The solution was to spell `process` as `globalThis.process` and that was sufficient to avert the gaze of 👀📎Clippy.
