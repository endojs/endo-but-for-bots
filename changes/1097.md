@mhofman Am I wrong that this indicates a `yarn` bug is in play?

---

### @mhofman (CONTRIBUTOR) — 2022-03-01T20:26:02Z

No, yarn is conservative and attempts to not introduce changes to existing packages. So when introducing a package with semver constraints that cannot be satisfied by existing packages, it adds a new package, but it does not remove the existing package even if the semver constraints that required it are also satisfied by the new package. Over time this leads to a lot of duplicate packages that can in practice be deduplicated without issues.
