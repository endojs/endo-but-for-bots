## Description

This PR adds a JavaScript implementation of the Guile Goblins `goblin-chat` backend to enable OCapN interoperability testing between Endo and Goblins peers. It includes:

1. **`packages/ocapn/test/goblin-chat/backend.js`** — A direct port of the Guile Goblins `(goblin-chat backend)` module, implementing:
   - `makeChatroom`: Creates a chatroom that manages subscriptions and broadcasts messages to connected users
   - `makeUserControllerPair`: Spawns a user and its controller, handling subscription sealing/unsealing and message encryption
   - `spawnSealerTriplet`: A helper for creating sealer/unsealer/sealed? triplets using WeakMaps to prevent forgery across peer boundaries
   - Method names use kebab-case to match Goblins' CapTP selector symbols

2. **`packages/ocapn/test/goblin-chat/index.js`** — A runnable host that:
   - Registers a chatroom on the tcp-testing-only netlayer
   - Prints both a peer locator and chatroom sturdyref for remote clients to connect to
   - Supports configurable room name and port via CLI args and environment variables

3. **`packages/ocapn/test/goblin-chat/interop-client.scm`** — A minimal Guile interop client that:
   - Connects to the Endo chatroom host via sturdyref
   - Joins the room and sends a test message
   - Validates the round-trip by checking the ack response

4. **`.github/workflows/ocapn-guile-interop.yml`** — A new CI workflow that:
   - Builds Endo and starts the goblin-chat host
   - Sets up a Guix environment with Goblins dependencies
   - Runs the Guile interop client against the Endo host
   - Validates bidirectional OCapN communication between JavaScript and Guile

5. **`packages/ocapn/src/netlayers/tor-setup.md`** — Prospective documentation for a future Tor netlayer (not yet implemented), describing the expected operator-facing setup and API so eventual implementation has a stable target.

6. **`packages/ocapn/test/goblin-chat/README.md`** — User-facing documentation explaining how to host a chatroom, drive it from Goblins, and the app-layer surface that matches the Guile implementation.

### Security Considerations

The sealer/unsealer pattern uses WeakMaps to ensure sealed handles that escape to other peers carry no value and cannot be forged. This matches the Goblins approach and maintains the security boundary between mutually-suspicious components.

### Testing Considerations

The new CI workflow (`ocapn-guile-interop.yml`) provides automated interop testing. It:
- Builds Endo and starts the chatroom host
- Installs Guix and Goblins dependencies
- Runs a Guile client that joins the room and sends a message
- Validates successful round-trip communication

The workflow is marked `continue-on-error: true` since it's scaffolding that may require iteration on module paths and Guix manifests.

### Compatibility Considerations

This is a new test utility and does not affect existing APIs or deployments. It enables new interop testing capabilities without breaking changes.

### Documentation Considerations

- `README.md` documents the chatroom API surface and how to use it from Goblins
- `tor-setup.md` provides prospective guidance for operators who will eventually use a Tor netlayer
- Inline JSDoc comments in `backend.js` document the port from Guile and explain design choices (e.g., why controller-only methods are closed-over rather than warden-gated)
