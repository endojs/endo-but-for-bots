## Summary

- **What:** Makes `deeplyFulfilled` in `@endo/marshal` always return a promise, including for already-fulfilled inputs and synchronous error cases.
- **Why:** Normalizing the return type removes case analysis for callers who otherwise had to treat the immediate result and the error path differently.
- **Themes:** marshal, eventual-send, errors
- **Status:** merged

## Description

I already manually checked all uses in the endo and agoric-sdk repository. It looks like this change will be harmless. The advantage (discussed in private chat) is that it normalized the outcome of `deeplyFulfilled` to always be a promise, even if
   * the argument was already deeply fulfilled, i.e., a Passable without promises
   * an error needs to be reported, even if the error is immediate, e.g., the argument is not Passable

This normalization of the outcome, especially for the error case, should reduce the case analysis burden on callers.
