### @naugtur (MEMBER) — 2022-02-10T13:08:16Z

Reasons why the test is failing:
1. package.json includes `evan` as dependency but it doesn't exist. 
- removed evan
2. The requested module './module-exports-assigned-object.cjs' does not provide an export named 'default'
`esmcjs/module-exports-assigned-object.cjs` triggers a bug in cjs-module-analyzer where exporting an object with a field that doesn't contain a reference to something defined earlier is not recognized as export.  
(edit) Found out it's a known behavior: [test](https://github.com/endojs/endo/blob/master/packages/cjs-module-analyzer/test/test-cjs-module-analyzer.js#L582)
(edit) Added some [test cases](https://github.com/endojs/endo/pull/1070) to discuss
- changed the fixture to 
```js
const a = {
  name: 42,
};
module.exports = a;
```
2.1. BTW, when changed to 
```js
const name = 42;
module.exports = { name };
```
we're back to "does not provide an export named 'default'"
3. SyntaxError: The requested module './module-exports-assigned-object.cjs' does not provide an export named '*'
- hacked `'*'` into the right exports array for now
4. Cannot read properties of undefined (reading 'default')
And that's despite moduleExports.default being set to the correct value in parse-cjs->execute and the default property getter+setter being present  
- To be continued...

----

Continuation:  
cjs-module-analyzer can probably stay as is.

The root cause of the issue seems to be:  
`imports` function from `makeModuleInstance` expects notifiers for `default` and `*` to exist. Meanwhile `makeThirdPartyModuleInstance` is not guaranteed to define a notifier for `default` and does not create a notifier for `*` at all
