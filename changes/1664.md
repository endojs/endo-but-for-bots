### @erights (CONTRIBUTOR) — 2023-07-03T07:14:00Z

@phoddie 
> It is more severe! Seems fine. I understand that this is more developer-friendly for non-function-valued properties. For function-valued properties, is there a benefit to this approach over the previous one?

Only two things:
   * consistency with non-function valued properties, if we agree that this severe approach is right for those.
   * sometimes code picks up a function to call later. This detects the error as soon as possible.

OTOH this level of severity may break that reflectively discovers all the properties of an object, like `Object.assign`. To mitigate this I made the poisoned properties non-enumerable. See the extended comment in the code about why this may work surprisingly well.
