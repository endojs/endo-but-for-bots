## Summary

- **What:** Refactors `@endo/captp` into a reusable "captp engine" core, breaking out `makeRefCounter`, dispatch, send, ser/deser, eager promise resolution forwarding, trap, `getBootstrap`, `makeRemoteKit`, and GC-message export collection into separate modules with preserved call order and richer types.
- **Why:** Lets the OCapN implementation reuse CapTP's c-table machinery; closed pending OCapN consolidation.
- **Themes:** captp, ocapn, eventual-send, types
- **Status:** closed-unmerged

## Description

In working on the OCapN implementation I was studying CapTP internals.
I managed to incrementally extract a reusable core "captp engine", mostly just c-table mgmt.

I took great care to preserve all functionality and call order, and make commits individually reviewable.
also increased type coverage as I went to aide the refactoring.
