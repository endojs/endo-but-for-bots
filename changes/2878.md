## Summary

- **What:** Adds `enforcePackagePolicyByPath()` to `@endo/compartment-mapper`'s `findRedirect()`/`importNowHook()` so a compartment can dynamically require a module from an unrelated `CompartmentDescriptor` when policy explicitly allows it; refactors out `policyEnforcementFailureMessage()`, narrows `PolicyOption`, and adds composable type guards (`or`/`and`/`not`) in `policy-format.js`.
- **Why:** Closes #2876 where dynamic requires across policy-linked-but-unrelated compartments were rejected.

## Description

Closes: #2876

## Description

- This adds `enforcePackagePolicyByPath()` which accepts two (2) `CompartmentDescriptor`s (_A_ and _B)_ and determines if _B_ is allowed access to _A_ via package policy.  `findRedirect()`, called by `importNowHook()`, now uses this if it cannot enforce policy any other way.  This solves the issue described in [#2876](https://github.com/boneskull/endo/issues/2876), which is that a package needs to dynamically require a module from an otherwise-unrelated-except-by-policy `CompartmentDescriptor`. This _cannot_ happen if policy is not defined.

    Slightly changed the existing error hint to differentiate this case.

- Tangential to this change, I refactored some policy-related things while I was debugging:
    - Adds a reusable function, `policyEnforcementFailureMessage()`, to generate helpful error messages when policy enforcement fails
    - Narrows `PolicyOption` type (to have field of type `SomePolicy` instead of `any`)
    - Loosens `FullAttenuationDefinition` type, wherein `params` is actually an optional field per the extant test suites
    - `policy-format.js`:
      - Moves `generateCanonicalName()` here
      - Updates `PackageNamingKit.name` for use in this context
      - Adds many more type guards and assertions for validation. Some of these are likely useful elsewhere in the codebase, but I have not exported any new type guards.
      - Adds `or()`, `and()` and `not()` which can be used to compose type guards in a type-safe way (e.g., `or([isString, isArray])`)
      - Moved `ATTENUATORS_COMPARTMENT` here to avoid cycle
    - Added some helpers to `typescript.ts`
    - Update snapshots to reflect slight changes to error messaging

- Updated the `mermaid-deptree` script to take non-production-dependencies into account

### Security Considerations

See #2876.  This opens up what can be dynamically required via absolute path by any given `Compartment`, but _only_ works if package policy is defined—unlike current policy enforcement.

### Upgrade Considerations

This updates the `PolicyOption` external-facing type which has potential to affect consumers; it is more strict about the shape of the `policy` object provided to `policy`-accepting public APIs. Mitigating this is that runtime policy validation would throw an exception if the policy was invalid--so probably not that big of a deal.
