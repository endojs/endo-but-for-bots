I researched it more and this is a good heuristic but it's not what others are doing.

the field being named 'import' doesn't actually mean it should be interpreted as esm. It just so happens that all packages I've encountered to date point those fields at files with mjs extensions or locaded in folders with a type:module package.json file.

The implementation that'd be fully valid would need to collect all inferred types, check their folder trees for package.json files and decide the formats based on that.
