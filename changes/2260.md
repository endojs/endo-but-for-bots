## Summary

- **What:** In `ses`, ships `.d.cts` declarations alongside the existing `.d.ts` so CommonJS consumers can resolve types under TypeScript 5.5's stricter file-extension/`package.json` resolution.
- **Why:** TS 5.5 forbids importing types from a `type: module` package unless the file is named `.d.cts`, breaking CJS users of `ses`.
- **Themes:** ses-lockdown, types, ecosystem-compat
- **Status:** merged

## Description

Due to changes in TS v5.5, CJS consumers cannot import types from a `type: module` package unless the declaration file has the `.d.cts` extension. This may or may not work the other way.

See [the v5.5. beta announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-5-5-beta/#respecting-file-extensions-and-packagejson-in-other-module-modes) for further explanation.
