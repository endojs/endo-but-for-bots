## Summary

- **What:** Refactor `@endo/ses` Error/Date/Math tamings so their modules are unconditionally invoked by lockdown and the `noTameFoo` flag is interpreted per-taming; Error taming now always replaces the constructor and installs `captureStackTrace`/`stackTraceLimit` (forwarding to the original on V8 when `noTameError` is set).
- **Why:** Fixes #8 and aligns Error/Date/Math with the RegExp pattern of giving tamed constructors their own prototype, supporting tap/test tooling that depends on V8-specific stack APIs.
- **Themes:** ses-lockdown, ecosystem-compat, errors
- **Status:** merged

## Description

Fixes #8

Replaces #11 and https://github.com/jfparadis/SES-beta/pull/1

Prepared the ground for https://github.com/Agoric/SES-shim/tree/master/packages/error-stack-shim

RegExp, Error, and Date were tamed in a pattern where the tamed constructors had their own prototype rather than sharing the primordial one. 
 https://github.com/Agoric/SES-shim/tree/delta-tame-error fixed that for RegExp. But at the time I didn't realize that Error and Date also followed that pattern.

This PR fixes these so they follow the same pattern in the same way. The Math taming is also fixed to follow the parts of applicable to it.

For a given taming Foo, the `noTameFoo` flag no longer means to do nothing. Each noTame flag is passed to the individual taming module, which is now unconditionally called by lockdown. It is up to each taming how to react to the flag. RegExp, Date, and Math still do no taming when their noTame flags are truthy.

To fix #8, the Error taming ***always*** replaces the original unsafe Error constructor with the tamed one. It also always populates the tamed Error constructor with the non-standard v8-only `captureStackTrace` static method and the `stackTraceLimit` property, which it makes into an accessor property so it will still work after freezing the tamed `Error`. We support these non-standard because tap, which we use for testing, uses them.

For the sake of platform independent determinism, we install these on the tamed Error constructor whether we're on v8 or not. On non-v8, they don't do anything. On v8, if `noTameError` is truthy, they forward to the unsafeErrorConstructor, preserving platform behavior.
