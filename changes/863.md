## Summary

- **What:** `@endo/static-module-record` runs the Babel codegen with comments stripped from the AST and re-attaches them after, eliminating duplicated comments produced when a node's `trailingComments` were equal-but-not-identical to the next node's `leadingComments`.
- **Why:** Successive Babel transforms left those comment arrays distinct, and codegen's `retainLines` re-emitted both copies, fanning the source out across extra lines.
- **Themes:** compartments, ecosystem-compat, tests
- **Status:** merged

## Description

This fixes a problem with static module records duplicating comments.  The problem arises from running a babel transform on the AST produced by a prior transform, which in our case causes the trailingComments of one node to be equal but not identical to the leadingComments of a subsequent node, and the Babel codegen interpreting these as separate.  The effect is that the retainLines flag causes the codegen to attempt to fall back to its intended line number by folding subsequent lines.

This PR uses the TDD convention of posting a failing test followed by the code that fixes it, so the test can be tested by checking out the first commit and running the failing test, then verifying it passes on the second.

- test(static-module-record): Test comment duplication
- fix(static-module-record): Comment duplication
