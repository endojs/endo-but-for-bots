## Description

Makes the memoize package more robust in two ways:
- if the `arg` is not WeakKey compatible, it now errors before calling the underlying function, not after.
- if the underlying function recurs by calling its own memoization with the same `args`, that causes an error. Otherwise it could have caused an infinite regress.

### Security Considerations

Removes a possibly exploitable vulnerability. Though, even if not fixed, this potential vulnerability is highly unlikely to be exploitable.

> Nice! What led you to discovery of this gap?

@kriskowal reminding me of it in his README comment that I comment on at
https://github.com/endojs/endo/pull/3042#discussion_r2709532721

I looked at the code to determine why "after", as that did not seem like the best choice. It was to avoid an extra test prior to calling the underlying function. Adding such a test only for this purpose would be annoying, for something that might be in someone's fast path. But then the code pattern as it was didn't seem correct. To protect against recursion elsewhere, I would first set an entry to a pumpkin and then undo it. Or have some similar protection against unwanted recursion. Then I looked for what the damaging recursion would be here, which as you saw, was trickier than I expected. That's all.

If @kriskowal had not reminded me, I might never have noticed it. Certainly, I would expect this case never to be hit by benign accident. Could any of our AI tools have noticed it first if we just directed it to look for unnoticed bugs everywhere?
