## Summary

- **What:** Omnibus repackaging across `@endo/base64`, `cjs-module-analyzer`, `compartment-mapper`, `netstring`, `ses`, `ses-ava`, `static-module-record`, `syrup`, `zip`, etc.: drops Rollup, exposes finer-grain ESM entry points with self-aliased `exports`, subsumes `make-hardener` into `ses`, renames eslint/ses-ava/test262-runner under `@endo`, and removes the `parsers` straddle.
- **Why:** Prepares Endo packages to serve as the foundation for migrating Agoric SDK from `-r esm` to native Node ESM, while retaining RESM compatibility via aliased `exports`.
- **Themes:** ecosystem-compat, compartments, ses-lockdown, tooling, release
- **Status:** merged

## Description

Commits are individually reviewable and are generally divided along package boundaries.

This is an omnibus, largely mechanical change that homogenizes the current Endo treatment of packaging so we can use these modules as a foundation for migrating Agoric from using `-r esm` to using Node.js’s own module system.

To that end, all use of Rollup is removed. Packages only provide ESM entry points, and all `exports` are direct aliases for files with the same name. For example `"./encode.js": "./encode.js"`, such that code can be written like `import { encodeBase64 } from "@endo/base64/encode.js"` and NESM will see the `exports` but RESM will ignore the exports and still arrive at a working module resolution.

To make the treatment consistent, packages like Zip, Syrup, Base64, and Compartment Mapper all provide finer grain entry point modules where they did not before.

SES remains an exception. SES only provides a main entry point, but retains a `ses/lockdown` alias to ease migration from the prior incompatible version.

This change also attempts to bring more packages under the `@endo` organization heading, including eslint-config, eslint-plugin, ses-ava, compartment-mapper, and test262-runner. However, to *avoid* creating a very ephemeral `@endo/make-hardener`, this change subsumes `make-hardener` into SES.

In the process of normalizing package descriptors, this change backs out the use of `nyc` for coverage reports. These were unused and did not work. These will need to be replaced with `c8` so keeping `nyc` around isn’t purposeful.

This change audits the `"files"` entry in every package to ensure that all of the entry-points get packaged, and none of the defunct `ses` or `dist` directories get included.

This change adds an empty `build` script to every package so `yarn build` will run all of the build scripts. With this change, only SES has a build script. All of the Rollups are gone.

At this stage, the `parsers` directive in `package.json` which exists so that packages can take out `type: module` and straddle RESM/SESM has become superfluous and been removed.
