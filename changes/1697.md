## Summary

- **What:** Limits `@endo/compartment-mapper` to a single concurrent file read and uses `maybeRead` to better classify read errors; replaces #1696's adaptive governor.
- **Why:** Fixes #1593; massively concurrent reads exhaust file descriptors without any throughput win.
- **Themes:** compartment-mapper, bundle-source, performance
- **Status:** merged

## Description

This change limits read concurrency for the bundler to just one.

#1696 illustrates that a control loop governing read concurrency to optimize throughput will effectively limit concurrency to one. This confirms the conventional wisdom that concurrent file system reads do not improve throughput, but massively concurrent reads risk depleting the reservoir of available file descriptors. Perhaps we should just not do that.
