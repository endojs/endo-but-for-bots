## Summary

- **What:** Extracts the inlined Zip reader/writer from `@endo/compartment-mapper` into a standalone `@endo/zip` package.
- **Why:** Makes the Zip API reusable by tooling that inspects or decomposes Endo archives (relevant to Agoric's on-chain transmission story).
- **Themes:** compartment-mapper, ecosystem-compat
- **Status:** merged

## Description

This change produces a package to publish separately from compartment-mapper that provides the Zip file reader and writer to other tooling.

This is not new code, but does introduce new public API surface. I believe this leaves room for growth: for {,de}compression and an an async reader/writer based on a seekable stream as might one day become necessary.

The justification for breaking this out and making it public is that it makes it easier to write tools that inspect the archives, or decompose and recompose them as part of our Agoric’s on-chain transmission narrative.
