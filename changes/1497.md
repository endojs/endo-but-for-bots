## Summary

- **What:** Adds a `restrict-comparison-operands` ESLint rule to `@endo/eslint-plugin` (modeled on `restrict-plus-operands`) plus an `ENDO_LINT_TYPES` env var in `@endo/eslint-config` that toggles type-aware linting (`SRC` or `FULL`); fixes 71 files of newly-detected issues.
- **Why:** Catch the kinds of `object > bigint` comparisons that the agoric-sdk timestamp-record migration would otherwise hide.
- **Themes:** tooling, ci, types, security
- **Status:** merged

## Description

This PR adds to the eslint-plugin package a new "restrict-comparison-operands" rule (inspired by and roughly analogous to [@typescript-eslint/restrict-plus-operands](https://typescript-eslint.io/rules/restrict-plus-operands)) that uses TypeScript-derived type information to reject relational comparisons between mixed types such as `number <= string` (and much more importantly for the agoric-sdk conversion of timestamps from bigints to records, **`object > bigint`**). The rule currently disallows use of unknown type for either operand by default and unconditionally allows mixed numeric comparisons such as `number >= bigint`, but could easily be tweaked and/or extended for different behavior.

It also updates the eslint-config package (relied upon by other packages) to dynamically configure type-aware linting including that new rule in the presence of a nonempty ENDO_LINT_TYPES environment variable. There are two distinct type-aware modes:
* `ENDO_LINT_TYPES=SRC` limits type-aware linting to "src" directories, increasing runtime slightly (on my slow machine, from about 1.50 minutes to 2.25 minutes [+50%] for the entire repository—which should be even further reduced if we eliminate the probably-now-redundant `tsc` invocations in "lint-types" scripts of various packages in the repository).
* `ENDO_LINT_TYPES=FULL` includes all files, increasing time _greatly_ (and making me thing that most of the slowdown motivating https://github.com/Agoric/agoric-sdk/commit/4a84690f226c2e20bce25629757de4113f79d931 was due to files in "tests").

Finally, it updates files throughout the repository to fix newly-reported lint issues.

Next steps are to try using this in agoric-sdk, where I suspect it **will** be practical to use type-aware linting when restricted to "src" directories. If so, we could choose to make that the default and drop type-oblivious "src" linting altogether.

Basically just disabling the rules. There are a couple examples in [packages/ses/types.test-d.ts](https://github.com/endojs/endo/pull/1497/files#diff-1c85b197ae6044ea121bfdc4cf572798bb261d2a7e9e72df3e33a9e90951c623) to verify errors when adding bigint to number and number to string:
```js
(n: number | bigint) => {
  // @ts-expect-error
  // eslint-disable-next-line @typescript-eslint/restrict-plus-operands
  return n + 10n;
};
```
```js
(n: number | string) => {
  // @ts-expect-error
  // eslint-disable-next-line @typescript-eslint/restrict-plus-operands
  return n + 10;
};
```
