## Summary

- **What:** Adds globals attenuation to `@endo/compartment-mapper` policy: keeps `link` synchronous while supporting async global attenuators, aggregates errors, supports a `defaultAttenuator`, and validates policy shape; reaches LavaMoat feature parity.
- **Why:** LavaMoat-style runtime restrictions need per-compartment global filtering as part of the policy pipeline.
- **Themes:** compartment-mapper, security, ecosystem-compat
- **Status:** merged

## Description

The method allowing link to remain synchronous while globals attenuators are asynchronous was inspired by module-load in SES.  


Open issue: LavaMoat style attenuator I made as a demo works around compartment.globalThis being frozen with a prototype trick. LavaMoat may demand that we make freezing globalThis of the entry compartment optional.

- [x] Implement global attenuators
- [x] cover with tests
- [x] aggregate errors from attenuators
- [x] ability to specify default attenuator to avoid repetition in policy
- [x] policy shape validation and test coverage of policy validation

Open questions:
- Do we want to future-proof the policy shape by adding an options key where defaultAttenuator would be specified?
- Do we want a debug mode where stack traces from attenuator errors would propagate up to the user?
- Do we want to version the policy shape?
- I intend to not make breaking changes to the policy format lightly, so if there are any concerns about naming things, please raise them.
