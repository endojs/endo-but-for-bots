## Summary

- **What:** Adds an `errorTaming: 'unfiltered'` lockdown option in `ses` and changes `'safe'`/`'unsafe'` to apply ad-hoc V8 stack-frame filters by default.
- **Why:** Hides SES-internal frames in development to improve readability; only affects V8.
- **Themes:** ses-lockdown, errors
- **Status:** merged

## Description

First, let me acknowledge that this PR adds a configuration option in an ad-hoc and non-general way. The proper way would be for the filtering criteria to be more generally customizable by data, rather than building a particular filter in. This would require us to figure out how to pass in complex customization. In the meantime, for our current development practices, these simple ad-hoc filters seem to work rather well.

This PR adds a new `errorTaming` option `'unfiltered'`. The behavior with this option preserves the `'safe'` behavior before this PR. The behavior of the `'safe'` and `'unsafe'` options ***on v8*** now filters stack frames in terms of the ad-hoc rules added by this PR.

Outside of v8, this PR should have no effect. Whether filtered on unfiltered, either one is consistent with the current state of https://tc39.es/proposal-error-stacks/#sec-system since it leaves the contents of the error stack up to the host.
