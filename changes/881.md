## Summary

- **What:** Proposed `Compartment.prototype.__makeScopeProxy__` so callers in eval-forbidden environments (CSP-strict WebExtension MV3 service workers) could pre-wrap functor source and run it inside a compartment without `eval`.
- **Why:** Driven by LavaMoat's need to load modules under MV3 CSP; reviewers raised intrinsics-handling concerns (#903) and ultimately favored the multi-`with` "quadruple backflip" reform (#905) over exposing scope proxies.
- **Themes:** ses-lockdown, compartments, security, ecosystem-compat
- **Status:** closed-unmerged

## Description

this allows the ses shim consumer to construct compartments normally and then run code wrapped in the magic lines of code so that they execute as if they were in the compartment but without use of `eval`. This enables ses/endo like behavior in environments where eval is not allowed such a restrictive CSP environments like "WebExtension Manifest v3 Background Service Workers"

prolly some better factoring to be had here

### @kriskowal (MEMBER) — 2022-02-18T00:38:08Z

I believe we’ve agreed to pursue other options. Please reöpen if otherwise.

Specifically, what is needed here can in theory be accomplished with an inline version of the multi-with reform we have planned. The template for a module-without-eval would look like:

```js
lockdown();
(function (modules) {
  const opaqueProxy = new Proxy(/* ... */);
  const compartment = new Compartment(/* ... */);
  const require = makeRequire(/* ... */);
  // ... module
  modules[0]({ globalThis: compartment.globalThis, opaqueProxy, require, module });
})([
  (function () {
    with (this.opaqueProxy) { with (this.globalThis) { (function (require, module, exports) {
      // ... source of module inline
    }).call(this.globalThis, this.require, this.module, this.module.exports); } }
  }),
]);
```

Also, maybe even some `Reflect.apply` paranoia. The globalLexicals are presumably unused. The evalScope is unnecessary since there’s no use of eval. The bundler participates in the trusted-compute-base and must be secured against supply chain attack.
