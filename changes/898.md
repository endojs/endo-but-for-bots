## Summary

- **What:** Refactors `ses` to share one safe evaluator per Compartment when no module lexicals exist and sloppy globals are off; renames `performEval` to `makeSafeEvaluator`, adds `provideCompartmentEvaluator`, and lazily constructs evaluators so eval-free environments aren't broken at Compartment construction.
- **Why:** Fixes #876 and reduces churn for the planned scope-proxy `has`-trap reform; reviewers added a hazard test and a warning comment to protect future contributors from regressing the `has` trap.
- **Themes:** ses-lockdown, compartments, security, performance
- **Status:** merged

## Description

This PR introduce the reuse of a Compartment's evaluators when the same scope proxy can be shared, aka when no module lexicals are defined and sloppy globals is not enabled. This fixes #876: the `Function` and `eval` of the compartment now use this shared evaluator.

This refactor gets us within a few line changes of the `has` hazard danger zone, so the PR adds a big warning section to the `has` trap implementation, and a test to make sure the trap is not exploitable. Once we figure out the `has` reforms (#820), the danger will be further mitigated, but warning and tests should remain for future contributors.

Best reviewed commit by commit with whitespace changes hidden.
