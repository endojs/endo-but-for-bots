## Summary

- **What:** `@endo/netstring` writer now serializes concurrent unsynchronized writes correctly, with new tests for both concurrent writes and chunk-fragmented reads.
- **Why:** Existing callers serialized writes manually, but the planned use of netstring as a generic CapTP transport requires interleaved writers.
- **Themes:** captp, tests
- **Status:** merged

## Description

Currently, all known uses of the netstring library are highly synchronized and do not attempt to send concurrent writes. However, novel uses of netstring as a generic CapTP transport require the support for independent and unsynchronized writes to the stream. This change includes a failing case, a change to fix the test, and an incidental improvement on reader tests made in a vain attempt to isolate the concurrent writer problem.
