## Summary

- **What:** Alternate take on #881: adds `Compartment.prototype.__applyPrecompiledModuleFunctor__` so caller-supplied magic-wrapped functions execute under a compartment's scope without `eval`.
- **Why:** Same MV3-CSP motivation as #881; closed in favor of the #881 approach (then both were superseded by #905).
- **Themes:** ses-lockdown, compartments, ecosystem-compat
- **Status:** closed-unmerged

## Description

replaces https://github.com/endojs/endo/pull/881

enables Compartment semantics for pre-magic-wrapped functions
this is **useful for environments where eval is not supported** like "WebExtension Manifest v3 Background Service Workers"

api is designed to "rhyme" with `Compartment.prototype.evaluate`

```js
// byo magic-wrapped function
const myPrewrappedFn = FERAL_FUNCTION(`
  with (this) {
    // optimizer goes here
    return function() {
      'use strict';
      // this part is normally inside an "eval" call
      return power(123)
    };
  }
`);

// construct compartment as normal
const compartment = new Compartment({ power });
// evaluate the pre-magic-wrapped function in the context of the compartment
const result1 = compartment.__applyPrecompiledModuleFunctor__(myPrewrappedFn);
// equivalent to
const result2 = compartment.evaluate('power(123)');
```
