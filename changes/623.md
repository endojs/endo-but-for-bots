## Summary

- **What:** Adds non-standard `Compartment.prototype.__isKnownScopeProxy__` to `ses` so consumers can detect scope-proxy leaks and apply workarounds.
- **Why:** Provides a building block for LavaMoat-style consumers working around ses-shim's `with`-based scope proxy implementation.
- **Themes:** ses-lockdown, compartments, ecosystem-compat
- **Status:** merged

## Description

While trying to come up with a workaround for the scopeProxy leak, I came up with this utility method

it is intended to be a non-standard utility method to help deal with non-standard ses-shim behavior

this enables ses-shim Compartment consumers to apply a workaround like this
```js
  const compartment = new Compartment({ getThisValue });
  const valueBeforeFix = compartment.evaluate('getThisValue()');
  fixProxyLeak(compartment);
  const valueAfterFix = compartment.evaluate('getThisValue()');

  t.not(valueBeforeFix, compartment.globalThis);  // <--- asserts *not* equal
  t.is(valueAfterFix, compartment.globalThis);    // <--- asserts equal
 ```

Fixes https://github.com/endojs/endo/issues/622
