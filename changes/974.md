## Description

To address feedback in #967, this reimplements the Node.js reader in terms of the new mapReader. This reveals that `reader.return` and `reader.throw` should not be relied on to abort the read side of a stream since they must be received in the sequence of the iteration, so two of the existing tests were invalid.

This creates a coverage gap for the underlying Node.js reader's protocol. I’ll need to investigate further to create a scenario that exercises these methods.
