## Summary

- **What:** Splits `@endo/netstring`'s reader/writer types out into a shared `stream.js` typedef module so dependees see explicit type exports instead of ambient declarations.
- **Why:** Lint in dependees (Agoric SDK PR #2978) was failing because `netstring`'s types weren't actually exported.
- **Themes:** types, ecosystem-compat
- **Status:** merged

## Description

The type definitions for netstring must be explicit for lint to pass in
dependees.

### @kriskowal (MEMBER) — 2021-08-04T22:50:55Z

@dckc The motivation for factoring the stream definition out of writer module was so that it could also be imported by the test, the reader module, and reexported from `index.d.ts`. As such, it would be a module with just one TypeScript definition. It could be in a `types.js`, and knowing now to avoid ambient `types.js` files, would also contain `export const moduleOnlyExportsTypes = true` to trick TSC into treating it as a `.d.ts` module. Given that we *must* write `index.d.ts` as TypeScript, there’s not much won from not being equally fluent in `.d.ts` and taking advantage of the more succinct and expressive style for pure definition files. That’s my reasoning at least and I’m open to refactoring it as JavaScript with jsdoc TS annotations.
