## Summary

- **What:** Stops `@endo/patterns` mismatch error messages from redacting the pattern itself, so error text shows the expected shape rather than `[Seq]` placeholders.
- **Why:** Patterns are typically schemas, not secrets, and seeing them aids debugging; secrets-as-patterns become a documentation caveat.
- **Themes:** patterns, errors
- **Status:** merged

## Description

If we accept this PR, we also need to make it clear, *somewhere findable*, that secrets should not be placed into patterns (other than keys-as-patterns), since they will not be redacted in error messages. But where?
