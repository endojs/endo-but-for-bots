## Summary

- **What:** PoC adding multiple-entrypoint support and runtime dynamic policy lookup (using `compartmentDescriptor.path`) to `@endo/compartment-mapper` for LavaMoat-style applications.
- **Why:** Discussion-only — explores a more native alternative to `retained`/imports-injection for cases where the application loads code at runtime from user-supplied locations.
- **Themes:** compartment-mapper, security
- **Status:** draft

## Description

This is not meant to be merged as-is but used in a discussion first.

I believe adding an option to have additional entrypoints to the endo app solves a few issues with inflexibility of compartment-mapping when applied to lavamoat.
This is a change that feels more native to how compartment-mapper behaves than stuffing imports and setting retained to allow dynamically importing from locations indicated by the user.

The test without policy works fine and without abusing compartmentMapper beyond what's clearly indicated (the mock isAdditionalEntry function where I'm not sure if I even want to drill down that information or just allow everything)

As of the 3rd commit here, policy enforcement on the dynamically loaded entry  doesn't work because it can't be identified with the contents of compartmentMap. I might find a way around that, if not - the input to importLocation would need to change to also contain information about the linkage to put in place (which feels like an annoyance to the end-user, even in lavamoat - we might be able to help them with that)

---

Added 4th commit with an implementation of a dynamic policy lookup at runtime. 
- What I like about it: eliminates the need to resolve items within the package that's being imported from ahead of time to put them in modules
- What I don't like about it: compartmentDescriptor.path was not used for runtime policy lookups before and there was less damage a confused contributor could do to policy enforcement. (could be mitigated by introducing a brand-check on compartmentDescriptor.path values. I'll start by freezing them)
