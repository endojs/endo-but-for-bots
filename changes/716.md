### @michaelfig (MEMBER) — 2021-05-11T00:12:15Z

> The last line would need to be `$h_once.default(meaning)` to work properly.

In my understanding of things, this bug can only properly be fixed by changing the definition of `$h_once` (and possibly `$h_live`).

It *really is* correct that it should be `$h_once.meaning(meaning)`.  The call is symmetrical to `$h_live.meaning(meaning)`, which modifies the scope target for the method name.  Keeping these semantics allows for easier audits that don't have to deal with many source code changes just because the export name has changed.

The scope target should not be affected by the exported name, only the inter-module linkage machinery should be sensitive to that.
