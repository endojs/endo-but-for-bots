### @gibson042 (MEMBER) — 2025-06-10T17:59:45Z

Without diving into this PR just yet, I'd like to draw your attention to #2285 (emphasis mine):
> I think we'd be better off replacing `(cond: boolean, details?: Details | undefined) => boolean` "[Checker](https://github.com/endojs/endo/blob/fa20921dc8bd05084258e4783f93fe016d6e162a/packages/pass-style/src/types.d.ts#L184-L203)" parameters with optional `(template: TemplateStringsArray | string[], ...args: any[]) => false` "Rejector" parameters, recovering the old local pattern but without local function creation.
> 
> And per [#2285 (comment)](https://github.com/endojs/endo/issues/2285#issuecomment-2115922362) , **we'll also want to rename internal functions for indicating the progress of this transition**.
> ```patch
> -const checkSomething = (candidate, check = undefined) => {
> +const confirmSomething = (candidate, reject = false) => {
>    return (
>      isOk(candidate) ||
> -    (!!check && CX(check)`…`)
> +    (reject && reject`…`)
>    );
>  };
> ```
> And at the highest possible level, we'd replace use of `x => x` checkers with `undefined` rejectors and [`assertChecker`](https://github.com/endojs/endo/blob/5bdb77d2689fef284475176f52e81b166ad788f7/packages/pass-style/src/passStyle-helpers.js#L76-L79) with `assert.Fail`.
> ```patch
> -    checkSomething(candidate, assertChecker)
> +    confirmSomething(candidate, Fail)
> ```
> …
> **If any exports _do_ expose a Checker parameter, we'll need to consider a deprecation strategy.**
