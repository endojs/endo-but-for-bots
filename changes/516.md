## Description

This change replaces some scaffolding that previously partially emulated what `lockdown` would do, and instead just uses `lockdown`. This should improve the time to discover regressions. There is some risk that `lockdown` would break the test scaffold.

### @kriskowal (MEMBER) — 2020-11-27T02:48:01Z

Disclosure: This change may violate some principle for “orthogonal testing”. Without this change, most of these tests are testing a specific mechanism, and after this change, they are testing that mechanism *and* lockdown. The alternative way to refactor this such that we don’t need spies and environment restoration would be to break these tests into individual files so they’d each run in a disposable subprocess. That would sacrifice confidence in the effects of lockdown. Some of these tests could probably be duplicated such that one tested a specific mechanism in isolation, and another test covered the mechanism as a side-effect of lockdown. If I had to choose one or the other, I’d favor testing the mechanism as a side-effect of lockdown.

So, there’s some space here to discuss whether we want unit tests, integration tests, or sufficient duplication that we have both.
