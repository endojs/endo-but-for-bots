> Whatever method you used to identify claimed vs. unclaimed should apply in the context of a specific tsconfig, and I'm wondering about that process.

The analysis leverages [`ts.parseJsonConfigFileContent(…)`](https://github.com/Microsoft/TypeScript/issues/6387#issuecomment-169739615) to parse all relevant configs (ie un-suffixed or indicated in package scripts) while honouring `extends`… etc then compares the resulting `fileNames` arrays to determine:

- Scoped or nested counts for the set of files matched by a config including top-level and nested configs relative to the respective package scopes (ie `package.json`) to align with the `nodejs` module resolution mode.
- Claimed or unclaimed counts for the subset of files matched by a top-level config which are in fact in a nested package scope and are either subsequently matched by a respective nested config or not, respectively.
