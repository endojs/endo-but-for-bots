## Summary

- **What:** `@endo/static-module-record` is reworked to load under both Node ESM and the `node -r esm` shim, including a workaround for extracting Babel's default export, and adopts `ses-ava` for tests.
- **Why:** A breaking change in NESM's CJS-from-ESM emulation broke importing the Babel dependency, blocking RESM/NESM dual compatibility.
- **Themes:** ecosystem-compat, tests, compartments
- **Status:** merged

## Description

This change allows the StaticModuleRecord package to be used both on Node.js ESM and `node -r esm` emulation of ESM on Node.js 14 and 16. A breaking change in NESM requires a word-around to extract the default exports of the ESM-compiled-down-to-CommonJS Babel dependency.

I’ve also pedaled the version forward to the last release of its predecessor `transform-module`, so that the NEWS.md doesn’t lose continuity. This reverses a version reset that came with the package rename.

This also incorporates `ses-ava` in the tests, to give that path some practice in local integration testing.
