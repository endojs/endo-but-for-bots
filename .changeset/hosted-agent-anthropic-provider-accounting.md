Breaking (pre-1.0): the inference provider registry now enforces limits and a request policy, so calls that used to succeed can be refused. Migrate as follows.

1. Default limits (`DEFAULT_PROVIDER_LIMITS`, `DEFAULT_AGENT_LIMITS`, `DEFAULT_OWNER_INFERENCE_LIMITS`) now apply to every provider, owner, and grant, including those restored from persisted state. To keep a higher limit, set it explicitly with `setLimits(limits, operationId, true)`, `setOwnerLimits(limits, operationId, true)`, or `setGrantLimits(grantId, limits, operationId, true)`.
2. Raising a limit through any of those methods is refused with `limit-raise-unconfirmed` unless the final `confirmed` argument is `true`. Lowering one needs no confirmation.
3. Requests to `/v1/messages` must name the granted `model`, give a positive integer `max_tokens` within the grant's `maxOutputTokens`, and use only allowlisted body fields and no credential headers. Anything else, including the bare `{}` body the registry used to forward, is refused with `inference-request-refused`. The registry forwards its own serialization of the validated body.
4. A model with no `INFERENCE_PROVIDER_MODEL_PRICES` entry is refused with `unpriced-model` by every scope that budgets in dollars. To use one, give both the provider and the owner a `dailyTokens` budget; an agent on that provider then inherits the provider's token budget. A limit record may carry only one of `dailyDollars` and `dailyTokens`, and a deployment ceiling on one kind refuses a budget of the other kind.

New: the `@endo/hosted-agent/anthropic-api-key-issuer.js` export grants Anthropic API keys, and `@endo/hosted-agent/inference-provider-policy.js` exports the default limits. The registry meters per-agent, per-provider, and per-owner concurrency, rate, and daily token or dollar budgets. A reservation holds its concurrency slot until it settles. Settlement charges reported usage in full; usage above the reservation is flagged `overrun` and counts against the rest of the day. The module entry point reads per-model prices from the `INFERENCE_PROVIDER_MODEL_PRICES` environment variable, a JSON object of `{ inputPerMillion, outputPerMillion, cacheReadPerMillion?, cacheWritePerMillion? }` records, and refuses a malformed one at startup. `INFERENCE_PATHS` now includes `/v1/messages/count_tokens`. An upstream 404 for the granted model is reported as `model-not-available`.
