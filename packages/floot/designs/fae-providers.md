# Fae providers and CLI retirement

Fae runs the agent loop, dispatches endowed tools, and spawns child agents. A session selects OpenAI, Anthropic, or OpenRouter for model inference. Provider credentials belong to the installation. Presets describe what the agent may use, including its shell and network policy.

1. Expose each configured provider and its account-admitted models. Reuse the OpenRouter adapter and Secrets binding. Move OpenAI discovery off the Codex CLI factory and keep the direct OpenAI and Anthropic account pools usable without CLI provisioning. Only offer models admitted by automatic account routing. Preserve the credential route of an existing generic provider session when introducing named choices. Exercise a tool turn with each provider and check Whylip.
2. Switch new sessions to Fae. Retire Codex CLI, Claude Code, and OpenCode in both repositories. Fence creation by old clients, quiesce pending work, and identify the owning controller and session IDs. Delete CLI sessions and any non-root Fae descendants they own, proceeding leaf first. Recheck ancestry and the durable queue at the owning controller before each deletion. After a verified cutover, delete sessions whose recorded backend identifies one of those three harnesses through the session owner's cleanup path. Preserve direct Fae roots, including fae-codex and fae-claude, their children outside retired subtrees, presets, shared credentials and pools. Test classification on mixed sessions and interruption during cleanup.
3. Reassess the session design after removal. Trace turn acceptance, durable tool intent, observed results, restart, compaction, and chat presentation. Remove CLI thread reconciliation. Keep protocol data required by direct providers, including opaque reasoning data. Verify duplicate submissions and crash boundaries so recovery never automatically repeats a tool whose outcome is unknown.
4. Use Preset, Provider, and Model in the shared Floot UI and preset editor. Apply saved model defaults and keep the preset's grants when changing a model. Keep account selection automatic. Exercise the Android voice shortcut and show an unavailable saved selection explicitly.

Each commit receives an independent adversarial review, fixes, and another review of the fixes. Before changing Tokyo, review the exact deployment and cleanup procedure. Verify direct sessions on the deployed host before deleting any retired sessions.

## Session storage after CLI retirement

Fae and Floot already share the provider/tool loop in `fae/src/turn-engine.js`. Standalone Fae attaches turns to a conversation-tree leaf and reconstructs the path to that leaf for inference. Floot has additional obligations. Its callers can disconnect while a turn is running, send the same submission again, and inspect uncertain tool outcomes after a daemon restart. The private Floot journal owns those facts. Writing a second conversation tree for each Floot session would introduce a second commit point between a tool effect and the next model request.

A Floot submission has a stable request identity. The durable pending queue tracks it until the turn journal acknowledges the input. The journal records dispatch intent before the provider call and tool intent before an endowed tool executes. An acknowledged result settles the corresponding intent. If a process dies before the result is recorded, the uncertainty survives. Recovery can report what happened and accept an explicit resolution. Reconstructing context must never invoke a tool.

Both visible history and model context are derived from the journal. Visible history includes cancelled and failed turns and presents tool results and usage. The model receives dispatched turns and the latest compaction summary plus its retained tail. The projection carries forward unresolved or late tool results even across a summary. Full records are read through private content references where the journal stored only a preview. Archived pages and their checkpoint index let the projection skip superseded content.

The former CLI adapters also had to reconstruct an independent native thread. The direct providers instead rebuild requests from Floot records. OpenAI Responses output and Anthropic Messages content, including signed thinking, belong to the assistant message that produced them. They are restored only under the matching provider format. A whole-thread CLI checkpoint cannot be submitted to a direct provider. Rejecting it before dispatch prevents accidentally starting a different conversation or sending a retired session's history elsewhere.
