# Fae sessions, Floot, and Whylip

Fae owns agents, inference connections and model selection, delegation, tool execution, session lifetime, presets and their grants, and durable conversation records. Floot supplies the chat UI and speech input/output. Whylip supplies books, narrative prompts and the reading interface. Both applications consume Fae. Neither defines the execution or recovery protocol for the other.

1. Move the streaming session factory, its private journal, Endo setup and providers into Fae. Keep retained Endo formula URLs and public capability methods working through small compatibility entry points. Preserve stored session IDs, namespaces, grant identities and opaque provider records. Inject Floot speech behavior at its boundary. Keep standalone Fae's branching conversation tree for clients that actually select a branch.
2. Move Whylip's installation and book coordination into Whylip and expose the inference selection it consumes through Fae. Preserve existing book factories and subscriptions. Exercise fresh installation and revival. Avoid a dependency from Fae on Whylip or Floot.
3. Record a stable local identity for each requested tool operation and carry it through intent, result, and presentation. Keep protocol IDs for sending model requests. Use legacy matching when reading existing records. Exercise identical concurrent calls, pre-effect intent refusal and uncertainty after restart.
4. Give session history a reader over private storage that does not require starting an agent. Provide a bounded recent-history path with older pages on demand. Keep complete history and compaction semantics for existing consumers. Centralize connection discovery, model admission and reopening of persisted selections. Remove the tree-specific cursor name from the shared turn loop.
5. Verify package dependencies and persisted entry points, run focused tests for both consumers and the session engine, and review each commit adversarially. Review fixes again before committing. Package dependency lockfile changes follow the repository's separate commit convention.

Verify that history remains readable with the guest and provider unavailable. Use the same serialized journal for reads and live writes. Page by a stable turn identity even when a late result changes archive publication order. Validate that tool correlation preserves provider wire IDs and opaque reasoning blocks. Check the dependency graph and cold-load each retained module URL in addition to testing new entry points.
