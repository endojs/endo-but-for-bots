document.all & @endo/pass-style: old vs new isPrimitive / passStyleOf

document.all is the only known JavaScript value with the [[IsHTMLDDA]] internal slot (HTML § the HTMLAllCollection interface, ECMA-262 § B.3.7). It is an object, but typeof document.all === 'undefined', and document.all == null is true while document.all === null and document.all === undefined are both false.

Before @endo/pass-style #3156, both isPrimitive and the passStyleOf discriminator used a falsy short-circuit on typeof, which mis-classified document.all as the primitive 'undefined'. The fix routes through a strict === null / === undefined check first, and falls through to 'object' for any value that is loose-equal to nullish but not strict-equal. The object branch then rejects it as “Cannot pass non-frozen objects” because HTMLAllCollection's [[PreventExtensions]] always returns false.

Important distinction (thanks to @erights): the two passStyle class. columns below are not the value that passStyleOf returns. They are the result of passStyleOf's internal classification step alone (the typeof / strict-nullish discriminator that decides which branch a value takes), reimplemented inline. For document.all the NEW classification is 'object', but that tag is never returned to a caller: it merely routes the value into the object branch, which then throws Cannot pass non-frozen objects because document.all is not frozen and cannot be frozen. So the 'object' in that column is an internal routing tag, not an observable passStyleOf result. The Observable passStyleOf behavior section below shows what calling passStyleOf actually does: OLD returns 'undefined' (the silent bug); NEW throws.
