## Remaining work and evidence

Read the last status paragraph, `Status at 1b130df7`, under F149 in
[the architecture review](../architecture-review/2026-09-06/ARCHITECTURE-REVIEW.md).
The explicit Script/Eval/Module goal and strict Script var-hoisting distinction
already exist and must be preserved.

In [coder.rs](../ironhorse-compile/src/coder.rs), `compile_goal_metered` still marks
both non-module goals with `flags::EVAL` and sets `coder.eval_flag = true`.
`code_program` always calls `code_scope_eval`.
In [the production embedder](../../endo/src/ironhorse_engine.rs), `compile_metered`
calls `compile_atoms_with_meter`, which selects `Goal::Eval`.
The public scoper fixtures and production compilation traversal are not equivalent:
`run_goal_for_compile` omits the access log.
Current [scoper.rs](../ironhorse-compile/src/scoper.rs) does contain explicit
public/private traversal comparisons, so the historical statement that no fixture
exercises that variant must not be repeated as a current blanket claim.
Real Eval-root coverage still needs an explicit audit alongside Script-root coverage.

In the pinned C source, `fxScopeCodingProgram` in `xsCode.c` emits lexical
`NEW_CLOSURE` slots first, emits var/function slots next, and retains the lexical
prefix after `PROGRAM_ENVIRONMENT`.
`fxRunProgramEnvironment` installs realm lexical bindings, checks declaration
conflicts, and hoists var/function bindings.
By contrast, [interp.rs](../ironhorse-vm/src/interp.rs) combines
`XS_CODE_EVAL_ENVIRONMENT | XS_CODE_PROGRAM_ENVIRONMENT`, calls
`hoist_vars_to_global` over `id_map`, and clears `locals` and `id_map`.
`Interp::run` also resets `env` between runs.
Recognizing the opcode therefore does not implement a persistent Script environment.
Merely switching the compiler's opcode would mis-hoist or discard lexical bindings.

## Proposed changes, including the frozen file

1. In `interp.rs`, give the realm a persistent lexical environment distinct from
   global-object properties and temporary execution frames.
   Split the Script environment path from the eval path: retain lexical cells,
   enforce lexical/var/function declaration conflicts and restricted globals,
   and hoist only the declarations that belong on the global object.
   Make `PROGRAM_REFERENCE` consult realm lexical bindings before global properties.
2. Preserve that environment across ordinary runs and persistent-machine cranks.
   Integrate its roots, symbol relinking, snapshots, restore validation, and rollback
   with the existing realm lifecycle; retaining stale frame indexes is insufficient.
   Coordinate ownership with the decided Realm extraction in
   [W6](../../../designs/ironhorse-w6-decisions.md), rather than inventing a second
   independently owned realm namespace.
3. Port `fxScopeCodingProgram` in the compiler and select it only for `Goal::Script`.
   Set Eval flags only for `Goal::Eval`; keep the eval byte-identity entry unchanged.
   Add explicit goal/root scoper fixtures for both access-log modes.
4. Specify the production entry contract before changing call sites.
   Proposed contract: top-level evaluation and persistent cranks are Scripts whose
   lexical bindings survive in their realm; guest `eval` remains Eval and modules
   remain Module.
   This is a proposed behavior change, not a statement about current production.
   Assess compatibility for existing callers that rely on eval redeclaration or
   strict-eval locality before switching `compile_metered` to an explicit goal.

Compiler and scoper work can be prepared independently, but cannot by itself close
persistent Script semantics.
Do not simulate lexical bindings with hidden global properties: reflection,
redeclaration rules, and environment lookup would still differ.

## Machinery to preserve

Preserve the shared compile meter, sticky refusal, and billed work on failure.
Keep the ordered declaration indexes and the production access-log omission;
restore fixture coverage without restoring an unnecessary retained allocation.
The relevant carried costs are documented in
[the performance tradeoffs](../architecture-review/2026-09-06/PERFORMANCE-TRADEOFFS.md).
Persistence must retain the validation and transactional guarantees documented in
[W3](../architecture-review/2026-09-06/W3-COMPLETION.md).

## Acceptance tests for the follow-up

- Oracle-free VM tests must execute two separately compiled Scripts in one realm:
  `let x = 1` followed by `x` must yield `1`, while `globalThis.x` stays absent.
  Cover const/class bindings, mutable lexicals, TDZ, closures, and redeclarations.
- Check lexical/var/function conflicts and restricted global properties before any
  body side effect; verify globals and lexicals have distinct reflection behavior.
- Verify isolation between realms, persistence through snapshot/restore and symbol
  relinking, and rollback after a failed crank.
- Preserve strict/sloppy Eval behavior, direct/indirect eval lookup, and Module
  behavior separately; a passing Script case does not prove these paths unchanged.
- Compare genuine Script bytecode with an oracle entry using Script parse flags,
  and retain the existing Eval byte-identity suite.
  Runtime assertions must also be oracle-free so they run on the macOS lane.
- Exercise Script and Eval roots through both scoper traversal variants, checking
  equivalent binding decisions and metering while preserving omitted access logs.

These are future acceptance criteria, not implementation or test-success claims.
