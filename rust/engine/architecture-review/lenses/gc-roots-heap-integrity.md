# Lens review — GC root-set completeness and heap-model integrity

Reviewer scope: `ironhorse-vm/src/value.rs`, `gc.rs`, `bulk.rs`, `interp.rs` 43488–44942 (the
collector seam) plus the `Interp` field block and the persist gate, `ironhorse-vm/tests/
gc_visitation_registry.rs` / `gc_anchor_truth.rs`, `ironhorse-snapshot/src/machine.rs`
(`partial_collect`/`generational_collect`), `store.rs` (`derive_page_edges`, `validate_store`),
and `rust/endo/src/ironhorse_engine.rs` (the only production collector caller).

Empirical work: one standalone probe binary in the scratchpad linking `ironhorse-vm`,
`ironhorse-compile` and `ironhorse-snapshot` as path crates (no repo file was modified).
Three results below are **reproduced**, not inferred.

---

## 1. Assessment

The collector kernel itself is good. `gc.rs` is ~100 lines of pure, testable mark/ephemeron/
sweep/compact over the arenas, with the machine's mess quarantined behind one `GcHooks` trait.
Root order is sorted and deduped, the sweep is index-order, `ChunkArena::compact` sorts its live
set and validates every block *before* `mem::take` so a panic never leaves an emptied byte space,
and the WeakMap ephemeron pass is genuinely correct (map-and-key gated, dead keys pruned before
the sweep, entries physically removed for weak kinds). Every conservative choice is labelled with
its failure direction. The two prune rosters really do agree today: I diffed
`collect_garbage`'s in-hook + late prune against `free_pages` mechanically — 46 tables each,
symmetric difference empty — and `extra_edges` against `each_side_table_ref_tail` — identical
table sets. The chunk-holder roster is complete: only three `ChunkOffset`-typed field families
exist (`FuncInfo.name_chunk`, `ArrayBufferData.data`, `StaticStrings`) and all three are visited,
and every `Slot`-bearing side table reaches `external_chunk_refs`.

What is *not* sound is the layer above the kernel: the contract by which the machine tells the
collector what is a root. Three of its load-bearing premises are false in the tree today.

**(a) The boundary-empty premise.** The snapshot ledger classifies `result`/`locals`/`id_map`/
`env`/`args`/`this_val`/`cur_func`/`target_func`/`pending_new_target` as TRANSIENTS
(sidetable.rs:716–720) — provably default at a persistable boundary, so never serialized. The GC
registry classifies the same fields `Req::GcRoots`. Both claims cannot be wrong at once without
consequence: if a register is non-default at a boundary, the continuous machine roots it and its
resumed twin does not, the two collect differently, and free-list order feeds allocation order,
which the design itself calls replica-visible. `run()` clears the registers only `if completed`
(interp.rs:11229–11238), and two paths added to emulate the oracle shim's post-run
`String(result)` (11199, 11206) turn a *clean* `Halt::Return` into a synthetic `Halt::Throw`
after the clear decision. `is_quiescent()` (10733) does not look at any of those registers, so
the machine is still accepted by every persist verb. I reproduced the full fork: for
`let a={p:1}; let b={q:2}; let s=Symbol(); s`, the crank-1 snapshot is byte-identical to the
completing twin's, yet after the same scheduled collection and the same next crank the continuous
image and the resumed image differ (`f22f0619…` vs `76a9b922…`), with identical results and
identical computrons. A control with the same program body and a non-Symbol completion is
byte-identical. This is a silent consensus fork that the design's own twins suites cannot see
(they compare results and computrons) — the W6-11 class, re-opened by the shim emulation.

**(b) The complete-root-set premise.** `gc_roots`' doc says "the machine's complete GC root set".
It is not: `error_stack_accessor` (interp.rs:4355, minted 6262–6264) holds two function slots that
are reachable from nothing until a crank names an Error-family name (install gated at 7683–7706).
I reproduced it: crank 1 `var x = 1; x`, `collect_garbage()` reclaims exactly 2 slots, crank 2
`var e = new Error('m'); typeof e.stack` halts `Unsupported("callback:non-user-function")` where
the uncollected twin answers `"string"`. The registry classifies the field `DocumentedOnly` with a
justification that is simply false, and `gc_anchor_truth.rs` — which holds behavioral twins for
five other `DocumentedOnly` anchors — has no twin for this one.

**(c) The "classification is checked, not just recorded" premise.** The registry's own header
claims each classification is verified against the real visitor bodies. `Req::DocumentedOnly =>
true` (registry:458) is unconditional, and 29 of the registry's entries use it. Worse,
`Req::PrunedBothPaths`'s full-sweep half is vacuous: the whole `impl GcHooks for Hooks` block is
nested *inside* `pub fn collect_garbage`'s body, so `fn_body("pub fn collect_garbage")` textually
contains `extra_edges`, `swept` and `external_chunk_refs`; a word-bounded mention of the table
name anywhere in the collector satisfies "pruned". Deleting a `remove`/`retain` from `swept` or
the late prune passes the net. And `mentions` is name-based, so `("target_func", GcRoots)` is
satisfied by `f.target_func` in the frame loop while `self.target_func` is never rooted.

Two further structural facts frame all of this. First, the exact collector has no production
caller: `rust/endo` calls only `partial_collect`, and the two `collect_garbage` sites in
`machine.rs` (1723, 1759) are `#[cfg(test)]`. So in the shipped configuration chunk space is never
compacted and `each_side_table_ref` (44747) roots *every* collection entry including WeakMap and
WeakSet keys — weak collections are strong maps for the life of a worker, which is the wrong
property for the SES identity-brand idiom. Second, there is no allocation-pressure collection, no
heap cap, and no heap-exhaustion `Halt` variant, while `ChunkArena::alloc` mints its offset as
`v.len() as u32` (value.rs:1481) — the u32 handle space is the only bound, and it wraps silently.

## 2. Findings

### F1 — A quiescent machine with uncleared boundary registers forks the durable heap between a continuous and a resumed replica (CRITICAL, high confidence, known-fixed-regressed: W6-11 / W6-10)

**Claim.** For a crank whose completion value is a Symbol or a null-prototype object, `run`
converts a clean `Halt::Return` into a synthetic `Halt::Throw` *after* the `if completed` register
clear, leaving `result`/`locals`/`id_map` populated and rooted on a machine that `is_quiescent()`
accepts; the resumed twin of that machine's snapshot roots strictly less, so the two diverge in
free-list content and in every subsequent durable image.

**Sites.** `ironhorse-vm/src/interp.rs:11199` (Symbol completion), `:11206` (null-prototype
completion), `:11229–11238` (the `if completed` clear), `:10733` (`is_quiescent`),
`:43511`/`:43523` (`result`/`locals` as roots); `ironhorse-snapshot/src/sidetable.rs:716–720`
(the same fields classified TRANSIENT).

**Evidence (code).**
```rust
        if halt == Halt::Return && self.result.kind == Kind::Symbol {
            halt = Halt::Throw("TypeError: cannot coerce symbol to string".to_string());
        }
...
        if completed {
            self.result = Slot::undefined();
            self.locals.clear();
            self.id_map.clear();
        }
```
```rust
    pub fn is_quiescent(&self) -> bool {
        self.call_stack.is_empty() && self.stack.is_empty() && self.jumps.is_empty()
```

**Evidence (reproduced).** Probe: run crank 1, snapshot, resume, `collect_garbage()` on both,
then the same crank 2 (`var z = {r:3}; var w = {t:4}; 42`) on both, compare `write_machine` bytes.
```
crank1 = "let a={p:1}; let b={q:2}; let s=Symbol(); 1"   completed=true  quiescent=true
  snapshot A sha=47b44592…   crank2 both: "42", 78 computrons
  post-crank2  cont=76a9b922…  resumed=76a9b922…  IDENTICAL=true
crank1 = "let a={p:1}; let b={q:2}; let s=Symbol(); s"   completed=false quiescent=true
  snapshot A sha=47b44592…   crank2 both: "42", 78 computrons
  post-crank2  cont=f22f0619…  resumed=76a9b922…  IDENTICAL=false
```
Root/live counts at the boundary: continuous 632 roots / reclaims 2 / 720 live; resumed 629 roots
/ reclaims 7 / 715 live. The same divergence reproduces for
`let o=Object.create(null); o`. Six control programs (ordinary completions, `with`, a caught
throw, a function call) all show `DIVERGE=false`.

**Impact.** Two validators that ran the identical crank sequence — one continuously, one across a
suspend/resume — hold different heaps and therefore different store roots and commit seals, after
agreeing on every observable the differential suites compare. The crank-1 snapshot is byte-identical
in both cases, so the integrity stack cannot attribute the fork; it surfaces one crank later.
`Object.create(null)` and `Symbol()` completions are ordinary JavaScript, not adversarial input.

**Recommendation.** Make the register clear a function of the *boundary*, not of `completed`:
clear `result`/`locals`/`id_map` whenever the dispatch returned `Halt::Return` (before the two
shim coercions), and move the shim's `String(result)` emulation out of `run` into the 262 harness
where it belongs. Then make `is_quiescent()` assert the whole TRANSIENT set (`result`, `locals`,
`id_map`, `env`, `args`, `this_val`, `pending_new_target`) rather than three stack-shaped fields,
so the persist gate and the GC root set agree by construction. Add a twin test of the shape used
in the probe (continuous vs resumed image bytes after a boundary collection) — the existing carry
twins compare results and computrons and are blind to this by construction.

### F2 — Confirmed GC-root omission: `%Error.prototype%.stack`'s accessor pair is root-less until installed (HIGH, high confidence, new)

**Claim.** A `collect_garbage()` at a crank boundary after a crank that names no Error-family name
sweeps the two boot-minted `stack` accessor function slots, and the next crank that names `Error`
installs dangling indices, so every `err.stack` read halts the crank.

**Sites.** `ironhorse-vm/src/interp.rs:6264` (mint), `:7683–7706` (gated install), `:4355` (field),
`:43502–43695` (`gc_roots` never mentions it), `ironhorse-vm/tests/gc_visitation_registry.rs:360`.

**Evidence.**
```rust
        let stack_getter = self.alloc_named_method(NativeMethod::ErrorStackGetter, "get stack", 0);
        let stack_setter = self.alloc_named_method(NativeMethod::ErrorStackSetter, "set stack", 1);
        self.error_stack_accessor = Some((error_proto, stack_getter, stack_setter));
```
```rust
    ("error_stack_accessor", &[Req::DocumentedOnly], "identity cache; the proto and both accessor functions are boot slots, and the installed pair is a property of the rooted %Error.prototype%"),
```
Reproduced:
```
B crank1 ("var x = 1; x") completed=true
B gc stats=GcStats { slots_reclaimed: 2, slots_live: 715, ... }
B crank2 ("var e = new Error('m'); typeof e.stack") completed=false halt=Unsupported("callback:non-user-function")
B-control (no collection)                          completed=true  result="string"
```

**Impact.** Collection is supposed to be observation-invariant; here it changes a program's
outcome. SES `assert`/error paths read `.stack`, so a machine that hits this fails every later
error report. It is masked today only because the full collector has no production caller (F4) and
because the partial collector is page-conservative over dense boot pages — both accidents, not
guarantees, and the design calls for allocation-triggered collection.

**Recommendation.** Push `(proto, getter, setter)` into `gc_roots` beside the `proto_accessors`
rows (the sibling W6-4 fix), or move the pair into `proto_accessors` so it is rooted by the same
loop. Change the registry entry from `DocumentedOnly` to `GcRoots` and add a `gc_anchor_truth.rs`
twin (`Error` named only in crank 2, collect between).

### F3 — The GC ground-truth registry's two escape hatches are unconditionally satisfied; its own "checked, not just recorded" claim does not hold (HIGH, high confidence, partially-known)

**Claim.** `Req::DocumentedOnly` is `true` with no check (29 registry entries use it, one of them
demonstrably wrong — F2), and `Req::PrunedBothPaths`'s full-collector half is vacuous because the
entire `impl GcHooks for Hooks` block is nested inside `collect_garbage`'s body, so any mention of
a table name in the collector satisfies "pruned".

**Sites.** `ironhorse-vm/tests/gc_visitation_registry.rs:458`, `:443–445`, `:435`;
`ironhorse-vm/src/interp.rs:43805` (`impl crate::gc::GcHooks for Hooks<'_>` nested inside
`pub fn collect_garbage` opened at `:43707`, closing at `:44290`).

**Evidence.**
```rust
    let full_sweep = strip_comments(fn_body("pub fn collect_garbage(&mut self)"));
    let partial_sweep = strip_comments(fn_body("pub fn free_pages(&mut self, pages: &[u32])"));
...
                Req::PrunedBothPaths => {
                    mentions(&full_sweep, name) && mentions(&partial_sweep, name)
                }
...
                Req::DocumentedOnly => true,
```
Verified by structure: `awk` over 43707..44420 shows `impl crate::gc::GcHooks for Hooks<'_>` at
relative line 99 and the closing brace of the impl at relative 584, i.e. `extra_edges`, `swept`
and `external_chunk_refs` are all inside the string `full_sweep`.

**Impact.** The net is the designated defence against the forgot-the-table class that waves 2–6
kept producing. As written it kills only "the field name appears nowhere"; it cannot catch a
deleted prune, and a new field can be waved through with a one-line prose note — which is exactly
how F2 is currently sanctioned. Note the mechanism is also a false-positive source:
`("target_func", &[Req::GcRoots], …)` is satisfied by `roots.push(f.target_func)` inside the
`call_stack` loop while `self.target_func` is never rooted.

**Recommendation.** (i) Split the collector so the hooks impl is a top-level `impl` and the sweep
markers name `fn swept` and the late-prune block specifically; (ii) require `DocumentedOnly`
entries to name a behavioral twin test function that the net asserts exists in
`gc_anchor_truth.rs`; (iii) qualify `mentions` for register requirements with `self.` so a
same-named frame field cannot satisfy a machine-register root claim.

### F4 — The exact collector has no production caller: WeakMap/WeakSet are strong and chunk space is never reclaimed in the shipped configuration (HIGH, high confidence, known-open)

**Claim.** No non-test code in `rust/` calls `Interp::collect_garbage`; production reclaims only
via `partial_collect`, whose root projection roots every collection entry including weak keys and
which never compacts chunks — so WeakMap/WeakSet entries, dead-keyed side-table values and all
chunk garbage (strings, BigInts, ArrayBuffer backing stores) accumulate for the life of a worker.

**Sites.** `rust/endo/src/ironhorse_engine.rs:680` (`partial_collect` is the only reclaim call);
`ironhorse-snapshot/src/machine.rs:1723`, `:1759` (the only other `collect_garbage` calls, both
inside `#[cfg(test)] mod tests`); `ironhorse-vm/src/interp.rs:44747–44752`; `:44550–44552`.

**Evidence.**
```rust
        for c in self.collections.values() {
            for (k, v) in c.live_entries() {
                k.each_ref_slot(&mut *visit);
                v.each_ref_slot(&mut *visit);
            }
        }
```
```rust
    /// summaries; chunk space held by freed string slots is reclaimed
    /// by the next full [`Self::collect_garbage`] (partial collection
    /// never compacts).
```
The store-seam design (designs/ironhorse-snapshot-store-seam.md:3977–3979) says GC scheduling is
"a pure function of release-fixed allocation thresholds"; no allocation-threshold trigger exists
anywhere in `ironhorse-vm`.

**Impact.** `free_pages`' doc promise ("keeps its values' pages one partial collection longer")
is indefinite in practice. WeakMap is the SES idiom for identity-keyed caches (passStyle brands,
remotable registries); under partial-only collection those caches never release, so a long-lived
worker's heap grows with the number of objects ever branded. Chunk bytes only ever grow.

**Recommendation.** Either wire the exact collector into the crank-boundary cadence (it needs F1
and F2 fixed first, and a chunk-compaction checkpoint story), or stop advertising weak semantics:
document that `WeakMap`/`WeakSet` are strong in the deployed configuration until the full
collector is scheduled, and add a store-level bound on chunk growth.

### F5 — No allocation-pressure GC, no heap cap, no heap-exhaustion `Halt`; chunk offsets wrap silently at 4 GiB (HIGH, high confidence, partially-known)

**Claim.** The engine has no path that refuses or reclaims on allocation pressure, and
`ChunkArena::alloc` derives a `u32` offset from a `usize` length with a bare cast, so once the
chunk arena passes 2^32 bytes two distinct blocks alias and `ChunkOffset::NULL` becomes mintable.

**Sites.** `ironhorse-vm/src/value.rs:1479–1483`; `interp.rs:34410–34412` (`alloc_array_buffer`);
`interp.rs:3517–3569` (the `Halt` enum has `StackOverflow` but no memory analogue).

**Evidence.**
```rust
        let v = self.bytes_mut();
        v.extend_from_slice(&(data.len() as u32).to_le_bytes());
        let off = v.len() as u32;
```
```rust
    fn alloc_array_buffer(&mut self, byte_length: u32) -> crate::value::SlotIndex {
        self.meter.tick_chunk_new(byte_length as u64);
        let data = self.chunks.alloc(&vec![0u8; byte_length as usize]);
```
`Halt::StackOverflow`'s own doc calls the stack limit "a deterministic, consensus-relevant limit
in the xsnap lineage" — the memory limit XS aborts on (`fxGrowSlots` → `XS_NOT_ENOUGH_MEMORY_EXIT`)
has no counterpart here.

**Impact.** Per-crank RSS is O(total allocation), not O(live), bounded only by the meter (and by
nothing at all when no meter host is installed — the current `rust/endo` state). Past 4 GiB of
chunk bytes the offset wrap is silent aliasing of string/BigInt/ArrayBuffer payloads inside a
`#![forbid(unsafe_code)]` crate: memory-safe, and exactly the "silent wrong state" the design
rules out. It is also a divergence from the oracle in the other direction: a program XS aborts on
for memory runs to completion here.

**Recommendation.** Make `ChunkArena::alloc` and `SlotArena::alloc` fallible on handle-space
exhaustion, add a configurable arena ceiling, and give `Halt` a `HeapExhausted` variant that the
dispatch loop can return so the limit is a deterministic, release-versioned abort like
`StackOverflow`.

### F6 — The GC schedule is consensus state and its only input is unauthenticated at rest (HIGH, medium confidence, partially-known)

**Claim.** `PersistentMachine` derives every scheduled collection from `manifest.cranks`
(`total_after % collect_every`), and `validate_store` never checks `cranks` against anything, so a
length-preserving flip of that field at rest changes when the replica next collects — which
rewrites the free list, which changes allocation order and every subsequent durable image.

**Sites.** `rust/endo/src/ironhorse_engine.rs:512–513`; `ironhorse-snapshot/src/store.rs:221`
(`pub cranks: u64`), `:3106–3200` (`validate_store` — version, schema, signature, epoch != 0,
cost table, symbol counter, empty STAC, accounting, leaf/edge counts, root recombination; no
`cranks` check and no recomputation of the stored manifest's seal).

**Evidence.**
```rust
            let collect_due = self.cadence.collect_every > 0
                && total_after % self.cadence.collect_every as u64 == 0;
```
```rust
/// a replica that collects and one that does not diverge in
/// subsequent allocation order).
```
(the `partial_collect` doc, machine.rs:1936–1942, states the replica-visibility itself).

**Impact.** The design asks for GC scheduling to be "a pure function of release-fixed allocation
thresholds". It is instead a function of an embedder-chosen `collect_every` and a stored counter
that the integrity stack does not cover. A single-bit change to a field outside the Merkle root
forks the heap layout of that replica silently — and, since a manual `PersistentMachine::collect`
is also available, two honestly-configured replicas can diverge by operator action alone.

**Recommendation.** Bring `cranks` inside the authenticated set (recompute the seal over the
stored manifest at open, or fold `cranks` into the row-hash root), and move `collect_every` out of
`CadencePolicy` into a release constant stamped beside `COST_TABLE_VERSION` so the collection
schedule is part of the versioned consensus artifact rather than deployment configuration.

### F7 — Six hand-mirrored side-table rosters with only a name-presence tie (MEDIUM, high confidence, known-open)

**Claim.** Every side table's GC participation is spelled out by hand in six bodies — the `Hooks`
field list, `extra_edges`, `swept` + the late prune, `external_chunk_refs`, `free_pages`, and
`each_side_table_ref_tail` — and the only mechanical check that they agree is F3's name-presence
test.

**Sites.** `ironhorse-vm/src/interp.rs:43711–43755`, `:43806–43999`, `:44001–44043` +
`:44343–44383`, `:44137–44289`, `:44577–44644`, `:44761–44941`.

**Evidence.** The rosters *currently* agree — I diffed them mechanically: the two prune lists
contain the same 46 tables (symmetric difference empty), and `extra_edges` vs
`each_side_table_ref_tail` differ only by `symbol_key_ids`/`symbol_registry_keys` (deliberate).
The code records what a past disagreement cost:
```rust
        // A table missing here let the collector sweep a live proxy target
```
and the mirroring is maintained by comment (`"mirrored from the full collector's functions arm"`,
:44790). `symbol_key_ids` is pruned three separate times per full collection (:44019, :44134,
:44346) — the fingerprint of roster drift.

**Impact.** This is the generator of the bug class the review waves keep re-finding (F2 is a fresh
instance). Nothing makes an omission a compile error; the 46-table agreement is one careless PR
away from a silent hole in exactly one of six places.

**Recommendation.** Replace the six bodies with one per-table description — a small trait
(`edges`, `chunks`, `prune`, `partial_roots`) implemented once per side-table type, plus a single
`for_each_side_table!` macro/registry the six entry points drive. Then adding a table without
implementing the trait is a compile error, and the registry test degrades to a completeness check
over the registry rather than a textual grep.

### F8 — Neither collector checks quiescence; `pending_new_target` is an unrooted register kept safe by a convention `run()` does not enforce (MEDIUM, high confidence, partially-known)

**Claim.** `collect_garbage` and `free_pages` are `pub` with no `is_quiescent()` guard, and
`pending_new_target` — a `SlotIndex` register that is not in `gc_roots` — is disarmed only by the
eval wrapper and by `unwind_to_jump`, not by `run()`, so a host collection after a
`StepLimit`/`MeterAbort` halt can sweep the pending `new.target`.

**Sites.** `ironhorse-vm/src/interp.rs:3856` (field), `:43707` / `:44556` (both collectors, no
guard), `:8072` and `:34603` (the only two disarm sites), `:13496` / `:24008` (arm sites);
`ironhorse-vm/tests/gc_visitation_registry.rs:362`.

**Evidence.**
```rust
    ("pending_new_target", &[Req::DocumentedOnly], "armed by SUPER, consumed/disarmed before every boundary (W6-15); collections run only at quiescent boundaries"),
```
`grep -n pending_new_target interp.rs` shows no assignment inside `run` (11157–11250);
`partial_collect` asserts only clean dirty state (machine.rs:1957–1960), never quiescence.

**Impact.** The registry's justification is an unenforced convention. The moment the design's
allocation-threshold trigger lands (or a host calls the `pub` collector after a halt), this
register becomes a live dangling root. It is also the register that the vm-tests wave found
leaking into the next crank's `new.target`.

**Recommendation.** `debug_assert!(self.is_quiescent())` at the top of both collectors (after F1
makes `is_quiescent` mean what it says), and reset `pending_new_target` at `run()` entry beside
`strict` and `active_segment`.

### F9 — Arena accessors never consult the free bit; `free` has no double-free guard (MEDIUM, high confidence, known-open)

**Claim.** `SlotArena::get`/`get_mut`/`mark` index the record vectors without checking
`free_marks`, so a stale index into a freed-not-reused slot returns its old bytes and passes every
kind check, and `free` can push the same index twice, aliasing one record to two later
allocations.

**Sites.** `ironhorse-vm/src/value.rs:853–859`, `:861–876`, `:901–912`, `:841–846`; the O(1)
predicate that would catch it is right there at `:929–931`.

**Evidence.**
```rust
    pub fn free(&mut self, index: SlotIndex) {
        debug_assert!(!index.is_null());
        self.free.push(index.0);
        self.free_marks[index.0 as usize] = true;
        self.live -= 1;
    }
```
```rust
    fn is_free(&self, i: u32) -> bool {
        self.free_marks.get(i as usize).copied().unwrap_or(false)
    }
```
The design says a stale index is "a logic bug caught by kind checks, not undefined behavior"; the
code records having hit exactly the uncaught form ("a reused slot answered Temporal's brand
check", interp.rs:44351–44356). With no `[profile] overflow-checks` in either Cargo.toml,
`self.live -= 1` wraps silently in release on a double free.

**Impact.** The failure mode of the whole root-omission class is *silent wrong read* rather than a
deterministic panic — the opposite of the design's memory-safety-confidence posture. Under a lazy
arena, `get` on a freed index also faults its page in.

**Recommendation.** `debug_assert!(!self.is_free(index.0))` in `get`/`get_mut`/`mark`, and a
`debug_assert!(!self.is_free(index.0))` plus a `checked_sub` on `live` in `free`. That converts
the class into a deterministic debug panic at no release cost, and would have caught F2 in the
existing test suite.

### F10 — ArrayBuffer restore validates the declared length against the arena, not against the chunk header, and compaction then truncates the buffer (MEDIUM, medium confidence, new)

**Claim.** `restore_typed_array_family` accepts a buffer whose declared `length` exceeds the
stored length of its chunk block; `slice_mut` then reads and writes across neighbouring blocks,
and the next `compact()` copies only `len_of(data)` bytes, so the buffer's tail silently changes
across a collection.

**Sites.** `ironhorse-vm/src/interp.rs:9031–9042`; `ironhorse-vm/src/value.rs:1529–1534`
(`slice_mut`), `:1605–1613` (compaction copies `len_at(old)`).

### F11 — `ChunkArena::compact` silently resurrects a stale in-range offset, contradicting its own doc (MEDIUM, high confidence, known-open)

**Claim.** The only filter compaction applies to the reported live set is `!o.is_null()`;
out-of-range offsets panic, but a stale *in-range* offset is treated as a live block, reads a
bogus length header from mid-payload bytes, and is copied and remapped — silently changing the
arena's layout — even though the doc promises unknown offsets are ignored.

**Sites.** `ironhorse-vm/src/value.rs:1541` (doc), `:1550–1556` (the filter), `:1566–1588`
(validation rejects only out-of-range), `:1602–1616` (copy + remap).


## 3. Strengths

- **The kernel/seam split is right.** `gc.rs` is small, pure and independently testable; the
  machine's ~40 side tables are confined to one `impl` behind `GcHooks`. The two-pass
  `external_chunk_refs` (liveness, then rewrite) gives side-table-held strings exactly the
  treatment arena-resident strings get, and the chunk-holder roster is genuinely complete —
  only three `ChunkOffset`-typed field families exist and all three are visited.
- **Determinism is engineered, not incidental.** Roots are sorted and deduped, the sweep is
  index-order, `compact` sorts its live set, the reaction/code-segment arenas compact through
  `BTreeSet`/`BTreeMap`, and `side_table_ref_page_bits` is a bitmap. Every `HashMap` iteration I
  traced perturbs only worklist order, never the mark set, the free list, or byte layout.
- **The in-hook vs late-prune split is correctly reasoned and documented**: only chunk-bearing
  tables must be pruned before compaction, and the code says exactly why.
- **Weak-collection semantics are precise where the full collector runs**: ephemeron marking gated
  on map *and* key, dead-keyed entries physically removed before the sweep, unmarked collections
  dropped wholesale through the counted accessors.
- **`bulk.rs`'s privacy-as-soundness pattern is the right shape** — private maps, counted
  accessors, no `Clone`, a single documented escape hatch — and the restore path rebuilds the
  counts through the same accessors (`restore_bulk_side_tables`, interp.rs:10525–10555).
- **The struct-derived registry is an unusually good idea.** Deriving the slot-bearing field set
  from the struct source so a new field cannot be silently unclassified is the correct shape; F3
  is about its checks, not its premise.
- **`compact` validates before `mem::take`** so a corrupt offset can never leave the arena emptied
  — a subtle failure mode caught deliberately, with the reasoning in the comment.
- **The absence of `WeakRef`/`FinalizationRegistry`** (they appear only as default key names) is
  what currently makes GC timing guest-*unobservable*; that is a real, load-bearing property, and
  the code is honest that only `WeakMap`/`WeakSet` exist.
- **`free_pages` does its page arithmetic in `u64` with the wrap explained**, and the store-side
  decoder gates the free list hard (range, no duplicates, accounting) — image.rs:810–828.

## 4. Recommended architectural direction

The heap model's defining choice — index arenas plus dozens of `Interp`-side `HashMap` side tables
holding `Slot`/`SlotIndex` — is what makes snapshots nearly structural and what makes the root set
open-ended. That trade is defensible, but it converts "which fields are roots, edges, chunk
holders and prune targets" from a property of the type system into a hand-maintained roster
mirrored across six bodies and two collectors. The single highest-leverage change is to make that
roster a *type-level* fact: one small trait per side table (`edges`, `chunks`, `prune`,
`partial_roots`) and one registry that all six entry points drive. Then adding a table without
classifying it is a compile error, the registry test degrades to a cheap completeness check, and
the two-collector duplication disappears — `free_pages` and `collect_garbage` become two policies
over one visitor rather than two rosters that happen to agree today.

The second structural gap is that the machine has two disagreeing definitions of "boundary". The
snapshot ledger says nine registers are provably default at a persistable boundary; the GC
registry says the same nine are roots; `is_quiescent()` checks three stack-shaped fields and none
of the nine. F1 is what that disagreement costs — a silent consensus fork on ordinary JavaScript,
invisible to the differential suites because results and computrons agree. Collapse the three
definitions into one: `is_quiescent()` should assert exactly the set the ledger calls TRANSIENT,
every persist verb should gate on it, and both collectors should `debug_assert` it. That single
invariant subsumes F1, F8, and the `pending_new_target`/`target_func` residue, and it makes the
"uninterrupted twin == resumed twin" property checkable by a test rather than argued in prose. Add
the twin shape my probe used — continuous vs resumed *image bytes* after a boundary collection —
to the carry suites; nothing in the tree compares post-collection heap layout across a resume
today, which is precisely why W6-11 could regress.

Third, decide what GC *is* in this system. Right now the exact collector is a test-only artifact
while production runs a page-conservative partial collector on an embedder-chosen cadence, which
means weak collections are strong, chunk space never shrinks, and the design's "release-fixed
allocation thresholds" do not exist. Since the schedule provably feeds the free list and therefore
durable bytes, the schedule is a consensus artifact and belongs beside `COST_TABLE_VERSION`, not
in a `CadencePolicy` struct — and its stored input (`manifest.cranks`) belongs inside the
authenticated root. Wiring the exact collector into that release-fixed schedule is what makes
`WeakMap` honest and bounds heap growth; it also makes F2's class immediately fatal instead of
latent, which is the right pressure to have on the root set before `WeakRef`/`FinalizationRegistry`
(which would make GC timing guest-observable) are ever considered.
