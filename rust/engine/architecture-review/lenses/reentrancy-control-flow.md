# Lens: Re-entrancy, nested dispatch, and suspension

HEAD 97d8de25. All findings below were verified by reading the cited lines in the current
tree; the ones marked **(probe)** were additionally reproduced by a standalone binary built
OUTSIDE the repo (`scratchpad/probeRE/p*.rs`, `rustc -O` linked against the already-built
`target/debug/deps/libironhorse_vm-a67d9d349a051016.rlib` +
`libironhorse_compile-7173d8fbec500ced.rlib`). No repo file was created, modified, or built.

## 1. Assessment

The engine has exactly one *designed* re-entrancy discipline and it is a good one: every
nested guest run goes through `dispatch_at` (interp.rs:11280), which brackets a
`dispatch_depth` counter against `DISPATCH_REENTRY_LIMIT = 64`; a nested loop knows the call
depth it was entered at (`return_depth`) and refuses to consume a `CatchJump` that belongs to
a frame below it, returning `Halt::Resume(target)` upward instead; suspension moves an entire
activation (`locals`/`id_map`/`args`/`this_val`/`env`/`strict`/`result`/stack slice/rebased
handlers) into a `SavedFrame`, and `frame_slots` accrual/release is symmetric across
`enter_call`/`leave_call`/the three resume drivers. The `strict` latch is correct at every
seam I checked (`enter_call` clears it, `leave_call`/`unwind_to_jump`/resume restore it,
`run` resets it per crank). Hostile-bytecode suspend shapes fail closed by name rather than
panicking. Where the discipline is applied, it works: 200 levels of `.forEach`-mediated
recursion halt cleanly with `Halt::StackOverflow(1346)` (probe).

The problem is that **none of these three invariants is enforced by a mechanism — each is a
convention that must be re-typed at every site, and I found live sites where it was not.**

The `return_depth` protocol lives in one macro (`dispatch_result!`, :3573) and in two
hand-written copies in `THROW`/`RETHROW` (:15706, :15729). There are **eleven other
hand-expanded raise arms** — `match self.raise_js(error) { Ok(target) => { pc = target; …
continue } }` at :11738, :11800, :11830, :11915, :11928, :12624, :12666, :13076, :13093,
:13168, :13184 — and **not one of them tests `call_stack.len() < return_depth`**. Inside any
nested dispatch, an unresolved-variable ReferenceError, a `ToObject(null)` TypeError, a TDZ
ReferenceError, a const-assignment TypeError or a strict `delete`/assignment TypeError that
unwinds to a handler *below* the re-entry boundary makes the **inner** loop resume the
**outer** frame's handler. Probes: `try { [1].forEach(function(){ nosuchvar; }) } catch {}`,
`try { '' + {toString(){ nosuchvar }} } catch {}`, a getter, a Proxy `get` trap and
`Array.prototype.map` each end the crank with `Unsupported("end:frame-underflow")`; the same
raise inside a generator body escapes as an uncatchable `Throw("ReferenceError")`. The
identical programs written with an explicit `throw` are all caught correctly. This is a
silent correctness hole across the whole native-callback surface, and the interp-06 region
map recorded this very invariant as "upheld consistently".

The re-entry budget has the same shape. `dispatch_at` is a chokepoint only for
*guest*-re-entry; **native→native cycles never pass through it and have no counter at all.**
Two are guest-reachable and abort the process (SIGABRT, not a panic, not a `Halt`,
uncatchable by `catch_unwind`): `finish_async_generator_request` ↔ `kick_async_generator`
(:16971 ↔ :16914/:16919/:16932), one Rust frame pair per queued request — `for(i<40000)
g.next()` on an async generator aborts (probe); and `ordinary_get` → `proxy_get` → `mop_get`
→ `ordinary_get` (:36206) over a prototype cycle that `prototype_chain_would_cycle` (:36613)
deliberately permits through a proxy — `Object.setPrototypeOf(t, new Proxy(t,{})); t.zzz`
aborts (probe). Other regions found the same class in `render`, `JSON.parse/stringify` and
the compiler front end. The design's memory-safety envelope ("a panic is a crashed crank,
not a compromised daemon") does not cover a stack abort.

Native "run guest code under a try" is implemented three incompatible ways: fenced
(`step_async` :17238, `step_async_generator` :17017, both `mem::take(&mut self.jumps)`);
deliberately unfenced (`resume_generator`, matching XS); and **accidentally unfenced**
(`run_callback_catching_throw` :16588, `call_any_catching_throw` :21740), which record a
`jump_depth` they never enforce and catch only `Halt::Throw`. Consequence (probe):
`try { p = new Promise(function(){ throw 1; }) } catch(e) { r='caught:'+e }` yields
`"caught:1"`; spec and XS reject `p` and never enter the handler. The fenced twins' own
comments say the async version of this bug was found and fixed during a rebase review — the
sync one was never given the same primitive.

Two more registers cross the re-entry boundary out of band. `callback_return_depth`
(:15229/:15296/:15452/:15502 ↔ :16443/:16578/:36528) is a machine-global `Option<usize>`
that decides whether a nested `Halt::Return` means "the callback returned" or "a throw
unwound past me"; it is set to `None` before each nested dispatch but never cleared after,
and three different substrates share it. `pending_new_target` (:13496, :24008 → :16291) is
disarmed only by `unwind_to_jump` (:34603) and the eval wrapper; `run()` does not reset it
and `is_quiescent` does not check it, so **every non-throw halt leaks it across the crank
boundary**: probe — a `StepLimit` between `SUPER` and the construct frame makes the *next*
crank's `new F()` observe `new.target !== F`. It is also absent from `gc_roots` (:43502), so
a boundary collection can free the slot it names.

GC safety under re-entrancy is not broken today, but only because **no code in
`ironhorse-vm` ever collects**: the only `collect_garbage`/`free_pages` callers are
`ironhorse-snapshot/src/machine.rs`. Every native that holds a `SlotIndex` in a Rust local
across a guest callback (`settle_promise`'s `derived`, `array_from_async`'s result promise,
combinator `derived`, `run_callback`'s frame slots) is unrooted. The design promises XS's
allocation-triggered collector; landing it turns those into use-after-sweep sites.

## 2. Findings

### F1. The `return_depth` protocol is enforced by a macro that eleven hand-expanded raise arms do not implement — nested dispatch resumes an outer frame's handler inside the inner loop

- **Severity** critical · **Confidence** high (probe) · **Category** reentrancy · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:11800`; other sites `:11738`, `:11830`,
  `:11915`, `:11928`, `:12624`, `:12666`, `:13076`, `:13093`, `:13168`, `:13184`;
  correct forms at `:3577-3583` (`dispatch_result!`) and `:15705-15712` (`THROW`).
- **Claim** Inside any nested `dispatch_at` (a callback, a coercion, a getter, a proxy trap,
  a generator/async resume, a cross-segment call), an error raised by one of the eleven
  hand-expanded `raise_js` arms whose handler lives in a frame *below* the re-entry boundary
  makes the inner loop continue executing the outer frame — ending the crank with
  `Unsupported("end:frame-underflow")` or escaping as an uncatchable `Halt::Throw`, where the
  same program written with `throw` is caught correctly.
- **Evidence** (the defective form; note the absent depth test)
  ```rust
  match self.raise_js(error) {
      Ok(target) => {
          pc = target;
          if self.check_meter() == MeterCheck::Abort { return Halt::MeterAbort; }
          continue;
      }
      Err(halt) => return halt,
  }
  ```
  versus `THROW` at :15705 —
  ```rust
  Some(target) => {
      if self.call_stack.len() < return_depth { return Halt::Resume(target); }
      pc = target;
  ```
  Probe results (all should answer `"caught"`):
  | program | Ironhorse |
  |---|---|
  | `function g(cb){[1].forEach(cb);} function h(){try{g(function(){throw new ReferenceError()})}catch(e){return 'caught'}} h()` | `"caught"` (baseline OK) |
  | same, callback body `nosuchvar;` | `completed=false halt=Unsupported("end:frame-underflow")` |
  | `function h(){var o={toString:function(){nosuchvar}}; try{return ''+o}catch(e){return 'caught'}} h()` | `Unsupported("end:frame-underflow")` |
  | getter body `nosuchvar` behind `Object.defineProperty` | `Unsupported("end:frame-underflow")` |
  | Proxy `get` trap body `nosuchvar` | `Unsupported("end:frame-underflow")` |
  | `[3,1,2].map(function(){nosuchvar})` in a `try` inside a function | `Unsupported("end:frame-underflow")` |
  | `function* gg(){ nosuchvar; yield 1 } try{gg().next()}catch(e){r='caught'}` | `Throw("ReferenceError")` (uncatchable) |
  | same generator with `throw 1` | `"caught"` (baseline OK) |
- **Impact** A whole class of ordinary, spec-legal `try`/`catch` programs gets the wrong
  answer or dies. It is worse than a halt in the cross-segment case: when `run_callback`
  switched `body_code` to a different segment buffer, `pc = target` is a pc in the *caller's*
  buffer decoded against the *callee's* bytes — arbitrary opcode execution. For a consensus
  engine this is a result divergence on inputs that look completely benign, and it defeats
  the differential harness because `Halt::Unsupported` is scored as a coverage skip
  (`xst.rs` → `Verdict::RunSkip`), not a divergence.
- **Recommendation** Delete all eleven hand-expanded arms and route them through
  `dispatch_result!(self.raise_js(error), pc, self, return_depth)` (14 sites in the same file
  already do exactly that: :11534, :11684, :12286, :12458, …). Better: make `raise_js`
  private and expose only `catchable_*_error() -> Halt::Resume`, so the depth test cannot be
  omitted; then add a grep-level test asserting no `match self.raise_js(` remains in
  `dispatch_at_inner`. Also add a differential fixture per raise arm × per re-entry substrate.

### F2. Guest-reachable native→native recursion cycles bypass `DISPATCH_REENTRY_LIMIT` entirely and abort the process

- **Severity** critical · **Confidence** high (probe) · **Category** robustness · **Novelty** new
  (the async-generator instance is interp-07 candidate 2 of this same wave; the proxy
  instance is interp-13 candidate 4)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16971`; other sites `:16914`, `:16919`,
  `:16932`, `:36206-36207`, `:36613-36625`; the guard that does not cover them `:11280-11290`.
- **Claim** `DISPATCH_REENTRY_LIMIT` counts only re-entry through `dispatch_at`; two
  native-only cycles recurse once per guest-controlled unit with no counter, overflowing the
  Rust stack — a `SIGABRT` of the whole worker, not a `Halt`, not a panic, not containable by
  `catch_unwind`.
- **Evidence**
  ```rust
  // finish_async_generator_request, :16960-16971
  self.settle_via_function(if reject { request.reject } else { request.resolve }, value)?;
  self.kick_async_generator(code, gen)
  ```
  ```rust
  // kick_async_generator, :16910-16914 — Completed + Next calls straight back
  AsyncGeneratorState::Completed => match request.status {
      GenStatus::Next => { let result = self.new_generator_result(Slot::undefined(), true);
          self.finish_async_generator_request(code, gen, result, false) }
  ```
  ```rust
  // ordinary_get :36206 — proxy in the prototype chain re-enters the MOP, no depth counter
  if owner != inst && self.proxies.contains_key(&owner) {
      return self.proxy_get(code, owner, id, receiver);
  }
  // prototype_chain_would_cycle :36623 — the cycle check deliberately stops at a proxy
  if self.proxies.contains_key(&p) { return false; }
  ```
  Probes (`rustc -O`, 8 MiB main thread):
  `async function* ag(){} var g=ag(); for(var i=0;i<40000;i++) g.next(); 1` →
  `fatal runtime error: stack overflow, aborting`, exit 134.
  `var t={}; var p=new Proxy(t,{}); Object.setPrototypeOf(t,p); t.zzz` → same, exit 134.
  Control: 200-level `.forEach` recursion → `Halt::StackOverflow(1346)`, exit 0.
- **Impact** Any guest can kill the validator/vat process. In a consensus setting the abort
  threshold is a function of host thread stack size and build profile, so replicas do not
  even agree on *when* they die. Sibling instances of the same class were found by other
  lenses in `render` (cyclic array completion), `JSON.parse`/`stringify`, and the parser /
  scoper / coder — i.e. this is a repo-wide missing invariant, not three bugs.
- **Recommendation** Make the re-entry budget a machine invariant rather than a property of
  one function: a `ReentryGuard` RAII token incremented by *every* function that can re-enter
  guest code or itself (`dispatch_at`, `kick_async_generator`/`finish_async_generator_request`,
  `ordinary_get`/`proxy_*`/`mop_*`, `render`, JSON walkers), returning `Halt::StackOverflow`
  on exhaustion. Convert the async-generator drain cycle to a loop over the request queue
  (it is already a `VecDeque`) rather than mutual recursion. Add a `#[deny]`-style test
  (or a fuzz target) that asserts no guest program can abort the process.

### F3. `run_callback_catching_throw` does not fence the caller's handler chain: a promise executor's throw is caught by the caller's `try/catch` and the promise never settles

- **Severity** high · **Confidence** high (probe) · **Category** reentrancy · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16588`; twin `call_any_catching_throw`
  `:21740`; the correct form at `:17017` and `:17238`.
- **Claim** The function records `jump_depth` but leaves `self.jumps` live across the nested
  run, and catches only `Halt::Throw`; a guest throw inside a promise executor / thenable
  `then` / disposer therefore unwinds into the *caller's* live handler and returns
  `Halt::Resume`, which is passed straight through.
- **Evidence**
  ```rust
  /// Run a callback behind a native `mxTry` boundary. Promise executors,
  /// reactions, and thenable jobs catch a guest throw in native code: … the
  /// surrounding promise is rejected instead of the machine halting.
  fn run_callback_catching_throw(…) -> Result<Result<Slot, Slot>, Halt> {
      let jump_depth = self.jumps.len();           // recorded, never enforced
      match self.run_callback(code, func, this, args) {
          Err(Halt::Throw(_)) => { … self.jumps.truncate(jump_depth); … }
          Err(halt) => Err(halt),                  // Halt::Resume escapes here
  ```
  versus `step_async` :17238 `let fenced_jumps = std::mem::take(&mut self.jumps);`.
  Probe: `var r=0; var p; try { p = new Promise(function(){ throw 1; }); } catch(e){ r='caught:'+e; } r`
  → `"caught:1"`. Spec/XS: `r === 0` and `p` is rejected.
- **Impact** Silent result divergence plus a promise that never settles (an unresolvable
  vat message). The doc comment asserts the opposite of the behavior.
- **Recommendation** Extract one `run_guest_under_native_try` primitive that fences
  (`mem::take`), runs, catches both `Halt::Throw` and `Halt::Resume` (a `Resume` reaching a
  fenced boundary is by construction the body's own unfinished unwind), restores the chain,
  and clears `self.exception`; use it for the executor, thenable jobs, reactions, disposers,
  `call_any_catching_throw`, and `from_async_try`. Keep `resume_generator` explicitly
  unfenced with a comment naming XS's behavior.

### F4. `enter_call` returns a catch-handler pc through its `Ok(usize)` success channel, and `cross_segment_callee` classifies every object reference as a callee — `try { obj() } catch {}` inside a function frame is silently wrong

- **Severity** high · **Confidence** high (probe) · **Category** api-boundary · **Novelty**
  partially-known (`designs/ironhorse-snapshot-store-seam.md:3143-3160`, ledger item P2-2,
  "a cross-crank `.call` on a guest function … throws in the UNINTERRUPTED baseline too" — the
  same root cause, recorded but not diagnosed)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16220-16223`; other sites `:16525-16536`
  (`cross_segment_callee`), `:16553` (`call_cross_segment`), `:16564-16580`
  (`dispatch_entered_cross_segment`), `:13936-13981` (the `RUN` arm).
- **Claim** `enter_call`'s non-callable branch returns `raise_js`'s handler pc as if it were
  a body start; `cross_segment_callee` treats any `Payload::Reference` as a callee (segment
  `None`), so once any function has been defined (`code_segments` non-empty, `active_segment`
  = `Some(k)`) a non-callable call inside a function frame routes into a nested dispatch at
  the handler pc over the wrong buffer.
- **Evidence**
  ```rust
  // enter_call :16220 — Ok(catch pc) through the body-start channel
  _ => { let error = self.build_error("TypeError", 0, 0); return self.raise_js(error); }
  ```
  ```rust
  // cross_segment_callee :16529 — no callability test
  let f = match self.stack.get(base + 1).map(|slot| slot.value) {
      Some(Payload::Reference(f)) => f, _ => return None, };
  let seg = self.callee_segment(f);
  (seg != self.active_segment).then_some(seg)
  ```
  Probes:
  `var r; try { ({})(); } catch(e){ r = e instanceof TypeError ? 'TypeError':'other' } r`
  at top level → `"TypeError"` (correct);
  `function f(){ try { ({})(); } catch(e){ return e instanceof TypeError?'TypeError':'other' } return 'no' } f()`
  → `completed=false halt=Throw("ReferenceError")`;
  `function assertThrows(fn){ try { fn(); } catch(e){ return e instanceof TypeError; } return false; } var o={}; assertThrows(function(){ o(); })`
  → `"undefined"` (spec: `true`).
- **Impact** The `assert.throws(TypeError, () => obj())` shape — pervasive in test262 and in
  defensive contract code — returns a wrong value or halts the crank, on any program that
  defines a function. The `Ok(usize)` overload is a loaded gun for the other three consumers
  (:16408, :36524, :13971), which are safe only because they pre-screen `functions.contains_key`.
- **Recommendation** Change `enter_call`'s error channel to `Err(Halt::Resume(target))`
  (the shape `catchable_type_error` already uses at :34654) so the success type means one
  thing; give `cross_segment_callee` a callability test (`self.functions.contains_key(&f)`)
  before it claims the callee. Add a fixture for each of the four `enter_call` consumers.

### F5. `pending_new_target` is a hidden control latch that survives every non-throw halt into the next crank, and is not a GC root

- **Severity** high · **Confidence** high (probe) · **Category** reentrancy · **Novelty**
  partially-known (W6-15 fixed the throw path only; the registry note asserting the general
  claim is false)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:13496` (arm), `:24008` (arm), `:16291`
  (consume), `:34603` (the only in-loop disarm), `:11157-11175` (`run` does not reset it),
  `:10733-10743` (`is_quiescent` does not check it), `:43502-43695` (`gc_roots` does not root
  it); `ironhorse-vm/tests/gc_visitation_registry.rs:362`.
- **Claim** `Halt::StepLimit`, `MeterAbort`, `Unsupported`, `StackOverflow` and `Decode`
  return out of the dispatch loop without passing through `unwind_to_jump`, so an armed
  `pending_new_target` persists; the next crank's first `new`-call consumes it as its
  `new.target`.
- **Evidence**
  ```rust
  self.pending_new_target = Some(self.target_func);     // :13496 (SUPER)
  self.target_func = if has_target { self.pending_new_target.take().unwrap_or(func) } …  // :16291
  ```
  Registry note (unconditionally satisfied — `Req::DocumentedOnly => true`):
  `("pending_new_target", &[Req::DocumentedOnly], "armed by SUPER, consumed/disarmed before every boundary (W6-15); collections run only at quiescent boundaries")`
  Probe: crank 1 = `class A{constructor(){this.a=1}} class B extends A{constructor(){super()}} new B(); 'done'`
  under `run_bounded(.., 50)` → `StepLimit(50)`; crank 2 (unbounded, same machine) =
  `function F(){ this.t = (new.target === F); } var o = new F(); o.t ? 'own' : 'STALE'`
  → `"STALE"`.
- **Impact** Cross-crank silent wrong state on a consensus-critical machine. Because the
  register is not a GC root, a boundary `collect_garbage`/`free_pages` between the two cranks
  can free the constructor slot it names; `SlotArena::get` does not consult the free bitmap
  (`value.rs:853`), so the stale index reads as whatever now occupies the record — a
  kind-confusion read, not a caught error. `PersistentMachine` masks it by rewinding any
  `!completed` crank; the 262 harness, `Machine::eval`, and any raw embedder do not.
- **Recommendation** Clear `pending_new_target` (with `callback_return_depth`,
  `resume_status`, `eval_direct`) at the top of `run`, add all four to `is_quiescent`, and
  add `pending_new_target` to `gc_roots`. Replace `Req::DocumentedOnly => true` with a
  behavioral twin: arm, halt by every `Halt` variant, assert `new.target` in the next crank.

### F6. `DISPATCH_REENTRY_LIMIT = 64` is a second stack budget that aborts ordinary programs at a third of the value-stack budget, and the abort point depends on which native mediates the recursion

- **Severity** high · **Confidence** high (probe) · **Category** robustness · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:205` (const), `:11281-11285` (guard),
  `:164`/`:179` (`STACK_SLOT_COUNT = 4096`, `STACK_SLOT_RESERVED = 32`), `:16248` (the only
  `would_overflow` check).
- **Claim** Recursion mediated by any callback-taking native (`map`/`forEach`/`reduce`/`then`,
  a getter, a coercion, a proxy trap) aborts the crank at 64 levels — with the value stack at
  ~1/3 of XS's `fxOverflow` budget — while the same recursion expressed as direct JS calls
  runs to ~4064 slots. The overflow point is therefore a function of program *shape*, not of
  a modeled machine limit.
- **Evidence**
  ```rust
  if self.dispatch_depth >= DISPATCH_REENTRY_LIMIT {
      return Halt::StackOverflow(self.stack_slots_in_use());
  }
  ```
  Probe: `function rec(n){ if(n===0) return 0; var r=0; [1].forEach(function(){ r = rec(n-1); }); return r; } rec(200)`
  → `completed=false halt=StackOverflow(1346)` — 1346 of a 4064-slot budget.
  The const's own doc concedes it is chosen from a fuzz crash, not from a measured
  `dispatch_at_inner` frame size ("the `dispatch_at` activation is tens of KiB").
- **Impact** A recursive tree walk through `.map` deeper than 63 — routine in SES/Endo
  marshalling code — halts on Ironhorse where XS completes. `Halt::StackOverflow` is an
  abort to the host, so this is a liveness failure of the vat, and the divergence is not
  listed anywhere in the design.
- **Recommendation** Shrink `dispatch_at_inner`'s activation (hoist the mid-sized `RUN` and
  `GET_PROPERTY` arms into `#[inline(never)]` methods) so a large budget is affordable; then
  set the limit from a measured frame size against a documented minimum thread stack, and
  document the resulting maximum nesting as an engine-visible limit alongside
  `STACK_SLOT_COUNT`. Run the engine on an explicitly sized thread rather than relying on
  the host default.

### F7. Three incompatible "native try" boundaries and no shared primitive

- **Severity** medium · **Confidence** high · **Category** modularity · **Novelty** new
  (structural cause of F3)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16588` (unfenced, `Throw`-only),
  `:21740` (`call_any_catching_throw`, same), `:17017` and `:17238` (fenced),
  `:16668-16859` (`resume_generator`, deliberately unfenced), `:21633-21660`
  (`from_async_try`, a fourth hand-rolled unwind), `:21893-21895` (`array_from_async`
  isolates `jumps` by hand for its prologue).
- **Claim** Whether a native that runs guest code isolates the caller's handler chain, which
  `Halt` variants it treats as "the guest threw", and whether it clears `self.exception` are
  decided independently at each of five sites.
- **Evidence** `let fenced_jumps = std::mem::take(&mut self.jumps);` (:17238) vs
  `let jump_depth = self.jumps.len();` (:16590) vs `let r = self.call_any(...); self.from_async_try(r, sb, cd, jd)` (:21752).
- **Impact** F3 exists because the fix applied to the async twin was not applied to the sync
  twin; the next native that runs guest code will pick one of five patterns at random.
- **Recommendation** One primitive (see F3's recommendation), with the unfenced generator
  case expressed as an explicit flag on it rather than as a separate code path.

### F8. `render_uncaught` executes guest code after the halt is decided, and silently discards any halt it raises

- **Severity** medium · **Confidence** high · **Category** reentrancy · **Novelty** new
  (interp-05 candidate 5 of this wave)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:11072-11088`; call sites `:15049-15051`,
  `:15715-15717`, `:15738-15740`.
- **Claim** After `meter_host_escape()` has adjusted the meter and with `self.exception`
  already set, the throw arms call `render_uncaught`, which re-enters guest code through
  `to_primitive` → `call_primitive_method` → `run_callback` → `dispatch_at`; a nested throw,
  meter abort or `Unsupported` inside that `toString` is dropped by `if let Ok(prim)`, while
  its allocations, meter ticks and queued promise jobs stay in the halted machine.
- **Evidence**
  ```rust
  if let Ok(prim) = self.to_primitive(code, v, true) {
  ```
  with `to_primitive` (:38792) documented as running `call_primitive_method`/`run_callback`.
- **Impact** The "halted crank is the state at the throw" contract that the rewind path and
  the persist gate rely on is not true; `RunOutcome.computrons` includes the post-halt
  `toString` while the oracle shim captures its count before stringifying, so every uncaught
  user-object throw with a non-trivial `toString` diverges in computrons.
- **Recommendation** Capture the meter and the halt outcome before rendering; render on a
  cloned/quiesced view or render structurally without guest re-entry (the `error_data` path
  already does); if guest `toString` must run, run it under the F3 primitive and account its
  cost outside `RunOutcome.computrons`.

### F9. Re-entrant resume of an executing generator is an uncatchable `Halt::Unsupported`, not the spec's catchable TypeError

- **Severity** medium · **Confidence** high (probe) · **Category** error-model · **Novelty**
  known-open (self-named in the code)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16681-16685`
- **Claim** The one path the `Executing` state exists to guard answers with a crank halt.
- **Evidence**
  ```rust
  GeneratorState::Executing => {
      // Re-entrant resume of a running generator: `TypeError`
      // ("generator is running") in XS — a named skip for now.
      return Err(Halt::Unsupported("generator:already-running"));
  }
  ```
  Probe: `var it; function* gg(){ try { it.next(); } catch(e){ yield 'te'; } yield 'x'; } it = gg(); it.next().value`
  → `completed=false halt=Unsupported("generator:already-running")`. XS/spec: `'te'`.
- **Impact** Result divergence on legal JS; and because `Halt::Unsupported` is scored as a
  coverage skip by the 262 harness, the divergence is invisible to the acceptance bar. The
  guard itself is sound (no corruption) — only the reported error is wrong.
- **Recommendation** Replace with `self.catchable_type_error()` and a differential fixture.
  Do the same audit for the async-generator and async-function re-entry states (`kick`
  returns `Ok(())` and queues, which is correct; `step_async`'s `done` guard should be
  checked against `AsyncGeneratorState::Executing`'s handling).

### F10. The single value-stack overflow check is in `enter_call`; the three resume paths reinstall an arbitrarily large saved frame with no check

- **Severity** medium · **Confidence** high · **Category** robustness · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16248` (the only `would_overflow` call in
  the crate — verified by grep); resume sites `:16712`, `:16991`, `:17212`.
- **Claim** `resume_generator`/`step_async`/`step_async_generator` add `driver_footprint` to
  `frame_slots` and then `self.stack.extend(saved.stack_slice)` plus `self.locals = saved.locals`
  with no budget test, so `stack_slots_in_use()` can exceed `STACK_SLOT_COUNT - STACK_SLOT_RESERVED`
  and the abort fires only at the next `enter_call` inside the body.
- **Evidence** `grep -n "would_overflow(" interp.rs` → definition at :8213 and exactly one
  call site at :16248; `self.frame_slots += driver_footprint;` at :16712 with no guard.
- **Impact** `Halt::StackOverflow` is meant to bracket XS's `fxOverflow`; on the resume side
  the bracket does not hold, so a deeply nested generator/async chain aborts at a different
  point than XS. Deterministic per release, but not the modeled limit.
- **Recommendation** Add a `would_overflow(saved.stack_slice.len() + saved.locals.len() +
  saved.args.len() + FRAME_OVERHEAD_SLOTS)` check to all three resume paths before
  installing the frame, returning `Halt::StackOverflow`.

### F11. `callback_return_depth` gives `Halt::Return` two meanings through a machine-global register shared by three re-entry substrates

- **Severity** medium · **Confidence** medium (structural; I could not construct a program
  that aliases two boundaries at the same depth, and the `return_depth` check in
  `dispatch_result!` prevents the obvious shapes — but F1 shows that check is not universal)
- **Category** reentrancy · **Novelty** new (interp-06 candidate 13 of this wave)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16443`; other sites `:16578`, `:36528`
  (readers) and `:15229`, `:15296`, `:15452`, `:15502` (writers), `:16412`, `:16571`, `:36526`
  (the pre-dispatch `= None`).
- **Claim** Whether a nested `Halt::Return` is "the callback returned" or "a throw unwound
  past me and the outer loop ran to its end" is decided by comparing one global
  `Option<usize>` against `return_depth`; the field is cleared before each nested dispatch
  but never after, and the `XS_CODE_RETURN` arm (`:15268`) returns `Halt::Return` without
  touching it, so a stale `Some(d)` from a completed inner callback is visible to any outer
  boundary that happens to sit at depth `d`.
- **Evidence**
  ```rust
  self.callback_return_depth = Some(return_depth); return Halt::Return;   // :15229
  Halt::Return if self.callback_return_depth != Some(return_depth) => Err(Halt::Return),  // :16443
  ```
  vs `XS_CODE_RETURN => { return Halt::Return; }` (:15268), which leaves the field as it was.
- **Impact** If aliased, the native reads an arbitrary value off the stack as its callback's
  result and continues iterating on a machine whose program has already ended. Even without
  a live alias, the return type of the interpreter's central function does not carry its own
  meaning — which is what made F1 hard to see.
- **Recommendation** Return a typed outcome from `dispatch_at`
  (`enum NestedOutcome { CallbackReturned(Slot), UnwoundPast, Halt(Halt) }`) instead of
  `Halt` + a side register; or at minimum clear `callback_return_depth` in every reader after
  the comparison and set it in `XS_CODE_RETURN` too.

### F12. GC-root coverage of the re-entrancy registers is convention, not mechanism: `target_func` and `pending_new_target` are unrooted, and natives hold unrooted `SlotIndex`es across guest re-entry

- **Severity** medium · **Confidence** high · **Category** gc-roots · **Novelty**
  partially-known (interp-16 candidates 8/9 and interp-09 candidate 10 of this wave; the
  registry's name-matching blind spot is `gc_visitation_registry.rs:241`)
- **File** `rust/engine/ironhorse-vm/src/interp.rs:43502-43695` (`gc_roots`); the only
  collection triggers are `ironhorse-snapshot/src/machine.rs:1723`, `:1759`, `:2002`, `:2105`.
- **Claim** `gc_roots` roots `cur_func` but not `self.target_func` and not
  `pending_new_target`; the registry test is satisfied for `target_func` by the *frame* field
  `f.target_func` (`roots.push(f.target_func)`), and for `pending_new_target` by an
  unconditional `Req::DocumentedOnly`. Both are safe today only because no code inside
  `ironhorse-vm` ever collects — a global property nothing asserts.
- **Evidence** `grep -n "collect_garbage(\|free_pages(" ironhorse-vm/src` → no call sites;
  `roots.push(self.cur_func);` at :43610 with no `self.target_func` anywhere in the body;
  registry entry quoted in F5. The design (§ Value and heap model) specifies XS's
  allocation-triggered collector.
- **Impact** The moment allocation-triggered GC lands — which the engine design and the
  store-seam design both call for — every Rust-local `SlotIndex` held across a guest callback
  (`settle_promise`'s `derived` :21585→:21608, `array_from_async`'s promise :21866→:21894,
  combinator `derived` :22685→:22766, `run_callback`'s pushed frame) plus `target_func` and
  `pending_new_target` become use-after-sweep sites, read through an arena whose `get`
  (`value.rs:853`) does not consult the free bitmap. F5 makes one of them reachable *today*
  at a boundary collection.
- **Recommendation** Root `target_func` and `pending_new_target` now (cheap, and it removes
  the registry false positive); add `debug_assert!(self.dispatch_depth == 0 && self.is_quiescent())`
  at the top of `collect_garbage`/`free_pages` so the boundary-only premise is enforced rather
  than documented; make `Req::DocumentedOnly` require a named behavioral twin in
  `gc_anchor_truth.rs`; and add a `debug_assert!(!self.is_free(i))` in `SlotArena::get`/`mark`
  so a stale index is a deterministic panic rather than a stale read.

### F13. `enter_call`'s four early `Err` returns leave the frame quartet and arguments on the shared value stack

- **Severity** low · **Confidence** high · **Category** reentrancy · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:16200`, `:16222`, `:16233`, `:16249`;
  the truncate they precede is at `:16253`; the propagating `?` at `:16408`, `:16553`.
- **Claim** `self.stack.truncate(base)` happens after the underflow, non-callable, bodyless

  `run_callback_catching_throw` truncates by hand) resumes with `4 + argc` stale slots.
- **Evidence**
  ```rust
  if self.would_overflow(FRAME_OVERHEAD_SLOTS + argc) {
  ```

### F14. The async fence's own invariant is a `debug_assert!`, so a release build would silently discard live handlers

- **Severity** low · **Confidence** high · **Category** verification · **Novelty** new
- **File** `rust/engine/ironhorse-vm/src/interp.rs:17155`; other site `:17412`.
- **Claim** After the nested body run, both fenced drivers assert the chain is empty and then
  *overwrite* it; in release a body that left handlers behind loses them silently.
- **Evidence**
  ```rust
  debug_assert!(self.jumps.is_empty(), "async body left handlers behind");
  self.jumps = fenced_jumps;
  ```
- **Impact** Every arm truncates to `jumps_base` today, so the invariant holds; but the
  guard that would catch a regression is compiled out of shipped builds, and the failure mode
  (a caller's `catch` silently disappearing) is exactly the class F3 belongs to.
- **Recommendation** Either make it a hard check that returns `Halt::Unsupported`, or write
  `self.jumps.truncate(0); self.jumps = fenced_jumps;` → `self.jumps.splice(..)` semantics
  that cannot lose entries; and add the fence/unfence to the single primitive proposed in F3.

## 3. Strengths

- **The suspension protocol is genuinely symmetric.** `SavedFrame` captures the complete
  activation, `frame_slots` accrual in the three resume drivers (:16712/:16991/:17212)
  matches `leave_call`'s `saturating_sub` (:34571), and suspended handlers are stored
  frame-relative (`SavedJump.stack_offset`/`call_depth_offset`) and rebased on resume with an
  explicit `rebased` flag that feeds a deliberate metering delta. Getting suspend/resume of
  live `try` blocks right is hard, and this is right.
- **The `strict` register latch is correct at every seam.** `enter_call` clears it (:16270),
  `CallerState` saves and `leave_call` restores it, `unwind_to_jump` restores it via
  `leave_call`, `SavedFrame` carries it across suspension, and `run` resets it per crank with
  the W6-6 incident cited at the site. I found no path that latches strictness.
- **`dispatch_depth` is exception-safe by construction.** The counter is incremented and
  decremented around a single call with no `?` between (:11286-11289), so the ~200 early
  returns inside `dispatch_at_inner` cannot unbalance it.
- **Hostile suspend shapes fail closed by name.** `yield:stack-underflow`,
  `await:stack-underflow`, `end:frame-underflow`, `start_async:frame-underflow`,
  `generator:non-boundary-return` and the async twins each cite the fuzz trophy that
  motivated them, and every one degrades to a `Halt` rather than a `panic!`.
- **`harden` is an iterative worklist with mark-at-enqueue** (:35718-35807) — the one
  guest-controlled deep traversal in the engine that cannot overflow the native stack. It is
  the model the MOP, JSON and `render` should follow.
- **Where the re-entry budget applies, it applies uniformly.** All four guest re-entry sites
  (`run_callback`, `resume_generator`, `step_async`, `step_async_generator`) plus
  `dispatch_entered_cross_segment` funnel through the one `dispatch_at` wrapper, and the
  `nested_run_unwind_floor.rs` test pins the XS-agreement cases.
- **The `Halt::Resume` / `return_depth` idea is the right design.** F1 is a failure to apply
  it, not a failure of it: the macro's contract is exactly correct and 14 sites use it.
- **GC coverage of *suspended* state is complete and cross-checked**: `saved_frame_slots`
  (:43757) visits locals, args, the stack slice, `this`, `result`, `env`, `jumps[].env`,
  `cur_func` and `target_func`; the three run stacks are roots; async-generator `requests`
  and `active` are edges.

## 4. Recommended architectural direction

**Make the three re-entrancy invariants mechanical instead of textual.** Every finding above
is an instance of the same failure: an invariant that exists as a pattern a human must
re-type. (1) *Unwind ownership* — delete `raise_js` from the callable surface of the dispatch
loop and expose only helpers that return `Halt::Resume`, so the `return_depth` test lives in
one macro that cannot be bypassed (F1, F4). (2) *Native-try* — one
`run_guest_under_native_try` primitive with an explicit `fence: bool`, replacing five
hand-rolled unwind blocks (F3, F7). (3) *Re-entry budget* — one `ReentryGuard` RAII token
that any function capable of re-entering guest code or itself must hold, so adding a new
recursive native is a compile-time obligation rather than a review catch (F2, F6). Each of
these is a small refactor whose payoff is that the *next* built-in cannot reintroduce the
class.

**Give the interpreter's central function an honest return type.** `Halt` today carries
completion, internal control transfer (`Resume`, `Yield`, `Await`, `AsyncYield`), host aborts
and errors in one enum, and its meaning is further modulated by four machine-global registers
(`callback_return_depth`, `resume_status`, `pending_new_target`, `eval_direct`) that each
nesting seam must remember to save, clear, or restore — `eval_source` hand-saves fourteen of
them. Splitting the nested-dispatch outcome into its own type and folding the control
registers into the value that crosses the boundary would have made F1, F5 and F11 either
impossible or compile errors. As a cheap down payment, reset all four registers at the top of
`run`, add them to `is_quiescent`, and root `pending_new_target`/`target_func` in `gc_roots`.

**Close the doctrine gap on process death before the allocation-triggered collector lands.**
The design's memory-safety envelope says "a panic is a crashed crank, not a compromised
daemon", but the engine's actual worst case for guest input is a `SIGABRT` from native stack
exhaustion — reproduced here from an async generator and from a spec-legal proxy prototype
cycle, and by other lenses from `render`, JSON, and the compiler front end. That is
uncontainable, host-dependent, and therefore consensus-relevant. Two things follow: the
design should state a stack-depth budget as an engine-visible limit alongside
`STACK_SLOT_COUNT`, enforced by the `ReentryGuard` above; and the fuzz surface should carry a
target whose only assertion is "no guest program aborts the process". Separately, the
boundary-only-GC premise that keeps every unrooted Rust-local `SlotIndex` safe today is
documentation (`bulk.rs:235`, `interp.rs:3031`, the registry note) with no assertion behind
it — add `debug_assert!(self.dispatch_depth == 0 && self.is_quiescent())` to both collectors
now, so that when allocation-triggered collection arrives the premise fails loudly instead of
turning ~a dozen natives into use-after-sweep sites at once.
