# Lens: module structure, code organisation, maintainability

Reviewer notes: every claim below was verified by me against the tree at
HEAD (`rust/engine`), by reading the cited lines and by running the
commands quoted. Region-map candidates are cited where they corroborate,
but nothing is reported on a map's word alone.

## 1. Assessment

IronHorse is a faithful transliteration organised as a transliteration: the
unit of organisation is *the XS source file being ported*, not the
subsystem being built. `ironhorse-vm/src/interp.rs` is 44,942 lines. Thirteen
`impl` blocks live in it; the dominant one, `impl Interp` at 5184–39169, is
33,986 lines. The file holds 252 constants (241 `pub`), 90 types, 135 free
functions, and a `#[cfg(test)]` module of 42 tests at 41970–43488. Three
functions dominate: `dispatch_at_inner` (11292–15862, 4,571 lines, 149
top-level match-arm groups over 225 opcodes), `call_native_method`
(25202–28899, 3,698 lines), `create_intrinsics` (5439–6387, 949 lines).

The first thing to say honestly is that **compile time is not the cost**.
Measured here: `cargo clean -p ironhorse-vm` then `cargo build -p ironhorse-vm`
= **10.6 s**; `cargo test -p ironhorse-vm --no-run` (relinking all 40 test
binaries) = a further **11.3 s**; the full PR-CI job runs in ~26 s. `touch
interp.rs && cargo build` is 1.2 s because rustc's fingerprint is unchanged.
A 45k-line file is not what is hurting this project, and a review that leads
with build time would be aiming at the wrong target.

What the monolith actually costs is **the absence of any seam layer**. The
entire engine defines five traits (`SourceCompiler`, `PageSource`, `GcHooks`,
`MachineSnapshot`, `HeapStore`) and six `macro_rules!`, none of which
abstracts the thing that actually varies: the ~44 per-instance side tables
that stand in for XS's slot-union arms. Every one of them is enumerated by
hand, repeatedly. Tracing a single table (`disposable_stacks`) across the
workspace finds **104 mentions in 8 files across 2 crates** — 46 in interp.rs,
25 in image.rs, 12 in store.rs, 9 in machine.rs, 6 in sidetable.rs, 3 in
format.rs. Inside interp.rs alone its GC participation is spelled out
separately in a 44-field `Hooks` struct *declared inside the body of*
`collect_garbage` (43711), in `extra_edges` (43806), `swept` (44001),
`ephemeron_edges` (44045), `prune_dead_keyed` (44109), `external_chunk_refs`
(44137), `free_pages` (44556) and `each_side_table_ref_tail` (44761). The code
knows this and says so: `// Wave-6 W6-1: … mirrored from the full collector's
saved_frame_slots` (44778). Documenting the duplication is not the same as
removing it, and the W6-1..W6-4 findings the comment cites are precisely the
bugs that mirroring produced.

The compensating control for that is remarkable and fragile: two tests derive
ground truth **by parsing interp.rs as text** — `include_str!("../src/interp.rs")`
(gc_visitation_registry.rs:34) and, from a different crate,
`read_to_string(concat!(env!("CARGO_MANIFEST_DIR"), "/../ironhorse-vm/src/interp.rs"))`
(sidetable.rs:663 and :891). They locate `pub struct Interp {` and brace-match
named function bodies. This makes the monolith **load-bearing for the safety
nets**: any decomposition either breaks them or silently narrows them, which
is why the decomposition has to start with replacing them, not with moving code.

Naming carries no layering information. There are five property-read families
— `instance_get` (35 call sites), `ordinary_get` (45), `mop_get` (21),
`resolve_get` (2), `property_at_get` — and nothing in the names says which
is the seam and which is the bypass, while the block comment at 36348 asserts
"All ordinary/`Object.*`/`Reflect.*`/syntax property operations route through
the same `mop_*` seam so a trap cannot be bypassed."

Documentation is written as changelog at the moment of authoring and never
revised. The crate doc still says "Stage 1 (thin slice) delivers … the
arithmetic / logic / bitwise / comparison / branch / stack opcode subset"
(lib.rs:7-9); interp.rs's module doc is a stage-2 narrative about `var`
hoisting metering; README.md:17's crate table describes the VM as an
interpreter "over the stage-1 opcode subset". One function documents the
opposite of its own body two lines later (`instance_get`, 38123 vs 38126).
Fifteen shipped comments say "the llm rebase" / "the llm sweep's tables" —
provenance a future maintainer cannot resolve — and 37 cite `W6-*` review
waves. The 204 KB README is a per-stage acceptance ledger with headings like
"fix6-verify 2/2 — FULL-TREE re-measurement", retaining four superseded
"NOT MET" verdicts. There is no reference document for the engine's structure.

Finally there is no mechanical floor at all: no `[workspace.lints]`, no
`rustfmt.toml`, no `clippy.toml`, no `rust-toolchain.toml`, no `[profile]`
section anywhere. `cargo fmt --check -p ironhorse-vm` = **469 diff hunks (384
in interp.rs)**. `cargo clippy -p ironhorse-vm` = **92 warnings and 1
deny-by-default error**, so a clippy gate cannot even be added today — and the
error is a genuine redundancy in shipped Intl grouping logic. Every
`cargo build -p ironhorse-vm` emits `warning: method
accessor_function_persists is never used`. A build that is never
warning-clean teaches its maintainers to read past warnings, in the one
codebase where a warning is most likely to be a consensus bug.

## 2. Findings

### F1 — The engine has no seam layer: ~44 side tables are hand-mirrored across ~10 enumerations in 2 crates
**Severity: high · Confidence: high · Category: modularity · Novelty: new**
(no prior-wave ledger item; corroborated by maps interp-02, interp-16, vm-heap-gc)

Claim: adding or changing one `Interp` side table requires hand-editing ~10
independent enumerations spread over two crates, and a missed edit is a stale
row on a recycled slot — silent wrong state, not a compile error.

Evidence — `interp.rs:43711`, the GC roster declared inside a function body:
```rust
        let roots = self.gc_roots();
        struct Hooks<'a> {
            functions: &'a mut std::collections::HashMap<SlotIndex, FuncInfo>,
            bound_functions: &'a mut std::collections::HashMap<SlotIndex, BoundData>,
            ...  // 44 fields, one per participating table
```
and `interp.rs:44778`, the partial collector's twin admitting it is a copy:
```rust
            // Wave-6 W6-1: the suspended environment head and the saved
            // handlers' restore environments, mirrored from the full
            // collector's saved_frame_slots.
```
Measured coupling for one table: `grep -rn 'disposable_stacks|DisposableStackRow|DisposableStacks|DISP'` over `ironhorse-vm/src` + `ironhorse-snapshot/src` → 104 hits in 8 files (interp.rs 46, image.rs 25, store.rs 12, machine.rs 9, sidetable.rs 6, format.rs 3, two lib.rs). The whole engine defines only 5 traits and 6 `macro_rules!` (grep over all four pure-Rust crates' `src/`); none of them covers this roster.

Impact: this is the mechanism that produced W6-1..W6-4 and it is still the
mechanism. Every future side table is another ten-site coordination with a
silent-corruption failure mode, and the review cost of each such change is
proportional to the reviewer's memory rather than to the diff.

Recommendation: declare the roster once. A `side_tables! { name: KeyTy => ValTy, gc: Edges|Weak|None, sweep: Prune|InHook, snapshot: TAG, persist: Always|Gated }` macro (or a generated const descriptor table) should emit the `Interp` fields, the `Hooks` struct, the `extra_edges`/`swept`/`external_chunk_refs`/`ephemeron_edges` arms, `free_pages`'s retains, `each_side_table_ref_tail`, and the `SideTable` ledger enum + `ALL` + `descriptor()`. This is a mechanical change with no behavioral surface and it is the single highest-leverage edit in the codebase.

### F2 — The two mechanical safety nets parse `interp.rs` as source text, making the monolith load-bearing
**Severity: high · Confidence: high · Category: verification · Novelty: new**

Claim: the GC-visitation registry and the snapshot side-table ledger derive
their ground truth by string-scanning `ironhorse-vm/src/interp.rs`, so any
split of that file breaks or silently narrows both nets.

Evidence — `ironhorse-vm/tests/gc_visitation_registry.rs:34`:
```rust
const SRC: &str = include_str!("../src/interp.rs");
```
with `fn fn_body(marker)` brace-matching named function bodies (`:38-57`), and
`ironhorse-snapshot/src/sidetable.rs:663` reaching across the crate boundary:
```rust
        let src = std::fs::read_to_string(concat!(
            env!("CARGO_MANIFEST_DIR"),
            "/../ironhorse-vm/src/interp.rs"
```
which then does `src.find("pub struct Interp {")` (`:668`) and parses fields by
indentation (`:673-688`), guarded only by `assert!(fields.len() > 100)`.

Impact: two consequences. (a) The nets are already blind to anything typed
outside interp.rs (a field of type `bulk::ArrayData` holds `Slot`s and reads as
slot-free) — the map interp-02 flagged this. (b) More importantly for this
lens, they make decomposition *dangerous rather than merely tedious*: move
`struct Interp` into `interp/state.rs` and the snapshot ledger's reconciliation
either panics or, if a maintainer "fixes" the path, quietly covers fewer
fields. This is why the file has not been split.

Recommendation: sequence F1 before any file movement. Once the roster is a
declarative table, both nets check a `const` array instead of parsing text, they
become crate-boundary-clean, and the monolith stops being a test dependency.

### F3 — Next-stage seams the design says are already carved do not exist
**Severity: high · Confidence: high · Category: api-boundary · Novelty: new**

Claim: none of the three stages named as next (SES lockdown, host functions,
debugger) has an abstraction to land on, and the design asserts the opposite.

Evidence — the design, `designs/ironhorse-engine.md:566-573`: "The stage 1
slice already carves the architectural seams these need: intrinsics are created
once per machine and referenced per-realm, every evaluator is reachable for
per-compartment replacement". Against the code:

*SES.* `compartment.rs:64-68` is the whole shared-intrinsics type:
```rust
pub struct Intrinsics {
    /// Whether `lockdown` has frozen the shared intrinsics. …
    pub locked_down: bool,
}
```
`grep locked_down compartment.rs interp.rs` returns exactly one line — the
declaration. And `compartment.rs:318-333`, whose doc says "two compartments over
one machine's intrinsics … agree on the intrinsic surface", begins
`let mut interp = Interp::new();` (`:320`) — a fresh machine per evaluation.

*Host functions.* The only host-installable closure in the VM is the meter:
`meter_host: Option<Box<dyn FnMut(u64) -> bool>>` (interp.rs:3712). There is no
native-registration surface; `Native`/`NativeMethod` are closed enums (46 and
280 variants) dispatched by the 3,698-line `call_native_method`. And
`run_callback` (16308) refuses anything else outright:
```rust
            Payload::Reference(f) if self.functions.contains_key(&f) => f,
            _ => return Err(Halt::Unsupported("callback:non-user-function")),
```
so a host function could not be passed to `map`, `then`, `forEach` or a
`Proxy` trap even if one could be minted.

*Debugger.* `designs/ironhorse-debugger-recovery-and-uncaught.md` names "there
is no centralized raise/throw_error helper" as its prerequisite. Counts today:
47 `raise_js(` call sites vs 46 inline `Halt::Throw(` — half-centralised.

Impact: each next stage will either grow the monolith by another few thousand
lines of enum variants and match arms, or force the refactor under schedule
pressure. Host functions in particular are not additive: a `Native::Host(u32)`
needs a GC-rooted host table, a snapshot row, and a `run_callback` path — i.e.
it hits F1's ten-site problem on its first day.

Recommendation: land the three seams *before* the features. `trait HostCallable`
plus a rooted host table registered through the side-table registry of F1; a
`Realm` type that actually owns the primordial graph so `Compartment::evaluate`
takes `&mut Interp` instead of constructing one; and collapse the 46 inline
`Halt::Throw` sites onto `raise_js` so the debugger has one interception point.

### F4 — CI exercises only the profile in which arithmetic overflow panics; production ships the profile in which it wraps
**Severity: high · Confidence: high · Category: robustness · Novelty: new**

Claim: neither `rust/engine/Cargo.toml` nor the repo-root `Cargo.toml` defines
any `[profile]`, so `overflow-checks` is on in the debug profile CI tests and
off in the release profile a daemon ships, and the design's "logic bugs surface
as deterministic panics" holds only in the profile nobody deploys.

Evidence — `grep '\[profile' rust/engine/Cargo.toml rust/engine/*/Cargo.toml Cargo.toml`
returns nothing; the engine workspace manifest is 25 lines of `[workspace]` /
`[workspace.package]` with no profile or lints table. The engine CI job is
`.github/workflows/ci.yml:746`:
```yaml
        run: cargo test -p ironhorse-vm -p ironhorse-snapshot
```
with no `--release`, no second profile, no clippy, no fmt.

Impact: every confirmed overflow site changes meaning between the tested and
the shipped build — `days_from_civil`'s `era * 146097` (interp.rs:40866, reached
from `new Date(1e17,0)`), `DECREMENT` at `i32::MIN` (14757), `Meter::untick_raw`'s
unchecked `-=` (meter.rs:238), `SlotArena::free`'s `live -= 1` (value.rs:841).
In debug these are crashed cranks; in release they are silent wrong values in a
consensus engine — the exact failure class the whole design is built to exclude.

Recommendation: add `[profile.release] overflow-checks = true` to the engine
workspace (and to the root workspace for the shipped daemon), or make the
consensus profile explicit and run the suite in it. A metered engine can afford
the checks; a consensus engine cannot afford their absence.

### F5 — There is no mechanical style or lint floor, and a deny-level clippy error makes a clippy gate impossible today
**Severity: medium · Confidence: high · Category: verification · Novelty: new**
(corroborated by map docs-ci-process)

Claim: `cargo clippy -p ironhorse-vm` fails with 92 warnings and one
deny-by-default error, `cargo fmt --check -p ironhorse-vm` reports 469 diff
hunks, and no workspace-level lint configuration exists — so neither gate has
ever run, and the error blocking the gate is itself a real logic redundancy in
shipped code.

Evidence — measured here:
```
$ cargo clippy -p ironhorse-vm --message-format short | tail -3
ironhorse-vm/src/value.rs:618:24: warning: casting to the same type is unnecessary
warning: `ironhorse-vm` (lib) generated 92 warnings
error: could not compile `ironhorse-vm` (lib) due to 1 previous error; 92 warnings emitted
$ cargo fmt --check -p ironhorse-vm | grep -c '^Diff in'
469          # 384 of them in interp.rs
```
The error, `ironhorse-vm/src/intl_number.rs:779`:
```rust
        Grouping::Always => int_digit_count > 3 || notation == Notation::Standard && int_digit_count > 3,
```
`clippy::overly_complex_bool_expr`: the right disjunct is subsumed by the left,
so `Grouping::Always` is literally `int_digit_count > 3` and the `notation`
test is dead — copied from the `Grouping::Auto` arm on the next line.

Impact: the project's only mechanical quality signal is `cargo test`. The 92
warnings include two "very complex type", "too many arguments", 18 `is_*`/`to_*`
self-convention hits and several `?`-operator simplifications — individually
noise, collectively the reason nobody can add the gate incrementally. The
469-hunk fmt debt means every future diff is contaminated by formatting churn
whenever anyone does run `cargo fmt` on a file they touch.

Recommendation: three commits, in this order. (1) Fix intl_number.rs:779.
(2) `cargo fmt` the whole workspace in one mechanical commit (a 469-hunk diff
that reviews as noise exactly once) and add `cargo fmt --check` to
`test-ironhorse`. (3) Add `[workspace.lints.clippy]` allowing today's warning
families explicitly by name and denying everything else, plus
`cargo clippy --no-deps -- -D warnings` in CI; then retire the allow-list
family by family. Doing (2) before any decomposition is important — otherwise
the split diff is unreadable.

### F8 — Activation-record suspend is copy-pasted at 8 sites, 4 of them with an identical jump-rebase block
**Severity: medium · Confidence: high · Category: modularity · Novelty: new**
(corroborated by map interp-06 candidate "Frame-critical suspend/return logic is copy-pasted four times")

Claim: the sequence that captures a suspended activation is written out eight
times; a struct literal forces every field to be *present*, but nothing forces
the four in-dispatch sites to compute `stack_base`, the rebased `jumps`, or
`resume_pc` the same way.

Evidence — `SavedFrame {` construction sites: 9729, 15359, 15415, 15574, 15626,
15997, 16029, 16120. Four carry a byte-identical rebase closure (15350, 15402,
15565, 15617):
```rust
                        let stack_slice = self.stack.split_off(stack_base);
                        let jumps = self.jumps.split_off(jumps_base).into_iter()
                            .map(|jump| SavedJump {
                                target_pc: jump.target_pc,
                                stack_offset: jump.stack_len.saturating_sub(stack_base),
                                ...
```
They already differ in the metering constant charged and in which driver table
receives the frame (`async_generators` at 15376 vs `generators` at 15432).

Impact: the frame is 13 fields of consensus-critical machine state, and the
four dispatch-loop copies are the async-generator-yield, generator-yield,
async-generator-await and await paths. A future change to the activation model
(e.g. adding a register for host functions, per F3) has to be re-derived at
eight sites; getting one of them subtly wrong is a resumed generator with a
wrong `this`, wrong handler offsets, or a wrong `resume_pc` — silent wrong
state that only a carry twin for that exact family would catch.

Recommendation: one `fn suspend_activation(&mut self, stack_base: usize,
jumps_base: usize, call_depth_base: usize, resume_pc: usize) -> SavedFrame`
and one `fn reinstall_activation(&mut self, frame: SavedFrame, driver_base: usize)`,
with the four dispatch sites reduced to the call plus their table write.

### F10 — `Halt::Unsupported(&'static str)` is the universal bail: 376 sites in one file
**Severity: medium · Confidence: high · Category: error-model · Novelty: new**
(consequences catalogued by maps interp-11, interp-14, t262-harness-core)

Claim: one enum variant carrying a free-form string is the exit for four
different conditions — unported opcode, unmodelled runtime shape, resource
refusal, and internal invariant violation — and this is what lets the monolith
accrete without a design decision per gap.

Evidence — counts in interp.rs: `Halt::Unsupported(` 376 occurrences,
`Halt::Throw(` 46, `raise_js(` 47, `catchable_type_error` 265. Labels range from
port gaps (`"callback:non-user-function"`, 16310) through resource refusals
(id-space exhaustion) to invariant guards (`"yield:stack-underflow"` 15341,
`"end:frame-underflow"`). The 262 harness maps every one of them to a
non-gating `RunSkip`.

Impact: for this lens the point is structural, not semantic: because any
awkward case can be answered with a new string, no pressure ever accumulates
to factor the subsystem that keeps producing them. It is the accretion valve.

Recommendation: split the variant by cause — `Halt::NotPorted(&'static str)`
(a coverage gap, harness-skippable), `Halt::Refused(Resource)` (a guest-visible
resource limit, which should mostly become a catchable error), and
`Halt::Invariant(&'static str)` (an engine bug, which the harness must fail on,
never skip). The counts then become a tracked, monotone number per category.

### F11 — Copy-paste as the structuring principle in the persistence ladder and its test suite
**Severity: medium · Confidence: high · Category: modularity · Novelty: new**

Claim: `store.rs` contains 18 schema-migration functions that are the same
function with a different integer, and the snapshot test suite redefines its
core harness in 15 files, with the documented consequence that rigor differs
per family.

Evidence — `ironhorse-snapshot/src/store.rs` defines `migrate_v5_to_v6` …
`migrate_v22_to_v23` at 2077–2600. `migrate_v18_to_v19` (2487) and
`migrate_v19_to_v20` (2513) are byte-identical except for `manifest.store_schema
= 19` vs `= 20`. The copy-paste has already produced a defect of its own:
`migrate_v21_to_v22` is defined *before* `migrate_v20_to_v21` (2544 vs 2570) and
inherits the orphaned doc comment `/// 20 → 21: synchronous generator
activations join the small state.` immediately above it.

### F15 — A 45k-line file is the crate's public API surface
**Severity: medium · Confidence: high · Category: api-boundary · Novelty: new**
(corroborated by map vm-meter-opcode-tables)

Claim: `pub mod interp` plus a 40-line re-export list makes every `pub` item in

## 3. Strengths

These are real and should survive any refactor:

- **The invariant comments are outstanding where they are current.** Comments
  such as the `free_pages` Date-table note ("a recycled slot inherits the brand
  and `new Date(value)` answers the dead Date's time (locked in
  gc_side_tables.rs)", interp.rs:44626) name the failure mode, the mechanism,
  and the test that locks it. Most codebases have none of the three.
- **Nearly every invariant has a named executable lock.** The wave findings did
  not just get fixed; each produced a test file whose name is the finding
  (`gc_side_tables.rs`, `lazy_install_reach.rs`, `nested_run_unwind_floor.rs`,
  `id_space_exhaustion.rs`, and 26 `finding_<hash>_*.rs` fuzz regressions).
  That is a strong culture and it is what makes the decomposition in §4 safe.
- **The mechanical completeness nets exist at all.** Deriving GC ground truth
  from the struct rather than from the collector (gc_visitation_registry.rs) is
  a genuinely good idea that kills the "forgot the table entirely" class. F2
  criticises its *implementation medium*, not its intent.
- **The `cost-calibration` firewall is architecturally right**: a zero-sized
  recorder on the off side, strictly one-directional data flow, a
  `size_of == 0` structural proof and a grep invariant that `meter.rs` names no
  cost type. This is exactly how a determinism firewall should be shaped.
- **Determinism hygiene is applied consistently** across module boundaries —
  sorted seeding in `Compartment::evaluate` (compartment.rs:301-303) with the
  reason written down, owner-sorted snapshot views, BTreeMap where iteration is
  observable. The discipline crosses crates even though the abstractions do not.
- **Crate-level decomposition is sound.** `ironhorse-regexp` and
  `ironhorse-compile` are clean leaves; the VM depends on the compiler only
  through the `SourceCompiler` trait and only as a dev-dependency, which is
  better layering than the design diagram shows. The monolith is one crate's
  problem, not the workspace's.
- **Compile time is fine.** 10.6 s for a cold lib build, ~22 s to a runnable
  suite, 26 s for the whole PR job. The decomposition should be justified on
  review-ability and seam grounds, and no one should be told it will speed up
  their build.

## 4. Recommended architectural direction

**Sequence matters more than the target shape.** The decomposition has three
prerequisites that are each independently valuable, and doing them out of order
either destroys the safety nets or makes the diff unreviewable. Phase 0:
replace the two source-text-parsing nets (F2) with a declarative side-table
registry (F1) — a `side_tables!` macro or generated descriptor table that emits
the `Interp` fields, the collector `Hooks`, all four GC/sweep enumerations,
`free_pages`, `each_side_table_ref_tail`, and the snapshot `SideTable` ledger
from one source. Both nets then assert over a `const` array, become
crate-boundary-clean, and stop depending on interp.rs being one file. Phase
0b: fix `intl_number.rs:779`, run `cargo fmt` over the workspace in one
mechanical commit, and add `cargo fmt --check`, `cargo clippy -D warnings`
(with an explicit allow-list of today's 92 families) and
`[profile.release] overflow-checks = true` to the engine CI job. Formatting
must be settled *before* code moves or the split diff is 100% noise.

**Then split by subsystem, not by size.** Phase 1 moves the ~4,000 lines that
never touch `&self`: Temporal calendar algebra (40383–41190) and its record
types (3130–3251) → `temporal/calendar.rs`; BigInt limbs (43175–43490) →
`bigint.rs`; BCP-47 canonicalisation and the ICU4X approximations (39227–40322)
→ `intl/locale.rs`; UTF-16BE/CESU-8 codecs, JSON escaping, radix formatting and
`StringToNumber` → `text.rs`. These are pure functions; the move is
behaviour-preserving by construction and invisible to the nets. Phase 2 splits
`impl Interp` itself using Rust's ability to write inherent `impl` blocks in
sibling modules of one crate: `interp/state.rs` (the struct + registry),
`interp/boot.rs` (create/link intrinsics), `interp/dispatch.rs` (the 4,571-line
loop, further divided by opcode family), `interp/property.rs` (the MOP and
proxies), `interp/natives/{object,array,string,number,json,reflect,collections,
typed_array,promise,regexp,temporal,intl}.rs`, `interp/suspend.rs` (the eight
`SavedFrame` sites collapsed per F8), `interp/persist.rs` (the `*_snapshot` /
`restore_*` pairs), `interp/gc.rs`. No signature, visibility or behaviour
changes; the oracle-locked bytecode and computron results are untouched by
construction, and the 42 in-file tests travel with their subsystem. Run
`cargo test -p ironhorse-vm -p ironhorse-snapshot` plus the 262 corpus after
each move — the existing lock set is exactly the instrument this refactor
needs, which is why it can be done safely now and will be much harder after
three more stages land.

**Finally, put in the seams the next stages need, while the boundaries are
fresh.** `pub(crate) mod interp` with a deliberate `snapshot_api` (F15) so the
snapshot wire format stops being coupled to interpreter struct layout; a
`Realm`/`Intrinsics` type that owns the primordial graph so
`Compartment::evaluate` stops calling `Interp::new()` and SES lockdown has
something to freeze; a `Native::Host` variant plus a GC-rooted, snapshot-carried
host table registered *through* the phase-0 registry, so host functions do not
re-run the ten-site coordination problem on their first day; and one
`fn raise(&mut self, err) -> Halt` chokepoint replacing the 46 inline
`Halt::Throw` sites, which is the debugger design's stated prerequisite. Split
`Halt::Unsupported`'s 376 sites into NotPorted / Refused / Invariant (F10) so
that the harness stops skipping engine invariant violations and so the
remaining coverage gap becomes a number that can only go down. None of this is
speculative architecture: each item is named by an existing design document as
a thing the code already has, and in each case the code does not have it.
