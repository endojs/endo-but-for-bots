# Lens: Verification strategy — tests, fuzzing, oracle, CI

Reviewer pass over HEAD 97d8de25. Every citation below was read in the current tree.

## 1. Assessment

IronHorse's verification architecture is unusually *self-aware* and unusually *unfinished*.
The self-awareness is real and rare: `designs/ironhorse-snapshot-store-seam.md:2504` opens a
section titled "Why the suites did not catch these" and decomposes 1,093 green tests' collective
blindness into six named patterns — fixture bias, a structurally single-crank oracle,
self-referential validation, assertions that stop short of behavior, contracts without an
enforcement point, and an untested coverage frontier. Each pattern names the antidote that would
have caught its findings. That document is the best artifact in the repository.

The problem is that the antidotes were built as *fixtures*, not as *instruments*. Pattern 2's
antidote ("a multi-crank oracle mode … is the generalization") became
`ironhorse-262/tests/multi_crank_oracle.rs`: seven hand-written tests, ~20 cranks total. Pattern
6's antidote (test the boundary, not the interior) became
`ironhorse-snapshot/tests/crafted_row_refusals.rs`: 20 tests against 213 named `Corrupt`
refusals — I diffed the message literals mechanically and **204 of 213 are asserted nowhere in
`tests/`**. Pattern 3's antidote ("a GC net that checks against an INDEPENDENTLY DERIVED edge
list rather than the visitor's own output") is contradicted at `interp.rs:44712-44731`, where the
parity net compares the counted page projection against `each_side_table_ref`, which
`interp.rs:44740-44741` composes from *the same* `each_side_table_ref_tail` walk that produced
the projection — the doc comment even says so approvingly ("the tail body is shared … and cannot
drift from it") — and runs only under `#[cfg(debug_assertions)]`. The pattern the ledger named is
reproduced verbatim in the code the ledger's own wave shipped.

Above the fixtures, four load-bearing seams let a wrong answer pass as a named skip.

(a) `Halt::Unsupported` carries **269 distinct labels** in `interp.rs`, of which at least 14 are
pure interpreter-invariant violations (`end:frame-underflow`, `yield:stack-underflow`,
`async:non-boundary-return`). Every differential comparator treats the whole channel as
"uncovered ground": `ironhorse-fuzz/src/lib.rs:1699` returns `Ok(())`, and
`ironhorse-262/src/xst.rs:450` returns `RunSkip`. The engine controls its own exemption from the
oracle.

(b) `xst.rs:560` maps `Agreement::OracleOnlyComplete` to `RunSkip("ironhorse-aborted")`
*without inspecting the halt*. test262 positive cases signal failure by **throwing**
`Test262Error`; a wrong IronHorse value that trips an assertion therefore lands in the skip
bucket, never in the fail bucket. One entire divergence direction cannot redden the build.

(c) The two-directional ratchet is code without a caller. `--expectations` appears only in
`endot_ih.rs` and two design documents; **no expectation list exists anywhere in the repository**
and no workflow or script passes the flag. The only gate is `met_bar()` = zero-Fail, under which
a covered→skip regression is invisible — precisely what the ratchet was designed to prevent.
Even with a list, `Outcome::Fail` (`expectations.rs:35`) is payload-free, so a quarantined failure
whose *cause* changes compares equal, and `Fail→Skip` classifies as `SkipReasonChanged`, which
`is_gating` (`expectations.rs:237`) makes non-gating by default.

(d) The metering doctrine is inverted in the instruments. `corpus_conversion_equivalence.rs:64`
sets `gate_meter_exact: true` over ~1,711 cases in PR CI; `interp.rs` carries 12 unit locks
asserting `"bit-exact computrons vs XS"`; seven `ironhorse-vm/tests/finding_*` files pin XS raw
meter constants. The design's own §Metering says computron parity with XS is a NON-GOAL. A
doctrine-sanctioned `ironhorse-meter-2` recalibration is a red build in ~1,730 places.

CI shape compounds all of this. PR CI runs `cargo test -p ironhorse-vm -p ironhorse-snapshot`
plus an oracle lane; there is **no** Miri, ASAN/UBSAN, clippy, rustfmt, second OS, or second
architecture job anywhere in `.github/workflows` (verified by grep), against a design that
promises "Miri on the arena and GC test suites, ASAN/UBSAN on the oracle harness"
(`designs/ironhorse-engine.md:612-614`) and "GC test suite under Miri" as stage 2's acceptance
bar. Four tests named `*_is_miri_clean` exist and assert essentially nothing under `cargo test`.
Fuzzing was removed from PR CI; the nightly lane runs 4 of 9 targets and **none of the five
differential targets**, the corpus is gitignored, and the workflow header still describes a
`fuzz-ironhorse` PR job that does not exist. The oracle lane sets `RUST_MIN_STACK: '16777216'` —
i.e. CI is configured precisely so the recursive-descent stack-abort class other reviewers flag
as critical cannot fire.

Net: the instruments that exist are good at re-checking the interior of what has already been
made to work, and structurally incapable of finding the next class of defect. That is the same
verdict the store-seam ledger reached about the previous 1,093 tests.

## 3. Strengths

- **The retrospective itself.** `designs/ironhorse-snapshot-store-seam.md:2504-2580` is a
  first-class piece of verification engineering: six named failure patterns, each with the test
  class that would have caught it. Most projects never write this down.
- **Mechanical ground truth for GC and the ledger.** `ironhorse-vm/tests/gc_visitation_registry.rs`
  parses the `Interp` struct field list out of `interp.rs` source and *forces* a classification
  for every slot-bearing field; `ironhorse-snapshot/src/sidetable.rs` does the reciprocal
  reconciliation. These are enum-vs-struct nets, not visitor-vs-visitor nets, and they are the
  right answer to pattern 3. They caught real omissions.
- **The seven-way metamorphic runner.** `store_suite.rs:261-287` compares uninterrupted / blob /
  store-eager / store-lazy / prefetch / evict / checkpoint-every-crank on **per-crank** results
  *and* per-crank computron vectors *and* final canonical bytes — the per-crank computron vector
  (`store_suite.rs:46-49`) specifically defeats a mid-run divergence that reconverges. It is
  generic over `HeapStore`, so the SQLite backend runs the identical instrument.
- **`carry()` fails loudly rather than baffling.** `store_suite.rs:333-342` asserts the anchored
  symbol-set discipline with an actionable message instead of letting a positional-id shift
  surface as a TypeError three layers down.
- **Honest, named skips everywhere.** The 262 runner never silently passes an unknown case; the
  taxonomy (`oracle-host-missing-intl`, `shared-test262-failure`, `abort-value-differs`) is
  granular and reported. The problem is what the taxonomy *gates*, not its honesty.
- **Fuzz trophies become executable regressions with provenance.** Each `finding_<hex>_*.rs`
  records target, toolchain, input sha256 and the causal analysis, and several state plainly that
  the *port* was correct and the *oracle harness* was wrong.
- **Refusing-side gates exist at all.** 213 distinct named `Corrupt` refusals is a real
  fail-closed decoder; the gap is test coverage of them, not their absence.
- **Determinism hygiene inside the encoders.** Owner-ascending sorted views everywhere, and the
  one genuine host dependence (platform libm) is documented as a decision of record at
  `interp.rs:29829-29843` rather than hidden.

## 4. Recommended architectural direction

**Close the escape hatches before adding any more fixtures.** Three changes, all small, convert
the existing instruments from interior-checkers into boundary-checkers. First, split
`Halt::Unsupported` into `Halt::NotPorted(&'static str)` and `Halt::InvariantViolated(&'static
str)`; move the 14 underflow/non-boundary labels to the latter and make every comparator
(`fuzz/src/lib.rs:1699`, `xst.rs:450`) treat `InvariantViolated` as a hard divergence. Second,
replace `xst.rs:560`'s blanket `RunSkip("ironhorse-aborted")` with a halt-kind match: `Halt::Throw`
whose constructor is `Test262Error` is a **Fail** (IronHorse computed a wrong value and the
harness caught it); only `NotPorted`/`StepLimit`/`MeterAbort` remain skips. Third, commit an
expectation list produced by `endot-ih --update-expectations` over the whole tree, wire
`--expectations` into a workflow, give `Outcome::Fail` a reason payload, and make `Fail→Skip`
gating. These three land the design's stated bar ("matching the fail vector matters as much as
the pass vector") without writing a single new test case.

**Then buy the two missing instrument classes with primitives that already exist.**
`Interp::run_bounded(code, k)` (`interp.rs:11147`) halts mid-crank at `Halt::StepLimit`, and
`collect_garbage` is `pub` and unguarded — so a *step-indexed metamorphic sweep* (for k = 1..N:
`run_bounded(code, k)`; `collect_garbage()`; continue and compare results/computrons against the
unswept baseline) is perhaps 40 lines and is the only thing that will ever exercise the
frame-register GC roots (`stack`, `args`, `call_stack`, `jumps`, `this_val`, `cur_func`,
`target_func`, `env`), which today are collected only when empty. The same shape with
snapshot/restore at every safe point is the snapshot analogue. Second, drive the *refusing* side
mechanically: a build test that greps the `Corrupt("…")` literals out of `ironhorse-snapshot/src`
and requires each to appear in `tests/` (with an explicit, commented allowlist for the
unreachable ones) turns 204 dark refusals into a ratchet, exactly as
`gc_visitation_registry.rs` did for GC roots. Both instruments run oracle-free in the cheap PR
lane.

**Finally, fix the lane topology.** Make `xs-oracle` an *optional* dev-dependency of
`ironhorse-compile` and `ironhorse-regexp` behind a `parity` feature, so the ~3,000 lines of
oracle-free lexer/parser/scoper/regexp unit tests can run in `test-ironhorse` and 21.6k lines of
compiler and regexp source stop being invisible to the cheap lane and hostage to one submodule
fetch. Add the promised Miri job scoped to the arena/GC tests and a `cargo clippy -- -D warnings`
job (the tree currently has one deny-level clippy error at `intl_number.rs:779`, so that job must
land with its fix). Extend the PR change probe to
`packages/test262-runner/test262/test/ironhorse/`, which today can be edited or deleted with no
engine job running. Restore a 30-second-per-target differential fuzz tripwire to PR CI — the
justification for removing it ("a latent crash never reddens an unrelated PR") is exactly what
the path filter already solves. And add one non-x86_64-linux lane: the libm decision of record
scopes determinism per platform, but nothing today would *notice* a second host dependence
sneaking in.
