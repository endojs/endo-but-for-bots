# Lens: error and exception model — IronHorse engine

HEAD 97d8de25, `rust/engine`. Every finding below was verified by reading the
cited lines; the ones marked **reproduced** were additionally executed against
`ironhorse-vm` + `ironhorse-compile` from a throw-away probe crate outside the
repo (path deps, own target dir, now deleted). No repo file was modified.

## 1. Assessment

`Halt` is not an error type. It is a union of four unrelated protocols wearing
one Rust enum: a normal completion (`Return`), three *control transfers* the
dispatch loop must consume (`Resume(usize)`, `Yield/Await/AsyncYield(Slot)`),
three *host aborts* (`MeterAbort`, `StepLimit`, `StackOverflow`), and two
*errors* (`Decode(String)`, `Throw(String)`) — plus `Unsupported(&'static str)`,
which is all three at once. Nothing in the type separates "this value must be
handled by the enclosing loop" from "this value is the answer". The separation
is a hand-maintained convention: ~73 `dispatch_result!` invocations, four
hand-expanded copies of the same match, and a fixed rule that each nesting seam
compare `call_stack.len()` against a `return_depth` it was passed. That
convention is already known to have failed once — interp.rs:13008-13013 carries
a comment explaining that a raw `return halt` on the *getter* path "would exit
the dispatch loop with the Resume unhandled, so a getter that throws … inside a
`try` would escape its handler." It was fixed for getters. It was never fixed
for **setters**, for `to_primitive` in a template substitution, or for the
`with`/env-reference read and write paths: five sites still say
`Err(halt) => return halt`. Result, reproduced:
`var o={set x(v){throw 1;}}; try { o.x=1 } catch(e){ /*never runs*/ }` returns
`Halt::Resume(110)` to the host, `completed=false`. The daemon prints
`halted: Resume(110)`. This is the shape of the whole lens: the model is
correct in the paths someone probed and quietly wrong everywhere else, because
the type system was given no part in it.

The second structural fault is that the thrown *value* does not travel in
`Halt`. `Halt::Throw` carries a rendered `String`; the real value lives in the
`self.exception` register. `catch` reads it (`XS_CODE_EXCEPTION`, :15691), and —
critically — so do all three "native mxTry" boundaries
(`run_callback_catching_throw` :16606, `from_async_unwind` :21639,
`call_any_catching_throw` :21740). Their correctness depends on an invariant no
type enforces: *every* `Halt::Throw` must have set `self.exception`. The design
ledger records this exact gap ("only 3 of the 23 `Halt::Throw` constructions set
it", seam design:1313) and then declares it closed ("The mainline did that
conversion wholesale", :2054) — a claim `nested_run_unwind_floor.rs:20-23`
repeats. It is false: 29 sites still build `Halt::Throw(String)` inline without
touching `self.exception`, and the count has *grown*. Reproduced consequence:
`new Promise(function(){ Reflect.isExtensible(1) })` rejects with `undefined`
instead of a TypeError, and `try { Reflect.isExtensible(1) } catch(e){}` does not
catch at all.

Third, the error *objects* are thin where XS is thick and thick where XS is
thin. `catchable_type_error`/`catchable_range_error` (444 call sites between
them) call `build_error(name, 0, 0)` — no message, ever — so `e.message === ''`
where XS's `fxThrowMessage` carries a diagnostic; meanwhile the *uncatchable*
sites carry rich text ("TypeError: Reflect.isExtensible target") that only the
host ever sees. `ReferenceError` is the one family that gets it right
(`internal_error`, :11734). Stack traces do exist and are genuinely deterministic
(`capture_error_frames` :23037 → `"\n at <name> ()"`), which is a real strength.
But `render`/`render_uncaught` read a *write-once shadow* (`error_data`), so
`String(e)` ignores `e.message = 'b'` (reproduced: renders `Error: a`) and
ignores a subclass `toString`, while `e.stack` reads the live properties — the
two disagree by construction. And `render` walks guest arrays with no cycle or
depth guard (:10938-10949): a self-containing completion value aborts the whole
process (`fatal runtime error: stack overflow, aborting`, reproduced).

Finally, none of this is policed. `xst.rs` maps `Halt::Unsupported` to a skip
*before* the agreement match (:450), `OracleOnlyComplete` to
`RunSkip("ironhorse-aborted")` (:560), and a differing thrown value to
`RunSkip("abort-value-differs")` (:508). Every direction in which the error
model can diverge from XS is a non-gating skip. The oracle bar, the engine's
only real acceptance instrument, is structurally blind to this lens.

## 2. Findings

Severity key: critical = consensus divergence / silent wrong state /
process-killing DoS from guest code; high = correctness or safety defect in a
shipped path, or an architectural flaw that keeps producing such defects;
medium = design debt with a concrete failure mode; low = hygiene.

---

### F1. `render()` recurses over guest arrays with no cycle guard: a cyclic completion or exception aborts the process
**critical · confidence high · new**(partially-known: interp-05 map flagged the
completion path)
`ironhorse-vm/src/interp.rs:10938`, also `:11072` (`render_uncaught` falls back
to `render`), `:11219` (`run` calls it for every completion).

```rust
                    for i in 0..a.length {
                        if let Some(item) = a.items().get(&i) {
                            if item.kind != Kind::Undefined && item.kind != Kind::Null {
                                out.push_str(&self.render(item));
```

**Reproduced**: `var a=[]; a[0]=a; a` →
`thread 'main' has overflowed its stack / fatal runtime error: stack overflow,
aborting`. Not a panic — `catch_unwind` cannot contain it, and the design's
"a panic is a crashed crank, not a compromised daemon" does not apply.
**Impact**: three lines of untrusted guest JavaScript kill the daemon process.
The path is the *host boundary* — it runs after the crank has halted, so no
meter, no step limit and no `DISPATCH_REENTRY_LIMIT` is in play.
`render_uncaught` reaches the same code for `throw a`.
**Fix**: give `render` an explicit depth budget and a visited set (XS's
`fxToString` on an array runs `Array.prototype.join`, which is itself bounded by
the value stack); return a truncated marker past the budget rather than
recursing.

### F2. 29 engine error sites bypass `raise_js`: uncatchable by guest `try/catch`, and the tree's own docs say otherwise
**critical · confidence high · known-fixed-regressed** (seam design:1313 recorded
"only 3 of the 23"; :2054 declares it closed; `nested_run_unwind_floor.rs:20-23`
repeats the claim)
`ironhorse-vm/src/interp.rs:29003`; other sites: `:12319, :14017, :14021,
:16203, :25918, :25968, :26344, :26358, :26361, :26369, :26381, :26387, :26395,
:26427, :26455, :26464, :26492, :29017, :29097, :29115, :29124, :37861, :37869,
:37877, :37886, :37893, :37899, :37952`.

```rust
            NativeMethod::ReflectIsExtensible => {
                let object = match arg0.value {
                    Payload::Reference(object) if arg0.kind == Kind::Reference => object,
                    _ => return Err(Halt::Throw("TypeError: Reflect.isExtensible target".into())),
```
`dispatch_result!` (:3573) ends `Err(halt) => return halt`, so the jump chain is
never consulted.

**Reproduced**:
`try { Reflect.isExtensible(1) } catch(e){ r='caught' }` →
`completed=false halt=Throw("TypeError: Reflect.isExtensible target")`; likewise
`Object.defineProperty(1,'x',{})` and `Object.defineProperty({},'x',{get:1})`.
**Impact**: ordinary spec-mandated TypeErrors on `Object.defineProperty`,
`Object.create`, `Object.defineProperties`, `Reflect.*` and every descriptor
read (`descriptor_from_object`, the shared helper behind all of them) end the
crank instead of entering the guest handler. `assert.throws(TypeError, …)` can
never pass for them. This is also the hard prerequisite the debugger design
names ("Until Ironhorse gains a raise path that unwinds through `jumps`, a
break-on-uncaught mode built on the chain will simply never see an
engine-raised error", debugger design:210-217) — it is 90% done and reported as
100% done.
**Fix**: replace every remaining inline `Halt::Throw(String)` with
`catchable_type_error_msg(...)` built on `internal_error` + `raise_js`; add a
`#[deny]`-able lint or a grep test asserting the constructor is only reachable
from `raise_js`, `render_uncaught` and the two synthetic sites in `run`.

### F3. The thrown value travels in `self.exception`, which those 29 sites never set — promises reject with `undefined`
**critical · confidence high · new**
`ironhorse-vm/src/interp.rs:16606` (`run_callback_catching_throw`); identical
recoveries at `:21639` (`from_async_unwind`) and via `:21740`
(`call_any_catching_throw`, the promise-reaction path at `:21609`).

```rust
            Err(Halt::Throw(_)) => {
                ...
                let thrown = self.exception;
                self.exception = Slot::undefined();
                self.unmeter_host_escape();
                Ok(Err(thrown))
```
The `Halt::Throw` payload (a rendered `String`) is discarded; the value is taken
from a register the raiser was supposed to have populated.

**Reproduced**:
- `new Promise(function(){ Reflect.isExtensible(1); })` → rejected with
  `undefined` (probe R1: `log="rej:UNDEFINED"`), against `rej:42` for an
  ordinary `throw 42` (R2).
- `Promise.resolve(1).then(function(){ Reflect.isExtensible(1); })` → derived
  promise rejected with `undefined` (R3).
- With a prior `try { throw 'STALE' } catch(e){}` the register is `undefined`
  again only because `XS_CODE_EXCEPTION` cleared it; any path that leaves a
  value in `exception` would hand a *stale* object to the rejection (R4).

**Impact**: a silent wrong value in a shipped path — the promise carries a
rejection reason that no guest code produced. Secondary: `unmeter_host_escape`
(`:34711`) subtracts `THROW_HOST_ESCAPE_METERING` that was never charged
(`meter_host_escape` only runs in `raise_js`/`THROW`), so the meter drifts by
+32768 raw per occurrence; `Meter::untick_raw` is an unchecked `-=`
(`meter.rs:238`).
**Fix**: make `Halt::Throw` carry the `Slot`, not a `String`, and render only at
the host boundary. That makes F2's invariant unnecessary rather than
unenforced. If the string is needed for the oracle comparator, carry both.

### F4. A throwing accessor **setter** (and `toString` in a template literal) returns `Halt::Resume(pc)` to the host: the `catch` is skipped
**critical · confidence high · new** (the class is noted abstractly in
interp-06; the sites and the reproduction are new)
`ironhorse-vm/src/interp.rs:12652`; other sites `:11753` (env-ref
`ordinary_get`), `:11944` (`XS_CODE_SET_VARIABLE` → `ordinary_set`), `:12018`
(computed-key `to_primitive`), `:14729` (`XS_CODE_TO_STRING` → `to_primitive`).

```rust
                        } else if !match self.ordinary_set(code, inst, id, value, obj) {
                            Ok(accepted) => accepted,
                            Err(halt) => return halt,
                        } {
```
compare the guarded twin 30 lines further on, whose comment names this exact bug:
```rust
                        // Route a thrown getter through the enclosing
                        // `catch` (`Halt::Resume`) ... a raw `return halt` would exit the
                        // dispatch loop with the Resume unhandled            (:13008-13013)
```

**Reproduced** (all `completed=false`, an internal control value delivered as
the host outcome):
| source | halt |
|---|---|
| `var o={}; Object.defineProperty(o,'x',{set:function(v){throw 1}}); try{o.x=1}catch(e){}` | `Resume(148)` |
| `var o={set x(v){throw 1;}}; try { o.x=1 } catch(e){}` | `Resume(110)` |
| ``var o={toString:function(){throw 1;}}; try { `${o}` } catch(e){}`` | `Resume(117)` |
| `function g(){ try { o.x=1 } catch(e){ return 'c' } }` (setter throws) | `Resume(58)` |
| `var o={get x(){throw 1;}}; try { o.x } catch(e){}` (guarded twin) | **`Return`, `caught:1`** |

**Impact**: a guest `try/catch` around an assignment to an inherited or
defined-property setter, or around any template literal, is silently skipped;
the crank aborts and the daemon reports `halted: Resume(148)` to the operator.
The persistent machine rewinds the session. Deterministic, so no consensus
*divergence* — but a completely wrong answer on ordinary JavaScript.
**Fix**: make the control-transfer variants unrepresentable in the terminal
channel. `dispatch_at_inner` should return a `Terminal` enum with no `Resume`
arm, and every fallible callee should return
`Result<T, ControlFlow>` where `ControlFlow::Resume` cannot be `return`ed by
mistake. Short of that, convert all five sites to `dispatch_result!` *and* add a
test that sweeps every native-callback re-entry site.

### F5. Member access and assignment on `null`/`undefined` raise no error at all
**critical · confidence high · new**
`ironhorse-vm/src/interp.rs:13032` (`XS_CODE_GET_PROPERTY` default arm) and
`:12612` (`XS_CODE_SET_PROPERTY`'s `if let Payload::Reference(inst)` with no
`else`).

```rust
                        _ => Slot::undefined(),
                    };
                    self.push(v);
```

**Reproduced**: `null.f` → completion `undefined` (`completed=true`);
`var k='f'; null[k]` → `undefined`; `null.f = 1` → silent no-op, program
completes. (`null.f()` *does* throw, because the call site checks callability.)
**Impact**: the single most common runtime error in JavaScript produces a wrong
value instead of a TypeError, silently, in a consensus-critical engine whose
design states it "declines a program it cannot run rather than returning a wrong
answer". Every `if (x.y)` guard over a nullish `x` now takes the wrong branch
rather than throwing — divergence from XS on the *value*, not on the halt, so
the oracle comparator would catch it only for cases that reach a completion in
both engines with different results.
**Fix**: `RequireObjectCoercible` on both opcodes via `catchable_type_error`.

### F6. `run_callback_catching_throw` does not fence the caller's handler chain: a promise-executor throw is caught by the caller's `try`
**high · confidence high · known-open** (interp-07 map reproduced it; no ledger
item)
`ironhorse-vm/src/interp.rs:16588`; contrast `step_async`'s fence at `:17238`.

```rust
        let jump_depth = self.jumps.len();
        match self.run_callback(code, func, this, args) {
```
`jumps` is read but never truncated *before* the callback runs; `step_async` does
`let fenced_jumps = std::mem::take(&mut self.jumps);`.

**Reproduced**:
`try { p = new Promise(function(){ throw 1; }); } catch(e) { r='caught:'+e } r`
→ `completed=true, result="caught:1"`. The spec and XS reject `p` and never
enter the `catch`.
**Impact**: a promise that should be rejected is left un-settled while an
unrelated handler runs; six callers share the defect — the executor (`:18566`),
thenable adoption (`:22513`), `Promise.prototype.finally` (`:22627`), the
combinators (`:22713`, `:22766`) and `AsyncDisposableStack` (`:24245`).
There are **three** different implementations of "run guest code under a native
try" (`run_callback_catching_throw`, `from_async_unwind`+`from_async_try`, and
`step_async`/`step_async_generator`'s fence), which differ in exactly this
property.
**Fix**: one `with_native_try(|m| …)` primitive that takes the chain, runs the
body, restores the chain on every arm, and recovers the value from a typed
result rather than a register. Delete the other two.

### F7. `enter_call` returns a catch-handler pc through the `Ok(body_start)` channel; a non-callable object call inside a function yields an uncaught `ReferenceError`
**high · confidence high · partially-known** (interp-07 candidate, which
required an `eval`; no `eval` is needed)
`ironhorse-vm/src/interp.rs:16220`, consumers `:13971` (`pc = body_start`),
`:16553` (`call_cross_segment` → `dispatch_entered_cross_segment(body_start,…)`),
`:16408`, `:36524`; router `:16525` (`cross_segment_callee` accepts *any*
`Payload::Reference` callee).

```rust
            _ => {
                let error = self.build_error("TypeError", 0, 0);
                return self.raise_js(error);
            }
        };
```
`raise_js` returns `Ok(handler_pc)` when a handler exists — the same channel
callers treat as the callee's body start, and the only channel with **no**
`call_stack.len() < return_depth` guard.

**Reproduced**:
`function boom(o){ try { o(); return 'no'; } catch(e){ return 'caught:'+e.name; } } boom({})`
→ `completed=false halt=Throw("ReferenceError")`. The same call at top level
(`var o={}; try{o()}catch(e){}`) correctly yields `caught:TypeError`, and an
`undefined` callee inside a function also works — only an *object* callee inside
a function frame misroutes, because `cross_segment_callee` classifies it as a
foreign-segment callee and `dispatch_entered_cross_segment` then dispatches the
handler pc over `top_level_code`.
**Impact**: a wrong error class, an uncaught halt where the program had a
handler, and a handler pc interpreted as an offset into a different bytecode
buffer — the one place in this lens where a *wrong buffer* can be executed.
**Fix**: return `Result<usize, Halt>` where the `Ok` is only ever a body start;
route the non-callable case as `Err(Halt::Resume(pc))` so the existing depth
guard applies. Also make `cross_segment_callee` require
`self.functions.contains_key(&f)`.

### F8. `String(err)` / `'' + err` abort the crank unless the source text happens to mention `toString`
**high · confidence high · known-open** (seam-ledger item "to_primitive
resolves toString/valueOf through the crank's compiled symbol table";
interp-14 map)
`ironhorse-vm/src/interp.rs:38834`.

```rust
        for name in names {
            let Some(&id) = self.symbol_ids.get(name) else {
                ...
                continue;
            };
```
falling through to `Err(Halt::Unsupported("to_primitive:no-primitive-result"))`
(`:38860`-ish).

**Reproduced**:
- `var e=new Error('a'); String(e)` → `Unsupported("to_primitive:no-primitive-result")`.
- `var e=new Error('a'); '' + e` → same.
- Adding one unrelated mention of the identifier (`var u = ({}).toString;`) makes
  the identical program complete with `"Error: a"`.
- `e.message` alone works.

**Impact**: the ordinary way guest code reports an error — `String(e)`,
`'' + e`, a template substitution — is an *uncatchable* crank abort whose
reachability depends on whether an unrelated token appears elsewhere in the
source. For a consensus engine this is worse than a gap: two textually different
but semantically identical programs behave differently. It also makes the error
model untestable from inside the guest.
**Fix**: resolve `toString`/`valueOf` through `intern_key_unmetered` (as
`build_error` already does for `message`, with the comment explaining exactly
why: "XS's key table is machine-global", `:23103-23108`), not through the
per-crank `symbol_ids`.

### F9. `Halt::Unsupported` is a 269-label channel that conflates unimplemented features, guest-value gaps, and **engine invariant violations**
**high · confidence high · partially-known** (t262 map, fuzz map)
`ironhorse-vm/src/interp.rs:3535` (the variant's doc: "An opcode outside the
stage-1 subset was reached"); 376 construction sites, 269 distinct labels.

Invariant-violation labels sharing the variant with coverage gaps:
```
15247: Halt::Unsupported("end:frame-underflow")
15341: Halt::Unsupported("yield:stack-underflow")
16566: Halt::Unsupported("function:missing-segment")
17463: Halt::Unsupported("async:bad-resolving-fn")
21588: Halt::Unsupported("promise:job-bad-capability")
```
**Impact**: there is no outcome that means "the engine's own state is wrong".
`rust/endo/src/ironhorse_engine.rs:91` renders all of them as
"unsupported opcode `{op}` (a named, unlanded engine gap)", and
`ironhorse-262/src/xst.rs:450` records all of them as a non-gating
`RunSkip`. An interpreter bug that corrupts the frame geometry on
oracle-produced bytecode is therefore indistinguishable — to the operator and to
the acceptance suite — from "we have not ported `Array.prototype.sort` yet".
`Halt::Unsupported("Math:non-numeric-argument")` (reproduced for
`Math.max('1',2)`) shows the third category: a guest-*value*-dependent refusal,
not an opcode at all.
**Fix**: split into `Halt::NotImplemented(&'static str)` (a coverage gap; the
262 skip is correct), `Halt::Refused(&'static str)` (a deliberate
value-dependent refusal) and `Halt::Invariant(&'static str)` (an engine bug —
which the harness must treat as a **Fail** and the daemon must log distinctly).

### F10. Every direction of error-model divergence is a non-gating skip in the differential harness
**high · confidence high · partially-known** (t262-harness-core map named the
`OracleOnlyComplete` half)
`ironhorse-262/src/xst.rs:450`, `:508`, `:560`.

```rust
    match &run.ironhorse_halt {
        Halt::Unsupported(op) => return Verdict::RunSkip(format!("unsupported-opcode:{}", op)),   // :450, before agreement
...
                    Verdict::RunSkip("abort-value-differs".into())                                // :508
...
        Agreement::OracleOnlyComplete => Verdict::RunSkip("ironhorse-aborted".into()),            // :560
```
**Impact**: F2 (ironhorse throws where XS catches) → `ironhorse-aborted` skip.
F9 (an engine invariant fires) → `unsupported-opcode` skip, checked *before* the
agreement match. F11 (a message-less TypeError where XS carries a diagnostic) →
`abort-value-differs` skip. F4/F5/F7 land in the same three buckets. The engine's
only real acceptance instrument cannot fail on anything in this lens, which
explains why every defect above survived six review waves. The design's own bar
("matching the fail vector matters as much as the pass vector") is not
implemented.
**Fix**: gate `ironhorse-aborted` when `ironhorse_halt` is `Halt::Throw` or
(post-F9) `Halt::Invariant` — those are semantic divergences, not coverage gaps;
keep the skip only for `NotImplemented`. Commit the expectation list the design
specifies so a covered→skip flip is visible.

### F11. Engine-raised `TypeError`/`RangeError` never carry a message; the *uncatchable* sites carry the diagnostics instead
**high · confidence high · new**
`ironhorse-vm/src/interp.rs:34654` (263 call sites) and `:30943` (181 call
sites); the messaged helper exists but is used only for `SyntaxError` (`:34681`)
and `ReferenceError` (`:11734`, `:11796`, `:12204`, `:12282`).

```rust
    fn catchable_type_error(&mut self) -> Halt {
        let error = self.build_error("TypeError", 0, 0);
```
(`base = 0, argc = 0` ⇒ `build_error` takes the "no message argument" branch,
`:23068-23085`.)

**Reproduced**: `var f; try { f() } catch(e) { e instanceof TypeError }` → `true`,
`e.name` → `"TypeError"`, `e.message` → `""` (XS: `"f is not a function"`).
`try { nosuchvar } catch(e) { e.message }` → `"get nosuchvar: undefined variable"`
— the ReferenceError family is correct, so the machinery exists and is unused.
**Impact**: guest-observable (`e.message`, `String(e)`) divergence from XS on
every engine TypeError and RangeError; and `DualRun::error_agrees`
(`ironhorse-262/src/lib.rs:528-533`) compares `oracle.error` against the
`Halt::Throw` string, so every uncaught engine TypeError is an automatic
mismatch — absorbed by F10's `abort-value-differs` skip. Diagnostics are
*inverted*: the uncatchable sites (F2) carry hand-written text the guest can
never see, the catchable ones carry nothing.
**Fix**: add `catchable_type_error_msg`/`catchable_range_error_msg` over
`internal_error` and port XS's `fxThrowMessage` texts site by site, starting
with the sites the 262 corpus reaches.

### F12. `run()` mints two synthetic `Halt::Throw`s from the oracle shim's post-run coercion — the only halts that pass `is_quiescent()`
**high · confidence high · known-open** (interp-05 / interp-01 maps)
`ironhorse-vm/src/interp.rs:11200` and `:11214`; gate at `:10733`; register clear
at `:11234`.

```rust
        if halt == Halt::Return && self.result.kind == Kind::Symbol {
            halt = Halt::Throw("TypeError: cannot coerce symbol to string".to_string());
        }
```

**Reproduced**: `Symbol()` → `completed=false, halt=Throw("TypeError: cannot
coerce symbol to string"), is_quiescent()==true`. Contrast `throw 1`
(`quiescent=false`) and `Reflect.isExtensible(1)` (`quiescent=false`).
**Impact**: (a) a perfectly legal program is reported to `rust/endo`'s
`PersistentMachine::eval` as a halted crank and forces a full session rewind —
the test harness's `String(result)` behaviour is baked into the engine's only
run entry; (b) it is the one counter-example to the documented invariant
"A crank that HALTED … returns with … a set exception; a checkpoint there would
serialize … a resumed chimera" (`:10724-10732`). Because `completed==false`,
`run` skips the boundary-register clear at `:11234`, so `result`/`locals`/
`id_map` stay populated and rooted while every persist verb accepts the machine —
re-opening wave-6 W6-11's root-set asymmetry for exactly this shape.
**Fix**: move the shim coercion into `ironhorse-262`'s runner, where it belongs;
report `Halt::Return` with a `result_kind` the harness can coerce. If it must
stay, clear the boundary registers unconditionally for these two synthetic
halts.

### F13. `DISPATCH_REENTRY_LIMIT = 64` reuses `Halt::StackOverflow`, aborting ordinary callback nesting at a third of the value-stack budget
**medium · confidence high · known-open** (interp-06 map)
`ironhorse-vm/src/interp.rs:205`, sites `:11284` and `:16249`.


**Reproduced**: a 70-deep `[1].forEach(...)` recursion →

limit from a porting artifact; raise the budget by running nested dispatch on an
explicit heap-allocated continuation rather than the Rust stack, or at minimum
document it as a deliberate, versioned engine limit.

### F15. `render_uncaught` runs guest code after the halt is decided and clobbers `self.exception`
**medium · confidence high · new**
`ironhorse-vm/src/interp.rs:11072`; call sites `:15051`, `:15717`, `:15740`.

### F16. `CatchJump` records a bare `target_pc` with no code-segment identity
**medium · confidence high · new**
`ironhorse-vm/src/interp.rs:4971`.

**Impact**: (a) routing a `Resume` to "the loop that owns the handler's frame" is

### F19. `self.exception` is never cleared after an uncaught throw: a live machine is permanently non-quiescent
**medium · confidence high · known-open** (vm-tests map)
`ironhorse-vm/src/interp.rs:10741` (`&& self.exception.kind == Kind::Undefined`);
`run`'s boundary clear at `:11234` is gated on `completed` and never touches

## 3. Strengths

- **`raise_js` + `unwind_to_jump` is a faithful `fxJump`.** It restores exactly
  what XS's `c_setjmp` restore does — call frames back to `jump->call_depth` via
  `leave_call` per crossed frame, then the establishing frame's `stack`/`locals`
  cuts, `id_map`, and the `with`/eval environment head (`:34594-34630`). The
  `env` restore in particular ("so a throw out of a `with` body resets the
  environment for the surviving catch/finally") is a detail most ports miss. The
  `rebased` flag and `RESUMED_HANDLER_THROW_METERING` model XS's one extra
  dispatch for a handler live across a suspend — genuinely careful work.
- **Cross-frame catches through nested Rust dispatch actually work.** The
  `Halt::Resume` + `return_depth` propagation is a real solution to a hard
  problem (a JS handler owned by an outer Rust stack frame), it is locked by
  `nested_run_unwind_floor.rs`, and the generator cases it pins
  (`function* g(){ throw 1 } try { g().next() } catch(e){}` completing with `1`)
  are full XS agreement where an earlier design settled for an honest escape.
- **Error objects are realm-local and correctly shaped.** `build_error`
  (`:23051`) chains to the right `%Type.prototype%` so `instanceof` holds
  (verified: `e instanceof TypeError` → `true`), `name` stays inherited (so
  `hasOwnProperty('name')` is `false`, matching XS), `message` is own and
  non-enumerable *and* interned machine-globally with a comment explaining
  precisely why a later crank must still resolve it, and `cause` is installed
  with the spec's `{writable, !enumerable, configurable}`.
- **Stack traces are deterministic by construction.** `capture_error_frames`
  (`:23037`) records function names only — no file, no line, no address — and
  `ErrorStackGetter` (`:28752`) reads `name`/`message` live off the instance.
  For a consensus engine this is the right trade, and it is one of the few
  places where the "live property, not shadow state" discipline was applied.
- **`StackOverflow` as a host abort is correct XS lineage.** The variant doc
  (`:3546-3551`) states the reasoning — XS's `fxOverflow` → `fxAbort` is not a
  catchable `RangeError` — and `enter_call` checks `would_overflow` *before*
  opening the frame, which is the right place.
- **The debugger design's break-on-uncaught classifier is sound.** Its
  bytecode-shape heuristic (a chain entry is a genuine catch iff
  `code[target_pc]` is `CATCH_*`, finally-only transit iff `XS_CODE_EXCEPTION`)
  checks out against the coder: `coder.rs:5219-5222` places the first catch
  target on a second `CATCH_1`, `coder.rs:5249-5250` places a finally-only
  target directly on `XS_CODE_EXCEPTION`. Choosing that over a `flag == 2`
  compiler change (which would have perturbed byte identity) is the right call.

## 4. Recommended architectural direction

**Make the thrown value the payload and make control transfers unrepresentable.**
Two type changes remove five of the six worst findings at the root. First,
`Halt::Throw(Slot)` instead of `Halt::Throw(String)`: the rendered text is a
*host boundary* concern, produced once in `run()`, and every native-try boundary
then recovers the value from the halt it is already matching on rather than from
a register whose population is an unenforced invariant (F3), while F2's remaining
inline sites become a compile error the moment they cannot supply a `Slot`.
Second, split the enum: `dispatch_at_inner` should return a `Terminal` with no
`Resume`/`Yield`/`Await` arms, and fallible callees should return
`Result<T, Unwind>` where `Unwind::Resume(pc, segment)` is consumed by a single
helper that the type system forces every call site through. F4 (five unguarded
`Err(halt) => return halt` sites), F7 (a handler pc smuggled through an `Ok`
channel), F16 (a pc with no buffer identity) and F17 (`Resume(148)` printed to an
operator) are all the same missing distinction, and no amount of review will
keep 73 hand-written match arms in sync across a 45k-line function.

**Then unify the native-try boundary and the raise helpers.** There should be
exactly one `with_native_try` — taking the jump chain, running the body,
restoring the chain on every arm, returning `Result<Result<T, Slot>, Halt>` —
replacing `run_callback_catching_throw`, `from_async_unwind`/`from_async_try`
and the two fenced copies inside `step_async`/`step_async_generator` (F6). And
exactly one raise family, `catchable_<kind>_error_msg`, so the 444 message-less
TypeErrors and RangeErrors gain XS's diagnostics (F11) and the diagnostics stop
being carried only by the throws the guest can never catch. `to_primitive`'s
`toString`/`valueOf` lookup must move off the per-crank symbol table (F8) before
any of this is observable from guest code at all.

**Finally, give the acceptance instrument a way to fail on this lens.** Today
`Unsupported` → skip (checked before agreement), `OracleOnlyComplete` → skip,
and a differing thrown value → skip; that is why six review waves passed over
uncatchable TypeErrors, `null.f === undefined`, and a `Resume` returned to the
host. Splitting `Unsupported` into `NotImplemented` / `Refused` / `Invariant`
(F9) and gating the last two — plus gating `ironhorse-aborted` whenever
`ironhorse_halt` is a `Throw` — converts the entire class from invisible to
red. Pair it with an oracle-free vm test that asserts, for one representative
program per engine-error class, that `try/catch` catches and that `e.message`
matches XS: that is the acceptance bar the debugger design already specifies
("a dual-run test that `try/catch` catches each class of engine-raised error")
and that does not exist in `ironhorse-vm/tests/` today.
