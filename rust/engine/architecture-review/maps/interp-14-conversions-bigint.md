## Purpose and responsibilities

The region is the tail of the ~38k-line `impl Interp` plus the first block of free functions
after it. It holds:

1. **The abstract-operation conversion core** the opcode dispatcher calls directly
   (`XS_CODE_ADD/SUBTRACT/…/EQUAL/LESS…` at 14277–14402): `truthy` (ToBoolean incl. BigInt),
   `binary_arith`, `binary_bit`, `relational`, `equality`, `op_add`, `concat_add`,
   `to_primitive` (+ `call_primitive_method`), `to_number_value` (ToNumeric), and the
   `to_string_*_metered` trio (ToString with XS-site metering).
2. **BigInt storage and arithmetic glue**: `read_bigint`/`make_bigint`/`store_bigint`
   (chunk layout `[sign u8][LE u32 limbs]`), `bigint_num_loose_eq`, `bigint_arith`,
   `try_bigint_binop`. The limb math (`bi_*`, `number_to_bigint`) lives at 43184–43392.
3. **Free helpers**: `value_global` (realm value globals), `decode_element_le` /
   `encode_element_le` (TypedArray/DataView element codec — the only place NaN bits become
   observable), locale canonicalization (`canonicalize_locale`, `locale_to_tag`,
   `maximize/minimize_locale`, `supported_locale`), Intl approximations (`list_patterns`,
   `segment_units` via ICU4X, `collator_compare`, `plural_select`, `currency_digits`,
   `format_date_time_parts`, `resolve_time_zone`), the Date civil-calendar core
   (`civil_fields`, `time_clip`, `date_from_components`, `parse_date_string`,
   `date_*_string`), and the Temporal record algebra (`parse_temporal_plain`,
   `temporal_plain_add/difference`, `iso_date_until`, `iso_datetime_difference`,
   `iso_total_calendar_units`, `parse/format_temporal_duration`, `days_from_civil`,
   `civil_from_days`, `parse/format_temporal_instant`, `round_number_to_increment`).

## Architectural observations

- **Two error models coexist in one function family.** Spec TypeErrors are sometimes
  `self.catchable_type_error()` (Temporal/Intl paths: 24059, 24320) and sometimes
  `Halt::Unsupported` (the whole arithmetic/equality core: 38553, 38570, 38651, 38762, 38823,
  38856, 38874). A `try/catch` around `Symbol() - 1` or `({valueOf(){return{}},
  toString(){return{}}}) + 1` cannot catch what the spec says is a TypeError; the crank dies.
- **"Honest named skip" has become the production error model.** The doc comments (38523–38529,
  38595–38601, 38669–38674) still describe a "covered primitive subset" and "self-name
  unsupported" — stage-1 vocabulary. The dispatcher hands these functions every opcode with
  no general fallback (`dispatch_result!` at 3573–3587 returns any `Err(halt)`), so
  `"1" == 1`, `1n < 2`, `1n | 2n`, `4n / 2n`, `2n ** 3n`, `-"5"`, `~"5"`, `BigInt64Array` reads
  all abort the crank (probe-confirmed).
- **Silent-wrong results** exist alongside the visible-fail ones: reference-vs-primitive `==`
  (`loose_equals` never calls ToPrimitive: 41953–41968, comment "String and reference
  coercions arrive with the object model" — they never did), `string + Symbol` → string,
  and the `wrapper_data` shortcut in `to_primitive`. These would be red in a result-parity run;
  the ledger (store-seam.md 2381, 3486–3490) records only the visible-fail `to_primitive`
  halts on wrappers/promises.
- **Determinism hazards.** (1) NaN bits: `apply_arith` performs runtime f64 ops (41880–41889);
  x86-64 SSE produces the negative default NaN (`0xFFF8…`), aarch64 the positive one
  (`0x7FF8…`), and RISC-V canonicalizes — all observable through `encode_element_le`; payloads
  from `decode_element_le` flow into arithmetic where propagation rules differ per ISA and
  Rust leaves cast/arith NaN payloads unspecified (`n as f32` at 40342, `f32 as f64` at 39194).
  This is precisely what `mxCanonicalNaN` prevents in the oracle. (2) `fx_pow` (41930, other
  region) trusts libm `pow` to be "bit-exact with the oracle" — libm results differ across
  glibc/musl/macOS; flagged for the owning reader. (3) Everything else here is deterministic:
  `{:e}`/`{:.N$}` formatting and `str::parse::<f64>` are pure Rust; `rem_euclid`/`trunc`/
  `round` are exactly specified; `BTreeMap` for locale keys; `HashSet`/`HashMap` used only for
  membership/lookup; ICU4X data is compiled in (deterministic per build).
- **Panics on untrusted input (three confirmed):** `&str` byte slicing at non-char
  boundaries in `parse_date_string` (39624) and `parse_temporal_duration` (40801); unchecked
  `i64` multiply in `days_from_civil` (40866) reachable from `Date` with |year| ≳ 2.5e16.
  Debug builds (tests, fuzz) panic; release builds (no `overflow-checks`, census) wrap silently
  at 40866 → possibly wrong non-NaN dates. Also `u64` overflow at 40835.
- **Metering doctrine drift.** Constants are "raw-exact against the pin"; meanwhile real
  allocations go unmetered at 38813 (ToPrimitive hint chunk) and 38957 (boolean/null/undefined
  ToString chunk). Neither direction matches the doctrine's "calibrated cost table".
- **Monolith / coupling.** Intl, Date, Temporal calendar algebra, BigInt glue and the
  ECMAScript conversion core share one file and one `impl`; free functions after 39171 are a
  second, unrelated module living below the `impl`. `TemporalDurationRecord` has no magnitude
  validation at construction (24319–24323) so every formatter must cope with unbalanced fields
  and does not.
- **GC-root / snapshot / side tables.** This region adds no new side tables. `read_bigint`
  tolerates malformed chunks (sign byte ∉ {0,1} → positive; a snapshot-crafted `[1][0,0,0,0]`
  yields a `-0n` that `bi_cmp` orders below `0n`, 43355–43359 — low). `to_number_value`'s
  `unreachable!()` (38870) is a panic if a snapshot ever yields `Kind::String` with a non-String
  payload — depends on the decoder's kind/payload validation (other region).
- **Performance shape.** `to_primitive` linear-scans `well_known_symbols` and allocates a
  hint chunk per call; `truthy`/`read_bigint` allocate a `Vec` per read; `segment_units`
  constructs an ICU segmenter per call; `collator_compare` normalizes both strings per compare.
  None affect determinism.

## Candidate findings (most architecturally significant first)

**F1 — NaN bit patterns are never canonicalized; typed-array/DataView expose ISA-dependent bits (critical, determinism).**
`interp.rs:39196` (`Slot::number(f64::from_le_bytes([...]))`), `:40344` (`n.to_le_bytes()`), `value.rs:332` (`Slot::number` stores raw bits).
Claim: on x86-64 `new Uint8Array(new Float64Array([0/0]).buffer)[7]` is `255` while an aarch64 host yields `127`, and a NaN payload written via a Uint8Array view survives `f[0] + 1` and re-encoding — a consensus-visible divergence the design (line 336) says `mxCanonicalNaN` prevents (the oracle is built with `mxCanonicalNaN=1`, `xs-oracle/build.rs:81`).
Evidence: probe output `[0/0] → 255`, `[NaN] → 127`, payload byte `1` preserved through read→add→write. Confidence: high on the code; the cross-ISA sign-bit difference is standard IEEE-754 implementation behavior.

**F2 — Loose equality returns a silent wrong `false` for object operands (critical, correctness).**
`interp.rs:38738–38744` → `41953–41968` (`loose_equals` falls to `strict_equals`; no ToPrimitive).
Claim: `({valueOf(){return 1}}) == 1`, `[1] == 1`, `new Number(1) == 1`, `true == {valueOf(){return 1}}` all complete with `false` (spec: `true`).
Evidence: probe; comment at 41950–41952 "String and reference coercions arrive with the object model". Not a named skip — violates ironhorse_engine.rs:16–17.

**F3 — `string + Symbol` silently yields the string instead of a TypeError (high, correctness).**
`interp.rs:39008` (`Payload::Reference(_) => Vec::new(), // unreachable`), `:38905–38907`, Symbol payload at `:6308`.
Claim: `"a" + Symbol()` and `Symbol() + "a"` complete with `"a"`.
Evidence: probe. (`\`${Symbol()}x\`` correctly halts at 17925–17926, showing the guard exists elsewhere but not here.)

**F4 — The conversion core still aborts the crank on spec-valid programs (high, error-model).**
`interp.rs:38692–38697` (`"1" == 1`), `:38651` (`1n < 2`), `:38570` (`1n | 2n`), `:39123` (`4n / 2n`), `:14408` (`-"5"`), `:14345` (`~"5"`), `:39192` (BigInt64Array reads), `:38762/38856/38874` (TypeErrors as `Unsupported`), consumed at `rust/endo/src/ironhorse_engine.rs:91`.
Claim: each listed expression halts `Unsupported(...)` (probe-confirmed) and `try/catch` cannot observe the spec-mandated TypeError. Ledger (store-seam.md:3486–3490) records only the promise-instance `no-primitive-result` case.

**F5 — Guest-triggerable panic in `Date.parse`/`new Date(string)` (high, robustness).**
`interp.rs:39624` (`&fraction[..fraction.len().min(3)]`), reachable via `:25153`, `:17829`, `:17836`.
Claim: `Date.parse("2020-01-01T00:00:00.éé")` panics "byte index 3 is not a char boundary".
Evidence: probe panic at 39624:35.

**F6 — Guest-triggerable panic in `Temporal.Duration.from(string)` (high, robustness).**
`interp.rs:40801` (`rest = &rest[end + 1..]` after a multibyte designator), reachable via `:24475`.
Claim: `Temporal.Duration.from("P1é")` panics "byte index 2 is not a char boundary".
Evidence: probe panic at 40801:21.

**F7 — Unchecked `i64` overflow in `days_from_civil` from `Date` component construction (high, robustness).**
`interp.rs:40866` (`era * 146097`), `:40860` (`year - i64::from(..)`), guard at `:39587` admits the full i64 range.
Claim: `new Date(1e17, 0)` / `Date.UTC(1e17)` panic in debug ("attempt to multiply with overflow") and wrap silently in release (no `overflow-checks`), where the spec answers `NaN`.
Evidence: probe panic at 40866:11 for both.

**F8 — `Duration.prototype.toString` mis-renders and overflows unbalanced sub-second fields (medium-high, correctness/robustness).**
`interp.rs:40835` (`f[7] * 1_000_000 + f[8] * 1_000 + f[9]`), record validated only for sign at `:24319–24320`; fields admitted up to 2^53 at `:24303`.

Evidence: probe.

**F9 — `to_primitive` deviates from spec in three ways and shortcuts wrappers to a wrong value (medium, correctness).**
`interp.rs:38807` (null `@@toPrimitive` treated as present), `:38842–38851→38762` (non-callable `valueOf` → halt instead of skip), `:38834–38849` (`wrapper_data` bypass), `:38813` (unmetered hint chunk via `alloc_str_text`, 10895–10903).
Claim: `Number.prototype.valueOf = undefined; Object.prototype.valueOf = undefined; new Number(5) + 1` completes `6` (spec `"51"`); `({valueOf: 1, toString(){return "x"}}) + ""` and `({[Symbol.toPrimitive]: null, valueOf(){return 7}}) + 1` halt.
Evidence: probe.

**F10 — ToNumeric is interleaved with ToPrimitive in `binary_arith`/`binary_bit` (low, latent ordering bug).**
`interp.rs:38537–38538`, `:38566–38567` vs correct order in `relational` (`:38609–38610`, `:38653–38654`) and `op_add` (`:38889–38890`).
Claim: once F4's TypeErrors become catchable, `Symbol() - {valueOf(){sideEffect()}}` will throw before `b`'s `valueOf` runs, contrary to spec 13.15.3 (ToPrimitive both, then ToNumeric both).

**F11 — `StringToNumber` whitespace is ASCII-only (medium, correctness).**

## What is done well

- `encode_element_le` implements ToIntN correctly and documents why (`rem_euclid`, not
  saturating `as`), and `round_half_even` matches `c_nearbyint` for Uint8Clamped (40325–40381).
- `number_to_ecma_string` (value.rs 1759–1812) re-derives the spec's fixed/exponential
  threshold from Rust's shortest-round-trip digits — pure Rust, no libm, deterministic.
- `string_to_number`/`parse_decimal_body` (41613–41694) pre-filter the grammar so Rust's
  permissive parser cannot accept `inf`/`nan`, and rely on a correctly-rounded parser.
- BigInt chunk decoding is tolerant of malformed payloads (`read_bigint`, 39024–39042) and the
  digit-step meter cannot underflow (`bi_trim` ≥ 1 limb).
- `value_global` binds the realm value globals as real properties with the spec's
  non-writable/non-configurable flags (7443–7455) rather than a scope-chain shortcut.
- `canonicalize_locale` uses `BTreeMap` for extension keys so the canonical tag is
  order-deterministic; the Temporal calendar algebra is integer-exact with `checked_*` and
  bounded by `nsMaxInstant` (40598–40608), and `iso_total_calendar_units` seeds its search so it
  is O(1) rather than O(span) (40634–40637).
