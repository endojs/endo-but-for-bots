## Purpose and responsibilities

Two trailing `impl Interp` blocks form the machine's **collector seam**:

1. **The exact, whole-machine collector** — `gc_roots` (43502) assembles the root set;
   `collect_garbage` (43707) wires a 44-field `Hooks` struct (43711–43755) into
   `gc::collect_full` so that every Rust-side side table participates as *edges* (marking),
   *pruning* (sweep), *chunk holders* (compaction), *ephemerons*, and *dead-key pruning*.
   Two arena compactions follow the sweep: `compact_code_segments` (44516) and
   `compact_reaction_arenas` (44413).
2. **The page-granular partial-collector surface for the snapshot store** — `free_pages`
   (44556) frees whole pages the store proved unreachable and prunes every side table by the
   freed key set; `side_table_ref_slots` (44673) / `side_table_ref_page_bits` (44692) project
   "every slot index a side-table VALUE holds" as roots for the summary-driven partial
   collector; `each_side_table_ref` (44740) and `each_side_table_ref_tail` (44761) are the
   shared enumeration behind both, with the two BULK tables (arrays, collections) served by
   the counted per-page refcounts in `bulk::SideRefCounts` rather than walked.

## Architectural observations

- **Six hand-mirrored side-table rosters.** The same ~30 tables and their sub-fields are
  enumerated in (1) the `Hooks` field list + construction (43711–43755, 44292–44334), (2)
  `extra_edges`, (3) `swept` + the late prune (44009–44037, 44344–44383), (4)
  `external_chunk_refs`, (5) `free_pages` (44577–44644), and (6) `each_side_table_ref_tail`.
  Comments say "mirrored from the full collector's …" (44778, 44790, 44807). Adding one
  side table requires touching all six plus the registry test; the code itself records that
  missing one "let the collector sweep a live proxy target … a proven silent wrong read"
  (43827–43833). A per-table trait (`edges`/`chunks`/`prune`) with one table registry would
  collapse this to one implementation per table.
- **The ground-truth net is textual and has blind spots.** `gc_visitation_registry.rs`
  parses type definitions only from `interp.rs` (line 34, `type_defs` 86–121), so a
  slot-bearing type defined in another module is invisible (today `side_refs: SideRefCounts`
  legitimately passes as non-bearing, but the mechanism would also miss a future
  `bulk::NewTable<SlotIndex>`); `Req::Edges` (439) checks presence in the two edge walks but
  NOT pruning in either sweep path (deleting `self.promises.retain(...)` from `free_pages`
  passes); `Req::DocumentedOnly` is `true` unconditionally (458), and finding 2 shows one of
  those notes is wrong. The behavioral twins (`gc_anchor_truth.rs`) cover Intl, Temporal,
  generator protos and iterator identities but not `error_stack_accessor`.
- **Two collectors with different reclamation power, and only the weaker one is wired.**
  `free_pages` never compacts chunks (44550–44552), never prunes dead-keyed weak entries,
  and `each_side_table_ref` roots ALL collection entries including WeakMap/WeakSet keys
  (44747–44752). `ChunkArena` has no free path other than `compact` (value.rs fn list:
  `alloc` 1470, `compact` 1542). With no production caller of `collect_garbage`, chunk bytes
  (strings, BigInts, ArrayBuffer backing stores), WeakMap-keyed entries, and page co-resident
  garbage grow monotonically over a worker's life.
- **Quadratic scans on tuple-keyed tables.** `extra_edges` scans `accessors`,
  `private_values`, `private_accessors` in full for every newly-marked slot (43876–43902:
  O(marked × table)); `swept` `retain`s them per swept slot (44035–44037: O(swept × table)).
  Documented as "small in practice; a counted per-owner index is the named upgrade"
  (43871–43875). Hardened-JS code (classes with getters, private fields) makes these tables
  large.
- **Per-marked-slot hash-lookup fan-out.** `extra_edges` performs ~20 `HashMap::get`s per
  marked slot regardless of kind — an inherent cost of keeping internal slots outside the
  arena; XS pays a kind switch.
- **Ephemeron symbol-key pass is O(capacity) per round** whenever any unmarked symbol-key
  descriptor exists (44091–44106), and false-retains via `id` collision with frame argument
  counts (documented 44078–44083).
- **Determinism:** upheld by construction (sorted roots, index-order sweep, sorted compaction,
  `BTreeSet`/`BTreeMap` in the arena compactions). `HashMap` iteration in `extra_edges` /
  `ephemeron_edges` perturbs only the worklist order. No f64 formatting, no host time.
- **Panics / indexing:** `SlotArena::mark` indexes `marks[i]` (value.rs 906) — a stale
  out-of-arena index from a side table is a panic, not UB (design-consistent). The
  `HashMap`/`BTreeMap` `[]` indexing in `compact_reaction_arenas` (44470, 44474, 44488) and
  `compact_code_segments` (44536) is safe: keys derive from the same holders just scanned; a
  dangling arena index maps past the new length and stays dangling (checked by hand).
  `free_pages` uses u64 page arithmetic (44566–44567) and `side_table_ref_page_bits` bounds-
  checks (44706, 44721). Nothing here reads untrusted bytes directly.
- **Release/debug asymmetry.** The counted-ref parity net is `#[cfg(debug_assertions)]`
  (44716) and `SideRefCounts::remove_slot` saturates silently in release (bulk.rs 78–85), so
  the "second net" is absent in shipped builds; privacy of the bulk fields is the only
  release-time guarantee.
- **Hidden-state / redundancy:** `symbol_key_ids` is pruned three times per full collection
  (44134, 44019, 44346). `Hooks` carries `stack`/`locals`/`args`/… as `&mut` only for the
  chunk pass. `well_known_symbols` and `proto_value_data` are visited for chunks although
  they hold symbols/numbers — harmless belt-and-braces.
- **API boundary:** `free_pages` and `collect_garbage` are `pub`, unguarded by
  `is_quiescent()`; `free_pages` frees whatever pages it is handed with no in-machine
  liveness check (by design — the store layer is trusted).
- **Metering doctrine:** both collectors are unmetered and guest-invisible (indices never
  surface); consistent with the design. GC *timing*, however, is left to the cadence policy
  rather than the release-fixed allocation thresholds the store-seam design describes.

## Candidate findings (most architecturally significant first)

1. **The exact collector is never scheduled; production reclaims only by page-conservative
   partial collection.** — `rust/endo/src/ironhorse_engine.rs:670–680`; interp.rs 44550–44552,
   44747–44752. Claim: no non-test code path in `rust/` calls `Interp::collect_garbage`, so
   chunk space is never compacted, dead-keyed WeakMap/WeakSet entries are never pruned (their
   keys are page-rooted by `each_side_table_ref`), and page co-resident garbage is never freed.
   Evidence: `partial_collect(session, &*self.store.borrow())` is the only reclaim call in
   `PersistentMachine::collect`; `free_pages` doc: "chunk space held by freed string slots is
   reclaimed by the next full collect_garbage (partial collection never compacts)"; `ChunkArena`
   exposes `alloc` and `compact` only. Why: unbounded heap growth on long-lived workers; the
   store-seam design (3977–3979) claims allocation-threshold GC scheduling that does not exist.
   Confidence: high on the "never called" fact; medium on operational impact (the worker
   envelope is itself not yet wired). Not listed as an open ledger item that I could find.

2. **Confirmed GC-root omission: `error_stack_accessor`'s getter/setter are root-less until
   installed, and installation happens after the collection that sweeps them.** — interp.rs
   4355–4359 (field), 6262–6264 (mint), 7683–7706 (gated install), 43502 (`gc_roots` never
   visits it), registry `tests/gc_visitation_registry.rs:360` (DocumentedOnly). Claim: a
   `collect_garbage` at a crank boundary after a crank that names no Error-family/`stack`
   name reclaims the two accessor function slots; the next crank naming `Error` installs
   dangling indices and `err.stack` halts. Evidence (probe, GC-vs-plain twins identical
   otherwise): `gc: GcStats { slots_reclaimed: 2, … }` then
   `halt: Unsupported("callback:non-user-function")` vs plain `(true, "string", …)`; control
   with crank 1 naming `Error`: `slots_reclaimed: 0`, INVARIANT. Why: violates the
   "collection is observation-invariant" property the anchor tests enforce; a machine that
   hits it fails every later `.stack` read (SES `assert`/error paths read `.stack`). Masked
   today by production never running the full collector and by boot pages being page-
   conservatively live under `partial_collect`. Fix shape: push `(proto, getter)`/`(proto,
   setter)` into the rooted `proto_accessors` rows or root the tuple in `gc_roots`, and add
   a `gc_anchor_truth` twin. Confidence: high (reproduced).

3. **Side-table roster duplicated across six bodies with no single source of truth.** —
   interp.rs 43711–43755, 43806–43999, 44001–44043 + 44343–44383, 44137–44289,
   44577–44644, 44761–44941. Claim: every side table's GC participation is spelled out by hand
   in six places, mirrored by comment. Evidence: "Wave-6 W6-2: the super home object, mirrored
   from the full collector's functions arm" (44790); "A table missing here let the collector
   sweep a live proxy target" (43829–43831). Why: this is the generator of the headline bug
   class (waves 2–6 fixed many instances; finding 2 is a fresh one); a per-table trait with a
   single registry would make omission a compile error rather than a test-string match.
   Confidence: high.

4. **The struct-derived ground-truth net has three blind spots.** —
   `tests/gc_visitation_registry.rs:34, 86–121, 439, 458`. Claim: (a) type graph parsed from
   `interp.rs` only, so slot-bearing types in other modules are invisible; (b) `Req::Edges`
   does not require pruning in `collect_garbage`/`free_pages`, so a stale-row regression on any
   edge table passes; (c) `DocumentedOnly` is unchecked and one such note is false (finding 2).
   Evidence: `const SRC: &str = include_str!("../src/interp.rs");`;
   `Req::Edges => mentions(&extra_edges, name) && mentions(&partial, name)`;
   `Req::DocumentedOnly => true`. Why: the net is the designated defense against the
   forgot-the-table class; its gaps are exactly where the next omission lands. Confidence: high.

5. **Quadratic tuple-keyed scans in mark and sweep.** — interp.rs 43876–43902, 44035–44037.
   Claim: full-collection cost includes O(marked × |accessors ∪ private_*|) during mark and
   O(swept × same) during sweep. Evidence: `for ((owner, _id), a) in self.accessors.iter() {
   if *owner == idx {`; `self.accessors.retain(|(owner, _), _| *owner != idx);` inside
   `swept`. Why: hardened-JS heaps (class getters, private fields on many instances) make
   these tables large; a 100k-object heap with 10k accessor rows is ~10^9 comparisons per
   collection. Documented as deferred (43871–43875). Confidence: high on shape; unmeasured.

6. **Partial-collector conservatism is indefinite, and its doc says otherwise.** — interp.rs
   44669–44672, 44747–44752; machine.rs 1933–1937. Claim: WeakMap/WeakSet keys and dead-keyed
   side-table values remain page roots for the machine's lifetime because no full collection
   runs (finding 1). Evidence: `for c in self.collections.values() { for (k, v) in
   c.live_entries() { k.each_ref_slot(...)` (no kind filter); doc: "keeps its values' pages one
   partial collection longer". Why: WeakMap is the SES idiom for identity-keyed caches;
   under partial-only collection those caches leak by construction. Confidence: high.

7. **Determinism claim is right for the wrong reason.** — interp.rs 43704–43706, 43876,
   43886, 43892, 44050; value.rs 1550–1559. Claim: the documented mechanism ("trace order is
   worklist order from a fixed root sequence") is not literally true — `extra_edges` and
   `ephemeron_edges` iterate `HashMap`s — and outcome determinism instead rests on
   order-independence of the mark fixpoint plus `ChunkArena::compact` sorting. Evidence:
   `seen.sort_by_key(|o| o.0);` in `compact`. Why: a future change that made any hook
   order-sensitive (e.g., first-visit bookkeeping) would silently break replica determinism,
   and the doc would not warn. Low severity; a doc/test fix (`gc_roots` doc also says "two"
   HashMap sources; there are four). Confidence: high.

8. **Neither collector checks quiescence; `pending_new_target` and the run registers are
   rooted by convention.** — interp.rs 43707, 44556, 10733; registry 362; machine.rs
   1957–1960. Claim: `collect_garbage` and `free_pages` are `pub` with no `is_quiescent()`
   guard, so a mid-crank host call (or a future allocation-threshold trigger, which the design
   calls for) would sweep `pending_new_target`. Evidence: `pending_new_target: Option<SlotIndex>`
   absent from `gc_roots`; "collections run only at quiescent boundaries" (registry note).
   Why: the design intends allocation-triggered GC; the moment it is added, the boundary-only
   assumptions here become live bugs. Confidence: medium.

9. **`free_pages` trusts its caller absolutely.** — interp.rs 44556–44575. Claim: any `u32`
   page list frees every non-free slot on those pages with no marks, no `debug_assert` on
   reachability, and the side-table prune follows. Evidence: `if !self.slots.is_free_index(idx)
   { self.slots.free(idx); freed.push(idx); }`. Why: soundness of durable state rests entirely
   on the store's summary graph plus two root projections computed elsewhere; a debug-only
   cross-check against an in-memory mark (when resident) would catch a store-side regression
   before it persists. Confidence: high on fact; low-medium on risk.

10. **Release builds drop the counted-ref parity net and saturate undercounts silently.** —
    interp.rs 44716–44731; bulk.rs 78–85. Claim: in release, a missed counted mutation (or an
    external `Slot` mutation through a future non-counted path) is undetectable and can either
    pin a page forever (missed decrement) or free a live page (missed increment). Evidence:
    `#[cfg(debug_assertions)] { … debug_assert_eq!(bits, walked, …) }`;
    `None => { debug_assert!(false, "side-ref undercount on page {page}"); }`. Why: the design
    treats panics as acceptable and silent wrong reclamation as not; this is the one place the
    shipped build has no net. Confidence: high on fact; low on likelihood (privacy mechanism).

11. **Ephemeron symbol-key pass is O(arena capacity) per fixpoint round.** — interp.rs
    44091–44106. Claim: whenever any symbol-key descriptor is unmarked after the strong
    phase, every round scans every slot in the arena. Evidence: `for i in 0..slots.capacity()
    { … if let Some(&d) = wanted.get(&slots.get(idx).id) { visit(d) } }`. Why: symbol-keyed
    properties on short-lived objects are common (SES passStyle brands); combined with the
    lazy-arena `get` fault path (value.rs 853–858) this reifies the whole heap. Documented
    (44071–44090). Confidence: high; unmeasured.

12. **Triple pruning of `symbol_key_ids`.** — interp.rs 44134, 44019, 44346. Claim: the
    intern map is retained in `prune_dead_keyed`, removed per slot in `swept`, and retained
    again in the late prune; only the first is load-bearing. Evidence: `self.symbol_key_ids
    .retain(|d, _| slots.is_marked(*d));` then `self.symbol_key_ids.remove(&idx);` then
    `self.symbol_key_ids.retain(|k, _| !dead.contains(k));`. Why: harmless, but it is the
    fingerprint of roster drift across the six bodies (finding 3). Confidence: high.

## What is done well

- The `GcHooks` trait (gc.rs 72–96) is a clean seam: the arena collector is 100 lines of
  pure, testable code and the machine's mess is quarantined in one `impl`.
- Determinism is real, not incidental: sorted/dedup'd roots, index-order sweep, `BTreeSet`
  arena compactions, and a compactor that sorts its live set — no `HashMap` order reaches an
  observable.
