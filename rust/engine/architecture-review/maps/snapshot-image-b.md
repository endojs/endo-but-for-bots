## Purpose and responsibilities

This half of `image.rs` is the **validation and container assembly** end of the
snapshot codec:

- The tail of the Intl side-table decoder (`decode_intl`, 2937–3225) and the
  iterator-cursor codec (`encode_iterators`/`decode_iterators`, 3231–3313):
  per-atom byte decoders that refuse non-canonical shapes (unordered owners,
  bad option/boolean tags, non-tiling segment boundaries, unknown keys).
- `LangRows` (3317–3352) plus `EMPTY_*` statics (3354–3396): a bundle of
  borrowed "language" side-table rows handed to the semantic gate.
- The **semantic bounds gate** `check_image_slot_bounds` (3478–4177): every slot
  index and chunk offset carried by the heap, stack, symbols, and all ~25 side
  tables is checked against the image's own declared geometry
  (`slot_count`, `chunk_len`, free set), plus cross-table geometry (views vs
  buffers, generator PCs vs function bodies, combinator/reaction indices,
  cursor coverage, Intl bound functions vs Intl rows).
- The id-registration audit helpers `runtime_intern_floor` /
  `first_stored_unregistered_id` (3444–3469).
- `encode_stack`/`decode_stack` (4179–4203).
- `write_machine` (4210–4329): canonical atom order, optional atoms emitted only
  when non-empty, `NFLR` only when it differs from the table length.
- `read_machine` (4353–4735): VERS → SIGN → canonical-grammar check → per-atom
  decode → quiescence (empty STAC) → symbol counter vs name table → METR
  cost-table gate → per-atom present-but-empty refusals → bounds gate →
  unconditional-atoms gate (current version only).
- `read_validated_machine` (4743–4754): adds the stored-id audit and wraps the
  result in the proof-carrying `ValidatedSnapshot`.
- In-file tests (4756–5885): crafted-row refusals, round-trips, malformed-count
  over-allocation trophies, free-record hygiene.

The same decoders and the same gate are used by the store path
(`store.rs:1452–1656` call `crate::image::decode_*`; `store.rs:2975` and
`store.rs:3317` call `check_image_slot_bounds`), so the container and the
store share one validation surface. That is the region's most important
architectural property and it holds.

## Invariants and contracts claimed (from doc comments) — and whether the code upholds each

1. **"Two writes of the same image are byte-identical" / write(read(b)) == b for
   current containers** (4205–4209, 4222–4227, 4340–4345). UPHELD. Fixed atom
   order; optional atoms only when non-empty; reader refuses present-but-empty
   (4455–4611), explicit full `NFLR` (4631–4635), out-of-order/unknown/duplicate
   tags (4374–4387; a duplicate tag cannot be found in `CANONICAL_ATOM_ORDER[cursor..]`
   after the cursor advanced past it), and non-ascending/duplicate rows in every
   decoder (grep: 30+ "not strictly ascending" refusals). Tests 5447–5490,
   5612–5661 lock it. Caveat: claimed of CURRENT-version containers only
   (4679–4687); see candidate 7.

2. **"A mismatch fails closed exactly as fxReadSnapshot does"** (SIGN, 4331–4335).
   UPHELD at 4361–4366; test 5493–5536.

3. **METR: "fail closed on a cost-table version this engine did not produce — the
   metering analogue of the SIGN check"** (4436–4449). UPHELD for a present
   METR. PARTIAL as a doctrine guarantee: (a) an absent METR on a version-1..11
   container reads as a zeroed meter under the current table (4440–4443); (b)
   the engine has TWO independently stamped meter tables and only one is
   carried/compared — see candidate 4.

4. **The gate's doc (3398–3425): "every HEAP slot's next link and Reference
   payload … side-table owners, array item values, collection entry keys AND
   values, registry descriptors … against slot_count; every String/BigInt chunk
   offset against chunk_len."** UPHELD as literally stated, and `each_ref_slot`
   is complete over `Payload` (value.rs:281–296). BUT the doc's stated purpose —
   "a crafted index is rooted or walked by the collector and hits an unchecked
   Vec index — a RELEASE panic on the first collect_garbage" (3401–3403) — is
   NOT fully achieved: a live edge into a *free* record is accepted, and free
   records are opaque, so the collector can still be walked into an
   out-of-arena index. See candidate 1.

5. **"Free records are opaque … a side-table row whose OWNER sits in the free set
   can only be crafted"** (3499–3509). UPHELD for owners (`owned()` 3517–3525,

6. **"`SlotIndex::NULL` is skipped, matching `SideRefCounts::page_of`"** (3419).

7. **Typed-array family: "every buffer's backing extent lies inside the chunk

8. **Generator frame: "the cursor and every saved-handler target must be an

## Architectural observations

- **One gate, one decoder set, two callers.** The strongest property of the
  region: store and container paths cannot drift on WHAT is validated because
  they call the same function with the same row types. They CAN drift on the
  geometry inputs (manifest vs decoded), which `validate_store` derives from
  page inventory before the gate (store.rs:3187–3192, 3285), so the
  `vec![false; slot_count]` bitmap at 3510 is bounded by actually present pages.
- **Growth pattern is positional accretion.** `check_image_slot_bounds` has 16
  parameters (`#[allow(clippy::too_many_arguments)]`, 3477) and `LangRows` 14
  fields; `read_machine` has ~24 near-identical match arms (4454–4611);
  `write_machine` 24 near-identical `if !is_empty()` arms; `restore_side_tables`
  (machine.rs:432) takes 22 parameters. Adding one side table today touches
  format.rs (tag + `CANONICAL_ATOM_ORDER`), `MachineImage`, `write_machine`,
  `read_machine`, `LangRows`(+`EMPTY`), the gate, store.rs small-state
  encode/decode, machine.rs `restore_side_tables`, interp.rs snapshot+restore,
  and sidetable.rs's hand-written ledger. I found no struct-derived test tying
  `MachineImage` fields to `CANONICAL_ATOM_ORDER`/`LangRows` (the vm has one for
  GC roots: `gc_visitation_registry.rs`; the snapshot's `sidetable.rs` ledger is
  a hand-maintained enum, and `side_table_ledger.rs` tests behavior, not field
  coverage).
- **Three-layer belt-and-braces.** Invariants are checked in the byte decoder,
  again in the gate, and again in restore verbs (e.g. iterator cursor bounds at
  3290/3295, 4151–4171, and interp.rs:10397–10429). Deliberate (machine.rs
  425–430), but there is no single table saying which layer OWNS which
  invariant; the layers differ in small ways (restore checks against the live
  `collections` map, the gate against decoded rows) and could silently diverge.
- **Panics/unwraps on untrusted data in-region:** none reached. `Cursor` is
  fully bounds-checked with `checked_add` (838–896); all `Vec::with_capacity`
  are clamped to `p.len()/N`; `binary_search` callers rely on decoder-enforced
  ascending order (verified for arrays 991, collections 1042, buffers 1391,
  functions 1692, intl 2973, segments 3145) — a hidden coupling: the gate's
  correctness depends on every decoder keeping its ordering refusal.
- **Determinism:** no `HashMap` iteration in any encode path in-region; the
  only `HashMap` (3869) is a lookup memo. All owners sorted upstream
  (interp.rs:9775, 9823, 9830, 10464). No f64 formatting/parsing; Date/RegExp
  values travel as raw bits (267–270, 260). No host time/locale.
- **Chunk (BLOC) contents are trusted at the gate.** `check()` validates that a
  payload OFFSET lies in `[4, chunk_len]` (3538) but never reads the 4-byte
  little-endian length header the offset points at. `ChunkArena::payload` →
  `len_of` → `view(start, start+len)` (value.rs:1496–1519, 1414–1416) slices
  the raw `Vec`; `compact` explicitly asserts and panics on a bad length
  (value.rs:1572–1586, "record-content corruption is not validated at open —
  the design's named limitation").
- **Free-record opacity vs live edges.** The gate skips free heap records
  entirely (3546–3548) but `check()` for LIVE slots and side-table values tests
  only `r.0 >= slot_count`, never `is_free` (3528). `SlotArena::mark`
  (value.rs:901–912) and gc.rs:137–140 trace whatever a marked slot references,
  with no free check. So a crafted live→free→out-of-arena chain passes.
- **Validation CPU is not linear in container size.** Function bodies are
  walked per function row (3686–3693) and nested-body subtraction runs
  `set.retain` once per contained function (3949–3964); nothing requires bodies
  within a segment to be disjoint or laminar, or unique. `regexp_source_compiles`
  (3631) runs the full regexp compiler per row at validation time.
- **Owner KIND is not checked.** `owned()` proves range and non-free only; a side
  table row can name a live slot of any kind (a String slot as an ARRY owner).
  `restore_bulk_side_tables` inserts unconditionally (interp.rs:10531–10537).
  Consumers I opened degrade gracefully (`arrays.get(..).unwrap_or(0)`,
  interp.rs:32672), so I could not demonstrate a crash; it is a silent-state seam.
- **Version read range is wide (1..=12) with one set of decoders.** Only the
  unconditional-atoms gate is version-conditional (4688). Older stamps get the
  "absent METR = zero meter" leniency (4440–4443), so a downgraded stamp is a
  legal way to produce a non-canonical container that validates.
- **Meter versioning is split across crates.** `COST_TABLE_VERSION = "ironhorse-meter-1"`
  (vm/meter.rs:26) is what METR carries; `PARSE_METER_RELEASE = "ironhorse-meter-0"`
  (compile/meter.rs:22) is a second, independently numbered table that is not
  carried in the image and not compared at resume.
- **Error-handling shape:** uniform `SnapshotError::Corrupt(&'static str)` with
  a distinct message per refusal — good for tests and triage; the variant
  carries no offset/atom context for operators (a `SnapshotError::Corrupt`
  from a 50 MB store says which rule, not where).

## Candidate findings (most architecturally significant first)

1. **Live edge into a free record bypasses the bounds gate; the collector then
   walks the free record's unchecked stale payload (release panic class the
   gate exists to close).** `image.rs:3528` — evidence:
   `s.each_ref_slot(|r| bad |= !r.is_null() && r.0 >= slot_count);` (3528) /
   `if is_free(i as u32) { continue; // opaque …` (3546–3547) /
   `if self.marks[i] { false } else { self.marks[i] = true; true }` (value.rs:906–909).
   Claim: a 4-slot image with slot 0 = `Reference(2)`, slot 2 free with stale
   `Reference(9)`, passes `check_image_slot_bounds` and `read_validated_machine`,
   and the first collection marking slot 0 indexes `marks[9]` out of bounds.
   Why: refusing live→free edges is honest-safe by construction (the sweep frees
   only unmarked records and every edge of a marked record is marked), so the
   fix is one predicate: `r.0 >= slot_count || is_free(r.0)` in `check()`, applied
   to heap/stack/side-table values. Also closes the aliasing case (a live edge
   to a free slot that `alloc` later hands out). Confidence: high on the gate
   hole (code read end to end); high on the panic path (gc.rs:137–140 traces
   the free record; no `is_free` in gc.rs). Not in the design's open ledger.
   Category: robustness. Severity: high (crashed crank on crafted image, a
   regression of the wave-4/5 stated invariant — not memory unsafety).

2. **Validation time is superlinear in container size: per-row body walks and
   per-contained-function `retain` with no laminar/uniqueness requirement on
   bodies.** `image.rs:3686` — evidence:
   `while pc < end { let Some(len) = ironhorse_vm::instruction_len(code, pc) …` (3686–3693) /
   `for other in &lang.function_state.functions { … set.retain(|&pc| pc < start || pc >= end);` (3949–3963).
   Claim: F function rows each declaring `body_start=0, body_len=B` over one
   B-byte segment of 1-byte instructions validate in Θ(F·B) time (and a
   generator row naming one of them adds another Θ(F·B) in the retain loop);
   nothing refuses overlapping or duplicate bodies. Why: an untrusted image
   can pin a validator for minutes to hours with a few MB; a single per-segment
   tiling walk (O(B)) plus O(F log F) laminar/duplicate check on sorted body
   ranges gives the same guarantees linearly. Confidence: high on complexity;
   medium on operational impact (no container size cap found in the crate).
   Category: performance (DoS on untrusted input). Severity: medium.

3. **BLOC block lengths are never validated; the gate proves offsets only, so a
   corrupt 4-byte length header still panics at first string read or at
   compaction (the "design's named limitation", still open).** `image.rs:3538` —
   evidence: `if o < CHUNK_HEADER || o > chunk_len { return Err(OOC); }` (3538–3540) /
   `assert!(end <= total, "chunk payload out of range (corrupt heap)");` (value.rs:1586) /
   `ChunkSlice::Plain(&v[start..end])` (value.rs:1416).
   Claim: a container whose live String slot points at offset 8 while BLOC bytes
   4..8 encode length 0xFFFF_FFFF passes `read_validated_machine` and panics on
   `payload()`/`compact`. Why: the gate's own doc says it exists to prevent "the
   two asserts `ChunkArena::compact` would otherwise hit" (3536–3537) but checks
   half the precondition; a one-pass walk over the arena's header chain (or
   `len_of` per referenced offset with `checked_add ≤ chunk_len`) would close it.
   Attribution: acknowledged in value.rs:1563–1564 as a known limitation; not
   in the store-seam open ledger. Confidence: high. Category: robustness.
   Severity: medium.

4. **Two independently versioned meter tables, one gated: METR carries the vm's
   `ironhorse-meter-1` but the compiler's parse meter is stamped
   `ironhorse-meter-0` and neither travels nor is compared.** `image.rs:4444` —
   evidence: `if meter.cost_table_version != COST_TABLE_VERSION {` (4444) /
   `pub const COST_TABLE_VERSION: &str = "ironhorse-meter-1";` (vm/meter.rs:26) /
   `pub const PARSE_METER_RELEASE: &str = "ironhorse-meter-0";` (compile/meter.rs:22).
   Claim: recalibrating parse-unit weights (a `PARSE_METER_RELEASE` bump) without
   bumping `COST_TABLE_VERSION` is not refused by `read_machine`, so a machine
   suspended under one parse meter resumes and compiles later cranks under
   another with an unchanged METR. Why: the design (§ Metering) makes "every
   recalibration is a meter-version bump … never a silent change" the consensus
   property; a split version space with a single gate is the shape that lets a
   silent change through. Confidence: medium (I did not trace whether parse
   metering feeds the same accumulator the METR restores; the design's table
   lists "Parse unit" as a metered event). Category: metering. Severity: medium.

5. **The validation surface grows by positional accretion with no derived
   registry; a new `MachineImage` field is not forced through the gate.**
   `image.rs:3477` — evidence: `#[allow(clippy::too_many_arguments)] pub(crate) fn check_image_slot_bounds(` (3477–3478) /
   `pub(crate) struct LangRows<'a> { … 14 fields … }` (3317–3332) /
   `fn restore_side_tables( … 22 params …)` (machine.rs:432–456).
   Claim: adding a side table requires ≥9 coordinated edits across format.rs,
   image.rs (struct, writer, reader, gate, `LangRows`, `EMPTY`), store.rs,
   machine.rs, interp.rs, and sidetable.rs, and no test derives coverage from
   `MachineImage`'s fields (the vm has `gc_visitation_registry.rs` for roots;
   nothing equivalent here). Why: this is the mechanism by which "a side table
   missing from the ledger" bugs recur; the fix is a single table-of-tables
   (tag, field, encode, decode, gate, restore) iterated by all six sites, plus a
   field-count lock. Confidence: high on the shape; the absence of a registry
   test is by grep. Category: modularity. Severity: medium.

6. **`owned()` proves range and non-free but not KIND or reachability, so exotic
   state can be attached to a slot of the wrong kind.** `image.rs:3517` —
   evidence: `let owned = |o: u32| -> Result<(), SnapshotError> { if o >= slot_count {…} if is_free(o) {…} Ok(()) };` (3517–3525) /
   `self.arrays.insert(crate::value::SlotIndex(owner), a);` (interp.rs:10537).
   Claim: an ARRY row whose owner is a live `Kind::String` slot validates and
   restores. Why: consumers I opened tolerate it (`arrays.get(..).unwrap_or(0)`,
   interp.rs:32672), so today it is silent state rather than a crash, but it is
   an un-stated seam every future consumer must remember. Confidence: high on
   the gap; low on exploitability. Category: robustness. Severity: low.

7. **Version-downgrade escape from the canonical-form gates.** `image.rs:4688` —
   evidence: `if version.format_version == crate::format::IRONHORSE_FORMAT_VERSION {` (4688) /
   `None => MeterImage::current(),` (4442) /
   `pub const IRONHORSE_FORMAT_VERSION_MIN_READ: u32 = 1;` (format.rs:205).
   Claim: a container stamped format 11 that omits METR (and any fixed atom
   except VERS/SIGN/HEAP) is accepted with a zeroed meter, decoded by v12
   decoders, and re-writes as a different (v12) byte string. Why: the
   canonical-bytes/CAS-identity property is deliberately claimed of current
   containers only (4685), but a 12-version read range with one decoder set
   and no per-version fixtures beyond v5 store migration (migration.rs) is
   more leniency than any honest writer needs; tightening MIN_READ or making
   the leniencies explicit per version would shrink the crafted-input surface.
   Confidence: high on behavior; low on severity. Category: determinism.
   Severity: low.

8. **Regexp recompilation at validation time runs an unmetered compiler over
   untrusted patterns.** `image.rs:3631` — evidence:
   `if !ironhorse_vm::regexp_source_compiles(&r.source, &r.flags) {` (3631).
   Claim: validation cost includes a full regexp compile per REGX row with no
   size bound other than the container. Why: same DoS class as candidate 2,
   different engine; the check is correct (a non-compiling row must be
   refused) but could be bounded by a pattern-length cap or deferred to
   restore where the machine's own limits apply. Confidence: medium (I did not
   audit the regexp compiler's worst case). Category: performance. Severity: low.

9. **Invariant ownership is spread over three layers with no statement of which
   layer is authoritative.** `image.rs:3286` — evidence:
   `// Self-contained cursor sanity; the cross-table checks … run in the bounds gate` (3286–3289) /

## What is done well

- **A single shared gate and shared decoders for both persistence paths**
  (store.rs:1452–1656, 2975, 3317): the class of "the store path forgot a
  check" is structurally closed, and the design ledger records that this was
  learned the hard way (wave 5).
- **Fail-closed, structured refusals everywhere in-region**: no `unwrap`/index on
  untrusted bytes; `Cursor` uses `checked_add` and exact-consumption `done()`;
  every `Vec::with_capacity` is clamped to what the payload could hold
  (over-allocation trophies 5705–5885 lock it).
- **Canonical-form discipline is enforced on read, not just write**: unordered
  or duplicate rows, present-but-empty atoms, explicit full `NFLR`, foreign or
  out-of-order tags, and the non-canonical empty SYMB are all refused, so the
  SHA-256 CAS key really is an identity for current containers.
- **Cross-table geometry is checked where all tables are in hand**: views vs
  buffer rows (3579–3621), generator PCs vs the owning body's instruction
  starts with nested bodies subtracted (3916–3967), combinator/reaction indices
  (4042–4090), cursors vs covering rows (4125–4162).
- **Free-record hygiene is reasoned from the collector's actual behavior**
  (3499–3509) with both halves tested (5329–5361 and `free_record_hygiene.rs`),
  which is exactly the kind of reasoning candidate 1 extends.
- **The tests read as an audit log**: each refusal names the wave/review that
  motivated it and the shape a reviewer actually crafted (e.g. 5255–5317),
  which makes regressions attributable.
