## Purpose and responsibilities

`image.rs` is the plain-data model of a suspended machine (`MachineImage`) plus the
per-atom byte codecs. Lines 1–3000 hold: the `METR` meter image (35–112), `CREA`
creation params (114–139), the twelve side-table row image types (141–332), the
36-field `MachineImage` (334–409) and its `ValidatedSnapshot` proof wrapper
(411–437), the `from_arenas` constructor and 14 `with_*` builders (443–673), the
string/u32/heap primitives (686–831), a bounds-checked `Cursor` (838–896), and the
`encode_*/decode_*` pair for every ledger atom: `ARRY` `COLL` `SYMB` `REGY` `ERRD`
`ESTK` `ABUF` `TARR` `DVIW` `WRAP` `REGX` `DATE` `FUNC` `PROX` `ACCS` `IBFN` `PRIV`
`DISP` `GENR` `PRMS` `ARGB` `TMPR` `INTL` (898–2999+). The container assembly
(`write_machine` 4210, `read_machine` 4353) and the semantic bounds walk
(`check_image_slot_bounds` 3478) are in the sibling region but are the only callers
of everything here.

Architectural shape: a hand-rolled big-endian TLV codec, one function pair per table,
each decoder a `Cursor` walk that (a) clamps every pre-reservation to what the payload
could hold, (b) enforces strictly-ascending owners so the encoding is canonical, (c)
range-checks enum bytes, and (d) demands exact consumption via `Cursor::done()`.
Decoders construct `ironhorse_vm` row structs directly; the VM then re-validates on
`restore_*` and returns `bool` (machine.rs 514–581).

## Invariants and contracts claimed — and whether the code upholds them

1. **"A resume whose cost-table version differs fails closed" (35–40).** Upheld:
   `read_machine` compares to `COST_TABLE_VERSION` (4444–4449); store path mirrors
   (store.rs 2011, 2860, 3151). Note the gate covers only the VM table
   (`"ironhorse-meter-1"`, meter.rs 26); the compiler's parse meter is versioned
   separately as `"ironhorse-meter-0"` (ironhorse-compile tests
   parse_meter_determinism.rs 45) and is not carried.
2. **"Exact consumption: tolerated trailing bytes would defeat the store decoders'
   fail-closed rule" (96–98, METR).** Upheld for METR; **violated** by the sibling
   primitives the same store path uses: `decode_strings` (697–733), `decode_u32s`
   (744–763), `decode_stack` (4186–4203), `decode_heap` (807), `CreationParams::decode`
   (131), `Version::decode` (format.rs 251) all accept trailing slack.
3. **"One logical machine must have exactly one container encoding, or its SHA-256
   CAS key is not an identity" (format.rs 157–160; image.rs 939, 4341–4345,
   4626–4635).** Enforced at the atom envelope (atom.rs 138–148), atom order
   (4374–4387), optional-atom presence (4346–4351), NFLR canonical form (4631–4635),
   and every side-table decoder via `done()`. **Not** enforced for the six core atoms
   above, nor for slot records (slot_codec.rs 103–134 ignores byte 9 and unused
   payload bytes, and accepts any non-zero byte as `true`). The fuzz invariance arm
   checks `write(read(bytes)) == bytes` only for writer-produced `bytes`
   (ironhorse-fuzz/src/snapshot.rs 1229–1232); mutated inputs are checked only for
   no-panic (1246–1258), so this gap is invisible to it.
4. **"Every slot index and chunk offset the container carries must fall inside the
   decoded arenas, or the collector would index them out of range in release"
   (4640–4644; 3401–3403).** Upheld for indices and offsets. Not upheld for chunk
   *contents*: header lengths are unchecked, and `ChunkArena::compact` asserts on
   them (value.rs 1572–1586, "record-content corruption is not validated at open —
   the design's named limitation"). `ABUF` extents are checked (3587–3592) but
   `String`/`BigInt` chunk extents are not.
5. **"Strictly-ascending owners → import∘export idempotent" (983–992 and siblings).**
   Upheld consistently across all 24 side-table decoders.
6. **"Clamp pre-reservation so a malformed count cannot reserve gigabytes"
   (702–708 and siblings).** Upheld everywhere I checked; every `with_capacity` is
   `count.min(p.len()/k)`.
7. **"`checked_add`/`checked_mul` where an attacker-sized length meets `i`"
   (716–723, 798–806, 873–878).** Upheld except `MeterImage::decode` line 99
   (`28 + vlen`), a debug-profile panic on 32-bit for `vlen ≥ usize::MAX-27`.
8. **`ValidatedSnapshot` "callers cannot mutate validated state and then pass it to
   restore" (411–417).** Upheld: constructor is `pub(crate)`, `image_to_interp` takes
   the wrapper, `from_snapshot_bytes` routes through `read_validated_machine`
   (machine.rs 692–693).
9. **`with_side_tables`/`with_language_rows` "already in canonical order" (549–552,
   569–572).** A precondition on the caller, not checked; the VM sorts
   (`symbol_registry_snapshot` 10505–10513, `arguments_brands_snapshot` 9174–9178).
10. **Module doc "coverage today … ARRY/COLL/REGY; the ones marked Pending are the
    remaining atoms" (14–21) and `write_machine` doc "canonical order VERS…METR with
    METR last" (4205–4209).** Stale: 24 optional atoms follow METR. Pending ledger
    rows today are `AsyncInstances`, `AsyncGenerators`, `Modules` (sidetable.rs 558,
    568, 586), refused at the persist gate.

## Architectural observations

- **Coupling / monolith symptom.** The wire format's meaning is defined by row structs
  living inside interp.rs; decoders build them field-by-field (1716–1728, 2234–2242,
  2414–2422). There is no format-owned schema module and no compile-time link between
  a row struct's shape and `IRONHORSE_FORMAT_VERSION` (format.rs 197): a VM field
  added to `FunctionRow` forces a wire change that only a human remembers to version.
- **Duplication.** Two container grammars over the same encoders: atoms
  (`write_machine` 4210–4329, present-only-when-non-empty, refuses present-but-empty)
  and store sections (store.rs 1405–1428, zero-length section accepted as empty). Each
  new table is wired twice with two different canonicality rules.
- **Uneven validation discipline.** Three layers (byte decoders here; the bounds /
  cross-reference walk 3478–4178; VM `restore_*` bools) with the same invariant
  sometimes enforced twice (collection kind: 1028 and interp.rs 10540; typed-array
  kind: 1433 and 3597) and some semantic invariants enforced nowhere (Map/Set key
  uniqueness — `push_entry` appends blindly, bulk.rs 306–310; weak-collection keys
  being objects; registry key bytes being even-length UTF-16; regexp flag validity
  deferred to recompile). The promise cluster gets a 270-line cross-validation while
  collections get geometry-only.
- **Canonical-encoding discipline is split by age.** Everything added in waves 4–6
  uses `Cursor::done()`; the stage-6 core atoms (VERS, CREA, HEAP, STAC, KEYS, NAME)
  and the slot record codec predate the rule and were never brought under it.
- **Hidden state / order dependence.** `with_name_floor` canonicalizes against
  `self.names.len()` (671); `from_arenas` sets `names` first so it works today, but
  the builder chain has an undocumented ordering requirement.
- **Panics / unwraps on untrusted data.** None reachable in the assigned range:
  `try_into().unwrap()` at 92–94, 852, 860 follow explicit length gates; the single
  `unreachable!` (1626) is encoder-side on trusted state. `SlotArena::from_image`
  indexes `free_marks[i]` (value.rs 1045) but `decode_heap` (819–825) guards it.
- **Determinism.** No `HashMap`/`HashSet` in the range; `BTreeMap/BTreeSet` only
  (512, 1133, 2479, 2546, 2993). f64 travels as raw bits (`to_bits`/`from_bits`,
  slot_codec.rs 78, 125) — NaN payloads preserved. No time/locale/platform calls.
  The only 32-bit hazard left is line 99.
- **Versioning.** Read range `1..=12` (format.rs 197, 205). Every bump so far added an
  atom, never widened a row (1300–1306 explains why). Leniencies for old versions
  (absent METR → zeroed meter, absent CREA/STAC/KEYS/NAME/SYMB, legacy 4-zero SYMB)
  stay accepted; the "missing atom its version always writes" gate (4688–4696)
  closes them only for version 12. format.rs 341–344 says the branch is unreleased
  and every container regenerated, so this legacy grammar has no consumer.
- **Signature scope.** `Signature` is an opaque string compared for equality
  (format.rs 371–373); its doc (319–345) says it *must* also cover the boot-derived
  slot layout but that this is deferred to release as a process rule.
- **Metering doctrine.** METR carries the VM cost-table id and fails closed on drift
  (design row 6 honored). The parse meter is a second, independently numbered string
  (`ironhorse-meter-0`) not carried in METR.
- **Error model.** `SnapshotError::Corrupt(&'static str)`; a `Cursor` collapses every
  failure inside one decoder to one message (`what`), so diagnosability inside a
  table is coarse but deterministic. `present_and_non_empty` messages are per-atom.
- **Performance.** `decode_registry` descriptor uniqueness is O(n²) (documented,
  1196–1197); ESTK join in `read_machine` is O(errors × frames-rows) (4483–4490);
  `stored_unregistered_key_id` builds a `BTreeSet` of the whole free list (512). All
  acceptable at current scales; none is on a hot path.
- **API boundary.** `read_machine` is `pub` and returns a fully mutable `MachineImage`
  (all fields `pub`); adoption is fenced by `ValidatedSnapshot`. `encode_*/decode_*`
  are `pub(crate)`; `first_stored_unregistered_id` / `runtime_intern_floor` are `pub`.

## Candidate findings (most architecturally significant first)

1. **Core atoms accept non-canonical trailing slack** — image.rs:697 (also 744, 778,
   4186; format.rs:131/251).
   Claim: a container whose KEYS/NAME/HEAP/STAC/CREA/VERS payload carries extra bytes
   after its declared content decodes successfully and re-encodes to different bytes,
   so `write_machine(read_machine(b)) != b` for an accepted `b`.
   Evidence: `decode_strings` loop ends `Ok(out)` with no `i == p.len()` check
   (731–732); `decode_heap`: `if p.len() - i < want { return Err(...) }` (807);
   `CreationParams::decode`: `if p.len() < 8 { return Err(...) }` (131).
   Why: the crate's stated identity rule (format.rs 157–160) and the CAS key rest on
   one encoding per machine; the side-table decoders enforce it via `Cursor::done()`
   but the six oldest atoms and the store's free-list/keys/names sections
   (store.rs 1449–1451) do not. The fuzz invariance arm never checks identity on
   mutated inputs (fuzz snapshot.rs 1246–1258). Confidence: high (from reading).

2. **Slot record codec accepts kind/payload disagreement and non-zero reserved bytes**
   — slot_codec.rs:103 (consumed via image.rs:829, 886–889).
   Claim: `decode_slot` returns `Ok` for a record whose `kind` byte and payload tag
   name different arms (e.g. `Kind::Reference` + `P_INT`) and ignores byte 9 and
   unused payload bytes, so crafted records both re-encode differently and pass the
   payload-keyed bounds walk.
   Evidence: `let kind = Kind::from_u8(rec[0])…; let value = decode_payload(rec[8],
   &rec[10..20])?;` (105–109) with no agreement check; `P_BOOL => Payload::Boolean(d[0]
   != 0)` (123); `each_ref_slot`/`chunk_ref` match on `self.value` only
   (value.rs 375–390).
   Why: the HEAP atom is the largest untrusted surface; a kind/payload-mismatched slot
   reaches the VM as a "String" with no chunk or a "Reference" with no index, which
   the interpreter's `match` arms did not anticipate (a deterministic panic at best).
   Confidence: high that it decodes; medium on downstream effect.

3. **BLOC chunk contents are not validated; the bounds walk checks offsets only** —
   image.rs:3532 (context for 4640–4644; value.rs:1561–1586).
   Claim: a container with a live `String`/`BigInt` slot whose chunk header declares a
   length past the arena passes `read_machine` and panics at the first string access
   or `collect_garbage`.
   Evidence: `if o < CHUNK_HEADER || o > chunk_len { return Err(OOC); }` (3538) — no
   read of the header at `o-4`; `assert!(end <= total, "chunk payload out of range
   (corrupt heap)")` (value.rs 1586); ABUF *does* check `data + length <= chunk_len`
   (3589).
   Why: the reader's own doc claims to be "the SEMANTIC gate … a RELEASE panic on the
   first collect_garbage" (3401–3403); the VM calls the gap "the design's named
   limitation". A crashed crank is doctrine-acceptable, but the restore path is
   supposed to fail closed with a structured error, and the check is cheap (one header
   read per referenced chunk, as ABUF already does). Confidence: high.

4. **Wire schema is defined by interp.rs row structs with no versioning tie** —
   image.rs:1716 (also 2234, 2414; format.rs:197).
   Claim: adding, removing, or reordering a field in any `ironhorse_vm::*Row` struct
   changes the on-disk format without any compile-time or test-time forcing of an
   `IRONHORSE_FORMAT_VERSION` bump.
   Evidence: `functions.push(ironhorse_vm::FunctionRow { owner, segment, body_start,
   body_len, closures, name, arity, name_chunk, is_generator, home, class_derived })`
   (1716–1728); `ironhorse_vm::interp::MAP_MIN_TABLE_LENGTH` (1066).
   Why: the format crate "owns the format" (module doc 11–12) yet its vocabulary lives
   in a 45k-line file it does not control; the twelve past bumps were remembered by
   hand. Category: modularity. Confidence: high.

5. **Two container grammars with divergent emptiness rules** — image.rs:4346
   (store.rs:1455–1477).
   Claim: the same table encoders are framed once as optional atoms (present ⇒
   non-empty, else `Corrupt`) and once as fixed store sections (zero-length ⇒ empty
   table), so canonical form differs between the two persistence paths and every new
   table must be wired in both.
   Evidence: `fn present_and_non_empty… if rows.is_empty() { return Err(...) }`
   (4346–4351) vs store.rs `let arrays = if arrays_bytes.is_empty() { Vec::new() } else
   { decode_arrays(...) }` (1461–1465).
   Why: duplication of a 30-item ledger across two hand-maintained lists is the same
   bug class the `SideTable` ledger exists to prevent. Confidence: high.

6. **Unregistered-property-id audit covers 4 of ~15 slot-bearing tables** —
   image.rs:510.
   Claim: a stored key id absent from NAME/SYMB inside a wrapper value, bound-function
   arg, accessor, private value, disposable record, generator local/arg/stack slot, or
   promise result/reaction slot is not refused by `read_validated_machine`.
   Evidence: `first_stored_unregistered_id(live.chain(self.stack.iter()) …)` then
   `.or_else(arrays…)` `.or_else(collections…)` (519–535) and nothing else;
   `stored_key_id` recognizes `Payload::At` ids, which the VM doc says can be live
   across a suspend (value.rs 408–413).
   Why: the audit's rationale — "an unregistered id maps to nothing on resume"
   (497–500) — applies equally to a generator `stack_slice` `At` slot; the wave-5
   widening of the bounds walk to all tables was not mirrored here. Confidence:
   medium (gap certain; exploit path to a wrong lookup not traced).

7. **Collections: no key-uniqueness or weak-key gate; restore appends blindly** —
   image.rs:1021 (bulk.rs:306).
   Claim: a `COLL` row with two entries whose keys are SameValueZero-equal (or a
   WeakMap entry with a primitive key) decodes, restores, and yields a Map/Set whose
   `size`, iteration and `get` disagree, with no error.
   Evidence: the loop reads `let key = c.slot()?; let value = c.slot()?;
   entries.push((key, value));` (1035–1037) with only geometry checks after;
   `pub(crate) fn push_entry(… ) { … self.entries.push(Some((key, value))); }`
   (bulk.rs 306–310).
   Why: the decoder went to the trouble of proving XS's rehash geometry (1045–1079)
   yet not the one invariant every Map consumer relies on. Confidence: high.

8. **A 12-version read range is retained on an unreleased branch** — format.rs:205
   (image.rs:4440, 4688).
   Claim: eleven legacy container shapes (absent METR/CREA/STAC/KEYS/NAME/SYMB, the
   4-zero SYMB) remain accepted from untrusted bytes although no shipped writer ever
   produced them.
   Evidence: `pub const IRONHORSE_FORMAT_VERSION_MIN_READ: u32 = 1;` (205); "While
   this branch is unreleased and every container is regenerated" (format.rs 341–342);
   `None => MeterImage::current()` (4442).
   Why: each leniency is a second encoding and extra decoder surface; the "missing
   atom" gate only closes them for version 12 (4688). Raising MIN_READ to the release
   version at release shrinks the grammar for free. Confidence: high.

9. **Property keys travel as UTF-8 `String` because the VM interns keys lossily** —
   image.rs:351 (interp.rs:10891, 14869).
   Claim: `KEYS`/`NAME` cannot represent a lone-surrogate property name, and the VM
   produces such names via `from_utf16_lossy`, so `o["\uD800"]` and `o["�"]` alias
   before any snapshot; fixing the VM later is a wire-format change.
   Evidence: `pub keys: Vec<String>` (351); `fn str_text(&self, off) -> String {
   String::from_utf16_lossy(&self.str_units(off)) }` (10891–10892);
   `let s = self.str_text(off); self.intern_key(&s)` (14869–14870).
   Why: result parity with XS is the acceptance bar; this is a cross-region VM
   semantics hazard that the snapshot schema bakes in. Owner: interp reader.
   Confidence: high that the aliasing exists; medium on its observability in test262.

10. **METR carries only the VM cost-table version** — image.rs:54 (meter.rs:26).
    Claim: a parse-meter recalibration (`PARSE_METER_RELEASE`, `"ironhorse-meter-0"`)
    does not change what a resumed machine's METR gate compares, so a resumed machine
    that later `eval`s meters parse cost under a table the snapshot never recorded.
    Evidence: `cost_table_version: COST_TABLE_VERSION.to_string()` (54);
    `pub const COST_TABLE_VERSION: &str = "ironhorse-meter-1";` (meter.rs 26);
    `PARSE_METER_RELEASE, "ironhorse-meter-0"` (compile tests
    parse_meter_determinism.rs 45).
    Why: the design describes one `ironhorse-meter-N`; two independently numbered
    strings mean the METR gate is not the whole meter's identity. Confidence: high on
    the split; low on practical impact today.

11. **`with_name_floor` depends on builder order** — image.rs:670.
    Claim: calling `with_name_floor` before `names` is populated stores a spurious
    `Some(floor)`.
    Evidence: `self.name_floor = (floor as usize != self.names.len()).then_some(floor);`
    (671).
    Why: `from_arenas` happens to set `names` first, so this is latent; the 14
    `with_*` builders otherwise commute, and a hidden ordering rule on a 36-field
    struct is a maintenance trap. Confidence: high.

12. **`MeterImage::decode` uses an unchecked add where siblings use `checked_add`** —
    image.rs:99.
    Claim: on a 32-bit target with a `vlen ≥ usize::MAX-27`, `28 + vlen` overflows
    (debug panic; release wrap that still fails the equality).
    Evidence: `if 28 + vlen != p.len() { return Err(...) }` (99) vs `let end =
    i.checked_add(len).ok_or(...)` (721–723).
    Why: the wave-3 32-bit discipline is claimed file-wide (716–720). Low severity.

13. **`Signature` covers only the callback table, not the boot slot layout it says it
    must** — format.rs:329 (relied on by image.rs:4361).
    Claim: two builds with the same signature string but different `create_intrinsics`
    slot layouts accept each other's containers and attach this build's boot metadata
    to unrelated slots.

## What is done well

- The decoder discipline for attacker-sized counts is thorough and uniform: every
  `Vec::with_capacity` is clamped to what the payload can hold (702–708 and ~40
  siblings), every entry length goes through `checked_add`, and the two record-array
  gates use `checked_mul` (804, 4196). No panic on malformed input is reachable in
  the range I read.
- Canonical-encoding enforcement on the side tables (strictly ascending owners,
  refused non-canonical option/boolean bytes, `done()` exact consumption, refused
  present-but-empty atoms) is consistent across 24 tables and is explained in place
  with the concrete failure each rule prevents.
- `decode_promise_cluster` (2345–2635) is a model of cross-row validation: dense
  arenas, paired guards, capability pairing, and `remaining ≥ pending`, each with a
  stated resume-time consequence.
- `ValidatedSnapshot` (411–437) plus `pub(crate) from_validated_image` and
  `image_to_interp(ValidatedSnapshot)` make "validated before restore" a type-level
  property rather than a convention.
- Determinism hygiene: `BTreeMap/BTreeSet` only, f64 as raw bits, no host calls; the
  registry and brand snapshots on the VM side are explicitly sorted before encoding.
- Review lineage is legible: each gate cites the wave or fuzz trophy that motivated
  it, which made this audit's "what is still true" question answerable.
