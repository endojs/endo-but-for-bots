## Architectural observations

- Ledger drift within the ledger's own lifetime: two "not fixed" entries (P2-5, P3-2) are fixed in the tree; the phase-5 "still open" interior tree is closed; the P2-3 residue is closed by P1-5. The doc is the branch's memory, and its open set is scattered across ~8 sections with 6 different markers. A reviewer must grep the tree, not trust the ledger, for anything under two weeks old.
- The persist gate applied "traverse, don't enumerate" only halfway: `non_persisting_functions` is a precise set (interp.rs:8850), but the walk over holders is still a hand-maintained list (interp.rs:8745–8803, "Kept in the ledger's order so a new carried row is easy to slot in") — the next carried row (async instances) needs a manual addition, and unlike GC visitation there is no source-parsing net that fails when a Slot-bearing field is added but not walked here. The sibling audit `stored_unregistered_key_id` has a DIFFERENT, shorter list (image.rs:519–535).
- 32-bit fail-closed discipline is inconsistently applied: `decode_heap`/`decode_stack`/`decode_strings`/chunk validation carry `checked_*` (image.rs:4191–4198, 716–723), the small-state decoders do not (store.rs:1441, 1951). Low practical exposure (64-bit hosts) but exactly the inconsistency the ledger flagged three times.
- Metering doctrine drift (design level): the seam's bars are XS-exact computrons; deviations are recorded as defects (L11). Under the parent design's doctrine these are calibration questions, not correctness gaps. Either the doctrine or the bars should say so.
- Determinism is per-platform (libm), while the parent design and consensus story promise per-release across hosts.
- Dead API: `has_pending_jobs` is private and `#[allow(dead_code)]` (interp.rs:21449) while its doc says the daemon pump loop queries it; the embedding cannot call it. The real daemon seam (`PersistentMachine`) rewinds halts instead.
- Engine defects the ledger exposed but did not fix (L1, L4, L17) are program-dependent semantics: `to_primitive` resolves `toString`/`valueOf` through the crank's `symbol_ids` (interp.rs:38834) rather than a machine-global key table — the same class the ERRD carry diagnosed for error own-properties (doc:1721–1728). Fixing them piecemeal (force-interning names) treats symptoms.
- The design doc's own line cites to code are stale by construction (they pin an old head); the doc says so (doc:2227) but only for wave 6.
- Determinism hazards in this region: none new found; all HashMap iterations spot-checked are sorted or boolean-consumed.

## Candidate findings — most architecturally significant first

1. **Per-platform determinism via libm contradicts the parent design's "every host, architecture, and build" claim** — interp.rs:29829–29843 vs designs/ironhorse-engine.md:373–375. Claim: a heterogeneous validator fleet (glibc vs musl) can diverge in the last ulp of `Math.sin` et al. and therefore in results and computrons. Evidence: "determinism is scoped PER RELEASE BINARY PER PLATFORM … Heterogeneous-fleet consensus needs a vendored deterministic libm" (interp.rs:29833–29837). Why: consensus-critical property; recorded as W6-23 DECIDED (doc:2723) but the parent design still states the stronger claim. Attributed; still open. Confidence: high (both texts read).
2. **The seam's metering bars are XS-exact computrons, against the accuracy-over-parity doctrine** — doc:1953–1973 (async-generator −20/−26 pinned as a gap), doc:1180–1192, meter.rs:26. Claim: the branch's acceptance instrument for metering is oracle equality, so meter constants are XS-derived and any XS divergence is filed as a defect. Why: the doctrine (ironhorse-engine.md:363–367, DD5 :958) makes parity a non-goal; the ledger and README treat it as the bar, so the "release-versioned own cost table" is nominal. Attributed (census flagged); design-level. Confidence: high.
3. **Two stored-reference audits with divergent, hand-enumerated traversals; no mechanical net** — image.rs:510–536 vs interp.rs:8745–8820. Claim: a Slot-bearing side table added tomorrow can be missed by `stored_unregistered_key_id` (already misses private elements, bound `this_arg`/`args`, generator frames, disposable records, promises, proxies) and by the persist gate's holder list, with nothing failing at build time. Evidence: image.rs:519–535 chains only `live`, `stack`, `arrays`, `collections`; interp.rs:8743–8744 "Kept in the ledger's order so a new carried row is easy to slot in". Why: this is the exact "enumeration keeping up with the engine" failure class the wave-6 meta-cause named (doc:2581–2591). Attributed (P1-4 residue, doc:3344–3350); still open. Confidence: high.
4. **Three Pending rows make any worker retaining a suspended `await`, an async generator, or a module graph un-checkpointable** — sidetable.rs:558/568/586; interp.rs:8656–8686. Claim: `checkpoint_to_store` refuses by name whenever a live promise carries an `AsyncAwait`/`AsyncGenerator*`/`FromAsync*` reaction. Evidence: `return Some("a promise reaction that would resume a non-persisted async frame")` (interp.rs:8667). Why: the daemon's real workloads (CapTP, async vats) are await-heavy; fail-closed is correct but the product surface is narrow. Attributed (open workstream). Confidence: high.
5. **Cross-crank `.call` on a guest function throws on a CONTINUOUS machine** — store_suite.rs:398–401; doc:3153–3160. Claim: `f.call(o, 1)` where `f` was defined in a prior crank throws `TypeError` with no store involved. Evidence: "a cross-crank `.call` on a guest function is a defect this branch tracks separately (it throws in the UNINTERRUPTED baseline too)". Why: a live-engine semantic bug in `Function.prototype.call` across crank boundaries; the determinism suite deliberately avoids it. Attributed (P2-2 open); not run. Confidence: medium (comment-level evidence).

## What is done well

- Mechanical reconciliation nets: the ledger-vs-`Interp`-struct test (sidetable.rs:896 parses the source) and the GC visitation registry force a classification for every slot-bearing field — the right answer to the wave-6 meta-cause, and they caught real omissions (`dates`, doc:2795–2799).
- The reader is genuinely fail-closed and canonical: VERS range, SIGN with boot layout, in-order atom grammar, present-and-non-empty on every optional atom, STAC-empty, symbol-counter/name-table check, METR gate (image.rs:4353–4449); `AtomError::TrailingBytes` at the envelope.
- The persist gate's cheap common path: the doomed set is computed first and is almost always empty (interp.rs:8696–8702); the O(dirty) checkpoint form carries a written induction argument (:8631–8639).
- Every recorded finding carries a reproduction, a named lock, and (since wave 4) a bite-check; refuted findings are kept on the record with counterexamples (doc:3527–3533).
- Determinism hazards fixed with explanatory comments at the site (compartment.rs:296–303) rather than silently.
- Deferrals are measured before being deferred (sparse attach, phase 12) and their re-run conditions are stated.
