## Purpose and responsibilities

This slice of the single `impl Interp` holds five loosely related bundles:

1. **RegExp surface tail** (21024–21092): `regexp_source_bytes` (the `.source` escaping
   XS's `fx_RegExp_prototype_get_source` applies), and `instance_put_raw` (an unmetered
   linked-slot insert for exec-result fields). `regexp_to_string` is the last function of
   the previous region (20985) and consumes `regexp_source_bytes`.
2. **Promise core** (21094–21616, 22499–22650): `.then`/`.catch` registration
   (`promise_then`, `promise_then_with`), native reactions (`promise_then_native`,
   `register_native_reaction`), resolving functions (`call_promise_function`), the settle
   path with thenable adoption (`settle_promise`, `adopt_thenable`), the FIFO job queue
   (`queue_promise_job[_n]`, `has_pending_jobs`, `run_promise_jobs`), and the drain
   dispatcher (`run_promise_job`, `run_thenable_job`, `run_finally_reaction`).
3. **Array.fromAsync native state machine** (21618–22497): a promise-driven state machine
   with no guest frame; state lives in `Interp::from_async: Vec<FromAsyncData>` and is
   resumed by `ReactionKind::FromAsync*` payloads at the drain. Also `call_any` /
   `call_any_catching_throw` (the general `Call(F, this, args)` used by the drain).
4. **Combinators** (22651–22976): `Promise.all/allSettled/race/any` over a dense Array or
   String iterable; per-element `ReactionKind::Combine(ci, ei)` reactions fold into
   `Interp::combinators[ci]`.
5. **Error construction, bind/call/apply trampolines, unmetered own-property helpers,
   disposable stacks, Temporal construction start** (22978–24530): `build_error`,
   `internal_error`, `build_suppressed_error`, `build_aggregate_error`,
   `new_aggregate_error`, `capture_error_frames`, `id_name`, `make_bound_function`,
   `box_primitive_to_instance`, `build_wrapper`, `set_own_unmetered[_with_flag]`,
   `set_own_accessor_unmetered`, `call_dot_call_native`, `call_dot_apply_native`,
   `enter_call_dot_call`, `enter_call_dot_apply`, `enter_call_bound`,
   `enter_construct_bound`, `error_to_string`, `value_to_string`,
   `explicit_resource_method` (DisposableStack/AsyncDisposableStack), and the first
   Temporal helpers (`temporal_bigint_to_i128` … `temporal_duration_span`).

## Architectural observations

- **Determinism of the drain is sound.** `VecDeque` FIFO, `Vec` reactions, `Vec` index
  arenas; no HashMap iteration influences job order. `gc_roots` sorts+dedups (43692). No host
  time/locale/f64 formatting in this range except `k as f64`/`len as f64` constructions and
  `to_number`/`trunc` (deterministic IEEE ops).
- **Result-parity divergences are the dominant defect class here, and they are silent, not
  "honest skips":** the native-promise adoption shortcut (21265–21285), the combinator
  species/subclass handling (22671–22685), the `finally` tick shape (22608–22649), the
  enumerable `errors` on `Promise.any` (23014), the async-dispose non-await (24228–24264),
  `PromiseResolve` skipping the `constructor` check (22565–22569), bound `.length` from
  internal arity (23402). The codebase's stated rule is "self-name rather than answer a wrong
  value" (23753, 23826); these sites answer.
- **`Halt::Unsupported` density.** 45 sites in the promise/bind/call/apply/AggregateError
  families. Notable common-program halts: `Promise.all(new Set(...))`/`Promise.all(gen())`/
  `Promise.all(map.values())` (22762/22768), `p.finally(() => asyncCleanup())` (22638),
  `resolve({then: nativeOrBound})` (21297), `userFn.call("str")` (23771),
  `new AggregateError(new Set(errs))` (23259). For a consensus engine an Unsupported halt is a
  liveness failure of the vat, deterministic but total.
- **Rust `String` as a JS-string carrier.** `RegExpData.source: String`,
  `ErrorInfo.message: Option<String>`, `FuncInfo.name: String` (via `format!("bound {}")`,
  23409), `value_to_string`, `capture_error_frames`. `str_text` is `from_utf16_lossy`; the
  round trip `to_string_bytes_metered → from_utf8_lossy → alloc_str_text` turns a lone
  surrogate into U+FFFD in a guest-observable heap string.
- **Integer-index keys interned as names.** 22230 and 22366 (`intern_key(&k.to_string())`);
  14 such sites engine-wide (12087, 13136, 14558, 14627, 35263–35392, 36584, 37030). The id
  space is `u16` shared top-down with symbol keys; `append_name_key` saturates and poisons the
  machine (35007–35017). Interned names are machine-global and persisted, so the id budget is
  a lifetime budget, not a per-crank one.
- **Hidden state / monolith symptoms.** `pending_new_target` set as a field to be consumed by a
  later `enter_call` (24008); `then_id`/`value_id`/`done_id`/`length_id` caches seeded lazily
  by `ensure_from_async_protocol_atoms` (21814–21825); stringly-typed `intrinsics.get("Boolean")`
  lookups at runtime (21840, 21845, 22672, 22988, 23062); two `IsConstructor` implementations
  (21403–21418, 21775–21798); four copies of error construction (23051–23349, 22982–23020);
  three copies of the `[THIS, FUNCTION, RESULT, FRAME]` frame push (21683–21735, 23625–23632,
  23699–23706, 23779–23787, 23882–23890, 23930–23941, 23997–24006); two `Vec<Slot>`
  arraylike readers (23688–23694, 23856–23864); `from_async_try(sb, cd, jd)` duplicates
  `run_callback_catching_throw`'s unwind.
- **Latent GC-root hazard behind an unenforced invariant.** Every re-entrant call in this
  region holds live `SlotIndex`es in Rust locals: `derived` across the handler call
  (21585→21608), `derived` across the custom `@@iterator` callback (22685→22713/22766), the
  result `promise` across the whole fromAsync prologue (21866→21894) while `from_async[id]` is
  not yet anchored by any reaction. Safe only because `collect_garbage` never runs mid-crank.
  The design promises XS's allocation-driven collector; adding it would make these silent
  use-after-sweep sites.
- **Metering-doctrine drift.** `capture_error_frames` is O(depth) unmetered heap work per
  error (XS captures only under `mxDebug`); `explicit_resource_method` `move` allocates an
  instance slot with no `tick_slot_alloc` (24204); `untick_raw` credits; "Metering is
  advisory here" for fromAsync (21625) — deterministic but not modelled.
- **Panics/unwraps on guest-reachable paths.** `self.regexps[&inst]` (21025, 20998),
  `self.promises.get_mut(&promise).unwrap()` (21159, 21310, 22534) versus the guarded
  `contains_key` in `settle_promise` (21253) — inconsistent error shape; `unreachable!()` on
  the internal `kind` dispatch (24362); `.expect("brand checked")` ×8 (24131–24216); slicing
  `self.stack[base + 5..base + 4 + argc]` on bytecode-derived `argc` (23620, 23774, 23924,
  23974). `array_set_dense` `i + 1` on `u32` (22955) wraps in release (no overflow-checks
  profile per census).
- **`temporal_integer` passes `&[]` as `code`** (24301) into `to_number_value → to_primitive →
  call_primitive_method → run_callback`, which dispatches over `code` when the callee shares
  the active segment (16422–16434). A user `valueOf` on a Temporal field bag therefore runs
  against an empty buffer.
- **Style/formatting.** 24378–24443 are unformatted one-line blocks (`match n {0=>…}`), evidence
  that rustfmt is not enforced (census: no rustfmt job).
- **API boundary.** `has_pending_jobs` is dead; the drain is fused into `run(code)`, so the
  design's "per-machine pending-jobs query with identical pump-loop semantics" has no public
  surface in this crate. The `code: &[u8]` threading through the drain is a leaky
  parameter: `run_callback` ignores it for cross-segment callees anyway.

## Candidate findings (most architecturally significant first)

1. **Native-promise adoption bypasses `NewPromiseResolveThenableJob` — one microtask tick
   short of spec and blind to an inherited `then` override.** interp.rs:21268–21285.
   Claim: resolving a promise with a native promise that has no *own* `then` registers a
   pass-through reaction directly, so `new Promise(r => r(Promise.resolve(1))).then(A)` and
   `.then(() => otherPromise)` chains observe handlers one tick earlier than the spec (and
   XS, which follows the spec here) and never call a monkey-patched `Promise.prototype.then`.
   Evidence: `if self.promises.contains_key(&obj) && !has_own_then {` … `self.register_native_reaction(obj, reaction); return Ok(());` and `find_property` walks only own slots (35575–35583).
   Why: microtask interleaving is a *result* the oracle checks; a divergence changes ordering
   of guest-visible effects in any program mixing `.then`-returned promises with sibling
   chains. Root cause is `run_thenable_job` driving only bytecode `then`s
   (`run_callback_catching_throw`, 22513) although `call_any_catching_throw` (21740) exists.
   Confidence: high on spec divergence; medium-high on XS divergence (oracle absent here).
   Category verification; severity high.
2. **`Promise.all/allSettled/race/any` return a plain object for a subclass with own
   `@@species`, and ignore the receiver constructor otherwise.** interp.rs:22671–22685.
   Claim: `Promise.all.call(C, [...])` for `class C extends Promise { static get [Symbol.species](){…} }`
   returns `new_object()` (not a promise, `C` never invoked); for any other subclass it returns an
   intrinsic Promise. Evidence: `if intrinsic != Some(c) && has_own_species { return Ok(Slot::of(Kind::Reference, Payload::Reference(self.new_object()))); }` then `let (derived, _resolve, _reject) = self.new_promise_capability();`.
   Why: this is a silently wrong value shaped to pass a "species must not be accessed" probe,
   violating the file's own honest-skip doctrine (23753) and `NewPromiseCapability(C)`.
   Confidence high. Category verification; severity high.
3. **Integer-index keys on the fromAsync array-like/non-Array paths consume the machine-global
   `u16` name-id space.** interp.rs:22230, 22366 (cross-cutting: 14 sites).
   Claim: `Array.fromAsync({length: 70000})` interns 70,000 permanent string keys, hits the
   symbol-key floor in `append_name_key`, sets `id_space_exhausted`, and the crank halts;
   re-running the same message halts identically, so the vat cannot progress.
   Evidence: `let key = self.intern_key(&k.to_string());` and 35007–35017 `if next >= self.next_symbol_key_id as usize { self.id_space_exhausted = true; …`.
   Why: XS addresses integer indices through `fxGetIndex` without key-table growth; ironhorse
   turns an O(n) data structure into an O(n) drain on a 65k lifetime budget. Confidence high
   on mechanism; the reachable trigger is unusual but legitimate. Category robustness;
   severity high.
4. **Rust `String` intermediates lose lone surrogates in guest-observable strings.**
   interp.rs:23078–23080, 23104–23111 (also 2812/20135, 24061, 23409).
   Claim: `new Error('\uD800').message.charCodeAt(0)` is `0xFFFD` on ironhorse (`0xD800` on XS);
   likewise `new RegExp('\uD800').source` and `Error.prototype.toString` results.
   Evidence: `let bytes = self.to_string_bytes_metered(a);` … `Some(String::from_utf8_lossy(&bytes).into_owned())`; `to_string_bytes_metered` → `self.str_text(off).into_bytes()` (38979); `str_text` → `String::from_utf16_lossy` (10892).
   Why: contradicts design § Value and heap model ("lone surrogates included"); a value-model
   boundary leak, not a display-boundary one. Confidence high. Category verification;
   severity medium-high.
5. **`Promise.prototype.finally` settles its derived promise two ticks early and halts on a
   thenable or native `onFinally`.** interp.rs:22623–22648.
   Claim: the spec's `thenFinally` performs `PromiseResolve(C, result).then(valueThunk)` and the

## What is done well

- The job queue and reaction lists are strictly FIFO over `VecDeque`/`Vec`, and `gc_roots`
  sorts and dedups so no HashMap order can leak into allocation order — the drain is
  deterministic by construction, as the design demands.
- The W6-19 reaction-arena compaction (`compact_reaction_arenas`, 44413–44512) remaps
  `ReactionKind` payloads and `PromiseFnData.guard` coherently across `promises`,
  `promise_jobs` and `promise_functions`, with a regression lock (`reaction_arena_pruning.rs`)
  and a struct-derived visitation registry; the earlier "append-only forever" hazard is
  genuinely closed.
- `array_from_async` isolates the caller's `jumps` across the synchronous prologue
  (21893–21895) so a throwing first `next()` rejects the result promise instead of unwinding
  into the caller's `catch` — a subtle spec point handled deliberately.
- `from_async_try`/`call_any_catching_throw` cleanly separate a JS throw (`Ok(Err(thrown))`)
  from a host halt (`Err(Halt)`), so meter aborts and Unsupported skips cannot be swallowed by
  the fromAsync machine.
- `settle_promise` self-resolution and `[[AlreadyResolved]]` guard semantics (a second guard
  per thenable adoption, 21368–21370) mirror XS's two-level structure faithfully, and
  `ever_handled` bookkeeping is kept explicitly off the meter.
- Doc comments consistently name the XS function being ported and the metering rationale,
  which made every divergence above locatable from the comment alone.
