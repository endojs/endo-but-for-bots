## Purpose and responsibilities

`value.rs` is the heap model: the 24-byte-in-memory / 32-byte-accounted `Slot` record
(`next`, `id`, `flag`, `kind`, 16-byte `Payload`), `SlotIndex(u32)`/`ChunkOffset(u32)` handles
with `u32::MAX` as NULL, the `SlotArena` (dense `Vec<Cell<Slot>>` or, on a lazily-resumed machine,
a page-sparse `SlotBacking` behind a `PageSource`), its LIFO free list plus `free_marks` bitmap,
mark bits, per-page dirty/unbacked bitmaps for incremental checkpoints, and the `ChunkArena`
(`[u32 LE len][payload]` blocks; strings as UTF-16BE; BigInt digits; ArrayBuffer stores) with
slide compaction and lazy extents behind a `RefCell`. It also hosts two numeric helpers
(`to_int32`, `number_to_ecma_string`).

`gc.rs` is the collector kernel: `collect_full(slots, chunks, roots, hooks)` — worklist mark from
sorted roots, an ephemeron fixpoint, `prune_dead_keyed`, index-order sweep with a per-slot `swept`
callback, then chunk compaction with a two-pass `external_chunk_refs` (liveness, then rewrite).
`GcHooks` is the seam through which the interpreter's ~30 side tables participate.

`bulk.rs` is the two BULK side tables (`ArrayData` items, `CollectionData` entries) whose maps
are private so every mutation flows through counted accessors maintaining `SideRefCounts`
(page → refcount), which the store-side *partial* collector reads as its side-table root-page set.

The interpreter (`interp.rs:43488–44942`) supplies `gc_roots`, the `Hooks` impl
(`extra_edges`/`swept`/`ephemeron_edges`/`prune_dead_keyed`/`external_chunk_refs`), a late prune
list, `free_pages` (page-granular freeing for the store-side partial collector), and
`each_side_table_ref{,_tail}` / `side_table_ref_page_bits` (the partial collector's root projection).

The invariant lives two crates away from the type that depends on it.

## Architectural observations

- **Collection is host-triggered only.** No `collect_garbage`/`free_pages` call exists inside the interpreter; the "stage-2 no-mid-run-GC contract" (bulk.rs:235; interp.rs:4082, 3031) is load-bearing for `FromAsyncData`/`combinators` being append-only within a run, for `At`/`pending_new_target` being un-rooted "boundary-empty transients", and for stack copies of Slots never being swept underneath. `Halt` has no heap-exhaustion variant (interp.rs:3517–3569); no arena size cap exists; `ChunkArena::alloc` casts `data.len()`/`v.len()` to `u32` (value.rs:1480–1481) and `SlotArena::capacity` casts `slots.len()` to `u32` (:884) without a guard (4 GiB / 2^32 records — unreachable under metering, unguarded without it). Worst-case per-crank RSS is proportional to total allocation in the crank, bounded only by the crank meter (or `step_limit` for un-metered runs, :3713–3721).
- **The side-table architecture makes marking O(live × tables).** `extra_edges` runs once per marked slot and performs ~21 `HashMap` probes plus three full scans of the tuple-keyed `accessors`/`private_values`/`private_accessors` maps (interp.rs:43871–43902); `swept` does O(table) `retain` per swept slot (:44035–44037); `ephemeron_edges` walks the whole arena per fixpoint round when any symbol-key descriptor is unmarked (:44098–44106). XS marks by walking inline slots. For class/accessor/private-field-heavy SES code the mark phase is quadratic in practice; the comments acknowledge it as "small in practice".
- **Four hand-mirrored walks.** `extra_edges` ↔ `each_side_table_ref_tail` (edges), `swept`+late list ↔ `free_pages` (prunes), `external_chunk_refs` (chunks), `gc_roots` ↔ the partial collector's root pages. The registry test (`gc_visitation_registry.rs`) checks only that a *table name* appears in each body (word-bounded), so subfield omissions and same-named fields pass: `target_func` (Req::GcRoots) is satisfied by `f.target_func` while `self.target_func` is never pushed (interp.rs:43502–43695 vs registry:241).
- **Hidden runtime state.** `Cell`/`RefCell` interior mutability in the lazy arms (value.rs:65–99, 1131–1151) makes control flow depend on residency; `SideRefCounts` is a derived cache that must be rebuilt on restore (interp.rs:10525–10555 does so) and is not itself snapshotted.
- **Determinism.** No hazard found in-region: `gc_roots` sorted; `compact` sorts `seen`; remaps are lookup-only; `swept` in index order; `compact_reaction_arenas`/`compact_code_segments` use `BTreeSet`; `SideRefCounts` is only OR-ed into a bitmap; `HashMap` iteration in `ephemeron_edges`/`prune_dead_keyed`/`external_chunk_refs` affects only worklist order / per-collection-independent work, never the resulting mark set, free list, or byte layout. `number_to_ecma_string` and `to_int32` are pure-Rust-std and probe-correct; no libm, locale, or time.
- **Panics on untrusted data** (all deterministic): `get`/`mark`/`is_marked` index OOB on a corrupt index; `len_of`/`ensure_payload_resident` `expect` on offset < 4; `compact` asserts on out-of-range blocks; lazy faults assert exact row length and in-arena references. `SlotArena::free` has no double-free guard (value.rs:841–846) and `live -= 1` wraps in release (no `overflow-checks` profile per census).
- **Metering-doctrine shape.** Allocation and its charge are separate calls at every site (`slots.alloc` 153 sites vs `tick_slot_alloc` 72 sites — some sites charge through aggregate constants, boot is unmetered; the point is there is no fused `fxNewSlot` choke point). Map/Set use a linear `collection_find` (interp.rs:34435–34440) and O(n) `live_len` (bulk.rs:302; interp.rs:12795) while `table_length`/`collection_table_resize` charge XS's hash-table cost model (:34458–34489) — the meter models a data structure that does not exist.
- **API-boundary leaks.** `pub slots`/`pub chunks`; `pub` `alloc`/`free`/`get_mut`/`from_image`; `gc::Heap` is a second collector entry (`NoHooks`) used only by tests — a drift surface with no production consumer.
- **Weak semantics scope.** Only WeakMap/WeakSet exist (ephemeron pass + prune). `WeakRef`/`FinalizationRegistry` appear only as default key names (default_keys.rs:37, 68) — unimplemented, so no finalization/weak-ref GC interaction to audit.
- **Docs drift.** value.rs module header still describes stage 1 ("reference/string kinds … filled in as later stages land", "slide-compaction GC that lands in stage 2"); `Kind` doc says "full ~66-kind set arrives with stage 2" (15 kinds exist); contradictory `Kind::Property` docs; stale "argc in id" claim; "32-byte"/"repr(C)" claim.

## Candidate findings

1. **Collection never runs under allocation pressure; heap growth within a crank is unbounded by the engine** — `interp.rs` (grep) has no `collect_garbage(`/`free_pages(` call; `Halt` :3517–3569 has no heap-exhaustion variant; `value.rs:1480–1481` `(data.len() as u32)`, `v.len() as u32`. Claim: a single crank can grow the arenas to any size the meter permits and nothing in `ironhorse-vm` reclaims or refuses. Why it matters: XS collects on `fxGrowSlots` failure; here the only bound is the crank meter (none for `meter_host: None`), so per-crank RSS is O(total allocation) not O(live), and the `u32` casts are unguarded at the limit. Severity high (architecture), confidence high.
2. **Arena accessors never check the free bit, so the "stale index is caught by kind checks" claim is only half true** — `value.rs:853–859` (`get`), :861–876 (`get_mut`), :901–912 (`mark`) index `slots`/`marks` directly; `is_free` :929 exists and is O(1) but unused there. Claim: `get()` on a freed slot returns stale bytes, `mark()` marks it, and a reused slot reads as a different object; `debug_assert!(!self.is_free(i))` would make the class a deterministic debug panic. Why: this is the class the code repeatedly documents hitting ("a reused slot answered Temporal's brand check", interp.rs:44351–44356); the GC itself would touch free records if any root/edge were stale. Severity medium, confidence high.
3. **`XS_ENVIRONMENT_BEHAVIOR_ID` (u16::MAX) collides with the first minted symbol-key id, and the snapshot audit refuses honest heaps holding a live `with` environment** — `interp.rs:559` `pub const XS_ENVIRONMENT_BEHAVIOR_ID: u16 = u16::MAX;`, `:5295` `next_symbol_key_id: u16::MAX`, `:35069–35071` `let id = self.next_symbol_key_id; self.next_symbol_key_id -= 1;`, `:38196` `behavior.id = XS_ENVIRONMENT_BEHAVIOR_ID;`; `value.rs:420–426` `stored_key_id` returns any non-zero id; `image.rs:510–536` + `:3468` refuse a stored id `>= floor` not in the SYMB set; callers `store.rs:3389`, `machine.rs:980, 1400`, `image.rs:4748` return `Corrupt`. Claim: a machine that has minted no symbol key and has an environment instance live at a checkpoint (a generator/async frame suspended inside a `with` body keeps `SavedFrame.env` alive) fails to persist with "stored property id outside the name and symbol-key tables"; and once one symbol key is minted, that symbol's descriptor is spuriously retained by the ephemeron pass (:44101) whenever an env behavior slot is marked; `is_environment_instance` (:38246–38252) would also misclassify an object whose head property is keyed by that symbol. The constant's own doc (:553–558) says the top of the space is unreachable. Severity medium (snapshot-coverage), confidence high on mechanism, medium on production reachability (`with` in a suspended frame).
4. **Four hand-mirrored side-table walks with a name-only registry net** — `interp.rs:43806–43999` (`extra_edges`) vs `:44761–44941` (`each_side_table_ref_tail`); `:44001–44043` + `:44343–44383` vs `:44577–44644` (`free_pages`); `gc_visitation_registry.rs:59–75` `mentions()` is a word-bounded substring check, `:438–445`. Claim: every new slot-bearing field must be added in up to five places by hand and the only mechanical check is textual presence of the field name. Why: the census records wave after wave of "missed table" bugs; the structure that produced them is unchanged — a single side-table visitor parameterized by mode (edges / chunk-remap / prune / partial) would collapse the drift surface. Severity medium (modularity), confidence high.
5. **Mark phase is O(live × side-tables) with linear scans per marked slot** — `interp.rs:43871–43902` (`for ((owner,_id),a) in self.accessors.iter() if *owner == idx`, same for `private_values`, `private_accessors`), ~21 `HashMap::get` probes per marked slot :43807–43998, `swept` `retain` per dead slot :44035–44037, `ephemeron_edges` O(capacity) per round :44098–44106. Claim: a heap with A accessors and L live slots costs ≥ L×A comparisons per collection. Why: SES/Endo code is accessor- and private-field heavy; the design's "GC churn" microbenchmark target (design:756–760) will expose this. Severity medium (performance), confidence high.
6. **Map/Set are linear-scan collections metered as hash tables** — `bulk.rs:259` `entries: Vec<Option<(Slot,Slot)>>`, `:302–304` `live_len` counts per call; `interp.rs:34435–34440` `collection_find` = `position(...)`; `:34458–34489` charges `fxNewChunk(length*8)` rehash costs from `table_length`. Claim: `map.get`/`has`/`set`/`size` are O(n) in entries (O(ever-inserted) for tombstoned Map/Set) while the meter charges an O(1) hash-table model. Why: violates "best deterministic proxy for wall-clock cost" (design:363–367) in exactly the direction that enables under-priced quadratic work; a 100k-entry Map makes each lookup 100k `same_value_zero` calls. Severity medium (metering/performance), confidence high.
7. **Lazy-arena `RefCell` makes control flow residency-dependent (replica-divergent panic class)** — `value.rs:1414–1422` `view` faults then `cell.borrow()`; `:1351–1372` documents "constructing the second guard over a non-resident extent would `borrow_mut` under the first guard's live `Ref` and panic … a lazily resumed machine crashing on `a === b` while every other run mode succeeds"; `compare_payloads` :1358–1362 is the one sanctioned site. Claim: any future two-guard read (or a guard held across `ensure_*_resident`) panics only on lazily-resumed machines, and `evict_extent` (:1300–1322) makes residency a host-schedule variable. Why: an eager replica and a lazy replica of the same crank can differ (crash vs success) — the exact divergence the "evict schedule is observably irrelevant" claim (:668) rules out. Severity medium (determinism), confidence medium (no unguarded site exists today; grep found only :1361).
8. **Release builds have no net for a counted side-ref undercount** — `bulk.rs:79–85` `None => { debug_assert!(false, "side-ref undercount on page {page}"); }`; `interp.rs:44716–44731` parity check is `#[cfg(debug_assertions)]`. Claim: in release, a missed counted mutation silently under-roots a page and the partial collector frees live slots (or over-roots and leaks) with no diagnostic. Why: the partial collector's soundness rests on these counts; the design says logic bugs "surface as deterministic panics" (design:614–618) — here they don't. Severity medium (gc-roots), confidence high.
9. **Registry false positive: `self.target_func` is not a root although the ground-truth net says it is** — `gc_visitation_registry.rs:241` `("target_func", &[Req::GcRoots], …)`; `interp.rs:43502–43695` contains `roots.push(f.target_func)` (:43540) but never `self.target_func` (only `self.cur_func` :43565). Claim: the word-bounded `mentions(gc_roots, "target_func")` is satisfied by the frame field. Why: harmless while collections run at quiescent boundaries (the register is restored on return :34583), but `collect_garbage` is `pub` and callable after any `Halt`; and it shows the net can be fooled by same-named fields. Severity low (verification), confidence high.
10. **Heap invariants are enforced outside the type: `pub` arenas, `pub` raw allocators, decoupled metering, trusting constructors** — `interp.rs:3723–3725` `pub slots: SlotArena, pub chunks: ChunkArena`; `value.rs:808` `pub fn alloc`, :841 `pub fn free`, :861 `pub fn get_mut`, :1039 `from_image(slots, free, live)` (no dup/range check; `free_marks[i as usize] = true`); metering is a separate `tick_slot_alloc()` at each of 153 `slots.alloc(` sites (72 `tick_slot_alloc(` sites). Claim: any crate holding an `Interp` can allocate/free unmetered and desynchronize side tables; free-list validity is guaranteed only by `decode_heap` (image.rs:810–828) two crates away. Why: bulk.rs proves the team knows privacy-as-soundness works; the arena itself is the unprotected exception. Severity medium (api-boundary/metering), confidence high.
11. **`Slot` is 24 bytes and not `repr(C)`; several value.rs docs describe a different engine** — `value.rs:298–312` ("One 32-byte slot record … `#[repr(C)]`-style field order"), `:967–969` `capacity*32`, `:1–16` stage-1 header, `:172–174` "~66-kind set arrives with stage 2", `:197–201` vs `:402–406` (`Kind::Property`), `:307`/interp.rs:44080–44083 (argc in `id`). Claim: `size_of::<Slot>()==24` (probe) and no `repr` attribute exists. Why: the design's footprint claim ("slot accounting identical by construction", design:761–763) and the snapshot writer's assumptions should be stated against the real layout; contradictory docs mislead the next reader of a 45k-line file. Severity low (docs-drift), confidence high.
12. **`SlotArena::free` has no double-free guard and `live` underflows silently in release** — `value.rs:841–846` `debug_assert!(!index.is_null()); self.free.push(index.0); self.free_marks[..] = true; self.live -= 1;`; interp caller `:38075` `self.slots.free(cur)` (property `delete`). Claim: freeing an already-free index pushes it twice so two later `alloc`s return the same record (silent aliasing), and `live -= 1` wraps in release (no `overflow-checks` profile). Why: the bitmap that would detect it is right there (`is_free`); a one-line assert closes a silent-corruption path. Severity low (robustness), confidence high.
13. **`ChunkArena::compact` treats any in-range offset in `live` as live, contrary to its doc** — `value.rs:1541` "Duplicate/unknown offsets in `live` are ignored"; `:1571–1587` only out-of-range offsets die, `:1605–1613` everything else is copied and remapped. Claim: a stale but in-range `ChunkOffset` reported by any `external_chunk_refs` holder resurrects dead bytes as a block (and, if it points mid-payload, reads a bogus length header — validated only for range). Why: the compaction contract is what keeps `ChunkOffset`s meaningful; the doc promises a tolerance the code does not have, so callers may rely on it. Severity low, confidence high.

## What is done well

- The lazy-reification design is careful: exact-length faults, in-arena validation of faulted records (skipping free ones, with the reason documented), fail-closed eviction guards (`dirty`, `unbacked`, ahead-of-backing tail), and `compact` validating before `mem::take` so a panic never leaves an emptied byte space.
- Determinism discipline in the collector is real: sorted roots, index-order sweep, sorted compaction order, `BTreeSet`-based arena compaction, bitmap projections — every `HashMap` iteration I traced is outcome-neutral.
- The ephemeron treatment of WeakMap/WeakSet is correct and precise (map-and-key gated, pruned before sweep, entries physically removed for weak kinds), and the two-pass `external_chunk_refs` gives side-table strings exactly the compaction treatment arena strings get.
- bulk.rs's privacy-as-soundness pattern (private maps, counted accessors, no `Clone`, a documented escape hatch) is the right shape, and the restore path rebuilds the counts through the same accessors.
- The ground-truth registry test is an unusually good idea — deriving slot-bearing fields from the struct source so a new field cannot be silently unclassified — even though its mechanical check is currently name-level only.
- Numeric helpers (`to_int32`, `number_to_ecma_string`) are pure, platform-independent, and spec-correct on every corner I probed (`1e21`, `1e-7`, `-0`, `5e-324`, `2^32±`).
