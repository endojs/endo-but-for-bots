# interp-05-meter-run-render — map

## Purpose and responsibilities

This slice is the **crank lifecycle seam** of the interpreter: everything between the
embedder handing over a bytecode buffer and getting back a `RunOutcome`.

- **Meter arming and checking** — the three arm forms (`arm_meter`, `rearm_meter`,
  `reattach_meter_host`), the loop-closing `check_meter`, and the flat charge helpers
  (`tick_property_create_flat`, `tick_program_overhead`).
- **Quiescence contract** — `is_quiescent`, the single predicate every persist verb in
  `ironhorse-snapshot` gates on (machine.rs:200, :963, :1064).
- **Program-entry environment** — `hoist_vars_to_global` / `can_declare_global_function`
  (XS `fxRunEvalEnvironment`'s global-hoist branch), invoked from the
  `EVAL_ENVIRONMENT|PROGRAM_ENVIRONMENT` opcode arm (11533).
- **Stack and string primitives** — `push`/`pop`, `str_content`/`str_units`/`str_len`/
  `str_text`/`alloc_str_text` (UTF-16BE payload helpers).
- **Host-boundary rendering** — `render` (completion value → `String`, modeled on the XS
  oracle shim's `fxToString`), `render_uncaught` (thrown value → `String`, runs guest
  `toString`), `string_tag_of`, `symbol_descriptive_bytes`.
- **Run entry** — `run_bounded` → `run` → `dispatch` → `dispatch_at` (re-entry-depth
  guard) → `dispatch_at_inner` (the ~30k-line opcode `match`, other regions).

## Architectural observations

- **Harness semantics baked into the engine's only run entry.** `run` models the XS *oracle
  shim's* post-run `String(result)` (11193–11217: Symbol ⇒ `TypeError` abort; null-prototype
  object ⇒ `TypeError` abort) and `render` reproduces the shim's `fxToString` rendering
  table. These are test-harness conventions, yet `Machine::eval` in `rust/endo` (the
  production embedder) consumes `run`/`RunOutcome` directly (ironhorse_engine.rs:170–177), so
  a daemon program whose completion value is a Symbol is reported as a thrown `TypeError`.
  There is no "raw completion" entry that returns the `Slot`.
- **Fail-open metering.** The meter is armed by *host wiring* that cannot be persisted;
  absence of the wiring is indistinguishable from "unmetered by design" at every check
  point. Combined with the production embedder never arming, the deployed path runs
  every crank unbounded. The design's crank lifecycle (§ Metering, "the crank aborts on
  refusal") has no enforcement hook in the engine.
- **Hidden shadow state at the render boundary.** `error_data` (`ErrorInfo { name:
  &'static str, message: Option<String> }`) is write-once (inserts at 8954, 22993, 23085,
  23205, 23292; the only `get_mut` is `internal_error` 23149). `render` prefers it over the
  live `name`/`message` properties and `render_uncaught` skips the guest `toString` for any
  `error_data` instance — so the rendered abort text can disagree with what XS's
  `fxToString` (which runs `Error.prototype.toString` over live properties, or a guest
  override) produces.
- **Guest code runs after the halt is decided.** `render_uncaught` → `to_primitive` executes
  guest `toString`/`valueOf`/`@@toPrimitive` *after* `meter_host_escape()` has already
  applied the host-escape meter adjustment and with `self.exception` already set; a nested
  throw or meter abort inside it is discarded (`if let Ok(prim)` 11075) and its allocations,
  meter ticks and queued promise jobs remain in the halted machine. The oracle shim
  captures `out->computrons` *before* stringifying the exception (xs_shim.c:448–451) and on
  the completion path before `fxToString` (:418 vs :423).
- **Unbounded host-side work driven by guest data.** `render`'s array arm iterates
  `0..a.length` (`u32`, up to 4 294 967 295) and recurses into elements with no depth
  counter or cycle set (10938–10949). Neither loop nor recursion is metered or bounded. A
  Rust stack overflow is an *abort*, not a panic — outside the design's "a panic is a
  crashed crank" envelope, and not catchable by a fuzz harness's `catch_unwind`.
- **Determinism:** nothing in the region iterates a `HashMap`/`HashSet` observably
  (`id_map` walk is sorted; `well_known_symbols` is a `Vec`; other maps are point lookups).
  No f64 formatting here except via `slot_to_ecma_string` → `number_to_ecma_string`
  (other region). No host time/env.
- **Panics/indexing on untrusted data in-range:** `self.typed_arrays[&r]` (10957) and
  `self.regexps[&inst]` (21025) are guarded by `contains_key`/`get` immediately before.
  Operand macros index `code[pc+off]` but the loop bounds-checks `pc + ilen > len` first
  (11390) — safe. `pop()` never panics (masks underflow instead).
- **Monolith symptoms:** `render` is a 150-line type-switch over 14 side tables — a
  duplicated, hand-maintained mirror of `Object.prototype.toString`/`Array.prototype.join`
  /`Error.prototype.toString`/`RegExp.prototype.toString` semantics that the engine also
  implements as real built-ins elsewhere. Every new exotic side table needs a new arm here
  or its completion mis-renders as `[object Object]`.
- **Snapshot coverage:** `locals`, `id_map`, `result`, `exception`, `top_level_code`,
  `active_segment`, `strict`, `direct_eval_hoist`, `dispatch_depth` are classified
  TRANSIENT (sidetable.rs 716–731) — correct only if they are at fresh-boot values at every
  accepted persist boundary. `run` guarantees this for `result/locals/id_map` only on
  `completed` (11234–11238); `is_quiescent` does not check them.
- **Meter arithmetic edge:** `Meter::begin`/`rearm` compute `interval << 16` (meter.rs
  120, 137) — for a host interval ≥ 2^48 the high bits vanish silently (host-supplied, so
  low risk); `rearm` uses `saturating_add` while `check` uses `wrapping_add` (inconsistent
  overflow policy; unreachable at u64 width).
- **Performance:** `run` copies the entire bytecode into an `Rc<Vec<u8>>` every crank
  (11162) regardless of whether a function is defined; `str_text` allocates a `Vec<u16>` and
  a `String` per call, and `render` of an array calls it per element.

## Candidate findings (most architecturally significant first)

1. **`run` conflates engine completion with the oracle harness's `String(result)` coercion; the production embedder inherits it** — `api-boundary`, medium-high confidence.
   interp.rs:11199–11201 and 11206–11217.
   > `if halt == Halt::Return && self.result.kind == Kind::Symbol { halt = Halt::Throw("TypeError: cannot coerce symbol to string".to_string()); }`
   > `halt = Halt::Throw("TypeError: cannot convert object to primitive value".into());`
   Claim: a program whose completion value is a Symbol or a null-prototype object is
   reported by `Interp::run` (and thus by `rust/endo` `Machine::eval`, ironhorse_engine.rs:170–177)
   as a thrown `TypeError`, although the program completed normally. Why it matters: the
   engine's sole run entry encodes a test-harness convention, so every embedder gets
   shim semantics and there is no way to obtain the raw completion `Slot`. (Probe: see
   Appendix.)

2. **Metering is fail-open: an armed meter without a host closure silently runs unbounded, and no production caller arms it** — `metering`, high confidence.
   interp.rs:10749–10754; meter.rs:266–271; sidetable.rs:733; `rust/endo` grep: no `arm_meter` callers.
   > `match self.meter_host.as_mut() { Some(host) => self.meter.check(host), None => MeterCheck::Continue, }`
   > doc 10681–10683: "a restored machine that skips them reports armed state but never consults a host."
   Claim: a resumed machine whose snapshot carries `interval != 0` but whose embedder forgot
   `reattach_meter_host` never meter-aborts, and `rust/endo/src/ironhorse_engine.rs` never
   calls any arm form, so the deployed ironhorse path has no crank limit at all. Why it
   matters: the design makes the crank abort the liveness backstop for consensus workers;
   the engine has no "metering required" mode and cannot detect the missing wiring.

3. **The synthetic `Halt::Throw`s leave a *quiescent* machine with uncleared boundary registers — re-opening the W6-11 root-set asymmetry through the persist gate** — `gc-roots`/`snapshot-coverage`, medium-high confidence.
   interp.rs:11199–11217 vs 11234–11238; gc_roots 43511 (`locals`), 43523 (`result`); sidetable.rs:718–720 (`locals`, `id_map`, `result` TRANSIENT); is_quiescent 10733–10743.
   > `if completed { self.result = Slot::undefined(); self.locals.clear(); self.id_map.clear(); }`
   Claim: after a Symbol or null-prototype completion, `completed == false` so `result`/
   `locals`/`id_map` stay populated and rooted, yet `is_quiescent()` returns `true` (no
   unwinding happened; `exception` is `Undefined`), so `persist_gate`/`begin_store_session`/
   `checkpoint_to_store` accept a machine whose resumed twin roots fewer slots — the
   free-list divergence W6-11 fixed. The managed `PersistentMachine` path is shielded
   (it rewinds any `!completed`, ironhorse_engine.rs:584–596); raw `MachineSnapshot`
   callers are not. Also falsifies the `is_quiescent` doc's "a crank that HALTED returns
   with ... a set exception". (Probe: see Appendix.)

4. **`render` is an unguarded, unmetered recursive walk over guest-controlled arrays: a self-containing array completion overflows the native stack (process abort), and a sparse array with a large `length` loops up to 2^32 times** — `robustness`, high confidence on code shape.
   interp.rs:10933–10949; bulk.rs:120 (`length: u32`).
   > `for i in 0..a.length { ... if let Some(item) = a.items().get(&i) { ... out.push_str(&self.render(item)); } }`
   Claim: `var a = []; a[0] = a; a` as a program completion recurses `render` → `render`
   without a depth or cycle guard until the Rust stack overflows (SIGABRT, not a panic —
   not catchable by `catch_unwind`); `var a = []; a.length = 4294967295; a` makes the host
   build a ~4 GiB comma string outside the meter. XS's `join` on the same values fails
   *inside* the metered run (`fxOverflow`/heap limit). Why it matters: a guest-triggerable
   whole-process abort at the host boundary is outside the design's "panic = crashed
   crank" safety envelope and defeats the fuzz harness. (Probe: see Appendix.)

5. **`render_uncaught` executes guest code after the halt is decided and after the host-escape meter adjustment, and its cost is reported as crank computrons (the oracle's is not)** — `metering`/`error-model`, high confidence on ordering.
   interp.rs:15049–15051 (and 15715–15717, 15738–15740); 11072–11088; 11252; xs_shim.c:448–451.
   > `self.meter_host_escape(); let text = self.render_uncaught(code, v); return Halt::Throw(text);`
   > `if let Ok(prim) = self.to_primitive(code, v, true) {`
   Claim: for `throw {toString(){ <work> }}` Ironhorse's `RunOutcome.computrons` includes
   the `toString` body's dispatch/allocation metering while the oracle captures
   `out->computrons` before `endor_error_from_exception` runs `fxToString`; a nested throw,
   `MeterAbort` or `Unsupported` inside that `toString` is silently discarded, and its heap
   mutations/queued jobs persist in the halted machine. Why it matters: a raw-exact-parity
   codebase (~250 `*_METERING` constants) diverges on every uncaught user-object throw with
   a non-trivial `toString`; and guest code running post-halt blurs the "halted crank is
   the state at the throw" contract the rewind path relies on.

6. **`run_bounded`'s step ceiling is compared against the machine-lifetime dispatch count, not this run's** — `robustness`/`docs-drift`, high confidence.
   interp.rs:11147–11155 (doc 11149–11150 "the ceiling applies to THIS run"); 11325; `n_dispatched` set only at 5226, incremented at 11367.
   > `if self.n_dispatched >= self.step_limit { return Halt::StepLimit(self.n_dispatched); }`
   Claim: a second `run_bounded(code, N)` on a machine that has already dispatched ≥ N
   opcodes halts with `StepLimit` before executing a single instruction, and
   `RunOutcome.dispatched` is cumulative across cranks. Why it matters: `run_bounded` is
   the totality guard for the decoder fuzz harness and any bounded multi-crank caller;
   the guard silently changes meaning after the first crank. (Probe: see Appendix.)

7. **Error rendering reads write-once shadow state (`error_data`) and bypasses the guest's `toString`, so abort text can disagree with XS** — `error-model`, medium confidence (not oracle-checked here).
   interp.rs:11011–11015; 11074 (`!self.error_data.contains_key(&r)`); ErrorInfo 3096–3105; only `get_mut` at 23149.
   > `} else if let Some(info) = self.error_data.get(&r) { match &info.message { Some(m) if !m.is_empty() => format!("{}: {}", info.name, m), _ => info.name.to_string(), } }`
   Claim: `var e = new Error('a'); e.message = 'b'; throw e` renders `Error: a` (XS: `Error:
   b`), and `class E extends Error { toString(){return 'x'} }; throw new E('m')` renders
   `Error: m` (XS: `x`), because `name: &'static str` and `message` are captured at
   construction and never re-read from properties. Why it matters: the differential
   harness compares error identity/text on aborts; a shadow table that can drift from the
   heap is the same bug class as the side-table/heap desyncs prior waves fixed.

8. **`pop()` converts value-stack underflow into `undefined` instead of a decode/logic halt** — `error-model`, medium confidence on significance.
   interp.rs:10854–10856.
   > `fn pop(&mut self) -> Slot { self.stack.pop().unwrap_or_else(Slot::undefined) }`
   Claim: malformed or mis-compiled bytecode that pops an empty stack keeps running with
   `undefined` operands and can *complete* with a rendered result, whereas the opcode-byte
   and operand paths return `Halt::Decode`. Why it matters: for a consensus engine
   "silently succeed on invalid input" is the wrong default and hides compiler bugs that
   the byte-identity bar is meant to expose; a `Halt::Decode("stack underflow")` would be
   equally total for the fuzz harness.

9. **`is_quiescent` checks 3 of the 8 boundary-live rooted registers; `args`/`this_val`/`env`/`cur_func` are rooted (43514–43528, 43565) and TRANSIENT but neither checked nor cleared at the completed boundary** — `gc-roots`, low confidence (whether they can be non-default at a completed boundary was not verified).
   interp.rs:10733–10743; 11234–11238; 43514–43528.
   > `slot_roots(&self.this_val, &mut roots); slot_roots(&self.exception, &mut roots); slot_roots(&self.result, &mut roots); slot_roots(&self.env, &mut roots);`
   Claim: if any of `args`, `this_val`, `env`, `cur_func` can hold a non-boot reference after
   a completed crank, the W6-11 asymmetry recurs for that register. Why it matters: the
   quiescence predicate is the *only* guard, and it is enumerated by hand (a source-parsing
   test in sidetable.rs:890–947 reconciles it against the ledger's `EmptyAtBoundary` rows,
   but registers are outside that reconciliation).

10. **`can_declare_global_function`'s "accessors are not modeled" premise is stale** — `docs-drift`/`correctness`, low confidence.
    interp.rs:10832–10847; sidetable.rs:696 (`accessors` ledger row).
    > `// Accessor globals are not modeled, so every existing global here is a data property.`
    Claim: an `accessors` side table exists, so a non-configurable accessor global (spec:
    `CanDeclareGlobalFunction` ⇒ false) is judged by data-property flags here. Why it
    matters: small, but it is the kind of comment-encoded invariant that silently rots as
    the monolith grows.

11. **`RunOutcome.computrons`/`dispatched` are machine-lifetime counters documented as run-only** — `docs-drift`, medium confidence.
    interp.rs:3597–3602, 11246–11254; xs_shim.c:397 (`the->meterIndex = 0` per crank).
    > `/// Computrons, comparable bit-for-bit with the oracle's run-only count`
    Claim: only the first crank on a fresh machine matches that description; multi-crank

12. **`Meter::begin`/`rearm` shift a host `u64` by 16 with silent high-bit loss; `rearm` saturates where `check` wraps** — `metering`, low.
    meter.rs:120, 137–139, 291.
    > `let scaled = interval << 16;`
    Claim: `arm_meter(1 << 50, ..)` yields a 4-raw-unit window. Host-supplied input, so low
    risk; noted for the numeric-domain rule in AGENTS.md.

## What is done well

- The three arm forms are precisely specified and each is locked by a test
  (`persist_gates.rs:147–246`); the `reattach_meter_host` fix for review finding 7 is
  the right minimal shape (host only, counters untouched).
- Operands are bounds-checked as a unit (`pc + ilen > len` at 11390) *before* the
  `s1!/u1!/id!` macros index, and every decode failure is a typed `Halt::Decode`, so the
  decoder fuzz target genuinely cannot OOB-panic on truncated bytecode in this path.
- `hoist_vars_to_global` sorts the `HashMap` walk by `(index, id)` before observing it —
  the correct discipline for determinism over a hash table — and its spec citations
  (`CanDeclareGlobalFunction`, EvalDeclarationInstantiation 5.d.ii.2.a.i, IsExtensible)
  are accurate.
- `dispatch_at` brackets the native re-entry depth around the inner loop in one place,
  so all four re-entry sites (callbacks, async, async-gen, generator) share one guard.
- The snapshot ledger's reflection tests (`sidetable.rs:690–790` field classification,
  `:890–947` parsing the `is_quiescent` body) make omissions in the quiescence predicate a
  build failure rather than a review catch — an unusual and effective invariant lock.
- The `run` doc comments cite the wave-6 finding that motivated each reset (`W6-6`,
  `W6-11`, `W6-16`), which made this review's drift checks cheap.
