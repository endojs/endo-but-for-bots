## Purpose and responsibilities

`ironhorse-snapshot` is the persistence layer of the engine: it turns a quiescent `Interp` into the
XS-shaped `XS_M` FourCC atom container (and back), addresses the result by SHA-256 for the daemon's
CAS, and — since the store-seam design — also drives incremental page/extent checkpoints into a
`HeapStore` (that half lives in `store.rs`/`store_file.rs`, another reader's region; `machine.rs`
holds the session/checkpoint/lazy-resume verbs and the summary-driven collectors that consume it).

The region's own responsibilities:

- `atom.rs` — frame bytes: `[u32 BE size][FourCC][payload]` atoms inside one `XS_M` envelope
  (`AtomWriter` 27-55, `AtomReader::parse` 122-150 with `Truncated`/`BadLength`/`NotContainer`/
  `TrailingBytes`/`DuplicateAtom` refusals).
- `format.rs` — the 34 tags (20-150), the writer's `CANONICAL_ATOM_ORDER` (164-168), the Ironhorse
  `VERS` discriminator `IRON` + format version 12 with read range `1..=12` (177-205, `Version`
  219-300), the opaque host `Signature` string and its equality gate (314-374), `SnapshotError`
  (385-401).
- `slot_codec.rs` — `Slot` <-> fixed 20-byte big-endian record (`kind`,`flag`,`id`,`next`,payload
  tag + 10 data bytes), zero-filled so round trips are byte-identical (53-63, 103-134).
- `sha256.rs` — dependency-free FIPS 180-4 SHA-256 (`Sha256` 37-188, `hex` 191-198).
- `sidetable.rs` — the side-table completeness ledger: `SideTable` (41 variants, 176-394),
  `Coverage` (129-170), `descriptor()` exhaustive match (449-607), `ALL` (401-443), and four tests
  that reconcile the ledger against the `Interp` struct's source text and against `is_quiescent`'s
  body (629-970).
- `machine.rs` — the xsnap-shaped `MachineSnapshot` extension trait on `Interp`
  (`snapshot_image`/`persist_gate`/`write_snapshot`/`write_snapshot_to_file`/`suspend_to_cas`,
  129-257), the side-table image/restore bridge (`side_tables_of` 289-420, `restore_side_tables`
  432-616), `image_to_interp`/`from_snapshot_bytes`/`from_snapshot_file`/`resume_from_cas`
  (629-720), and the store session surface (`StoreSession` 785-865, `begin_store_session` 947-1034,
  `checkpoint_to_store` 1045-1369, `resume_from_store` 1377-1437, `StorePageSource`/`LazyPin`
  1439-1520, `resume_from_store_lazy` 1535-1652, `partial_collect` 1952-2007,
  `generational_collect` 2046-2108).

## Invariants and contracts claimed (from doc comments) — and whether the code upholds each

1. "One logical machine has exactly one container encoding, or its SHA-256 CAS key is not an
   identity" (format.rs:152-163, atom.rs:68-78, image.rs:4340-4345). **Partially.** The envelope
   (exact consumption, duplicates), atom order/unknown tags, and present-but-empty optional atoms are
   refused. But `Version::decode` accepts any payload `>= 10` bytes (format.rs:251),
   `CreationParams::decode` any `>= 8` (image.rs:131), `decode_heap`/`decode_stack` refuse only
   truncation (`p.len() - i < want`, image.rs:807, 4199) — trailing bytes in VERS/CREA/HEAP/STAC are
   accepted. Probe: all four one-byte-appended variants were **accepted**, produced a different
   SHA-256, and re-emitted to the honest bytes (Candidate 4).
2. "A snapshot is taken at machine quiescence — between top-level `run` cranks, never mid-dispatch"
   and `NotQuiescent` means "its last crank halted" (machine.rs:30-39, 83-87; sidetable.rs:159-169;
   `run` comment interp.rs:11232-11233 "A HALTED crank keeps everything: the quiescence gate refuses
   it"). **Violated.** `is_quiescent` (interp.rs:10733-10743) tests `call_stack`, `stack`, `jumps`,
   `promise_jobs`, the three run stacks, `exception == undefined`, `!id_space_exhausted`. A
   `Halt::MeterAbort` at a top-level backward branch leaves all of those empty while `locals`/`id_map`
   (top-level `let`/`const`) and the half-mutated heap are live; `run` clears `locals`/`id_map`/
   `result` only `if completed` (11234-11238). Probe: `let i = 0; while (true) { i++; }` under a
   refusing meter -> `completed=false halt=MeterAbort`, `is_quiescent=true`, `write_snapshot => Ok`.
   Same for the `var` form. The function-body and try-block forms are correctly refused. The only
   lock (`persist_gates.rs:35-44`) uses a top-level `throw`, which sets `exception` (Candidate 1).
3. "The side-table ledger is compile-checked, never a silent omission" (lib.rs:40-48;
   sidetable.rs:14-22, 397-400). **Partially.** `descriptor()` is an exhaustive `match` (true), and
   the struct-source reconciliation is mechanical (true). But `ALL`'s completeness rests on a
   hand-bumped `VARIANT_COUNT: usize = 41` (sidetable.rs:642-643), and the "excluded transients are
   empty at a crank boundary" audit trail (24-64) is prose only — nothing checks it, and (2) shows it
   is false for halted cranks. The human-readable variant docs contradict the descriptor for at least
   eight rows (Candidate 5).
4. "`Signature` covers the host callback table AND the boot-derived `SlotIndex` layout; a change to
   either must bump it" (format.rs:314-345; store-seam ledger 3084-3103 "Answered and implemented").
   **Partially / not mechanized.** The signature is an opaque string the host supplies; nothing in
   the engine derives or checks a boot-layout fingerprint. `image_to_interp` boots `Interp::new()`
   and swaps in the image's arenas (machine.rs:635-636); `boot_slot_count` (interp.rs:3738) is not
   serialized; `CREA` carries the *current* capacity, not boot geometry (image.rs:455-458). The lock
   `a_container_from_a_foreign_boot_layout_is_refused` (crafted_row_refusals.rs:246-277) only proves
   two different strings mismatch (Candidate 2).
5. "Streaming: the digest is fed the bytes as they are written, never re-buffered"
   (machine.rs:9-11, 151-155, 164-165; sha256.rs:7-9). **Docs drift.** `write_snapshot_to_file`
   first materializes the whole container (`self.write_snapshot(signature)?`, machine.rs:161) after
   `snapshot_image` already copied both arenas into a `MachineImage`; the hash is computed over the
   in-memory buffer. Peak memory at suspend is roughly three heap images.
6. "The writer emits atoms in canonical order; reader requires an in-order subsequence"
   (format.rs:152-168). **Upheld** (image.rs:4374-4387).
7. "The reader accepts `MIN_READ..=current` and refuses newer; older versions are a subset with the
   same encodings" (format.rs:179-205). **Upheld as coded; soundness rests on discipline.** There
   are no per-version decode branches, so it holds only if no atom encoding ever changed under a
   stable tag. The only committed fixtures are `store-v5.{container,ihstore}`; container versions
   1-4 and 6-11 are not pinned by a golden vector (low-confidence observation).
8. "`suspend_to_cas`: write to a temp file, atomically rename to `{cas_dir}/{sha256}`"
   (machine.rs:12-15, 175-178). **Upheld for a single writer; violated under concurrency.** The
   temp name is the constant `.snapshot.tmp` (125). The xsnap crate this surface mirrors uses
   `.snapshot.{pid}.{seq}.tmp` and its comment names exactly this race (xsnap/src/lib.rs:737-746).
   ironhorse also leaves the temp file behind on a write failure (xsnap removes it, 752-755)
   (Candidate 3).
9. "Metering state travels; a resumed machine continues its meter exactly" (format.rs:41-46,
   machine.rs:44-48). **Upheld.** `METR` + cost-table version gate (image.rs:4440-4449);
   `arm_meter` resets the index by design (interp.rs:10658-10670) while `rearm_meter`/
   `reattach_meter_host` preserve it (10672-10699), with locks in `persist_gates.rs:150-183,
   193+`. The machine.rs docs never mention that a resumed `Interp` has `meter_host == None` and
   must be re-armed through one of those three forms — only the vm's doc does (10680-10683).
10. "`partial_collect` roots every side-table-held reference; parity with the full collector's
    `extra_edges` is locked" (machine.rs:1924-1931; interp.rs:44658-44691). **Upheld in structure;
    release-unchecked.** `each_side_table_ref_tail` (44761-44941) enumerates functions (closures,
    home), bound functions (target, this_arg, args), ctor_prototype, wrapper_data, proxies,
    revokers, accessors, private elements, disposable stacks, async generators (frames + requests),
    segment iterators, Intl bound-function owners, `bound_format`, typed arrays/data views, iterators
    (iterable, result), promises (result + reactions + combinators + from_async), generators,
    async instances, promise functions, symbol key/registry descriptors; bulk arrays/collections come
    from `side_refs` counts. The counts-vs-enumeration parity net is `#[cfg(debug_assertions)]`
    (44716-44731); in release a missed counted mutation frees a live page silently (Candidate 13).
11. "Snapshot bytes are deterministic (no HashMap iteration order leaks)". **Upheld** in every
    accessor read: `arrays_snapshot` 8549, `collections_snapshot` 8577, `errors_snapshot` 8935,
    `array_buffers_snapshot` 8984, `typed_arrays_snapshot` 8998, `data_views_snapshot` 9011,
    `wrappers_snapshot` 9113, `regexps_snapshot` 9144, `arguments_brands_snapshot` 9176,
    `dates_snapshot` 9200, `function_state_snapshot` (BTreeSet 9214, sorts 9269/9282/9290/9297),
    `proxy_state_snapshot` 9416, `accessors_snapshot` 9498, `intl_bound_functions_snapshot` 9547,
    `private_elements_snapshot` 9595, `disposable_stacks_snapshot` 9662, `saved_frame_snapshot`
    sorts both `id_map`s 9688-9693, `generators_snapshot` 9775, `promise_cluster_snapshot`
    9823/9830, `temporal_snapshot` 10157/10163, `intl_snapshot` 10277, `iterators_snapshot` 10384,
    `symbol_key_table` 10464, `symbol_registry_snapshot` 10511. `metamorphic_determinism.rs` locks
    seven-way byte agreement.
12. "`#![forbid(unsafe_code)]`" (lib.rs:1). **Upheld.** `LazyPin.store_addr: *const ()`
    (machine.rs:782) is compared, never dereferenced.
13. "Compartment native from the start, SES/Compartment per XS" (design 565-579) vs.
    `Modules` ledger row naming `module::ModuleGraph` (sidetable.rs:380-383, 586). **Drift.**
    `ModuleGraph` lives in `compartment::Compartment` (compartment.rs:120, 149), a host-side Rust API
    that is explicitly *not* a guest-callable intrinsic and whose `evaluate` boots a fresh
    `Interp::new()` per call (compartment.rs:34-48, 294-307). No module or compartment state is
    inside the machine the snapshot serializes, and the persist gate cannot see it (Candidate 6).

## Architectural observations

- **Coupling / monolith symptoms.** The crate's correctness is a function of `Interp`'s 100+ fields
  and ~45 accessor/restore pairs in the 45k-line interp.rs. `machine.rs::side_tables_of` (289-420),
  `restore_side_tables` (432-616), `SideTableImages` (264-287), `SmallState` (902-940) and
  `MachineImage::with_*` each restate the same 22-row list by hand; adding a row touches five
  hand-maintained lists plus the ledger. The 22-argument `restore_side_tables` carries
  `#[allow(clippy::too_many_arguments)]` (431).
- **Hidden state outside `Interp`.** `Compartment` (globals, `ModuleGraph`, realm counter) is a
  host-side struct not reachable from the machine; `meter_host`/`source_compiler` are host closures
  that cannot travel and must be re-attached after resume, but the resume verbs return a bare
  `Interp` and the machine.rs docs do not say so.
- **Ledger reasoning vs. checking.** The reconciliation tests check membership of field names in
  classification groups and the presence of `self.X.is_empty()` substrings in `is_quiescent`. They do
  not check the *properties* the groups assert (transients empty at a boundary; boot-derived fields
  re-derivable). Candidate 1 is a direct consequence.
- **Panics/unwraps on untrusted data.** The container reader path in this region is clean:
  `AtomReader::parse`, `Version::decode`, `Signature::decode`, `decode_slot` all bounds-check and
  return errors; `sha256::hex`'s `unwrap` (194-195) is on `from_digit(<16)`, unreachable.
  `decode_slot` relies on `debug_assert_eq!` for its 20-byte precondition (slot_codec.rs:104) and
  would index-panic on a short slice in release — every caller passes exactly 20 bytes
  (image.rs:887, slot_codec.rs:150), so it is an internal contract, not an input hazard. The lazy
  fault path (`StorePageSource`, machine.rs:1464-1519) and the two collectors' `assert!`
  (1957-1960, 2051-2054) panic by design (documented deterministic crashed crank).
  `intl_bound_functions_snapshot` indexes `self.functions[function]` (interp.rs:9526, 9537) — an
  internal invariant, panics only if the live machine is already inconsistent.
- **Writer-side silent truncation.** `AtomWriter` casts `total as u32` (atom.rs:40, 50) with no
  check; a >4 GiB payload (a HEAP atom past ~214M slots, or a BLOC of that size) would emit a
  wrapped length and a mis-framed container rather than an error.
- **Determinism.** No `HashMap` iteration order reaches the wire (see contract 11). No f64
  formatting/parsing: numbers travel as raw bits (slot_codec.rs:78, 125-127; dates/regexp
  `last_index` as `to_bits`). No host time, locale, or randomness in the region. `generational_
  collect` is documented as not resume-invariant and is confirmed to be reached only from tests and
  benches (`rg generational_collect` over rust/: machine.rs, gc_machine.rs, gc_bench.rs,
  ironhorse-store-sqlite tests).
- **GC-root / side-table hazards.** The partial collector's root projection is the third hand-kept
  enumeration of side-table edges (`extra_edges` 43806+, `each_side_table_ref_tail` 44761-44941,
  and the gc_visitation_registry test); the counts-vs-walk parity net is debug-only.
- **Snapshot-coverage hazards.** Three honest `Pending` rows remain (`async_instances`,
  `async_generators`, `module::ModuleGraph`), gated by reaction kind / live owner
  (interp.rs:8656-8686). The remaining silent-wrong class recorded in the store-seam ledger — a
  runtime-minted native reached through a plain data property — is now covered by the traversal
  gate (8688-8730+, ledger P1-4 FIXED). `regexp_last_names` and `from_async` are documented per-crank
  satellites. The `lastIndex` docs (interp.rs:4365-4369, sidetable.rs:283-285) say it is an arena
  own property, but it is `RegExpData.last_index` in the side table and travels in `REGX`
  (interp.rs:9140, 9164) — stale prose, not a double source of truth.
- **Metering-doctrine drift.** None in this region: the `METR` atom carries a cost-table version
  string and refuses a mismatch (design row 6). The tests' comments still speak XS-parity language
  ("30 computrons ... captured from the oracle", machine.rs:1762-1764), consistent with the census's
  observation that the meter is calibrated raw-exact against XS.
- **Error-handling shape.** Two error enums: `SnapshotError` (pure decode, `Eq`) and
  `MachineSnapshotError` (adds `Io`/`NotQuiescent`/`PendingStateUnsupported`); `StoreError` wraps
  `SnapshotError`. vm `restore_*` verbs return `bool`, translated into `Corrupt(&'static str)` with a
  fixed message per verb (machine.rs:469-614) — the message set is the de-facto error taxonomy and is
  matched by string in tests (crafted_row_refusals.rs:46).
- **API-boundary leaks.** `MachineSnapshot::persist_gate` defaults to `Ok(())` (139-141) so any
  other implementor bypasses every gate; `Interp.slots`/`chunks` are `pub` and mutated directly by
  this crate (`clear_dirty`, `advance_backing`), so arena dirty-tracking is a cross-crate protocol
  with no type-level guard; `resume_from_cas` trusts the caller's digest.
- **Performance-architecture.** Suspend = arena copy into `MachineImage` + full serialization +
  chunked write with `sync_all` per file and a directory fsync (machine.rs:170-171, 193); resume =
  `read_to_end` + full boot (`Interp::new()`, unmetered intrinsic construction) + arena swap. The
  store path exists precisely to avoid the O(heap) blob rewrite; the blob path still is O(3×heap)
  memory. `AtomReader::parse`'s duplicate check is O(n²) over at most 34 atoms — fine.

## Candidate findings (most architecturally significant first)

1. **Persist gates admit a crank halted at a top-level loop-closing check.**
   `rust/engine/ironhorse-vm/src/interp.rs:10733` (consumed at machine.rs:199-201, 963, 1064).
   Claim: a `Halt::MeterAbort`/`StepLimit` at a top-level backward branch with an empty value stack
   and no open handler passes `is_quiescent()` and every persist verb, persisting a mid-crank heap
   while the un-serialized `locals`/`id_map`/`result` are dropped.
   Evidence: `is_quiescent` tests `call_stack, stack, jumps, promise_jobs, gen_run_stack,
   async_run_stack, async_gen_run_stack, exception, id_space_exhausted` (10734-10742); `if completed
   { self.result = Slot::undefined(); self.locals.clear(); self.id_map.clear(); }` (11234-11238);
   probe: `let i = 0; while (true) { i++; }` -> `completed=false halt=MeterAbort is_quiescent=true
   write_snapshot => Ok (23122 bytes)`.
   Why it matters: the gate is the documented safety net for every non-managed caller
   (machine.rs:961-962) and the ledger's whole "transients are empty at the boundary" audit trail
   (sidetable.rs:34-64) rests on it; a store checkpoint after such a halt commits a torn epoch that
   validates cleanly. The lock (`persist_gates.rs:37-44`) covers only the `throw` shape. Fix: an
   explicit `last_crank_completed` latch set by `run`, or add `locals`/`id_map`/`result` to the
   predicate and to the `empty_at_boundary` reconciliation. Confidence: high (reproduced).

2. **The engine-compatibility gate (`SIGN`) has no engine-side fingerprint; boot-layout
   compatibility is a host-string convention.** `rust/engine/ironhorse-snapshot/src/format.rs:327`.
   Claim: two engine builds whose `create_intrinsics` allocate different slot layouts, handed the
   same host `Signature` string, adopt each other's containers without error and bind boot-derived
   maps (`functions`, `*_proto`, `intrinsics`) to unrelated slots.
   Evidence: "Adoption boots a fresh machine and then REPLACES its arenas with the image's ...
   Nothing else catches it: `boot_slot_count` is not serialized" (format.rs:329-335); `let mut interp
   = Interp::new(); interp.restore_snapshot_state(slots, chunks, ...)` (machine.rs:635-636); the lock
   compares `Signature::new("ironhorse-worker-v1-boot2")` against `sig()` (crafted_row_refusals.rs:
   250-264).
   Why it matters: the design promises containers survive "daemon replacement and compatible engine
   upgrades" (format.rs:338-341; store-seam ledger 3084-3089). Every prior boot-heap change on this
   branch was a golden re-pin; at release the only thing standing between an upgrade and silent
   misbinding is a human remembering to change a string. A `boot_slot_count` + boot-arena digest in
   `VERS`/`CREA` compared at read is cheap. Attribution: store-seam ledger P1-2 follow-up, marked
   "Answered and implemented" (3084-3103) — implemented as prose contract, not mechanism.
   Confidence: high.

3. **`suspend_to_cas` uses a fixed temp filename in a shared CAS directory.**
   `rust/engine/ironhorse-snapshot/src/machine.rs:125`.
   Claim: two machines (or processes) suspending concurrently into one `cas_dir` both create
   `.snapshot.tmp`, so one `rename` can publish interleaved or truncated bytes under a digest they do
   not hash to.
   Evidence: `const CAS_TMP_NAME: &str = ".snapshot.tmp";` (125); `let tmp_path =
   cas_dir.join(CAS_TMP_NAME); let file = File::create(&tmp_path)?;` (185-186); xsnap: "Unique temp
   name: a fixed name would let two processes ... interleave writes and corrupt each other"
   (`rust/endo/xsnap/src/lib.rs:737-746`, `.snapshot.{pid}.{seq}.tmp`).
   Why it matters: the CAS's only integrity property is name == sha256(content); the daemon design
   shares one CAS across workers. The mirrored xsnap surface already fixed this; the port regressed
   it (and drops the failure-path `remove_file`). Confidence: high (by inspection; not exercised).

4. **Trailing bytes inside VERS/CREA/HEAP/STAC payloads are accepted, so one machine has many
   valid CAS keys.** `rust/engine/ironhorse-snapshot/src/format.rs:251`.
   Claim: appending one byte to any of those four payloads yields a container that `read_machine`
   accepts, hashes differently, and re-emits identically to the honest bytes.
   Evidence: `if payload.len() < 10 { return Err(VersionError::Truncated); }` (format.rs:251);
   `if p.len() - i < want { ... "HEAP records truncated" }` with no `==` (image.rs:807); probe:
   `VERS+1: ACCEPTED (sha256 7b1a...), re-emitted == honest: true` (likewise CREA, HEAP, STAC).
   Why it matters: format.rs:152-163 and atom.rs:68-78 make "exactly one container encoding" the
   stated basis for the CAS key being an identity, and `non_canonical_container_encodings_are_
   refused` claims to close the class. Fix: `Cursor::done()`-style exact-length checks in those four
   decoders (the side-table decoders already have them, image.rs:890-895). Confidence: high
   (reproduced).

5. **The ledger's human-readable variant docs contradict its machine-checked coverage for ~8 rows
   (plus stale module docs).** `rust/engine/ironhorse-snapshot/src/sidetable.rs:186`.
   Claim: `Proxies` (186-192 "honestly `Pending`"), `Accessors` (213-217), `PrivateElements`
   (302-303 "does not yet travel"), `DisposableStacks` (306-307), `Dates` (325), `CtorPrototype`
   (344-348 "stays `Pending`"), `RegExps` (283-285 lastIndex "in the arena") each say Pending/absent
   while `descriptor()` returns `Serialized` (505, 519, 569, 570, 567, 465, 560).
   Evidence: `/// ... so honestly `Pending` ... until an atom carries it` (191-193) vs
   `SideTable::Proxies => ("proxies/proxy_revokers", Serialized)` (505); machine.rs:50-56 "What it
   does not carry yet ... closures, generators, promises, collections"; machine.rs:88-91
   "(wave-6 W6-9: proxies, accessors, typed arrays)"; format.rs:237/432 "`ENDR` magic" (it is
   `IRON`, 177); format.rs:470 asserts `>= 10` under a doc describing versions 7-8 while the stamp is
   12.
   Why it matters: the ledger's stated purpose is to be the document a maintainer reads to know what
   travels; half of it now says the opposite of the code. Confidence: high.

6. **Module/compartment state is outside the machine the ledger and gates can see.**
   `rust/engine/ironhorse-snapshot/src/sidetable.rs:586`.
   Claim: the `Modules` row names `module::ModuleGraph`, which is not an `Interp` field — it lives
   in the host-side `Compartment` struct — so neither `stored_unpersistable_row` nor the struct
   reconciliation can ever gate or track it, and the design's "native Compartment" is not what
   exists.
   Evidence: `SideTable::Modules => ("module::ModuleGraph", Pending)` (586); `pub modules:
   ModuleGraph` / `modules: ModuleGraph` (compartment.rs:120, 149); "ironhorse models `Compartment`
   as a host-side Rust realm API ... **not** as a guest-callable `Compartment` intrinsic"
   (compartment.rs:34-37); `pub fn evaluate(&self, bytecode) { let mut interp = Interp::new(); ...`
   (294-307).
   Why it matters: today nothing is lost (no guest can create module state), but the snapshot
   architecture — one `Interp` is the whole machine — is incompatible with the SES/Compartment
   requirement as designed; whichever way that is resolved, the ledger's "enumerated against
   `Interp`'s fields" premise stops being sufficient. Confidence: high on facts; the severity is a
   design question.

7. **`resume_from_cas` never verifies the content address.**
   `rust/engine/ironhorse-snapshot/src/machine.rs:712`.
   Claim: a CAS blob whose bytes do not hash to its filename is accepted whenever it passes
   structural validation.
   Evidence: `let path = cas_dir.join(sha256); let file = File::open(&path)?; from_snapshot_file(
   file, expected_sig)` (717-719); `from_snapshot_file` does `read_to_end` then decodes (706-708).
   Why it matters: the store path verifies every row against sealed leaf hashes; the blob path
   trusts the name. The bytes are already fully in memory, so re-hashing is free and makes the
   identity two-sided (and would have caught Candidate 3's corruption). Confidence: high.

8. **`all_is_exhaustive` is not the compiler-forced guard its docs claim.**
   `rust/engine/ironhorse-snapshot/src/sidetable.rs:642`.
   Claim: adding a `SideTable` variant with a `descriptor` arm but without an `ALL` entry passes
   `all_is_exhaustive` unless a human also bumps `VARIANT_COUNT`.
   Evidence: "Adding a `SideTable` variant without adding it here fails `all_is_exhaustive`"
   (397-398); `const VARIANT_COUNT: usize = 41; assert_eq!(SideTable::ALL.len(), VARIANT_COUNT);`
   (642-643).
   Why it matters: `pending()`, the EmptyAtBoundary reconciliation and every `ALL`-driven check
   silently skip an unlisted variant. Derive `ALL` from the exhaustive match (or a discriminant
   range) instead. Confidence: high.

9. **The "streaming, never re-buffered" suspend path materializes three heap images.**
   `rust/engine/ironhorse-snapshot/src/machine.rs:161`.
   Claim: `write_snapshot_to_file` hashes an in-memory container built from an in-memory
   `MachineImage` that itself copied both arenas.
   Evidence: `let bytes = self.write_snapshot(signature)?;` then `for chunk in bytes.chunks(64 *
   1024) { hasher.update(chunk); file.write_all(chunk)?; }` (161-169); `MachineImage::from_arenas(
   ..., &self.slots, &self.chunks, ...)` copying `slots.records()`/`chunks.raw_vec()`
   (image.rs:459-460); docs "the digest is never computed over a re-buffered copy" (164-165) and
   sha256.rs:7-9.
   Why it matters: the design's suspend/resume envelope ("Streaming write/read ... unchanged") is
   not what ships; for a large worker heap this is the peak-memory event of its lifetime. Confidence:
   high (docs drift certain; memory figure by inspection).

10. **Hand-rolled SHA-256: correct by inspection, but its verification is partly self-referential and
    the code is duplicated.** `rust/engine/ironhorse-snapshot/src/sha256.rs:11`.
    Claim: the only independent oracle is three NIST vectors; `block_boundary_lengths_are_exact`
    compares the implementation's streaming path with its own one-shot path, so a padding bug common
    to both at lengths 55/57/63/64/65/119/120/128 would pass; `update` and `raw_update` are verbatim
    copies.
    Evidence: "covered by the known-answer tests in this module ... so a transcription error cannot
    slip through" (11-14); `assert_eq!(streamed, hex_sha256(&data), "len {len}")` (251); 64-89 vs
    115-138.
    Why it matters: the digest is the CAS identity and the store's leaf/seal hash; a dev-dependency
    on `sha2` (dev-deps already pull `ironhorse-compile`, Cargo.toml) for a differential KAT plus the
    million-'a' vector would make the claim true without touching the shipped surface. The
    "why not a crate" is the documented zero-external-deps policy (sha256.rs:4-7, lib.rs:37-38).
    Confidence: high on facts; low severity.

11. **`AtomWriter` silently wraps atom sizes past `u32::MAX`.**
    `rust/engine/ironhorse-snapshot/src/atom.rs:40`.
    Claim: a payload of >= 2^32 - 8 bytes emits a wrapped length prefix and a mis-framed container
    rather than an error.
    Evidence: `self.body.extend_from_slice(&(total as u32).to_be_bytes());` (40);
    `out.extend_from_slice(&(total as u32).to_be_bytes());` (50).
    Why it matters: unrealistic under metering today, but the writer is the one place that should
    never produce bytes the reader refuses; `u32::try_from(total)` is one line. Confidence: high;
    low severity.

12. **The 1..=12 read range is asserted, not pinned.**
    `rust/engine/ironhorse-snapshot/src/format.rs:205`.
    Claim: the reader decodes twelve format versions with no per-version branches, so every atom's
    encoding must have been frozen since its introduction, yet only a schema-5 *store* fixture is
    committed (`tests/fixtures/store-v5.{container,ihstore}`).
    Evidence: "every version-1 writer in this lineage either emitted the same atom encodings this
    reader knows or refused machines whose state could not travel" (200-204); `IRONHORSE_FORMAT_
    VERSION_MIN_READ: u32 = 1` (205).
    Why it matters: a container written by an intermediate version whose (say) `GENR` or `PRMS`
    encoding later changed under the same tag would decode into a wrong machine with no error, and
    nothing in CI would notice. Confidence: medium (I did not audit image.rs's encoders for
    historical changes).

13. **The counted side-table ref pages are cross-checked only in debug builds.**
    `rust/engine/ironhorse-vm/src/interp.rs:44716` (consumed at machine.rs:1991, 2092).
    Claim: in a release build, a `SideRefCounts` mutation missed by `crate::bulk` lets
    `partial_collect` free a page reachable only through an array item or collection entry, with no
    check anywhere.
    Evidence: `#[cfg(debug_assertions)] { ... debug_assert_eq!(bits, walked, "counted bulk pages
    diverge from the side-table enumeration"); }` (44716-44731); `for (p, hit) in interp.side_table_
    ref_page_bits()...` (machine.rs:1991).
    Why it matters: this is the exact unsoundness class the doc names (44667-44669); the release
    collector trusts a derived cache that only tests can validate. A release-mode consistency check
    at a low cadence, or a test that runs the collector in release profile, would bound it.
    Confidence: medium (soundness today depends on `bulk.rs`, which I did not read).

## What is done well

- The container reader is genuinely fail-closed on framing: exact envelope consumption, duplicate
  tags, canonical order, unknown tags, present-but-empty optional atoms, populated `STAC`, free-list
  and live/free accounting, and clamp-before-allocate on every count (atom.rs:122-150,
  image.rs:4374-4411, 786-828) — with fuzz trophies cited inline.
- Snapshot byte determinism is taken seriously everywhere I looked: every side-table accessor sorts
  by owner (including nested `id_map`s), numbers travel as raw bits, and a seven-way metamorphic
  suite locks it.
- The ledger's *mechanical* halves are real engineering: an exhaustive `descriptor` match, a
  two-way struct-field reconciliation parsed from source, and an `is_quiescent`-body reconciliation
  — so a new `Interp` field cannot land unclassified.
- The persist gate moved from "enumerate the holders" to "compute the doomed set, then traverse
  what is written" (interp.rs:8688-8730), which is the right shape and is O(dirty) at checkpoint.
- The store session makes the machine/session mispairing unrepresentable by ownership, verifies
  (epoch, seal) before every commit, re-checks the manifest after non-atomic reads, and refreshes
  the lazy pin's leaves on its own commits — each with the review finding that motivated it recorded
  at the code.
- Error handling is structured on all build profiles (every vm `restore_*` `false` becomes a named
  `Corrupt`), and the region has no `unwrap`/`expect` on untrusted bytes.
