## Purpose and responsibilities

This region is the **machine boot**: `Interp::new` builds the arenas and every side table, then `create_intrinsics` (5439–6386) plus the `create_*` family (6406–7145) allocate the whole primordial object graph — constructors, prototypes, namespace objects (`Math`, `JSON`, `Reflect`, `Atomics`, `Intl`, `Temporal`, `$262`), native method function instances, well-known symbols — **without installing any properties**. Properties are recorded as *pending rows* in five Vec side tables (`proto_methods`, `proto_data`, `proto_accessors`, `proto_value_data`, `well_known_symbols`) plus `error_stack_accessor`.

The second half is **linking**: `link_intrinsics(names)` (7373) → `bind_program_symbols` (7263: pure derivation of `symbol_names`/`symbol_ids`/the `*_id` caches from the program's SYMB atom) → `install_intrinsic_bindings(names, full, keep)` (7416–7888), which materializes global bindings and prototype properties **only for names the program's symbol table contains** (plus a set of force-intern heuristics), keyed by the compiler's program-local `u16` ids. The same body is reused with `full=false` by `relink_crank`/`install_pending_intrinsics` and the eval bridge to lazily install names a later unit first mentions, create-only.

Boot is unmetered by design (XS's intrinsics pre-exist the guest); `boot_slot_count` (5377) marks the boundary below which slots are "boot natives re-minted identically by a fresh boot", the invariant the snapshot restore path (`image_to_interp` → `Interp::new()` then arena replacement) depends on.

## Invariants and contracts claimed (from doc comments) — and whether the code visibly upholds each

1. **"Materialize the intrinsic constructor instances once, at machine boot, before any guest bytecode runs — so they carry no run-only metering"** (5432–5438). *Upheld.* No `meter.tick*` in the region's boot paths; `alloc_str_text` and `slots.alloc` are unmetered primitives; `create_global_property` documents "does not meter" (10596).
2. **"Boot-derived … at deterministic slot indices; a fresh boot lands them at the same indices the snapshot arena's boot region uses"** (sidetable.rs 72–80; interp 8266–8269). *Upheld for a given build* — every boot loop iterates fixed-order `Vec`/array literals; the single HashMap iteration (6371–6376) performs idempotent writes whose order is unobservable. *Not enforced across builds*: nothing serializes `boot_slot_count` or a boot-region fingerprint; the `Signature` is a hand-stamped string (format.rs 326–345 admits this).
3. **"`bind_program_symbols` is a pure function of `names` — touches no arena and reads no other state"** (7255–7262). *Upheld*; it only writes `symbol_names`, `symbol_ids`, and the id caches. (It does not bound `names.len()` — see finding 7.)
4. **Install passes are create-only on partial passes so "a re-install would clobber a guest monkeypatch or deletion" cannot happen; branches depending on no program name run "on every FULL link" only** (7384–7415). *Violated at two sites*: the `%AsyncGeneratorPrototype%.constructor` write (7625–7635) and the `%Error.prototype%.stack` accessor write (7683–7707) have no `keep`, no `full`, no `find_property` guard, and sit above the `if !full { return; }` gate (7735). The test the doc cites as the lock (`relink_preserves_guest_intrinsic_edits`) does not exist under that name; `tests/relink_preserves_guest_edits.rs` covers only the `@@iterator`/`@@toStringTag` branches.
5. **`gc_visitation_registry.rs:360`: `error_stack_accessor` is "DocumentedOnly" because "the installed pair is a property of the rooted %Error.prototype%".** *Violated*: installation is conditional on the program naming an Error-family constructor or `stack` (7684–7698); for every other program the getter/setter function slots (6262–6263) are reachable only through the un-rooted field.
6. **"The `prototype` link is a mandatory own property regardless"** (6064, 7567–7578). *Upheld*: `intern_key("prototype")` is unconditional in the methods loop and the id is stored in `prototype_key_id`.
7. **"Set.prototype.keys IS Set.prototype.values", "trimLeft IS trimStart"** (5834–5843, 7059–7075). *Upheld* — single allocation bound under two keys.
8. **"Every native function instance chains to %Function.prototype%"** (6341–6350). *Upheld*, but by `alloc_method`/`alloc_named_method`/`alloc_named_native`/`create_eval`/`create_proxy` all passing `self.function_proto`, which is set at 5448 before the first `alloc_method` (5603); the fixup pass at 6365–6385 therefore never finds a NULL prototype (dead code whose comment describes a hazard that no longer exists).
9. **"Force-interning charges no metering because the names are boot default keys"** (7488–7489, 7527, 7544). *Upheld*: `default_keys.rs` contains `done`, `has`, `keys`, `next`, `prototype`, `return`, `size`, `stack`, `value`, `values` (lines 192–472) and `intern_key` (34991) ticks only for non-default names.
10. **"`Temporal.Now`'s clock is a deterministic host hook"** (6732–6735) and `Date.now` (6981 op 2). Not verified in this region (dispatch lives elsewhere); the census reports no host clock in the vm crate.
11. **Design § SES/Compartment: "intrinsics are created once per machine and referenced per-realm"** (designs/ironhorse-engine.md 570–574; compartment.rs 4–9, 58–62). *Not upheld*: `Compartment::evaluate_with_symbols` boots a fresh `Interp::new()` per call (compartment.rs 318–333) and `Intrinsics` is `{ locked_down: bool }` (63–68); no primordial object is shared across compartments or across two evaluations.

## Architectural observations

**Coupling / hidden state.**
- The realm's *shape* is a function of the program's symbol table. `install_intrinsic_bindings` creates a global or prototype property only when `symbol_ids` has the name (7427–7436, 7579–7595). Runtime interning (`append_name_key`, 35006–35034) does **not** trigger an install; only the next `relink_crank`/eval unit does (`install_pending_intrinsics`, 8412–8419). So `Math["P"+"I"]` is `undefined` in the crank that first computes it and `3.14…` in the next crank; `Reflect.ownKeys(Math)` / `Object.getOwnPropertyNames(Array.prototype)` return only the names the program text (plus prior cranks) mentioned; an iterator result object carries `value`/`done` only if those names were interned (7505–7518 comment). This is deterministic per (program, crank-sequence) but it is not "shared frozen intrinsics", and SES `lockdown`/`harden` traverse intrinsics by `Reflect.ownKeys` — they would see a program-dependent permit surface.
- Four growing heuristics compensate: set-methods (7490–7519), iterator-helpers (7520–7536), `groupBy` (7543–7553), `fromAsync` (7561), plus the Intl reflective branch (7581–7592) and the Error-family `stack` branch (7684–7698). Each keys on bare identifier presence (a program that names `map` for an unrelated reason triggers the iterator-helper widening).
- `proto_methods` is simultaneously a GC-root list, an install worklist, and an ordered override list (last push wins because `set_own_unmetered_with_flag` overwrites, 23540–23544). Correctness of `Number.prototype.toString` (6951–6957) and Set `keys`/`values` (5834–5843) depends on push order; nothing asserts a `(holder, name)` pair is pushed once.
- `installed_names_len` is set at the *start* of a pass (7425) while the pass itself appends names (`prototype` at 7573, `stack` at 7699, Intl members at 7592, set-method atoms at 7503); so after almost every first link `symbol_names.len() > installed_names_len`, guaranteeing a partial pass at the very next relink — which is exactly when the two ungated branches fire.

**Duplication / monolith symptoms.**
- ~70 near-identical `alloc_method` + `proto_methods.push` blocks; `create_intl` repeats a 6-line constructor/prototype/link idiom 7 times (6411–6504); `create_temporal` inlines statements on one line (6627, 6638, 6650, 6662). The intrinsic table wants to be data (a static table of `(owner, name, arity, NativeMethod, flags)`), not 1,700 lines of imperative pushes.
- The `id_of` closure pattern in `bind_program_symbols` (7276) is re-expressed as a macro in `refresh_special_ids_from_symbols` (7332) over the same 25 names — two lists to keep in sync.

**Panics / unwraps / indexing on untrusted data.**
- None panic-prone in the region itself. `bind_program_symbols` casts `(k + 1) as u16` (7275, 7276, 7310) with no bound; `names` comes from `parse_symbols`, which reads to the buffer end regardless of the count field (symbols.rs 24–44). Ids wrap silently for ≥65,535 names; `relink_crank` has a `TableFull` refusal (8359) that the initial `link_intrinsics` lacks.
- `unwrap_or(SlotIndex::NULL)` for `array_proto`/`iterator_proto`/collection/`arraybuffer`/`dataview`/`promise`/`regexp` protos (5592–5601, 5756–5760, 5874–5878, 5902–5906, 5939–5943, 6096–6100) would, if ever taken, feed `NULL` (= `u32::MAX`) holders into `proto_methods` and panic far away at `slots.get(NULL)` during link. Unreachable today because `Native::intrinsics()` is static.
- `instance_prototype` (7239) returns NULL for `inst.0 >= capacity` instead of surfacing the logic bug — contrary to the design's "a wrong index … surfaces as a deterministic panic" (§ Memory-safety).

**Determinism hazards.** Boot order is fixed (Vec/array literals; `Native::intrinsics()` is an ordered Vec). The `functions` HashMap iteration at 6371–6376 is order-independent (idempotent same-value writes) and, as noted, dead. No f64 formatting, libm, time, or locale in the region; numeric constants use `std::f64::consts` and `f64::from_bits(1)` (7133–7144, 6943). `gc_roots` sorts+dedups (43692–43693). Compartment global seeding is sorted by id (compartment.rs 301–306).

**GC-root and side-table hazards.**
- `error_stack_accessor`'s getter/setter (6262–6264) are not in `gc_roots`; the registry justification assumes unconditional installation. All other lazily-installed boot natives are rooted via `proto_methods`/`proto_accessors` or installed on every full link (`iterator_identity`, `string_iterator_method`, `segments_iterator_method`, `segment_iterator_identity`, `async_iterator_identity` at 7789–7860).
- Mitigating context: `collect_garbage` is not called from any non-test path in the engine workspace (grep: only `machine.rs` test module lines 1723/1759), so this is latent until the collector is wired into the crank lifecycle.

**Snapshot coverage hazards.**
- Every field this region owns is classified `BOOT_DERIVED` and *not serialized* (sidetable.rs 735–775); restore = fresh boot + arena replacement. Correctness therefore requires bit-identical boot layout between writer and reader builds, guarded only by a manually bumped `Signature` string (format.rs 326–345; `crafted_row_refusals.rs` 232–257 tests the refusal for a *different* string, not for a *changed boot*). `boot_slot_count` is not serialized (format.rs 334).

**Metering-doctrine drift.** None here: boot/link are unmetered in both XS and ironhorse. The region does *reference* "bit-exact against the pin" (7447) and "measured against the pin as exactly 256" (10636), consistent with the census's parity-wording drift; not load-bearing for this region.

**Error-handling shape.** Boot is infallible by construction (`unreachable!` arms at 6553–6566 document the partition of `Native` between the global loop and the separate builders). `link_intrinsics` is infallible on malformed `names` (wraps rather than refusing).

**API-boundary leaks.** `link_intrinsics` is `pub` and takes the raw name list; `set_source_compiler` is `pub`. `__ironhorseDataVersion` (6603) and `$262` (6867) are installed into every realm, guest-visible.

**Performance-architecture.** ~600 `alloc_method` calls per boot each allocate an empty-string chunk (7153); `create_proxy` immediately orphans one (6893–6896). Boot cost is paid per `Compartment::evaluate*` call (fresh `Interp::new()`), not per machine.

## Candidate findings

1. **Intrinsic surface is a function of the program's symbol table, not of the realm** — `interp.rs:7579` (and 7427–7436, 35006–35034).
   Claim: a property of a built-in (e.g. `Math.PI`, `Array.prototype.push`) exists on the object iff some linked unit's SYMB atom or a force-intern heuristic contains its name; a runtime-interned name installs nothing until the next relink.
   Evidence: `} else if let Some(&id) = self.symbol_ids.get(mname) { Some(id) } … else { None };` (7579–7595); `if let Some(mid) = mid { … self.set_own_unmetered_with_flag(proto, mid, …)` (7596–7617); `append_name_key` only calls `refresh_special_ids_from_symbols()` (35032).
   Why it matters: `Reflect.ownKeys(intrinsic)`, `Object.getOwnPropertyNames`, `for-in`, `JSON.stringify(it.next())`, and computed-key access observe a program-dependent, crank-dependent realm; SES `lockdown`/`harden` permit traversal cannot be faithful over it; the compensating heuristics (7490–7561, 7581–7592, 7684–7698) grow per feature. Category: api-boundary. Severity: high. Confidence: high (by construction; behavior inferred from code, not executed).

2. **`%Error.prototype%.stack` accessor is re-installed on every partial install pass, reverting guest redefinition/deletion** — `interp.rs:7683`.
   Claim: for any program that names an Error-family constructor, the crank after a relink resets `Error.prototype.stack` to the boot getter/setter pair even if the guest redefined or deleted it in the previous crank.
   Evidence: `if let Some((proto, getter, setter)) = self.error_stack_accessor { … if names_error_family { let sid = self.intern_key_unmetered("stack"); self.set_own_accessor_unmetered(proto, sid, Some(…getter), Some(…setter)); } }` (7683–7707) — no `keep`, no `full`, above `if !full { return; }` (7735); `set_own_accessor_unmetered` overwrites an existing property (23574–23578); floor set before the pass (7425) while `intern_key_unmetered("stack")` appends, so `install_pending_intrinsics` (8413) fires next relink.
   Why it matters: SES error taming installs its own `stack` accessor; a later crank silently un-tames it. Same bug class the fn doc claims fixed ("locked by `relink_preserves_guest_intrinsic_edits`" — no such test exists; `tests/relink_preserves_guest_edits.rs` covers only symbol-keyed branches). Category: security. Severity: high. Confidence: high (code path traced; not executed).

3. **`%AsyncGeneratorPrototype%.constructor` is re-set on every partial pass** — `interp.rs:7625`.
   Claim: whenever `constructor_id` is `Some`, every `install_intrinsic_bindings` call (full or partial) overwrites `AsyncGeneratorPrototype.constructor`, resurrecting a deleted or redefined property.
   Evidence: `if let Some(cid) = self.constructor_id { self.set_own_unmetered_with_flag(self.async_generator_proto, cid, …, XS_DONT_SET_FLAG | XS_DONT_ENUM_FLAG); }` (7625–7635), no `keep`/`full`/`find_property` guard.
   Why it matters: violates the create-only contract (7384–7415); configurable property, so a guest `delete` is legal and silently undone. Category: other. Severity: medium. Confidence: high.

4. **`error_stack_accessor` getter/setter function slots are not GC roots; the registry's justification assumes an unconditional install** — `interp.rs:6262` (roots 43502–43695; registry `tests/gc_visitation_registry.rs:360`).
   Claim: for a program that never names an Error-family constructor or `stack`, a full collection frees both accessor function slots and drops their `FuncInfo`; a later relink that names `Error` installs an accessor referencing freed/reused slots.
   Evidence: `self.error_stack_accessor = Some((error_proto, stack_getter, stack_setter));` (6264) — the only holder; `gc_roots` roots `proto_methods`/`proto_data`/`proto_accessors` (43593–43607) but not this field; `self.functions.retain(|k, _| !dead.contains(k));` (44577); install is gated by `names_error_family` (7684–7698).
   Why it matters: a deterministic wrong-callee bug (kind-checked, so not memory-unsafe) in a SES-relevant path; the mechanical registry passes because the classification is `DocumentedOnly` with a false premise. Latent today: `collect_garbage` is called from no production path (only `machine.rs` tests 1723/1759). Category: gc-roots. Severity: medium. Confidence: high on the omission, medium on reachability (requires GC wiring).

5. **Snapshot restore's boot-layout identity rests on a hand-stamped `Signature` string; no boot fingerprint travels in the image** — `interp.rs:5377` / `ironhorse-snapshot/src/format.rs:326`.
   Claim: adding or reordering a single `alloc_method` in `create_intrinsics` shifts every boot `SlotIndex`, and a snapshot from the previous layout restores without refusal unless a developer also changed the signature string.
   Evidence: `interp.boot_slot_count = interp.slots.capacity();` (5377, never serialized — format.rs 334: "`boot_slot_count` is not serialized"); `let mut interp = Interp::new(); interp.restore_snapshot_state(slots, chunks, …)` (machine.rs 635–636); format.rs 341–344: "While this branch is unreleased … a boot-layout change is taken as a golden-pin content re-pin; at release the signature must move with it."
   Why it matters: this is the single most fragile coupling in the engine — 1,700 lines of boot code whose every edit is a silent wire-compatibility break; a serialized `boot_slot_count` + boot-region hash compared at restore would make it checkable. Acknowledged by the authors; reported as still open. Category: snapshot-coverage. Severity: high. Confidence: high.

6. **Intrinsic global bindings (and `globalThis`) are created with flag 0 — enumerable and configurable — where XS/spec require `enumerable: false`** — `interp.rs:7442` (7475; `value.rs:349–353`).
   Claim: `Object.keys(globalThis)`, `for (k in globalThis)`, and `Object.getOwnPropertyDescriptor(globalThis, 'Object').enumerable` report the intrinsic constructors and namespaces as enumerable.
   Evidence: `self.create_global_property(id, (Kind::Reference, Payload::Reference(func)));` (7442) with `Slot::property` → `flag: 0` (value.rs 355–363); only the `undefined/NaN/Infinity` branch adds flags (7454–7455); grep finds no `DONT_ENUM` applied to globals and no top-level `built-ins/*/prop-desc.js` in the 262 baseline.
   Why it matters: a result divergence from XS (`fxBuildGlobal`/`fxGlobalSetProperty` set `XS_DONT_ENUM_FLAG`) and from spec, unobserved because the corpus lacks the top-level `prop-desc` cases; SES's global-descriptor checks would trip. Category: other. Severity: medium. Confidence: medium-high (flag path verified; not executed).

7. **`bind_program_symbols` truncates ids with `as u16` on an unbounded, untrusted name list** — `interp.rs:7310` (7275, 7276; `symbols.rs:33–44`; `lib.rs:89–93`).
   Claim: a SYMB atom with ≥65,535 NUL-terminated strings yields wrapped ids (id 65,536 → 0 = `XS_NO_ID`, 65,537 aliases id 1) and `link_intrinsics` binds the wrong globals instead of refusing.
   Evidence: `let id = (k + 1) as u16; self.symbol_ids.entry(name.clone()).or_insert(id);` (7310–7311); `parse_symbols` "read strings to the buffer end rather than trusting the count" (symbols.rs 25–26); contrast `relink_crank`'s `return Err(RelinkError::TableFull)` (8359–8360).
   Why it matters: bytecode/SYMB is untrusted; the initial link should refuse like the relink does. Deterministic and memory-safe, so robustness not safety. Category: robustness. Severity: low. Confidence: high.

8. **`Compartment` does not share intrinsics with anything; each `evaluate*` boots a fresh machine** — `compartment.rs:320` (63–68; design §570–574).
   Claim: two compartments "over one machine's intrinsics" have no object in common, and two evaluations of the same compartment see different `Object.prototype` identities.
   Evidence: `let mut interp = Interp::new(); interp.link_intrinsics(&names); … interp.run(bytecode)` (compartment.rs 320–333); `pub struct Intrinsics { pub locked_down: bool }` (63–68); module doc: "intrinsics are created **once per machine** and referenced per realm" (4–5).
   Why it matters: the design's SES seam ("intrinsics created once per machine and referenced per-realm", "harden's transitive freeze worklist operates on the slot arena") has no implementation hook in this boot path — boot builds one realm per `Interp`, and there is no realm abstraction below `Interp`. Cross-region, included because it is a design claim I was asked to check. Category: docs-drift. Severity: medium. Confidence: high.

9. **Force-intern heuristics key on bare identifier presence and silently change iterator-result shape** — `interp.rs:7520` (7490–7561).
   Claim: a program that mentions `map`/`filter`/`find`/`some`/`every`/`reduce`/`forEach` for any reason interns `next`/`done`/`value`/`return` and seeds `value_id`/`done_id`, changing which own properties native iterator results carry.
   Evidence: `let iterator_helpers_used = ["map", "filter", …].iter().any(|name| self.symbol_ids.contains_key(*name));` (7520–7525); "the result carried no `done` and the driver spun forever" (7505–7512).
   Why it matters: each new built-in that drives the iterator protocol from Rust needs another site; the honest fix is to seed the protocol atoms unconditionally at boot (they are default keys, unmetered). Category: modularity. Severity: medium. Confidence: high.

10. **`proto_methods` install order is semantically load-bearing (last push wins) with no single-binding assertion** — `interp.rs:6951` (5834–5843, 23540–23544).
    Claim: the identity of `Number.prototype.toString` and `Set.prototype.keys` depends on Vec push order in `create_intrinsics`.
    Evidence: "a later push wins the link-time set, so this must follow the wrapper registration" (6952–6953); `if let Some(p) = self.find_property(inst, id) { … s.value = value.value; }` (23540–23544).
    Why it matters: a refactor that reorders builders changes intrinsic identity silently; the earlier wrapper `toString` function stays allocated and rooted forever. Category: modularity. Severity: low. Confidence: high.

11. **`installed_names_len` is set before the pass that appends names, so a partial pass always runs at the next relink** — `interp.rs:7425` (7573, 7592, 7699; 8413).
    Claim: after nearly every first link, `symbol_names.len() > installed_names_len` (because `prototype` is always interned at 7573), so `install_pending_intrinsics` runs a partial pass on the next crank even when nothing new was referenced.
    Evidence: `self.installed_names_len = names.len();` (7425) then `let pid = self.intern_key(mname);` (7573); `if self.symbol_names.len() <= self.installed_names_len { return; }` (8413).
    Why it matters: it is the trigger that makes findings 2 and 3 fire on the second crank of ordinary programs; setting the floor after the pass (or excluding pass-interned names) would confine partial passes to genuinely new names. Category: other. Severity: medium (as an enabler). Confidence: high.

12. **`instance_prototype` swallows out-of-range slot indices as NULL** — `interp.rs:7239`.
    Claim: a stale or corrupt `SlotIndex` reaching a prototype walk is treated as "no prototype" rather than surfacing as a deterministic panic.
    Evidence: `if inst.is_null() || inst.0 >= self.slots.capacity() { return crate::value::SlotIndex::NULL; }` (7239–7241).
    Why it matters: the design's memory-safety argument is that logic bugs surface as panics (crashed crank), not as silently different results; this hides them in `instanceof` and chain walks. Category: error-model. Severity: low. Confidence: high.

13. **The DET-6 "NULL-proto fixup" pass is dead code that iterates a HashMap and documents a hazard the code no longer has** — `interp.rs:6365`.
    Claim: no native function instance has a NULL prototype at 6365 because `function_proto` is assigned (5448) before the first `alloc_method` (5603) and every allocator passes it.
    Evidence: `let f = self.slots.alloc(Slot::instance(self.function_proto));` (7152, 7175, 6389, 6752, 6879); fixup: `.filter(|(f, fi)| (fi.method.is_some() || fi.native.is_some()) && **f != fp)` … `if p.is_null() { s.value = Payload::Reference(fp); }` (6374–6382).
    Why it matters: 45 lines of comment describe a restore-time version fork that cannot occur; dead determinism-sensitive-looking code (HashMap iteration) invites false alarms and hides the real restore hazard (finding 5). Category: docs-drift. Severity: low. Confidence: high.

14. **`%IteratorPrototype%[@@iterator]` is minted as `NativeMethod::AsyncIteratorIdentity`** — `interp.rs:5992`.
    Claim: the sync iterator identity function shares dispatch with the async one, so any future async-specific behavior in `AsyncIteratorIdentity` changes `%IteratorPrototype%[Symbol.iterator]`.
    Evidence: `self.iterator_identity = self.alloc_named_method(NativeMethod::AsyncIteratorIdentity, "[Symbol.iterator]", 0);` (5992–5996) beside `self.async_iterator_identity = self.alloc_method(NativeMethod::AsyncIteratorIdentity);` (5991).
    Why it matters: a latent coupling between two spec intrinsics that should be independent; harmless today (both return `this`). Category: modularity. Severity: low. Confidence: high.

Not promoted to a finding (uncertain): `Date.prototype` is registered as a Date instance with `NaN` (6979), which is ES5/XS-style rather than ES2015+ (`Date.prototype.getTime()` should throw); I believe XS's `fxBuildDate` does the same, so this is likely oracle-faithful — verify against the pin before treating it as a divergence.

## What is done well

- Boot allocation order is fully deterministic by construction: every intrinsic is enumerated from fixed-order `Vec`/array literals; the one HashMap walk is order-independent; `gc_roots` sorts and dedups so trace order never depends on hashing.
- The pending-row design (`proto_methods`/`proto_data`/`proto_accessors`/`proto_value_data`/`well_known_symbols`) gives a single place where boot objects are both rooted and installed, and the `BOOT_DERIVED` ledger group plus the struct-parsing reconciliation tests (`sidetable.rs` 777–798, `gc_visitation_registry.rs`) make it hard to add a field without classifying it.
- `bind_program_symbols` is a genuinely pure derivation, factored so boot and restore cannot drift; `refresh_special_ids_from_symbols` keeps a live machine and its resumed twin gating identically.
- Spec identities that test262 checks are modeled precisely: `Set.prototype.keys === values`, `trimLeft === trimStart`, shared `%TypedArray.prototype%` method identity across concrete prototypes, `.name`/`.length` via `alloc_named_method`, `MIN_VALUE = f64::from_bits(1)`.
- Unsupported surface is made honest: unimplemented methods are bound so a reference produces a named `Halt::Unsupported`, not a wrong value; the `unreachable!` arms partition `Native` explicitly.
- The create-only partial-install contract and its rationale are documented in unusual depth (7384–7415), and the parts of it that are implemented (`keep` gating, `find_property` create-only checks, the `full` gate for symbol branches) are correct.
