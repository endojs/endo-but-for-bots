## Purpose and responsibilities

The directory is the behavioral contract of the snapshot crate. It has five genres:

1. **Persist gates** (`persist_gates.rs`, `pending_row_gates.rs`, `dynamic_segments.rs`): which machines every persist verb
   (`write_snapshot`, `begin_store_session`, `checkpoint_to_store`) must refuse (non-quiescent/halted; async frames;
   live async generators) and which it must admit, with the admitted ones proven to resume faithfully.
2. **Carry twins** (14 `*_carry.rs` files, `side_table_ledger.rs`, `restore_side_tables.rs`, `boot_native_identity.rs`):
   per side-table family, an uninterrupted machine and a checkpoint/resume split run the same relinked cranks and must
   agree on `(completed, halt, result, computrons)`; the continuous answer is also pinned to the real JS value.
3. **Crafted-row refusals** (`crafted_row_refusals.rs` plus `malformed_*` tests inside some carries): an honest image is
   decoded, one field is poisoned, re-encoded, and the container reader / `validate_store` must refuse by exact name.
4. **Store seam locks** (`store_checkpoint.rs`, `store_hardening.rs`, `migration.rs`, `migration_fixtures.rs`,
   `metamorphic_determinism.rs`, `gc_machine.rs`, `free_record_hygiene.rs`): succession/seal guards, incremental
   dirty-row commits, seeded corruption sweeps of the file store, lazy fault/evict schedules, v5→current migration,
   the seven-way metamorphic determinism runner, partial/generational collection soundness.
5. **Instruments** (`gc_bench.rs`, `dispatch_bench.rs`, `attached_bench.rs`, `wake_latency_bench.rs`): six `#[ignore]`d
   wall-clock benches printing medians; no pass/fail criteria.

Two smaller engine-behavior files (`detached_natives.rs`, `suspend_in_try.rs`) test pure interpreter semantics (no
snapshot verbs at all) and arguably belong in `ironhorse-vm/tests/`.

## Architectural observations

**Coverage shape.** The suite is strongest exactly where prior review waves bled: gates from the refusing side, twins with computrons, canonical-grammar refusals, seal/succession forks, lazy fault/evict schedules. It is weakest in what was never a wave finding: (a) whole carry families whose decode gates have no crafted-row test, (b) the container reader as an untrusted-bytes surface, (c) migration on non-empty content, (d) the cross-host determinism pin.

**Enumerated-by-memory coverage.** `persist_gates.rs:484-489` explains why holder enumeration cannot be complete and moves the gate to traversal; but test coverage of the ~213 named refusals is itself enumerated by memory: 46 are reached by name, 167 are not. The families with zero refusing-side tests: typed-arrays (3 gates incl. `view geometry past its buffer`, `unknown element kind`), data-views (2), array-buffers (2, incl. `unknown flag bits`), iterator cursors (7, incl. `string cursor outside its text`, `for-in key id outside the name table`), error-data (5) / error-frame (4), wrapper, arguments brand, temporal (2), symbol registry (2), bound-function (2, incl. `owner has no function row`), ctor-prototype (2), deleted-fn-meta (2), private accessors (3, incl. `getter or setter is not callable`), private elements (1). The ledger's own text asserts these gates exist (`sidetable.rs:232-234`), so a `debug_assert!` regression or a fallthrough would go unnoticed in release.

**Two gate layers, one tested.** Decode gates (`image.rs`) and restore gates (`machine.rs` `side-table restore: malformed …`, 13 of them) are separate layers; only the FUNC collision arm reaches the second layer.

**Untrusted-input surfaces.** The store-file path gets 800 seeded mutations plus header-concentrated hostile lengths. The `XS_M` container — the CAS blob path `resume_from_cas` consumes and the format the design names as an untrusted input — gets whole-atom splices only. The fuzz crate has `decoder_is_error_free`/`mutate_bytes` (`ironhorse-fuzz/src/snapshot.rs:952,1000`) but runs in the oracle-gated job (ci.yml:833), not PR CI.

**Panic as API on the lazy path.** `PageSource` is infallible (`vm/src/value.rs:55,58`), so `StorePageSource` must panic on manifest re-read failure, torn read, leaf-hash failure, decode failure, AND plain I/O error (`machine.rs:1469-1477, 1488, 1492, 1501, 1510, 1514`). Tests assert on panic message substrings (`store_checkpoint.rs:438, 526`). This entrenches "transient I/O error == corrupt store == crashed crank" and makes the message text a compatibility surface.

**Determinism.** No `HashMap` iteration order reaches an assertion in tests/ (the one `HashMap` in `supervisor_suspend_resume.rs:110-112` is keyed access). Writers must emit owner-ascending rows or the reader's `not strictly ascending` gates would refuse their own output — a good by-construction canonicality mechanism — but that only holds for tables that have such a gate and is verified byte-for-byte only in-process. The golden vector (`metamorphic_determinism.rs:159, 252`) is a change detector re-pinned ~15 times; its 100-line comment history documents that every boot-heap change moves it, and it holds no side-table state.

**Wall-clock and platform.** `Instant` appears only in the four bench files. `std::env::temp_dir()` in `common/mod.rs:24`. No locale/time-of-day dependence in assertions (`date_carry` uses fixed epoch values and `timeZone: 'UTC'` in `intl_carry.rs:175`).

**Duplication.** The `crank`/`twin`/`assert_twin` trio and its 5-line rationale comment are copy-pasted into 14 carry files with drifting rigor. Coverage matrix (mem / file / blob / lazy / checkpoint+validate after resume / any crafted-row refusal):

## Candidate findings

1. **Refusing-side coverage is enumerated by memory: 167 of 213 named `Corrupt` gates, and 15 whole carry families, have no test that reaches them** — `tests/crafted_row_refusals.rs:1-5`. Claim: no test in `tests/` triggers `typed-arrays side table: view geometry past its buffer`, `data-views side table: view geometry past its buffer`, `iterator cursors: string cursor outside its text`, `array-buffers side table: unknown flag bits`, `private accessors: getter or setter is not callable`, or any error-data/error-frame/wrapper/arguments-brand/temporal/symbol-registry/bound-function/ctor-prototype/deleted-fn-meta gate. Evidence: `sidetable.rs:232-234` "element kind refused at decode past the dispatch table, view geometry refused past its buffer's length"; `typed_array_carry.rs` has no `malformed_*` test; `crafted_row_refusals.rs:1-5` "rows that pass STRUCTURAL decode but cannot faithfully restore must be refused … not debug-only asserts". Why it matters: these gates are what turn a crafted snapshot into a structured error instead of an out-of-bounds read of the chunk arena in the interpreter; untested, a gate can regress to `debug_assert!` or fall through in release with the whole suite green — the exact failure mode `store_hardening.rs:816-824` records having happened once already (`check_image_slot_bounds` shipped unwired). [snapshot-coverage, high]

2. **No byte-level mutation/truncation sweep of the `XS_M` container reaches PR CI; only the store file is fuzzed there** — `tests/store_hardening.rs:8-14`. Claim: every seeded corruption arm in `tests/` mutates a `FileStore` file; none feeds mutated bytes to `read_machine`/`from_snapshot_bytes`, the reader `resume_from_cas` uses. Evidence: `store_hardening.rs:9-11` "random single-byte corruptions and truncations of a committed `FileStore` file"; `crafted_row_refusals.rs:291-398` splices whole well-formed atoms only; `ironhorse-fuzz/src/snapshot.rs:1000` `decoder_is_error_free` exists but runs under ci.yml:833 (oracle job). Why it matters: snapshot images are a named untrusted input and the design requires the loader "must not panic on corrupt input from a bad snapshot" (design:704-706); the 120 structural `Corrupt` literals in `image.rs` (HEAP/STAC/METR headers, u32/string lists) are exercised only by honest bytes on every PR. [robustness, high]

3. **Migration is tested from a single v5 fixture whose side-table sections are all empty, across 18 ladder steps** — `tests/migration_fixtures.rs:1-6`. Claim: no frozen fixture at any schema in 6..22 exists, so no `migrate_vN_to_vN+1` step (`store.rs:2045-2062`) ever runs on a non-empty side-table section. Evidence: `migration_fixtures.rs:5-6` "The v5 set was frozen at `STORE_SCHEMA_VERSION` 5"; `ls tests/fixtures` → `store-v5.container`, `store-v5.ihstore` only; `store.rs:89` `STORE_SCHEMA_VERSION: u32 = 23`. Also `regenerate_file_store_fixture` (`migration_fixtures.rs:48`) writes to the hardcoded name `store-v5.ihstore` at the current schema, so running it silently destroys the v5 fixture and breaks `migration.rs:97` (`NeedsMigration { found: 5 }`). Why it matters: a store from any deployed intermediate era (say a v17 store with live accessors) is migrated by code that was never exercised on content; the ladder's progress guard is well tested but its payload transformations are not. [verification, high]

## What is done well

- **Refusing-side genre exists and is deep where it exists.** `crafted_row_refusals.rs` and `generator_carry.rs:296-481` are exemplary: they derive the honest image, poison one field, and demand the exact named refusal on both the container and the store path — including subtle ones (resume pc at an operand byte, a sibling body, a nested body; PRMS capability polarity; `remaining` race equality).
- **Twins carry computrons.** Every carry and `store_suite::assert_agrees` compare per-crank computron vectors, not just final results (`store_suite.rs:44-50`), so a resumed machine that answers right but charges differently fails — the right property for a consensus meter.
- **Seeded, reproducible property tests.** `store_hardening.rs` uses a Knuth LCG with printed seeds, no wall-clock, and both reference backends; arm 4 asserts commit cost with equality, not monotonicity.
- **Hang-shaped regressions run under explicit deadlines** (`migration.rs:319-340, 480-502`), and hygiene is real: `TempDir` is pid+sequence unique and removed on panic (`common/mod.rs`).
- **The side-table ledger is mechanical**: `sidetable.rs:662-798` parses `Interp`'s field list from source and reconciles it two-way, and `:890-947` reconciles `EmptyAtBoundary` against the actual `is_quiescent` body — the census's "headline bug class" has a compile-and-test-checked registry, and the integration tests build on it rather than re-deriving it.
- **Honest labeling.** `supervisor_suspend_resume.rs:8-19` states exactly what it does and does not prove; `pending_row_gates.rs` and the sidetable descriptors record graduation history rather than overstating coverage.
