Temporal in this engine is a **fixed-offset, ISO-8601-only, constant-clock model** (doc at 3176–3183): instances are
immutable scalar records in four `HashMap<SlotIndex, Record>` brand tables (`temporal_instants`, `temporal_durations`,
`temporal_plains`, `temporal_zoneds`, declared 3912–3915), the arena slot is an empty instance whose prototype selects
the brand, and getters are dispatched **by property-name string** inside `GET_PROPERTY` (12699–12776).

## Architectural observations

- **Coupling / monolith symptoms.** Temporal is ~1,300 lines scattered over five non-contiguous regions of one 44,942-line file (records 3130–3251, boot 6606–6746, getters 12699–12776, methods 24275–25146, helpers 40383–41190). The helpers are pure functions on `Copy` records with no `Interp` dependency; `intl_number.rs` (1,180 lines, census) is the in-repo precedent for extracting exactly this shape. Getter dispatch by string comparison inside `GET_PROPERTY` couples the property-read hot path to every Temporal getter name.
- **Two dispatch idioms in one family.** Instant/Duration use named `NativeMethod` variants (24628–24771); PlainX/Zoned/Now use `(kind, op: u8)` integer ops whose meaning lives only in the boot tables (6676–6745) and must be kept in sync by hand with the `match` arms (24404–24446, 24898–25080, 25110–25146). Each dispatcher ends in `_ => Halt::Unsupported(...)`, so a table/dispatcher drift becomes a runtime abort, not a compile error.
- **Duplication.** The nine-field bag reader (`year`…`nanosecond` → `u32::try_from … map_err(range_error)`) is copy-pasted four times (24379–24395, 24420–24424, 24813–24831, 24917–24932); the ten-field duration reader twice (17775–17783, 24459–24471); "time part re-assembled from ns" appears at 24600–24605, 40468, 40935–40940, 24993–24995. Several of these are single-line dense blocks (24421–24423, 40431–40442, 40455–40480) that defeat review.
- **Hidden state.** None beyond the four brand tables; records are immutable (`var d=…; d.hours=9; d.hours` → `1`, temporal_core.rs 34).
- **Panics / unwraps / indexing on untrusted data.** The `days_from_civil` i64 overflow (see finding 2) is the only guest-reachable arithmetic panic found; `temporal_unit_name(rank)` indexing is safe (rank ≤ 9 by construction). `unreachable!` at 24769/24362 are programmer-error only. In the non-Temporal part of the range, `self.arrays.get_mut(&arr).unwrap()` after `new_array()` (25400, 25512, 27002…) is sound, and `HashMap` index `self.dates[&inst]` 25169 is guarded by `contains_key` 25166.
- **Determinism hazards.** No host time, locale or randomness. f64 appears only in `Duration.total` (24751, 24760), `iso_total_calendar_units` (seed + final fraction, 40636–40651) and `round_number_to_increment` (40738–40769) — IEEE basic ops and `floor`/`ceil` only, no libm transcendental; `i128 as f64` conversions are round-to-nearest-even and deterministic. No `HashMap` iteration is observable (snapshot sorts, GC only `retain`s). The one determinism *footgun* is build-profile dependent integer overflow (no `overflow-checks` setting, census): debug panics where release wraps.
- **GC-root and side-table hazards.** Records hold no `SlotIndex`/`ChunkOffset`, so no roots are needed; prune is on both paths. `TemporalZonedRecord.time_zone: String` is heap-owned outside the arena (not metered, travels in `TMPR`).
- **Snapshot coverage hazards.** `kind == 5` records cannot round-trip (finding 1). Otherwise `TMPR` is complete and owner-sorted.
- **Metering-doctrine drift.** Temporal meters nothing but result strings (finding 4). In the non-Temporal range, honest skips are justified by *parity* rationales the 2026-07-04 doctrine retired (finding 5), and ~40 raw `*_METERING` constants are described as "calibrated against the pin".
- **Error-handling shape.** Temporal consistently raises realm-local `TypeError`/`RangeError` via `catchable_*` — good. But the dispatcher still leaks `Halt::Unsupported` and `Halt::Throw("TypeError: …")` string-typed errors (25918, 25968, 26344, 26358…) for ordinary inputs; the former aborts the crank, the latter bypasses the realm's error constructors.
- **API-boundary leaks.** Options readers (`intl_option_string` 18723, `temporal_zoned_round_options` 24891) read raw slot payloads via `instance_get` — accessor properties and proxy traps are not honored — while field-bag readers use `ordinary_get` (getters run). `symbol_ids.get(name)` returning `None` silently treats an option as absent when the program never spelled the name (e.g. an option passed through `JSON.parse`).
- **Performance-architecture.** Every property read on any object runs up to four Temporal `contains_key` probes (12699, 12707, 12720, 12742) plus a `string_key_name(id)` string materialization on a hit. `iso_date_until` and `iso_total_calendar_units` are O(1)-seeded loops bounded by the ±8.64e21 span guard (40598–40609), so no runaway CPU.

## Candidate findings

1. **Snapshot resume fails for any live `Temporal.Calendar` instance (kind 5).** `rust/engine/ironhorse-vm/src/interp.rs:10231` and `rust/engine/ironhorse-snapshot/src/image.rs:2747`. Claim: a machine holding the result of `Temporal.Calendar.from('iso8601')` (or `new Temporal.Calendar('iso8601')`) writes a `TMPR` plain row with `kind == 5` that both decoders reject as "unknown kind", so the snapshot cannot be restored. Evidence: `if kind > 4 { return false; }` (10231); `if kind > 4 { return Err(SnapshotError::Corrupt("temporal plains: unknown kind")); }` (image.rs 2747); minted at `return self.temporal_new_plain(TemporalPlainRecord { kind, ..Default::default() });` with `kind == 5` (24337), accepted by `if r.kind == 5 { return true; }` (40406). Why it matters: a guest can make its own vat un-suspendable with one line; the decoder's doc comment asserts a discriminant range the engine does not honor. Category: snapshot-coverage. Severity: high. Confidence: high (both sides read; not run).

2. **Unbounded years reach an i64 multiply overflow in `days_from_civil` from guest strings and numbers.** `rust/engine/ironhorse-vm/src/interp.rs:40866`. Claim: `Temporal.PlainDate.from("9223372036854775807-01-01")`, `Temporal.Instant.from("9223372036854775807-01-01T00:00Z")`, `Date.parse(<same>)`, and `new Date(9e18, 0)` all evaluate `era * 146097` with `era ≈ year/400` in `i64`, which panics under overflow checks and wraps to a wrong value in release. Evidence: `Some((era * 146097 + doe - 719468) as i128)` (40866); `r.year=p.next()?.parse().ok()?` (40435, unbounded i64); `if year < i64::MIN as f64 || year > i64::MAX as f64 { return f64::NAN; }` (39587, admits 9e18). Verified with a verbatim copy compiled with `-C debug-assertions=on` (panic "attempt to multiply with overflow") and `-O` (returns `Some(3662054879699092824)`). Also `temporal_plain_valid` (40404) never applies the spec's `ISODateTimeWithinLimits`, so `PlainDate.from({year: 2**53-1, month:1, day:1})` succeeds where a RangeError is required. Why it matters: a crashed crank from a string in overflow-checked builds; a silently wrong civil date in release; and the two build profiles disagree, undermining "determinism is a construction guarantee". Category: robustness. Severity: high.

3. **Ordinary guest inputs on shipped built-ins abort the crank via `Halt::Unsupported`.** `rust/engine/ironhorse-vm/src/interp.rs:26165` (and 25076, 24434, 28255, 28273, 28295). Claim: `Object.keys([1,2])`, `Object.values(arr)`, `[3,1,2].sort()`, `Array.from(x)`, `Array.of(1)`, `zdt.toLocaleString()`, `Temporal.PlainMonthDay.from(…).until(…)` return `Halt::Unsupported`, which is not a catchable exception but a host abort. Evidence: `return Err(Halt::Unsupported("Object.keys:exotic-object"));` (26165); `20 => Err(Halt::Unsupported("Temporal.ZonedDateTime.toLocaleString:needs-intl")),` (25076); `Halt::Unsupported` is documented as "An opcode outside the stage-1 subset was reached" (3535–3538). Why it matters: in a consensus/vat engine an uncatchable abort reachable by any guest is a liveness lever; the "honest skip" error model designed for the differential harness has become the production error model. Category: error-model. Severity: high (cross-cutting; scoped here to sites in range).

4. **Temporal natives are unmetered except for result strings.** `rust/engine/ironhorse-vm/src/interp.rs:24314`. Claim: every Temporal constructor/method allocates an arena slot and a HashMap row and runs its arithmetic for the price of the `CALL` opcode alone — no slot-alloc, chunk, or built-in-step tick. Evidence: `let inst = self.slots.alloc(Slot::instance(self.temporal_instant_proto));` (24314) with no adjacent `meter.tick_*`; range 24275–25146 contains only `new_string_metered` calls (24438, 24676, 24767, 25074, 25120); `pub fn alloc(&mut self, slot: Slot) -> SlotIndex { self.live += 1; …` (value.rs 808) meters nothing; the dispatch site 13744 adds no native-frame tick. Why it matters: design § Metering names slot allocation as a cost-table increment point; a whole built-in family with zero increment points is a hole in the "deterministic proxy for real cost" (and heap growth is uncharged until GC). Category: metering. Severity: medium.

5. **Metering-doctrine drift: features withheld for XS-computron parity.** `rust/engine/ironhorse-vm/src/interp.rs:28255`. Claim: `Array.prototype.sort/toSorted/of/from` are refused on the explicit grounds that their metering cannot match the pin, contradicting the 2026-07-04 "accuracy over parity" doctrine. Evidence: `"Array.prototype.sort:data-dependent-comparison-metering"` (28256); `// It does not reduce to a faithful constant this stage, so this self-names an honest skip rather than shipping a fitted (unfaithful) meter.` (28291–28292); design: "XS-computron parity is an explicit non-goal" (designs/ironhorse-engine.md 366–367). Why it matters: the doctrine change was supposed to unblock exactly this class; the code still treats XS's counts as the acceptance bar. Category: metering. Severity: medium.

6. **The Temporal (and Intl) surface is oracle-blind, contradicting the design's acceptance bar.** `rust/engine/ironhorse-262/src/xst.rs:459`. Claim: any test source containing `"Temporal"` whose result disagrees with XS is downgraded to `RunSkip`, so Temporal correctness is certified only by hand-written expected strings. Evidence: `if cfg.oracle && oracle_missing_temporal(run) { return Verdict::RunSkip("oracle-host-missing-temporal".into()); }` (459–460); `run.source.contains("Temporal") && (!run.result_agrees || …)` (604–605); `assert_eq!(run.agreement, Agreement::IronhorseOnlyComplete, …)` (temporal_core.rs 7). Design: "XS deliberately omits Intl; Ironhorse omits it identically" (629–630). Why it matters: the engine's correctness argument is oracle-based; ~1,300 lines of spec-divergent calendar/zone code sit outside it, and the substring gate also hides real divergences in non-Temporal code that happens to mention the word. Category: verification. Severity: medium.

7. **Fixed-offset zones present IANA identifiers with wrong semantics.** `rust/engine/ironhorse-vm/src/interp.rs:39684` (and 25306). Claim: `Temporal.ZonedDateTime.from('2026-07-01T12:00[America/New_York]')` resolves with the zone's standard offset year-round, and `Intl.supportedValuesOf('timeZone')` advertises DST zones the engine cannot model. Evidence: `fn resolve_time_zone(raw: &str) -> Option<(String, i32)>` (39684, static table); `"timeZone" => &["Africa/Cairo", "America/Los_Angeles", "America/New_York", …]` (25306); `// getTimeZoneTransition(direction): a fixed offset never transitions.` (25025). Why it matters: deterministic but silently wrong instants; the divergence is documented in a doc comment (3176–3183) but not in any exceptions ledger, and the oracle cannot catch it (finding 6). Category: other. Severity: medium.

8. **Options readers bypass accessors and proxies inconsistently.** `rust/engine/ironhorse-vm/src/interp.rs:24891`. Claim: `ZonedDateTime.prototype.round/until/since` read `roundingIncrement` with `instance_get` (raw slot, no getter, no proxy trap) while `Duration.prototype.round` reads the same option with `ordinary_get` (getter runs); `smallestUnit`/`largestUnit`/`roundingMode` everywhere go through `intl_option_string`, which also uses `instance_get`. Evidence: `let v = self.instance_get(r, id);` (24891) vs `let v = self.ordinary_get(code, r, id, options)?;` (24551); `let value = self.instance_get(options, id);` (18723); `instance_get` returns `Slot::of(s.kind, s.value)` of the found property slot with no accessor call (38134–38136). Why it matters: observable divergence between sibling methods and from spec `Get`; a Proxy options bag never sees its traps. Category: api-boundary. Severity: low.

9. **Brand/bag readers omit the `Kind::Reference` check the codebase's own idiom requires.** `rust/engine/ironhorse-vm/src/interp.rs:24715`. Claim: `duration.with(Symbol())`, `Temporal.Duration.from(sym)`, `Temporal.PlainDate.from(sym)` treat the symbol's description-slot index as an object and walk it with `ordinary_get`. Evidence: `let Payload::Reference(r) = arg0.value else { return Err(self.catchable_type_error()) };` (24715, no kind test); `if let Payload::Reference(r) = value.value { if let Some(record) = self.temporal_durations.get(&r) …` (24457–24458); contrast `Payload::Reference(r) if value.kind == Kind::Reference => records.get(&r).copied()` (40667) and symbols are `Slot::of(Kind::Symbol, Payload::Reference(d))` (26108). Why it matters: kind confusion is the logic-bug class the index arena is supposed to catch by kind checks; here it is skipped at an untrusted-input edge. Category: robustness. Severity: low.

10. **Two dispatch idioms and hand-synchronized integer op tables in one family.** `rust/engine/ironhorse-vm/src/interp.rs:24898`. Claim: PlainX/Zoned/Now methods are identified by bare `u8` ops defined only in `create_temporal`'s literal tables and re-interpreted in `match` arms with `_ => Halt::Unsupported` catch-alls, while Instant/Duration use named variants. Evidence: `fn temporal_zoned_method(&mut self, op: u8, …)` (24898) with `_ => Err(Halt::Unsupported("Temporal.ZonedDateTime:method")),` (25078); table `("with", 2u8, 1u32), ("add", 3, 1), … ("valueOf", 21, 0),` (6718–6726); `NativeMethod::TemporalInstantAdd | NativeMethod::TemporalInstantSubtract => {` (24649). Why it matters: a renumbering slip is a silent runtime abort instead of a compile error; two idioms double the review surface. Category: modularity. Severity: low.

11. **Temporal belongs in its own module, not the interpreter monolith.** `rust/engine/ironhorse-vm/src/interp.rs:40383`. Claim: the ~800 lines of pure record helpers (40383–41190) plus the record types (3130–3251) have no dependency on `Interp` and could be `temporal.rs` (as `intl_number.rs` already is), with only the ~900 lines of `Interp` glue remaining. Evidence: `fn iso_date_until(start: TemporalPlainRecord, end: TemporalPlainRecord, largest: &str) -> Option<TemporalDurationRecord>` (40508); `fn round_temporal(value: i128, quantum: i128, mode: &str) -> Option<i128>` (41125); the only helper touching `Interp` is `temporal_set_time_args(interp: &mut Interp, …)` (40386). Why it matters: five non-contiguous regions of a 45k-line file for one feature is the monolith symptom the review is hunting; extraction is mechanical and would make the arithmetic unit-testable without a machine. Category: modularity. Severity: medium.

## What is done well

- **Genuine determinism of `Temporal.Now` and `Date.now`**: one constant (25112) feeds all six `Now` ops, `Date.now()` and `new Date()` are `0.0` (25163, 17812), and there is no host clock, locale or tz database anywhere in `ironhorse-vm`.
- **Integer-exact arithmetic with overflow discipline where it counts**: i128 nanoseconds throughout, `checked_*` in every `TemporalDurationRecord` operation (3206–3243), `checked_mul`/`checked_add` on quanta (24587, 24973), explicit `LIMIT` checks on both instant constructors (24310, 24779) and on `iso_duration_span_nanoseconds` (40601–40609) that also bounds the calendar-unit search loops.
- **Side-table hygiene**: immutable records, brand-by-table with `Copy` records, pruning on both GC paths (44362–44365, 44620–44623) with a registry test that requires it, owner-sorted snapshot rows, and a decoder that fails closed on ordering and UTF-8.
- **Realm-local errors**: Temporal consistently raises catchable `TypeError`/`RangeError` (`catchable_*`) rather than string-typed `Halt::Throw`, and the tests check `instanceof` (temporal_core.rs 41–52).
- **Spec-aware corner handling documented at the site**: the identical-duration `compare` shortcut that still observes `relativeTo` getters (24686–24694), `offset: "reject"` agreement checks (24835–24843, 41083–41085), `DifferenceISODateTime` sign-borrow (40571–40579).
