## Purpose and responsibilities

`ironhorse-fuzz` is the design's § Fuzzability crate: a `#![forbid(unsafe_code)]` library
(lib.rs:1) holding **generators** (fuzzer bytes → JS source / regexp case / machine image),
**comparators** (ironhorse vs the XS oracle; write→read→write identity), and **totality
harnesses** (decoder/parser/snapshot reader must return, never panic/hang), plus a separate
cargo-fuzz workspace (`fuzz/`, its own `[workspace]`, fuzz/Cargo.toml:78) of nine thin
libFuzzer wrappers. The lib doubles as the home of fixed-seed "sweep" unit tests and of
regression locks for continuous-fuzz findings. It depends on ironhorse-vm, xs-oracle,
ironhorse-regexp, ironhorse-compile, ironhorse-snapshot (Cargo.toml:14–22).

## Architectural observations

- **Metering-doctrine drift is encoded in the tooling.** Every wired differential comparator
  fails on `oracle.computrons != ironhorse.computrons` (lib.rs:1722, 1780; regexp.rs:266
  compares the raw 16.16 meter). The design (2026-07-04) says XS-computron parity is a non-goal
  and fuzz computron drift is advisory. Worse, generator *scope* is being shaped by the parity
  gate rather than by result semantics: `gen_json_structured_program` caps depth to dodge "a
  sub-computron raw drift in ironhorse's object-literal construction metering" (661–665);
  `gen_stage3_spread_program` stays single-segment because "each additional segment carries a
  sub-computron −8-raw residual" (889–893); `join` with a separator excluded (383–384); sparse
  receivers, `new boundFn`, primitive `this`, throwing handlers, rejections, astral strings all
  excluded as "self-naming"/"honest skip" corners. The result-only comparator that matches the
  doctrine (`differential_check_result_only`, 1799) has no fuzz target.
- **Most of the crate is a seeded unit sweep, not fuzzing.** 15 of the ~20 program generators
  (all stage-3/3b surfaces: arrays, array methods, iterators, for-of, string for-of, text/math,
  JSON ×2, promises, spread, for-in, re-entrant callbacks, collections, BigInt, binary data,
  fundamentals, object statics) are reachable only from `#[cfg(test)]` sweeps of 300–1200
  fixed seeds (2473–3400). None is a `[[bin]]` in fuzz/Cargo.toml. So coverage-guided search never
  touches those grammars; a sweep is ~10k deterministic programs total.
- **The flagship target runs nowhere in-repo.** The deep lane runs only the four pure-Rust
  targets (deep-fuzz.yml:129) while paying to fetch the oracle submodule (57–68). The PR tripwire
  job it describes is gone. Continuous differential fuzzing is asserted to happen in an external
  "garden" service whose design doc is not in this repo. The corpus is gitignored and exists only
  in the Actions cache; a red nightly has no consumer beyond the run status.
- **`Halt::Unsupported` is an overloaded escape hatch.** The comparators map it to Ok(()) (1699,
  1748, 1805; regexp.rs:231). The VM uses the same variant both for "not ported" and for
  hostile-bytecode refusals (`await:stack-underflow`, `end:frame-underflow`,
  `async:non-boundary-return`, `native-call:Array:bad-length`, … — 308 sites). A refusal
  misfiring on valid oracle-produced bytecode is a completion divergence the design calls
  crash-equivalent, but it is classified as uncovered ground; and skip rate is not measured
  (the `skipped` counter at 2997–3001 is dead code — it greps the *source text*).
- **The UTF-16 storage decision is unfuzzed here.** No transcoding target; generators are ASCII
  by construction and say so ("so case/.length/index math stays byte==unit" 573–575; astral
  "self-names an honest skip" 547–549); the regexp arm hands the matcher `subject.as_bytes()`
  (regexp.rs:250) and compares byte offsets — the code-unit↔byte remap the VM must do is "out of
  scope" (lib.rs:856–858). Untrusted JS source with non-ASCII content is exactly the input class
  the design names.
- **Number-rendering masking.** `results_agree` treats any two finite-Number spellings with equal
  f64 bits as agreement (1657–1665). The oracle returns `String()`-coerced completion values
  (xs-oracle lib.rs:224–226), so a *string* completion "57632001481506820" is indistinguishable
  from a Number — and `String(57632001481506816).length` genuinely differs (17 on XS per the
  harness's own comments vs 16 on ironhorse). Nine regression locks (1991–2269) pin the
  suppression. The design says a pass-where-XS-fails "gets an exceptions-ledger entry or a fix,
  never a silent improvement"; I found no ledger entry (`grep -i dtoa designs/` → one unrelated
  hit). Confidence: the divergence is asserted by the harness comments; I did not run XS.
- **Comparator fragilities.** `differential_check` lacks the `result_truncated` skip its
  siblings received for finding 493390fc03979205 (1691–1733 vs 1758, 1812) — latent because its
  grammars produce short results. `compile_differential_check` classifies oracle acceptance by
  `!error.contains("SyntaxError")` (1948): a *runtime* SyntaxError (e.g. `new RegExp("(")`)
  would read as a parse rejection. Oracle startup failure is `Ok(())` in all fuzz-wired
  comparators (1694, 1745, 1802; regexp.rs:226): under libFuzzer a broken oracle is an all-green
  run; only the unit sweeps assert `checked > 0`.
- **catch_unwind under libFuzzer.** `compile_differential_check` promises a coder `panic!` is a
  named `IronhorseRejected` (1936–1941, 1950–1954). libfuzzer-sys installs an aborting panic hook,
  so in the `differential_compile` binary every unported construct (census: 33 `panic!` in
  ironhorse-compile) is a crash artifact, which plausibly explains why that target is not in the
  nightly list.
- **Snapshot round-trip coverage shape.** The generated-image arm never adopts the image into an
  `Interp` and never runs the bounds gate (392–395); it tests `write_machine`/`read_machine`
  identity only. Families with real chunk extents or cross-table state are omitted (typed
  arrays/ABUF, IBFN, Intl, bound functions, ctor prototypes, deleted meta, class_derived, frame
  `jumps`, value stack). The adoption/restore path is exercised by `roundtrip_program_is_invariant`
  (unit test only, 4 grammars × 250 seeds) and resume-transparency only over symbol-free
  arithmetic (894–896; 400 seeds). Since side-table-vs-restore is the headline bug class, the
  fuzz arm covers the codec, not the restore.
- **Generator ⇄ decoder coupling is hand-mirrored.** "'Valid' is whatever the decoders accept"
  (261–268) — the generator re-implements acceptance rules (ascending owners, live-only refs,
  rehash geometry, pair-coherent promise functions…). The comments record the same failure
  recurring: waves 4, 5, and the graduation wave each found decoders "exercised by nothing but
  their own hand-written fixtures" (384–388) because the generator lagged. There is no shared
  builder/validity API in ironhorse-snapshot that both the writer and this generator consume;
  the fuzz crate instead imports ~20 `pub` row types from ironhorse-vm (API-boundary leak: the
  VM's side-table row structs are the fuzz crate's construction vocabulary).
- **Generator bias.** The modulo-wrapping cursor (lib.rs:57) makes every draw after exhaustion a
  replay, so byte mutations map non-locally onto grammar choices and short inputs are degenerate
  (13 of the 14 minimized trophies are 3–9 bytes). `gen_atom` (1606–1628) never emits strings,
  `undefined`, `null`, `NaN`, `Infinity`, `-0`, exponent or hex literals. `gen_regexp` never emits
  `u`/`v`/`g`/`y`, named groups, unicode escapes, non-ASCII subjects, or `{n,}`; groups get only
  bounded quantifiers (94–119). The parser target never fuzzes strict mode (`parse_once(…, false,
  …)` 1904–1905). `gen_compile_program` draws from only the stage-1/2/2b grammars (1884–1892) —
  none of the stage-3/3b surfaces reach the compiler differential.
- **Modularity.** `xs-oracle` is a hard dependency (Cargo.toml:15), so the pure-Rust arms
  (parser, bytecode decoder, snapshot ×2) and the oracle-free VM regression lock
  `hostile_yield_below_run_base_fails_closed` (3583–3648) cannot build in the PR `test-ironhorse`
  job (ci.yml:677–687, 746) nor here; a feature gate would let them run everywhere.
- **Three copies of the cursor** (lib.rs:44, regexp.rs:18, snapshot.rs:55) — minor duplication.
- Determinism of the harness itself: fine (BTreeSet, no HashMap, no clock, f64 parse via std).
  Panic surface: 42 `panic!` are all intentional finding reporters in tests/targets; `expect`s are
  in tests only; indexing on untrusted data is guarded (`% len`, `is_empty` checks).
- Deep-fuzz lane hygiene is good: pinned nightly (37), lockfile-freshness gate (100–109),
  digit-checked dispatch input (123–127), accumulate-failures loop (128–132), minimal permissions,
  artifacts on failure. cargo-fuzz builds with ASAN by default, so the nightly is effectively the
  only sanitizer run the engine gets (census: no Miri/ASAN job).

## Candidate findings (most architecturally significant first)

1. **Computron equality is a hard gate in every wired differential comparator, and generator
   scope is narrowed to keep it green (metering-doctrine drift).** lib.rs:1722–1730,
   1780–1788; regexp.rs:266–274; lib.rs:661–665, 889–893.
   Claim: every fuzz-wired differential arm returns `Err` on `oracle.computrons !=
   ironhorse.computrons`, contrary to design § Fuzzability, and at least three generators
   document excluding valid result-bearing programs solely because of sub-computron residuals.
   Evidence: `if oracle.computrons != ironhorse.computrons { return Err(Divergence {` (1722);
   "kept single-segment here so the arm is raw-clean" (893); design:697–702 "not equality
   assertions". Why: the fuzzer is tuned to a non-goal and its *result* coverage shrinks to
   protect it; the doctrine-compliant `differential_check_result_only` (1799) has no target.
   Confidence high.

## What is done well

- The substance lives in a plain, `forbid(unsafe_code)`, deterministic library with the
  libFuzzer wrappers reduced to 10–25 lines each; every generator has a seed sweep with
  diversity witnesses (`distinct.len() > N`, per-family flags) so a refactor cannot silently
  degrade an arm to one shape.
- Bounded totality for the bytecode decoder (`run_program_bounded` + `DECODER_STEP_LIMIT`,
  lib.rs:1845–1860) with the hang and OOM trophies locked as fast tests (3471, 3500).
- The mutated-valid corpus for the snapshot decoder (snapshot.rs:952–1014) is genuinely
  productive and *proved* so (`mutation_corpus_reaches_the_atom_decoders`, 1236–1259).
- Honest treatment of the NaN reflexivity trap (byte identity as the real invariant, 789–827) and
  of oracle capture-buffer truncation (`result_truncated`), each with pinned reproducers.
- The deep-fuzz workflow is careful engineering: pinned nightly, lockfile-freshness gate,
  template-injection-safe dispatch input, accumulate-all-failures loop, minimal permissions,
  artifacts on failure.
- Every trophy is documented with its exact minimized bytes, sha256, the folded program, and the
  causal analysis — the regression tests read as a ledger.
