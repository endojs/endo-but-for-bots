# Map: interp-01-constants-natives-halt

## Purpose and responsibilities

This is the *preamble* of the 44,942-line interpreter module: everything that precedes the `Interp` struct.
It holds five distinct kinds of thing that share one file and one namespace:

1. **The compiler/VM seam** — `CompiledSource`, `SourceCompileError`, `SourceCompiler` (lines 49–101): the trait the host installs so `eval`/`Function` can turn source into bytecode without `ironhorse-vm` depending on `ironhorse-compile`.
2. **The run-time cost table** — ~250 `pub const *_METERING`/`*_EXTRA`/`*_PER_*` constants (lines 103–1692, plus 103–405 for frame/program constants), each a raw 16.16 fixed-point residual "calibrated raw-exact against the pin `48ee02d8cfe0`" for one built-in path, plus the fixed-geometry limits `STACK_SLOT_COUNT`/`STACK_SLOT_RESERVED`/`FRAME_OVERHEAD_SLOTS`/`DISPATCH_REENTRY_LIMIT`/`BOUNDED_RUN_SLOT_CEILING` (164–205).
3. **XS flag/ID constants** — the property flag byte (`XS_DONT_DELETE_FLAG`…`XS_SETTER_FLAG`, 521–527), the instance flag byte (`XS_DONT_PATCH_FLAG`, `XS_DONT_MARSHALL_FLAG`, `XS_EXOTIC_FLAG`, 534–549), `XS_INTERNAL_FLAG` (552) and the reserved `XS_ENVIRONMENT_BEHAVIOR_ID = u16::MAX` (559).
4. **Per-instance side-table records** — `AccessorData`, `OrdinaryDescriptor`, `BoundData`, `ProxyData`, `FuncInfo`, `DisposalRecord`/`DisposableStackData`, `ArrayBufferData`, `TypedArrayType`/`TYPED_ARRAY_TYPES`, `TypedArrayData`, `DataViewData`, `PromiseData`, `RegExpData`, `RegExpGetterIds`, `RegExpResultIds`, `PromiseState`, `PromiseReaction`, `ReactionKind`, `PromiseFnData`, `PromiseJob`, `CombinatorKind`/`CombinatorState`, `FromAsyncData`, `IterState`, `ErrorInfo`, the Temporal records (`TemporalInstantRecord`, `TemporalDurationRecord`, `TemporalPlainRecord`, `TemporalZonedRecord`) — the payloads of the `HashMap<SlotIndex, _>` side tables declared later in the struct (3791–4370).
5. **The dispatch identity enums and the halt model** — `MathId` (1798), `NativeMethod` (1839–2621, ~280 variants), `Native` (3265–3358, 47 variants) with `display_name`/`arity`/`intrinsics`, `Halt` (3517–3569), the `dispatch_result!` macro (3573–3587), `RunOutcome` (3591–3609), `RelinkError` (3636–3642), and the snapshot row aliases `ArraySnapshot`/`CollectionSnapshot` (3646–3649).

## Invariants and contracts claimed (from doc comments) — and whether the code visibly upholds each

1. **"Computrons are bit-exact"** (module doc 21–22; `RunOutcome.computrons` 3597–3598 "comparable bit-for-bit with the oracle's run-only count"). *Stale vs. design doctrine* (design § Metering: XS parity is a non-goal, computrons advisory). Several constants in the same file already carry the doctrine's language ("advisory", "result-gated": 453–464, 673–680, 1110–1118, 1673–1692), so the file contradicts itself about what the constants are.
2. **"XS_ENVIRONMENT_BEHAVIOR_ID … the top of the `u16` space is unreachable by [program symbol or runtime-interned key]"** (553–559). **Violated**: `intern_symbol_key` (35056–35073) hands out `next_symbol_key_id` *before* decrementing (35069–35070) and the counter starts at `u16::MAX` (5295; `may_hold_runtime_interns` = `!= u16::MAX`, 8472–8474), so the first symbol used as a property key in a machine gets id `u16::MAX`. `is_environment_instance` (38246–38252) identifies environments *positionally* by `slots.get(inst).next.id == XS_ENVIRONMENT_BEHAVIOR_ID`, and is consulted on the `GET_VARIABLE`/`SET_VARIABLE` `with`-object path (11730–11733, 11904–11906) where `envref` can be an ordinary object.
3. **"`FuncInfo::body_start: Option<usize>` defuses the bound-function pc-0 trap"** (1735–1743). Upheld in shape (the `Option` exists; `Default` gives `None`, 2626); the "loud `Halt`" on unwrap is in `enter_call` (outside region; not verified here).
4. **`RegExpData.last_index`: "ToLength clamping on set, as `exec` applies"** (2814–2820) vs. `Native::RegExp`: "`lastIndex` is an ordinary own integer property" (3336–3337). *Internally contradictory*, and the set path (12639–12651) does clamp (`NaN`/negative → 0, `floor`) with a non-coercing `to_number` (41810–41827: objects → NaN). Spec/XS store the assigned value as-is; `ToLength` happens in `RegExpBuiltinExec`.
5. **`FromAsyncData` / `CombinatorState`: "append-only within a run and its reference-bearing slots stay live for the machine's lifetime (the stage-2 GC-roots contract — no mid-run collection sweeps under it)"** (3029–3031, 2994–3005). *Stale*: both tables are compacted at sweep (`compact_*` at 44491–44499) and rooted only through queued jobs (43645–43672); `collect_garbage` (43707) has no in-VM call sites (host-driven only), so "no mid-run sweeps" is true by construction, but the "stay live for the machine's lifetime" contract is no longer what the code does.
6. **`Halt::Yield`/`Await` "never seen by the top-level `run`"** (3554–3557, 3561–3562). Not verifiable from this region alone; `run` compares only `halt == Halt::Return` (11186, 11199, 11206, 11218), so a leaked `Yield` would render as an incomplete run rather than panic — benign failure mode.
7. **`PromiseData.ever_handled` "never metered"** (2797). Upheld by construction (a plain bool set on reaction registration; no `tick_*` near it in region).
8. **`Native::display_name` indexes `TEMPORAL_PLAIN_NAMES[i as usize]` / `TYPED_ARRAY_TYPES[i as usize]`** (3375, 3403; also 3427). Panics on an out-of-range payload — but payloads are never decoded from untrusted bytes: `FunctionRow` (4662–4674) carries no `native`/`method` field; natives are re-installed at resume by `install_intrinsic_bindings`. So the indexing is engine-internal only. Upheld (no untrusted path found).
9. **`STACK_SLOT_COUNT = 4096` models XS `fxOverflow` as a host abort, `DISPATCH_REENTRY_LIMIT = 64` bounds native re-entry** (151–205). Well-argued; the `DISPATCH_REENTRY_LIMIT` doc honestly records that the value-slot guard cannot protect the native stack (194–204). Enforcement is outside the region.
10. **`Meter` credits (`ASYNC_AWAIT_FASTPATH_CREDIT`, `unmeter_host_escape`) "net the fast path bit-exact"** (365–370). The credits are applied with unchecked `u64` subtraction (`untick_raw`/`untick_code`, meter.rs 163–165, 237–239) — no invariant enforces that a credit follows a charge of at least that size; census notes no `overflow-checks` profile setting, so release wraps silently.
11. **`TYPED_ARRAY_TYPES` "mirrors `gxTypeDispatches` (with `mxFloat16` off)"** (2673–2687). Order matches XS's table as I recall it (BigInt64, BigUint64, Float32, Float64, Int8, Int16, Int32, Uint8, Uint16, Uint32, Uint8Clamped); not re-verified against the C source (submodule absent).
12. **`Native::arity`** (3415–3465): spot-checked against ECMA-262/Intl/Temporal `length`s — all values I checked are correct (Object 1, Function 1, Symbol 0, Date 7, Array 1, Map/Set/WeakMap/WeakSet 0, Promise 1, RegExp 2, Proxy 2, TypedArray 3, DataView 1, ArrayBuffer 1, AggregateError 2, SuppressedError 3, Intl ctors 0 except Locale 1, Temporal.PlainDate 3, PlainDateTime 3, PlainYearMonth 2, PlainMonthDay 2, ZonedDateTime 2, Instant 1, Duration 0).

## Architectural observations

- **Cost table = scattered compile-time constants.** The design says weights are "entries in Ironhorse's own release-versioned cost table … the previous table remains addressable by its version" (design 388–411). In code the "table" is ~250 `pub const u64`s interleaved with type definitions across 1,600 lines of one 45k-line file, keyed by a single string `COST_TABLE_VERSION = "ironhorse-meter-1"` (meter.rs 26). Nothing makes a prior table addressable, nothing checks that a constant change bumped the version (the doc at meter.rs 25 says "Bump the trailing number whenever any metering weight or check point changes" — a convention, not a mechanism), and `cost.rs`'s `CostModel` (the instrumentation plan's table) is feature-gated off and holds no weights the meter reads (cost.rs 16–22 firewall). The constants' *values* are XS-raw-exact residuals (docs say "calibrated raw-exact against the pin" throughout) — i.e., the "accuracy" table is in fact the parity table under a new name. Deterministic per build, yes; a "model of real execution cost", no.
- **Doctrine leaks into the constants unevenly.** Some constants are honestly "advisory/directional" (`REFLECT_FRAME_METERING`, `TYPED_ARRAY_FROM_SOURCE_ELEMENT_METERING`, `PROMISE_FINALLY/COMBINATOR_*`, harden/petrify); most claim raw-exactness; a few model artifacts of the oracle's *C build* rather than cost: `RESUMED_HANDLER_THROW_METERING` is one dispatch that exists only because XS was built with gcc computed-goto (135–139: "In a plain-`switch` build … this surcharge would be WRONG"), `THROW_HOST_ESCAPE_METERING` models a `longjmp` skipping `mxBreak` (105–108). Under the accuracy doctrine these are exactly the constants that should *not* be in the table.
- **"Not a fitted total" — but several are.** `ARRAY_FOREACH_FRAME_METERING = 8`, `ARRAY_SOMEEVERY_FRAME_METERING = 8`, `ARRAY_FIND_FRAME_METERING = 8`, `ARRAY_REDUCE_FRAME_METERING = 8` (1023–1043), `JSON_STRINGIFY_OBJECT_NONEMPTY_METERING = (4<<14) - 8` (1291), `MAP_FOREACH_FRAME_METERING = 32776` (1381), `WEAK_CTOR_FRAME_METERING = 98312` (1360): 8-raw chunk-alignment residues back-fitted to the oracle.
- **Two meter versions in one engine.** `COST_TABLE_VERSION = "ironhorse-meter-1"` (vm) vs `PARSE_METER_RELEASE = "ironhorse-meter-0"` (compile meter.rs 22). The snapshot checks only the vm string. The version space is not coherent across the two halves of what the design calls one meter.
- **Parse cost has no channel across the compiler seam.** `CompiledSource` is `{bytecode, symbols}` (55–61); `SourceCompiler::compile_source` returns nothing else (96–100). The compile crate does have a `ParseMeter` (`charge_token`, `computrons()`, compile meter.rs 28–62), but the eval bridge (8001–8081) ticks nothing between `compile_source` and `dispatch_at`. The design's metering table lists "Parse unit: `fxMeterSome` calls from the parser → cost-table entry" (design 398). Runtime `eval`/`Function` therefore perform O(source) lexing/parsing/scoping/coding at zero computrons; XS meters this.
- **Provenance drift.** All 40 pin citations in interp.rs are `48ee02d8cfe0` (8.2.3); zero cite `23b4d6b0a65f` (8.3.1), which the README (28–30) and design decision 9 (1177–1179) name as the current oracle pin. Later constants (e.g. `DISPOSABLE_STACK_*`, 836–847, "2026-08-27") don't say which pin. The claimed calibration cannot be re-run against the oracle the repo actually builds.
- **Un-oracle-checkable surfaces in an oracle-locked port.** `Native::{Locale, Collator, ListFormat, PluralRules, Segmenter, DateTimeFormat, NumberFormat}` (3269–3275), ~30 `NativeMethod::Intl*`/`*Format*` variants (1881–1918), and the whole Temporal family (`TemporalInstant`, `TemporalDuration`, `TemporalPlain(u8)`, `TemporalZonedDateTime`, `TemporalNow(u8)`, 3276–3283, 1848–1880) exist while the design says "Intl is omitted (`intl402` stays out), matching the oracle" (design 1181–1185) and never mentions Temporal. XS 8.3.1 ships neither, so none of it can be dual-run. `Temporal.Now` is deterministic (fixed epoch 0 / `UTC`, 25110–25120 — good), but `TemporalZonedRecord` carries "a table of common IANA names carried at their standard offset" (3178–3183) — knowingly wrong for any DST zone.
- **Halt conflates four things.** Normal completion (`Return`), *internal* control transfer (`Resume(usize)`, `Yield/Await/AsyncYield(Slot)`), host aborts (`MeterAbort`, `StepLimit`, `StackOverflow`), and errors (`Throw(String)`, `Decode(String)`, `Unsupported(&'static str)`). `Throw` carries a "best-effort string" (3541–3543) while the real thrown value is `Interp::exception` (3861); `Unsupported` is used at 376 sites as an "honest skip" that aborts the whole crank. `PartialEq` on `Halt` is sound only because callers compare against payload-free variants (11186 etc.).
- **`run` bakes the oracle *shim's* post-run stringification into engine semantics** (11193–11217): a program that completes with a Symbol, or with a null-prototype object lacking `toString`/`valueOf`, is reported `completed = false, halt = Halt::Throw("TypeError: …")` because `String(result)` would throw *in the test harness*. `RunOutcome` is the host's view of a crank (3591–3609); a host that does not stringify completions receives a synthetic failure.
- **Dispatch identity is a ~280-variant flat enum with ad-hoc numeric sub-spaces.** `NativeMethod::Date(u8)`, `TemporalPlain(u8,u8)`, `Atomic(u8)`, `DataViewGet/Set(u8)`, `IteratorHelper(u8)` ("indexed in the order installed by `create_intrinsics`", 2618–2620) push meaning into opaque bytes whose legend lives in far-away `match` arms; cross-cutting predicates are hand-maintained lists (`is_object_static_on_operand`, 638–657). This is the monolith's spine: every built-in adds a variant here, a `match` arm ~15k lines away, and usually a constant above.
- **Untyped bit-flags and mixed units.** Instance-flag bits reuse property-flag bit values (`XS_DONT_PATCH_FLAG = 16 = XS_METHOD_FLAG`, `XS_DONT_MARSHALL_FLAG = 64 = XS_SETTER_FLAG`, `XS_EXOTIC_FLAG = 1 = XS_INTERNAL_FLAG`; 521–552) as bare `u8`s; correctness rests on prose ("the two never name the same slot"). `PROGRAM_INVOCATION_COMPUTRONS` is whole computrons (214) while every neighbour is raw 16.16 — all `u64`, no newtype.
- **`IterState` is a union-by-convention** (3075–3091): eight kinds share one struct with kind-specific fields (`enum_keys`, `str_bytes`, `generation`), so invalid combinations are representable and every reader must re-derive which fields are meaningful from `kind`.
- **Determinism (positive).** No host time/locale/randomness in the region; `Temporal.Now` is a fixed clock; `gc_roots` sorts and dedups so `HashMap` iteration order cannot leak into trace order (43690–43694); side tables are `HashMap<SlotIndex, _>` (3791–4370) whose serialization order is the snapshot readers' concern (`function_state_snapshot` uses a `BTreeSet` of owners, 9213–9219 — good precedent).
- **Panics/unwraps in region:** none in executable code besides the three unchecked `[i as usize]` table indexes (3375, 3403, 3427) and `.unwrap()`s on `self.regexps.get_mut(&inst)` in the (out-of-region) regexp paths after `contains_key` checks. `f64` use: `last_index: f64`, `to_length_u64` — no formatting/parsing in region.

## Candidate findings (most architecturally significant first)

1. **The "release-versioned cost table" is ~250 scattered XS-raw constants under one version string.** — `interp.rs:229` (`PROGRAM_ENV_SETUP_METERING`), `:342` (`ASYNC_INSTANCE_METERING = 414600`), `:452`; `meter.rs:26`.
   Claim: No versioned, addressable cost table exists; the meter's weights are compile-time `pub const`s calibrated to XS's raw `meterIndex`, so a recalibration is a scattered code edit with a manually-remembered string bump.
   Evidence: `pub const ASYNC_INSTANCE_METERING: u64 = 414600;` (342) · "Calibrated raw-exact against the pin" (276–277, and throughout) · `pub const COST_TABLE_VERSION: &str = "ironhorse-meter-1"; // Bump the trailing number whenever any metering weight or check point changes` (meter.rs 25–26).
   Why it matters: The design's consensus argument rests on "frozen table, versioned, prior tables addressable" (design 400–411). The code offers determinism-by-compilation only; there is no mechanism preventing a weight edit without a version bump, no way to run an older table, and the values are XS parity numbers rather than a cost model — the doctrine relocated the *reference* but the implementation kept the old one. Category: metering. Severity: high (architectural; not a runtime bug).

2. **Runtime `eval`/`Function` parsing is unmetered because the compiler seam has no meter channel.** — `interp.rs:55-61` (`CompiledSource`), `:96-100`, `:8005-8081`.
   Claim: A guest `eval(src)` performs O(|src|) lexing/parsing/scoping/coding at zero computron cost; nothing between `compile_source` and `dispatch_at` ticks the meter, and `CompiledSource` cannot carry the compiler's `ParseMeter` result.
   Evidence: `pub struct CompiledSource { pub bytecode: Vec<u8>, pub symbols: Vec<u8>, }` (55–61) · `let compiled = match compiler.compile_source(source, strict) { … }` then `let halt = self.dispatch_at(&buf[..], 0, 0);` with no `tick_*` in 8005–8081 · compile crate has `ParseMeter::computrons()` (compile meter.rs 56–61) that nothing in the VM can receive.
   Why it matters: The design lists "Parse unit" as a cost-table entry (design 398); XS meters `fxParseScript`. Under a consensus meter, an unmetered O(n) work path is a CPU-exhaustion vector priced only by the source string's own construction cost. Category: metering / api-boundary. Severity: high. Confidence: high that no charge occurs in the bridge; I did not check whether the host's `SourceCompiler` impl charges the VM meter out-of-band (it has no handle to do so through this trait).

3. **`XS_ENVIRONMENT_BEHAVIOR_ID = u16::MAX` collides with the first minted symbol-key id; environment detection is positional.** — `interp.rs:553-559`, `:35069-35070`, `:38250-38251`, `:11730-11733`.
   Claim: The first symbol used as a property key in a machine receives id `u16::MAX`, so `is_environment_instance` returns `true` for any ordinary object whose first own property is that symbol, and the `with`-object variable paths then treat it as a closure environment.
   Evidence: "the top of the `u16` space is unreachable by either" (556–557) · `let id = self.next_symbol_key_id; self.next_symbol_key_id -= 1;` with the counter initialised to `u16::MAX` (35069–35070, 5295) · `!behavior.is_null() && self.slots.get(behavior).id == XS_ENVIRONMENT_BEHAVIOR_ID` (38251), consulted at 11732/11906 where `envref` "resolved the name to a live `with`/eval object environment" (11724–11726).
   Why it matters: A falsified documented invariant, and a result-divergence path (`with (o)` where `o = { [firstSym]: …, x: 1 }`) that the oracle would catch only if a corpus happens to hit it. Category: robustness. Severity: medium. Confidence: high on the id collision; medium on the exact guest program that triggers misclassification (depends on which symbol boot interns first, which I did not trace).

4. **`RegExp` `lastIndex` is clamped/floored on *set*, not on exec; the two docs contradict each other.** — `interp.rs:2814-2820`, `:12639-12651`, `:3336-3337`.
   Claim: `re.lastIndex = -1; re.lastIndex` yields `0` (spec and XS: `-1`); `re.lastIndex = 1.5` reads back `1`; an object value becomes `0` without `ToPrimitive`.
   Evidence: `let n = to_number(&value); let clamped = if n.is_nan() || n < 0.0 { 0.0 } else { n.floor() };` (12645–12650) with the comment "the covered grammar assigns a non-negative integer" (12643–12644) · `to_number`: `_ => f64::NAN` for references (41825) · `Native::RegExp` doc: "`lastIndex` is an ordinary own integer property" (3336–3337) vs `RegExpData`: "with `ToLength` clamping on set" (2818–2819).
   Why it matters: A known approximation that survived into a result-visible surface (`lastIndex` is a writable data property in the spec; XS stores it as such). Category: other (correctness). Severity: medium. Confidence: high.

5. **`run` synthesizes a failure for completions the test harness could not stringify.** — `interp.rs:11193-11217`.

6. **Two meter-version strings coexist and only one is checked at resume.** — `ironhorse-vm/src/meter.rs:26`, `ironhorse-compile/src/meter.rs:22`, `ironhorse-snapshot/src/store.rs:2010`.

7. **Intl and Temporal are shipped contrary to the design and cannot be oracle-checked.** — `interp.rs:3269-3283`, `:1881-1918`, `:3176-3193`; design `:1181-1185`.

8. **`Halt` conflates completion, internal control flow, host aborts and errors; the thrown value travels out-of-band.** — `interp.rs:3517-3569`, `:3861`.

11. **Meter credits use unchecked `u64` subtraction.** — `meter.rs:163-165`, `:237-239`; `interp.rs:365-370`, `:17444`.
    Claim: `untick_code`/`untick_raw` can underflow; nothing enforces "credit ≤ prior charge", and with no `overflow-checks` profile a release build wraps to ~2^64 (instant `MeterAbort` or absurd computrons) while debug panics.

## What is done well

- The `SourceCompiler` seam (78–101) is a genuinely principled layering decision: the VM never depends on `ironhorse-compile`, and the Syntax/Unsupported split maps cleanly to catchable-vs-abort.
- `FuncInfo::body_start: Option<usize>` (1735–1743) documents a real past bug (bound function re-executing from pc 0) and removes the representable-invalid-state rather than adding a check.
- Every constant carries a measurement narrative (what program isolated it, what shape confirmed it, what residual remains); several record later corrections honestly (`APPLY_ARRAY_BASE_METERING`, 714–719; `RESUMED_HANDLER_THROW_METERING`, 125–148). Provenance quality is far above typical.
- Determinism hygiene in and around the region is strong: `Temporal.Now` is a fixed clock (25110–25112); `gc_roots` sorts/dedups to erase `HashMap` order (43690–43694); `FunctionRow` carries no native tags so `Native` payloads are never decoded from untrusted bytes; `code_segments`, `combinators`, `from_async` are compacted at sweep.
- The fixed stack geometry constants (151–205) reason carefully about width-not-depth exhaustion and separately about native re-entry depth, with the fuzz trophy that motivated each.
- `Native::arity` values and `TYPED_ARRAY_TYPES` ordering are correct on inspection.
