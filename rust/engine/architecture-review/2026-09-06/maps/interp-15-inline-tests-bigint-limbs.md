## Purpose and responsibilities

This range is the tail of the 44,942-line `interp.rs`, *outside* the giant `impl Interp` (which
resumes at 43488). It holds three unrelated things that landed together by accretion:

1. **Free-standing pure helpers** used by the interpreter and built-ins (40920–41968):
   Temporal fixed-offset zone helpers, the `Native::*` unsupported-name table, RegExp flag-bit
   lookup, the `ArithOp`/`BitOp`/`RelOp` enums, the `count_new_locals` metering walker,
   `branch_target`, the "stage-1" value-only helpers (`to_boolean`, `to_number`, `strict_equals`,
   `loose_equals`, `apply_arith`, `unary_minus`, `math_to_integer`, `numeric_of`, `fx_pow`), the
   UTF-16BE/CESU-8 codecs, JSON string escaping, `parseInt`/`parseFloat`/`StringToNumber`,
   radix formatting, and the `fxArgToIndex`/`fxArgToPosition` clamps.
2. **The in-file `#[cfg(test)] mod tests`** (41970–43173): 37 tests that need private access to
   `Interp` internals (`slots`, `async_instances`, `do_harden`, `relink_program_symbols`, `chunks`).
3. **BigInt limb arithmetic** (43175–43392) plus the BigInt/index string parsers (43413–43484):
   little-endian `Vec<u32>` magnitudes with sign carried separately.

## Architectural observations

- **Two-tier value helpers with a silent wrong-tier failure mode.** Chunk-blind `to_boolean`/`to_number`/`strict_equals`/`loose_equals`/`slot_to_ecma_string` return *plausible* wrong answers for String/BigInt payloads instead of refusing. The arena-aware twins (`truthy`, `strict_equal`, `binary_equal`, `render`) exist, but nothing in the type system forces a caller onto the right tier — the descriptor parser (37853–37856) picked the wrong one. A narrowed input type (e.g. a `PrimitiveNoChunk` view) or `Option` return would make the class unrepresentable.
- **Duplicated instruction decoding for metering.** `count_new_locals` carries its own step table (`NEW_PROPERTY => 5`, `NEW_PROPERTY_AT => 1`, `NEW_PRIVATE_1/2 => 4/5`, `CODE_* => 2/3/5 + body`) that must agree with both the dispatch loop's advances and `opcode::instruction_len`. W6-17 was a desync in this table. It is also executed on every function-definition evaluation (13289): a closure created inside a loop re-scans its whole body each iteration, an O(body) cost with no cache keyed on `body_start`.
- **Three whitespace definitions in one file.** `is_ecma_ws` (ASCII-only), Rust `str::trim` in `parse_bigint_string_u64` (Unicode White_Space: includes U+0085, excludes U+FEFF), and whatever the lexer uses. None is the spec's StrWhiteSpaceChar.
- **Determinism.** Everything in the region is IEEE/integer arithmetic and deterministic, with one exception: `fx_pow` → platform `pow` (W6-23 decision-of-record: per-platform determinism). `parse_int` accumulates in f64 (`result * radix + digit`, 41552), which is deterministic but not correctly rounded for long decimal strings — faithful to XS's loop, not to a correctly-rounded parse. Rust's `str::parse::<f64>` (41689) is pure Rust and correctly rounded. No HashMap iteration, no host time, no locale in this region; Temporal zone resolution is a fixed table.
- **Untrusted-input surfaces.** `cesu8_to_units` (bytecode operand), `count_new_locals` (bytecode), `parse_temporal_zoned`/`parse_offset_ns` (guest strings), `read_bigint` (chunk bytes, incl. snapshot-restored). All bounds-guarded; ASCII-only slicing keeps `&str[..]` on char boundaries. `branch_target` wrap is caught at 11354. `number_to_radix_string` cannot see radix 0/1 because the caller range-checks (30151). `bi_to_decimal`'s `chunks.last().unwrap()` (43387) is unreachable for non-zero input. No panics on untrusted data found in this region.
- **Named skips as production semantics.** `Number.prototype.toString(radix)` on a fractional value (30173), BigInt `/`, `%` (39123) and — by absence of any `bi_div`/shift/bitwise helper in the crate (grep) — `**`, `<<`, `>>`, `&`, `|`, `^` halt the crank with `Halt::Unsupported`. For the Agoric consumer, BigInt division is in the hot path of ERTP/Zoe ratio math.
- **Metering-doctrine drift is visible in the tests.** Fifteen assertions read `"bit-exact computrons vs XS"`; no test references `COST_TABLE_VERSION`. A planned `ironhorse-meter-N` recalibration would redden 15 unit tests whose messages assert the declared non-goal.
- **Verification labels without a verifier.** Four tests are named `*_is_miri_clean`; README repeats "Miri-clean" six times and gives a manual `cargo +nightly miri test` command; no CI job runs Miri (or ASAN/UBSAN, clippy, rustfmt). With `#![forbid(unsafe_code)]`, Miri over this crate can only find UB in `std`/dependencies, so the label adds confidence it does not earn.
- **Fixture provenance.** Test comments say "captured from the pin `48ee02d8cfe0`" (42855, 42898) — moddable 8.2.3 — while README.md 27–29 names `23b4d6b0a65f` (8.3.1) as the current pin. The bytecode and computron constants in this module were captured against the superseded oracle.
- **Doc-comment drift in the BigInt block.** Three docstrings are stacked at 43298–43310: the `fxNumberToBigInt` paragraph and the `getBigInt64` paragraph both sit above `element_slot_to_i64`, whose own one-line doc is the third; `u64_to_signed_limbs` and `number_to_bigint` have no attached doc.
- **Test brittleness.** `hostile_suspend_below_run_base_fails_closed` asserts `Halt::Unsupported("bitwise:stack-underflow")` (42305) though its comment records that the terminal outcome already moved once; the invariant sought is "does not panic". A fuzz-trophy lock that pins an incidental refusal string will churn on every unrelated guard change.
- **GC-roots / snapshot / side tables:** nothing in this region owns a side table. BigInt chunk bytes `[sign u8][LE u32 limbs]` are serialized verbatim by the snapshot; `read_bigint` tolerates short/misaligned payloads (39026–39040), so a corrupt BigInt chunk cannot panic here.
- **Minor.** `balance_zoned_diff`: `ns.unsigned_abs() as i128` wraps for `i128::MIN` (41172) — unreachable given Temporal's ±8.64e21 ns range. `parse_offset_ns` accepts single-digit fields (`+1:2`) where the grammar requires two digits (40987–40989). `parse_temporal_zoned` accepts `"-000000"` as year 0.

Confidence: high.

## What is done well

- **The BigInt limb core is correct where it exists.** Carry/borrow arithmetic uses u64/i64 intermediates with no overflow path; `bi_mul_mag`'s final carry slot is provably untouched; `-0` is normalized at every signed wrapper; `number_to_bigint` is exact by construction (power-of-two scaling). `read_bigint` tolerates malformed chunk payloads without panicking.
- **UTF-16 storage is thoroughly locked.** Six tests (42925–43172) pin codec inverse, lone surrogates, O(1) indexing across supplementary characters, byte-lexicographic order == code-unit order, WTF-16 concat, and the exact snapshot bytes — exactly what design 318–336 asks for.
- **Untrusted-input hygiene in the region is good.** Every bytecode walk (`count_new_locals`, `cesu8_to_units`) uses `.get()`/length checks; string slicing is at ASCII boundaries; `branch_target`'s wrap is caught by the loop's `pc >= len` check; `Halt::Decode`/`Unsupported` are used instead of panics.
- **`every_opcode_decodes_and_dispatches_without_panic_or_decode_error`** is a strong structural test: full 245-opcode dispatch coverage with an exhaustive `Halt` match that makes an escaped `Yield`/`Await` a test failure.
- **Fuzz trophies are kept as executable locks with their exact bytes and CI provenance**, and the async-instance leak test asserts a bounded side table (`async_instances.len() <= 1`), not just a halt.
- **`meter_module_is_firewalled_from_cost`** is a cheap, effective architectural invariant (a one-directional dependency) enforced in both feature configurations.
