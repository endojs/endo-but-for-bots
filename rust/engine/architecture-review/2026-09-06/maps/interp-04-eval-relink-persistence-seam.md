## Purpose and responsibilities

This region is the **linkage-ownership and persistence seam** of the interpreter:

1. **Runtime source execution** — `set_source_compiler`, `eval_source`,
   `create_dynamic_function`, `relink_program_symbols`, `intern_program_symbol`. An
   independently compiled unit (program-local symbol numbering) is relinked into the realm's
   shared symbol space, its intrinsics lazily bound, its bytecode retained as a code segment,
   and it is run as an isolated program activation on the same heap/meter.
2. **Per-crank relinking** — `relink_crank`, `install_pending_intrinsics`, the installed-names
   floor (`installed_names_floor` / `restore_installed_names_floor`), and the id-space
   witnesses (`first_runtime_intern_id`, `may_hold_runtime_interns`, `stored_runtime_intern`).
3. **The persistence seam the snapshot crate consumes** — the read-side projection
   (`stack_slots`, `program_symbol_names`, `meter_state`, ~20 `*_snapshot` views) and the
   write-side `restore_*` verbs, plus the persist gate (`stored_unpersistable_row[_at_checkpoint]`,
   `function_persists`, `non_persisting_functions`) and the restore-time rebuilds
   (`rebuild_global_props`, `rebuild_boot_accessors`).
4. **Global-property materialization** — `define_global_id`, `create_global_property`,
   `materialize_global_property`, `tick_property_create`.

The atom *format* lives in `ironhorse-snapshot` (image.rs); this region owns the
`Interp` ↔ rows conversion and every invariant a restored machine must satisfy.

## Architectural observations

- **Two persistence idioms coexist without a type-level tie.** The `SideTable` ledger in the snapshot
  crate is an exhaustive `match` (good), but the *vm-side* correctness of "what resume brings back"
  is an ad-hoc allowlist: `function_persists` (8831–8844) enumerates four tables plus an index
  test; `stored_unpersistable_row_inner` (8644–8822) enumerates every Slot-bearing side table by
  hand ("Kept in the ledger's order so a new carried row is easy to slot in", 8743–8744). A new
  runtime-minted native class must be added in three places (allowlist, snapshot verb, restore
  verb) with no compiler help. The census's `gc_visitation_registry.rs` covers GC visitation, not
  persistence classification.
- **Fresh-boot side tables are never reconciled with the restored arena.** `image_to_interp` boots
  a fresh machine and replaces its arenas (machine.rs 635–636); `restore_snapshot_state` rebuilds
  exactly three derived tables (symbols, `global_props`, boot accessors). Every other fresh-boot
  row keyed by a boot slot index (`functions`, `ctor_prototype`, `proto_methods` …) is kept even if
  the image's free list says that slot is free. Live machines prune those rows at sweep
  (44577–44641); resumed machines do not — a divergence class between the twins whenever a boot
  slot dies.
- **Boot natives are only *mostly* rooted.** `gc_roots` roots `intrinsics`, `proto_methods`,
  `proto_data`, `proto_accessors`, `proto_value_data`, `well_known_symbols` and the `*_proto`
  fields, but not the five field-only natives listed above. Their only heap edge is the property
  a guest may delete.
- **The eval bridge reuses the relink install pass with a different `names` argument**, and the
  pass has a side effect (`installed_names_len = names.len()`, 7425) that is correct for a
  whole-table argument and wrong for a unit-local one. The three callers (`link_intrinsics`,
  `install_pending_intrinsics`, `eval_source`) pass different shapes of `names` into one body.
- **Validation is split across crates by prose.** Some restore verbs re-validate ("belt and
  braces"), others state "the decoded slots were already bounds-checked with the heap"
  (9118–9119). The `ValidatedSnapshot` proof wrapper (machine.rs 625) is a real type witness for
  *decoder* validation, but which invariants the decoder proves is documented only in comments on
  both sides.
- **Panics/unwraps/indexing.** In-region panics are on live-state invariants, not image bytes:
  `.expect("every guest bytecode function owns a code segment")` (9232, upheld by 13302–13313),
  `self.functions[&owner]`/`[owner]`/`[function]` (9250, 9422, 9526, 9905), `segment_remap[..]`
  (9253), `self.promise_guards[old]`/`self.combinators[old]` (9910, 9915), `comb_map[&ci]`
  (9875), `results_lengths[r.a]` (10038, bounds-guarded), `.unwrap()` (9579, guarded by the match
  arm), `unreachable!` (8172, internal). Sweep pruning of `functions`/`proxy_revokers`/Intl/promise
  tables uses one `dead` set (44577–44641), so the `[]` lookups on snapshot are consistent.
- **Determinism.** No `HashMap` iteration order reaches an observable: all views sort by owner,
  `stored_runtime_intern` and `live_dynamic_segment_function` take `min`, `saved_frame_snapshot`
  sorts `id_map`. f64 leaves the region only as `to_bits()`; `time_clip` (39578) and
  `date_from_components` (39584) return the `f64::NAN` literal, so the `dates_snapshot` boot-seed
  filter (9197) compares canonical bits. `last_index` values are integer-valued (12651, 20176–20895).
  No host time/locale.
- **Metering doctrine.** Install/relink/restore work is deliberately unmetered ("pre-existing
  globals", 7414). `relink_crank`'s O(n·m) name search (8355–8365) is unmetered host work whose
  size a guest can drive (interned keys grow the table). `intern_key` charges one slot allocation
  for a novel non-default key (34991–34995), consistent with XS's `fxNewNameX`.
- **API boundary.** `Interp` exposes ~45 `pub fn` persistence verbs taking tuples like
  `Vec<(u32, u8, u32, u32, u32)>`; the snapshot crate re-packages them into image structs. Row
  structs (`FunctionRow`, `PromiseRow`, …) exist for the later carries; the earlier ones stayed
  tuples — two generations of API shape in one seam.
- **Monolith symptom.** The seam is ~2,750 lines inside the 38k-line `impl Interp`, interleaved
  with unrelated global-property metering (10598–10650). It reads as an accretion log: comments
  cite wave-4 P1, W6-7, W6-9, W6-18, W6-19, W6-24, W6-25, G1, G2, schema 11/12/13/14/18/23.

## Candidate findings

1. **Boot-slot immortality is assumed by the persistence seam but not enforced; a guest can free a boot native, and an honest snapshot then becomes un-restorable.** `interp.rs:8832` (`function.0 < self.boot_slot_count` ⇒ "persists"), `9317–9319` (`if self.functions.contains_key(&owner) { return false; }`), `8273–8318` (no reconciliation of fresh-boot rows), `gc_roots 43502–43695` (no root for `iterator_identity` 5992 et al.). *Claim:* after `delete Iterator.prototype[Symbol.iterator]`, `collect_garbage()`, and one crank that defines functions, `is_quiescent()` is true, `stored_unpersistable_row()` is `None`, `write_snapshot` succeeds, and `from_snapshot_bytes` returns `Corrupt("side-table restore: malformed retained function state")`. *Evidence (probe run):*
   `crank1: completed=true result="true/undefined"` / `quiescent=true unpersistable=None` / `RESTORE REFUSED: Corrupt("side-table restore: malformed retained function state")`.
   *Why it matters:* the store accepts a state it can never resume — a bricked worker/vat, reachable by legal guest code (SES's `removeUnpermittedIntrinsics` deletes properties from intrinsics). The dual symptom (a non-function object reusing the index inherits the fresh boot's stale `FuncInfo`) was not reproduced but follows from the same root cause. Confidence: high (reproduced). Category: snapshot-coverage / gc-roots. Severity: high.

2. **The eval/`Function` install pass regresses the installed-names floor to the unit's own name count, so the next relink resurrects intrinsics the guest deleted.** `interp.rs:8026–8027` (`install_intrinsic_bindings(&eval_names, false, …)`) with `7425` (`self.installed_names_len = names.len();`), then `8412–8418` re-considers every id above the (now tiny) floor create-only — a deletion has no property, so it is re-created. *Evidence (probe):* control `delete globalThis.Math` → next crank `typeof Math` = `"undefined"`, floor 3→3; with `eval('1')` between: `floor 4->0`, next crank `"object"`; `delete Array.prototype.map; eval('1')` → next crank `typeof [].map` = `"function"`. *Why it matters:* a guest's (or SES lockdown's) deliberate removal of an intrinsic is silently undone after any `eval`/`Function` use — a confinement regression, and the regressed floor is what NFLR persists (8432–8446), so the resumed twin agrees (deterministic, but wrong). The existing lock `relink_preserves_guest_edits.rs` covers relink-only, not eval-then-relink. Confidence: high (reproduced). Category: security. Severity: high.

3. **Restore keeps every fresh-boot side-table row even when the restored free list says the slot is dead; live machines prune, resumed machines don't.** `interp.rs:8273–8318` (only symbols, `global_props`, boot accessors rebuilt) vs `44577–44641` (live sweep `retain`s `functions`, `ctor_prototype`-adjacent tables by `dead`). *Claim:* a boot function slot freed before suspend has a stale `FuncInfo` after resume, so a later allocation at that index is treated as that native. *Evidence:* `self.functions.insert(f, FuncInfo { method: Some(m) … })` at boot (7177) is never removed on the resume path; `restore_snapshot_state` has no free-list pass. *Why it matters:* silent-wrong divergence between continuous and resumed twins — the class every carry test guards. Not reproduced (my probe's reused slots did not land on plain objects); same fix locus as 1 but a distinct mechanism (reconcile at restore vs. pin at GC). Confidence: medium. Category: snapshot-coverage. Severity: medium.

4. **Restore-side validation is split across two crates by prose, and inconsistent per verb.** `interp.rs:9444–9453` (`restore_proxy_state` inserts `target`/`handler` unchecked), `9120–9124`, `9205–9210`, `9181–9185`, `9666–9685`, `10207–10229`, `9611–9619` insert blindly, while `9025–9100`, `10475–10500`, `9942–10135`, `10396–10450` re-validate; every verb's `insert` silently overwrites a duplicate owner. `9118–9119`: "the decoded slots were already bounds-checked with the heap." *Why it matters:* the fail-closed property depends on image.rs (e.g. frame validation 3876–4004) whose obligations are stated only in comments on both sides; a decoder relaxation would not be caught by the vm. Confidence: high on the asymmetry; the decoder may well cover each case today. Category: api-boundary. Severity: medium.

5. **The persistence allowlists are hand-enumerated and index-keyed with no compile-time tie to the mint sites.** `interp.rs:8831–8844` (`function_persists`: four tables + index test), `8699–8822` (per-table traversal, "Kept in the ledger's order so a new carried row is easy to slot in"). *Claim:* adding a runtime-minted native class requires coordinated edits in the gate, a snapshot verb, and a restore verb, with only a runtime test (`persist_gates.rs` 259–277 says the doomed set is empty today and the net is "future-proofing") to catch omission. *Why it matters:* the headline bug class of prior waves (a table missing from the ledger) is structurally re-creatable; the `SideTable` exhaustive match protects the crate-side ledger but not this vm-side classification. Confidence: high. Category: modularity. Severity: medium.

6. **Doc comments in the seam describe retired mechanisms, and the seam's correctness argument lives in those comments.** `interp.rs:8238–8241` ("rich per-instance side tables enumerated `Pending` … are the honest remainder"), `8285–8286` ("only `symbol_names` is serialized"; SYMB travels at 10458/machine.rs 652), `8599–8610` ("These two side tables do not travel … a resumed guest function is uncallable today"; FUNC/PRXY/ACCS travel at 9213/9405/9486), `10263–10271` ("The bound-function LINK tables … are not emitted at all"; emitted at 9523), `8581–8585` (legacy name kept). *Why it matters:* reviewers and maintainers reason from these comments; several now assert the opposite of the code. Confidence: high. Category: docs-drift. Severity: medium.

7. **`eval_source` under-counts the value-stack budget for nested units, contradicting the documented XS overflow bracket.** `interp.rs:8048–8051` (`mem::take` of `locals`/`args`), `8074` (`self.frame_slots = 0`), `8205–8207` (`stack_slots_in_use = frame_slots + live`), doc `8189–8195` ("ironhorse never *completes* a program XS overflows on"). *Claim:* inside an eval unit, the caller's suspended frames vanish from the overflow count, so the abort point differs from an uninterrupted dispatch; only `stack.len()` residue and `DISPATCH_REENTRY_LIMIT = 64` (205) bound it. *Why it matters:* deterministic per release (fine for consensus) but a documented parity claim does not hold across the eval boundary. Confidence: medium (not measured). Category: robustness. Severity: low.

8. **`relink_crank`'s non-aligned path is quadratic unmetered host work over guest-growable input.** `interp.rs:8352–8367`: `let mut extended = self.symbol_names.clone();` then `extended.iter().position(|n| n == name)` per crank name, ignoring the existing `symbol_ids` map. *Claim:* a machine whose table a guest has grown toward the u16 ceiling (JSON.parse keys intern, 34986–35021) pays O(table × crank_names) string compares on every crank whose names are not byte-identical to the table. *Why it matters:* the relink is outside the meter; cost is borne by the host per crank. Confidence: high on the shape; magnitude depends on realistic table sizes. Category: performance. Severity: low.

9. **`restore_regexps` runs the regexp compiler over image-supplied patterns at resume time.** `interp.rs:9153–9169` (`ironhorse_regexp::compile(&source, &flags)` per row). *Claim:* a crafted image can drive the recursive pattern compiler (the census notes the regexp suites need `RUST_MIN_STACK=16 MiB`) at *resume*, not inside a metered crank, so a deep pattern yields a thread-stack abort rather than a refused image. *Why it matters:* snapshot images are an untrusted input per the design; a resume-time process abort is worse than a crashed crank. Confidence: medium-low (regexp compiler not read; the same surface exists live via `new RegExp`, where the crank boundary contains it). Category: robustness. Severity: low.

10. **`accessor_function_persists` is dead code the compiler flags** (`interp.rs:9473–9482`; observed `warning: method accessor_function_persists is never used`). *Why it matters:* small, but the seam's gate logic keeps a second, unused notion of "persists"; delete or wire it. Confidence: high. Category: other. Severity: low.

Aside (not a finding of this region, observed while probing): `[][Symbol.iterator]()` at top level halts with `Throw("TypeError")`, while `Iterator.prototype[Symbol.iterator]` is reachable. Another reader should check the computed-symbol-key call path.

## What is done well

- The relink design is genuinely append-only and fail-closed: `remap_ids`/`instruction_len` return `Option` on any undecodable byte, id 0 is left alone, `TableFull` is refused before the string-key and symbol-key id spaces can meet (8355–8385), and the split id space retired a whole refusal class (8368–8376).
- Determinism discipline is consistent across ~20 views: every snapshot sorts by owner, witnesses take `min`, and compacted arenas (guards, combinators, segments) are emitted in canonical dense order — the snapshot image cannot depend on `HashMap` order.
- The promise-cluster restore (9942–10135) re-proves cross-row coherence (pair polarity per guard, combinator element bounds, no capability slots on native reactions, settled rows hold no reactions) rather than trusting the decoder.
- `rebuild_global_props` (10573–10592) is written for hostile arenas: bounds-checked indices and a budget-capped walk so a cyclic `next` terminates.
- Code segments are reclaimed by the collector (`compact_code_segments` 44516–44538) and compacted again on snapshot (9221–9244), so retained bytecode does not leak across cranks.
- The quiescence gate (10733–10743) and the `NotQuiescent` refusal were confirmed live: a halted crank cannot be snapshotted.
