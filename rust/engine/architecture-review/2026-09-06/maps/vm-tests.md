## Purpose and responsibilities

`ironhorse-vm/tests/` is the oracle-free, PR-CI-run (`ci.yml:746`, `cargo test -p
ironhorse-vm -p ironhorse-snapshot`) lock set for the interpreter. It has two populations:

1. **Invariant locks (14 files, 41 tests)** — each file pins one review-wave finding (W5, W6-1..
   W6-19, llm-rebase review) as a behavioral regression: GC visitation of side tables and
   frame-adjacent state, the GC-ground-truth registry, id-space exhaustion, lazy install
   floor, nested-run unwind, reaction-arena pruning, relink preserving guest edits, step-limit
   scoping, strict-register crank hygiene, TypedArray source-length bound, uncaught-throw
   new-target hygiene, endowment seeding order, Error own-property materialization.
2. **Fuzz-finding regressions (26 files, 26 tests)** — one file per continuous-fuzz finding,
   named `finding_<16-hex-id>_<class-slug>.rs`, with fixtures
   `fixtures/finding-<id>.{input,bytecode,symbols}.bin` and `.expected-result.txt`. Three
   classes: `large_integer_dtoa` (9), `regexp_meter_overflow` (6), `regexp_source` /
   `regexp_tostring` / `long_regexp_tostring` / `regexp_source_meter` (8). Roughly 20 of the 26
   record findings where "the port was never wrong" (oracle capture-buffer truncation, oracle
   32-bit meter truncation, XS non-shortest dtoa); they lock the port's side so the port can
   never be "corrected" toward the oracle.

The suite depends on `ironhorse-compile` (dev-dep, `Cargo.toml` dev-dependencies) to turn JS
source into bytecode + SYMB atom, and on `ironhorse-regexp` (a *regular* dependency of the vm,
`Cargo.toml [dependencies]`) for the six regexp-meter files.

## Architectural observations

**GC coverage is aimed at the wrong collector.** Every behavioral GC lock in this crate
(`gc_frame_state.rs:31`, `gc_side_tables.rs:36`, `gc_anchor_truth.rs:33`,
`reaction_arena_pruning.rs:36,73`) invokes `Interp::collect_garbage`, which no production
path calls. The collector production runs — `free_pages` fed by the store's page-reachability
query — has zero behavioral tests here. The registry closes the *forgot-the-table* class for
both walks textually, and the snapshot crate's parity net compares the two collectors'
outcomes, but the W6-1..W6-4 fixtures (suspended `with` env, detached `super` home, fromAsync
thisArg under compaction, pending Intl getter) are never run against the shipped collector in
this crate. Note also that `ephemeron_edges` (weak-collection precision) exists only in the
full collector ("the partial walk stays page-conservative", registry :308) — so production
never exercises the ephemeron pass the tests lock.

**No mid-crank collection exists**, and the tests reflect that: every `collect_garbage()`
call sits between `run()`s. The frame-register roots (registry :233-243) are therefore
textually verified but behaviorally unverifiable through the public API; if allocation-pressure
GC is ever added (design § Value and heap model, lines 311-314, describes XS's collector), an
entire root class comes online untested.

**The halted-crank contract is ambiguous and the suite pins both readings.** `run()` says a
halted crank "keeps everything" and is rewound; `uncaught_throw_hygiene.rs`,
`step_limit_scope.rs`, and `id_space_exhaustion.rs:65-72` pin re-use of the same machine after
a halt. Under the re-use reading the hygiene is incomplete (confirmed `new.target` leak on
`StepLimit`/`MeterAbort` escapes; `exception` never cleared → permanent non-quiescence and a
permanently rooted thrown graph). Under the rewind reading, W6-15's disarm and these three
tests guard a path that must never be taken. Either way the vm-level contract should be
stated once and the suite aligned to it.

**Metering doctrine drift is baked into CI.** `finding_1898f584e9bf841a_regexp_source_meter.rs:35-38`
asserts `computrons == 36` because that is "the oracle's 36 computrons"; the six
`regexp_meter_overflow` files assert `match_meter_raw == steps * 65536` bit-exact (e.g.
`finding_5565a021…:45-47, 63-66`). Their stated purpose (no u32 truncation, no panic) is served by
`> u32::MAX` plus a run-twice equality; the exact XS constants make an `ironhorse-meter-N`
recalibration a seven-test breakage in a job whose tests are about something else.
`RunOutcome`/`Interp` docs (3597-3598, 3620-3625) still describe parity as the contract.

**Untrusted-input surfaces have thin oracle-free coverage.** The threat model names bytecode
and snapshot images as untrusted. `ironhorse-fuzz/Cargo.toml` hard-depends on `xs-oracle`, so
the decoder fuzz target and its lib tests cannot build in the PR job; ironhorse-vm/tests has no
malformed-bytecode, `Halt::Decode`, or `run_program_bounded` test (grep), leaving
`lib.rs:141-172` (`nested_start_async_degrades_to_stack_overflow`) as the only decoder-totality
regression in PR CI. `Halt::MeterAbort` (48 return sites) and `arm_meter` appear in no test file.

**Error model.** `Halt::Unsupported(&'static str)` is documented as "an opcode outside the
stage-1 subset" (3535-3538) but is the general refusal channel (376 uses), including resource
refusals a guest could observe (`property-key:id-space-exhausted`, id_space_exhaustion.rs:50;
`native-call:TypedArray:bad-length`, typed_array_source_length.rs:58-61). Tests pin these string
identities as the contract; a host cannot distinguish "not implemented" from "refused".

**Monolith symptoms in the suite.** 26/40 files are one-test regressions with 30-50-line
provenance docblocks; ~20 lock oracle-harness bugs ("the port was never wrong"). `fn compile`
is copied 11 times; five variants of a two-crank runner exist; two hand-copies of the fuzz
generator claim byte-equivalence with `ironhorse_fuzz::gen_program` with nothing enforcing it
(currently in sync for the arms compared: `gen_expr` 0-2 and all of `gen_atom`). Fixture naming
deviates once (`finding-67a52af412f03a7b-input.bin`, hyphen vs `.input.bin`). The design's
"trophies ledger" (ironhorse-engine.md:720-721) is these scattered docblocks; there is no index.

**Determinism.** Registry iteration uses `BTreeMap` (deterministic). `endowment_order.rs` proves
insertion-order independence with two orders in one process (sound: each `HashMap::new()` has
its own `RandomState`). No test runs one program on two fresh machines and compares the full
`RunOutcome` (`computrons`, `meter_raw`, `dispatched`); a probe shows it holds in-process, and
the cross-host golden vector lives in `ironhorse-snapshot/tests/metamorphic_determinism.rs`.
No f64-formatting hazards beyond `number_to_ecma_string` pins (which lock shortest-round-trip
spelling — correct per spec). `typed_array_source_length.rs:55` uses a 20 s wall-clock
deadline (deliberate: the failure mode is a process abort or a minutes-long stall).

**Test-suite cost.** `id_space_exhaustion.rs` builds a 66,000-key JSON source (~1 MB) and takes
19.5 s in debug (census) — the single slowest PR-CI test; `typed_array_source_length.rs`
spawns a thread that is not joined on timeout.

**Registry net robustness.** `fn_body` brace-matching runs over raw source (comments not
stripped first), so an unbalanced `{` inside a comment within a visitor body would mis-scope a
check; `strip_comments` truncates any line containing `//` inside a string literal. Neither
currently bites. The net is "textual presence", acknowledged at :26-30 — it proves a field is
*named* in a walk, not that every subfield is visited; the behavioral twins carry that burden
and (see above) are aimed at the non-production collector.

## Candidate findings (most architecturally significant first)

1. **The vm's GC behavior locks test a collector production never runs.**
   `gc_frame_state.rs:31`, `gc_side_tables.rs:36`, `gc_anchor_truth.rs:33`,
   `reaction_arena_pruning.rs:36` — all call `m.collect_garbage()`.
   Claim: no non-test code in `rust/` invokes `Interp::collect_garbage`, and no file in
   `ironhorse-vm/tests` invokes `free_pages`, the collector production actually runs.
   Evidence: `grep -rn "collect_garbage(" rust --include=*.rs` (excluding tests/benches) →
   only `ironhorse-snapshot/src/machine.rs:1723,1759`, inside `#[cfg(test)]` (line 1654);
   `rust/endo/src/ironhorse_engine.rs:670-681` `pub fn collect(...) { ... partial_collect(session, ...) }`;
   `machine.rs:2002` `let freed = session.machine_mut().free_pages(&dead);`
   Why it matters: the W6 fixtures that found real sweeps (suspended `with` env, detached
   `super` home, fromAsync compaction, pending Intl getter, Date-brand prune) are never run
   against the shipped page collector in this crate; the ephemeron precision pass exists only in
   the untested-in-production full collector. Confidence: high. Category: gc-roots.

2. **`pending_new_target` leaks across a non-throw halt (StepLimit/MeterAbort) into the next crank's `new.target`** (registry claims it is "disarmed before every boundary").
   `ironhorse-vm/tests/uncaught_throw_hygiene.rs:1-7` (only the THROW escape is locked);
   `interp.rs:11157-11175` (run entry resets `strict`/`active_segment`/`top_level_code` only);
   disarm sites `interp.rs:8072`, `34603`; consume `16291`.
   Claim: after `run_bounded` halts with `StepLimit` (or `arm_meter` halts with `MeterAbort`)
   between `XS_CODE_SUPER` and the construct frame, the next `run` on the same machine
   observes `new.target !== K` inside `new K()`.
   Evidence (probe, scratch crate): `A crank1 halt=StepLimit(5000) ... A crank2 completed=true probe=false`;
   `D2 crank1 halt=MeterAbort ... D2 crank2 completed=true probe=false`; control `probe=true`.
   Why it matters: the suite pins machine re-use after halts (`step_limit_scope.rs:22-27`,
   `id_space_exhaustion.rs:65-72`) while `run()` (11232-11233) says halted cranks are rewound
   whole — the contract is contradictory and, under the re-use reading, W6-15 is only one-third
   fixed. Confidence: high (confirmed). Category: error-model.

3. **An uncaught throw makes the machine permanently non-quiescent and roots the thrown value forever.**
   `interp.rs:10733-10743` (`is_quiescent` requires `exception.kind == Undefined`);
   `exception` clears only at catch sites (15693, 15828, 16607, 17129, 17373, 21640), never in `run`.
   Claim: after a `Halt::Throw` escape, later cranks that complete normally leave
   `is_quiescent() == false`, and `exception` (a `GcRoots` field, registry :237) keeps the thrown
   object graph alive across every later collection.
   Evidence (probe): `E2 crank1 halt=Throw("[object Object]") quiescent=false; crank2..4 completed=true quiescent=false; after collect_garbage quiescent=false`.
   Why it matters: `uncaught_throw_hygiene.rs` establishes vm-level re-use after an uncaught
   throw as a contract, but nothing locks that such a machine can ever persist again or that it
   drops the exception; the persist gate then conflates "mid-frame" with "once threw". Confidence:
   high (behavior confirmed; root-cause by code reading). Category: gc-roots.

4. **Fuzz regressions pin XS raw meter constants as CI acceptance — metering-doctrine drift.**
   `finding_1898f584e9bf841a_regexp_source_meter.rs:35-38`: `assert_eq!(output.computrons, 36, ...)`
   ("the oracle's 36 computrons"); `finding_5565a021a8cc30bc_regexp_meter_overflow.rs:47,63-66`:
   `const EXPECTED_MATCH_METER_RAW: u64 = 8_411_414_528;` `assert_eq!(outcome.match_meter_raw, EXPECTED_MATCH_METER_RAW, "... pinned bit-exact")` (six files).
   Claim: seven PR-CI tests fail on any `ironhorse-meter-N` recalibration although their stated
   purpose (no u32 wrap, no allocation on the source getter) is independent of XS's weights.
   Why it matters: designs/ironhorse-engine.md:441-458 says computron equality with XS is "never
   an acceptance gate"; `RunOutcome` doc 3597-3598 still says "comparable bit-for-bit with the
   oracle". Confidence: high. Category: metering.

5. **The untrusted-bytecode surface has one oracle-free regression in PR CI.**
   `ironhorse-fuzz/Cargo.toml` `[dependencies] xs-oracle = { path = "../xs-oracle" }` (unconditional);
   `ironhorse-vm/tests/*`: zero mentions of `Halt::Decode`, `run_program_bounded`, `StackOverflow` (grep);
   `lib.rs:141-172` is the only decoder-totality test; `ci.yml:746` PR job = vm + snapshot only.
   Claim: no test in `ironhorse-vm/tests` feeds malformed or truncated bytecode to the decoder.
   Why it matters: design § Fuzzability target 2 ("loader still must not panic on corrupt input

## What is done well

- **Struct-derived ground truth** (`gc_visitation_registry.rs`) is a genuinely good idea: it
  kills the "forgot the table entirely" class for every future field, forces an explicit
  classification, and checks each classification against the real visitor bodies instead of
  recording a dead note. Its own header is honest about what textual presence cannot prove.
- **Churn-then-read fixture discipline** (`CHURN` constants; `a_recycled_slot_does_not_inherit_a_dead_dates_brand`
  probing all 64 reused slots) converts silent-wrong bugs into deterministic failures rather than
  lucky passes, and the GC-vs-plain twins compare results *and* computrons, so a collection that
  perturbs metering is caught too.
- **Fail-loud test plumbing**: marker lookup panics with the missing marker; parse-sanity
  thresholds (:370, :381-385) guard against a parser silently matching nothing.
- **Fuzz-regression provenance is exemplary**: each file records target, toolchain, sha256,
  minimized bytes, the arithmetic of the reproducing value, and whether the causal fix was
  port-side or oracle-side, and explicitly refuses to let the port be "corrected" toward a
  non-conformant oracle (dtoa shortest-round-trip).
- **Determinism hazards are treated as first-class regressions** (`endowment_order.rs`,
  `strict_crank_boundary.rs` "a resumed machine DIVERGED from its uninterrupted twin").
- **Negative-space coverage**: `typed_array_source_length.rs` locks an unmetered-allocation
  class by deadline, naming both failure modes (process abort vs. minutes-long stall).
