# Region map: compile-coder-a — `ironhorse-compile/src/coder.rs` 1–3000 + `opcodes.rs`

Reader: compile-coder-a. Read fully: coder.rs lines 1–2999 (the range ends mid-`code_field_init_function`;
line 3000 onward is the other coder reader's region) and all of opcodes.rs (254 lines). Cross-region
facts below were confirmed by grep/targeted reads, cited individually. I also built a scratch probe
crate (scratchpad/probe) against the `ironhorse-compile` lib to settle four questions empirically;
results are quoted where used. No repo file was modified.

## Purpose and responsibilities

`coder.rs` is the last stratum of the pure-Rust compiler (lexer → parser → scoper → **coder**): a
transliteration of XS's `xsCode.c` that walks the parsed AST (`ast::Item`/`Node`) with the scoper's
`ScopeTree` alongside and emits a list of `Code` records, then serializes them with XS's three-pass
width-selecting serializer into (a) the `codeBuffer` bytecode and (b) the `SYMB` symbols atom. The
public entry points (`compile`, `compile_with`, `compile_atoms`, `compile_atoms_with`,
`compile_module`, `compile_module_atoms`, lines 905–996) are the crate's API; everything else is
private. `opcodes.rs` is a generated table of the 246 XS opcode byte values as `i32` constants whose
contiguity (`_1`/`_2`/`_4` triples) the coder relies on for arithmetic widening (`id += 1`).

The first half (this region) holds: the record/payload model, CESU-8 string encoding, the symbol
(atom) table with XS's bucket-walk ID assignment, the `Coder` struct and its `fxCoderAdd*`
constructors, scope coding (`fxScopeCodingBlock`/`fxScopeCoded`/refresh/reset/using), the program and
module headers, node dispatch, expressions (literals, unary/binary/logical/conditional/sequence), all
control flow (labels, loops, `for-in/of/await`, break/continue, `switch`/`try` are in the second half
but their alias/finalize/jump machinery is used here), `yield`/`yield*`/`await`, declarations, name
inference, `super(...)`, and the first ~250 lines of class coding.

## Invariants and contracts claimed (from doc comments) — and whether the code visibly upholds each

1. **"`compile(src)` must equal `xs_oracle::run(src).bytecode` byte for byte"** (1–6, 905–908). Not
   checkable here (oracle cannot build). The mechanisms that carry it are present and faithful in
   shape: three-pass serializer, seed symbols, prepend-order buckets, CESU-8, LE encodings, `f64`
   emitted as raw bits (`to_le_bytes`, 5749). Caveat: the hash's signed-`char` promotion (221) makes
   the *oracle's* bytes platform-conditional for non-ASCII identifiers (see finding 11).
2. **"IDs are assigned by walking the buckets in index order and, within a bucket, most-recent-first"**
   (191–197, 246–263). Upheld: `assign_ids` builds per-bucket vectors in insertion order and iterates
   `.rev()`. `symbols_atom` repeats the identical walk (288–305), so strings land in id order. **Not
   upheld at the boundary**: the `u16` count uses `wrapping_add` (298, 307) and the emitter truncates
   ids with `as u16` (5787) with no bound check; probed: 70,001 used symbols compile "OK" to a
   700,004-byte program whose count field reads 4466 (= 70,002 mod 65,536).
3. **"`no_value`/`tail` are captured and cleared at the top of `code_node` so they apply only to the
   immediate expression"** (402–415). Upheld: `std::mem::take` at 1017 and 1021.
4. **"`pending_name` … set by the naming site, consumed by `code_function`"** (390–395). Partially
   visible: `set_pending_name` returns early without clearing when no name is inferred (2442–2444),
   so hygiene depends on every setter being paired with a consumer; `code_class` explicitly saves and
   restores it across heritage coding (2674, 2705) — evidence the authors have already hit an
   ordering hazard once.
5. **"ironhorse's coder is infallible, so it records the first [error] here and `compile` surfaces it
   after the pass"** (434–442, 476–487). Upheld for the three existing report sites (duplicate label,
   invalid break/continue, invalid const/using): each leaves the coder in a state that can keep
   coding (probe: all three return `Err(Syntax)`). But it is a soft contract — see finding 10.
6. **"A slotless (`NEW_TEMPORARY`) declare never reaches here"** (`add_variable`, 589–596). Enforced
   only by `expect` (595).
7. **"Deferred … assert loudly"** (module doc 40–42; 830–834; 871–877; 2623–2634). Upheld literally —
   the folds are `assert!`/`panic!` — which is itself the problem in finding 3: valid JS
   (`class C { static { let x = 1; } }`) reaches `panic!("static block with lexical declarations
   deferred")` (2997; probe confirmed).
8. **"the coder walks the *same* parsed tree the scoper walked, so a node's address keys back to the
   scope"** (scoper.rs 287–289, 356–363; coder.rs 1670–1672). Upheld today (no clones on the coding
   path I read; `code_label` explicitly dispatches by reference to avoid one). Fragile by construction.
9. **"No debug metering (`LINE`/`PROFILE`) — the oracle module entry compiles with no `mxDebugFlag`"**
   (1271–1273). Upheld: no `XS_CODE_LINE`/`XS_CODE_PROFILE` is emitted in the range read.
10. **"Even a symbol-free program yields a 2-byte `01 00` atom"** (284–286). Upheld (probe:
    `deep-blocks-500` → `symbols_atom_len=2 count_le=[1,0]`).

## Architectural observations

- **Panic census for lines 1–3000** (audited, not just counted): 12 `panic!`, 1 `unreachable!`,
  8 `assert!`/`assert_ne!`, 26 `.expect(`, 1 `.unwrap()` = **48 sites**. Triggers: (a) AST-shape
  invariants from our own parser (963, 1008, 1036–1059, 1150, 2328, 1465) — only a parser bug fires
  them; (b) scoper↔coder contract (526, 595, 701/712/714, 1991, 2538, 2774–2791, 2819, 2837,
  2918–2926) — only a scoper bug; (c) parser-guarantee invariants (loop `Label` wrapper 1698–1699,
  1713, 1733, 1808; return target 1175, 1350, 2169, 2253, 2317); (d) **unported folds** (836, 873,
  1201, 2654–2655, 2686, 2762, 2797, 2958, 2997); (e) **input-reachable semantics** (2403 "invalid
  initializer"). Classes (d) and (e) are the ones untrusted source reaches; `@host` (2686) is
  unreachable because the script entry passes `host=false` (934, lexer.rs 601–606).
- **Stack overflow is not a panic.** The whole pipeline is recursive (`intern_tree` 547–564,
  `code`/`code_node`, and the recursive-descent parser) with no depth budget anywhere in the crate
  (grep for depth/nesting/recursion guards: none). Probe (release, 8 MiB main thread): 2000 nested
  `(` compile, 4000 abort the process; with a 2 MiB stack (Rust's spawned-thread default) 500 compile,
  1000 abort. The abort happens in the parser first (parse-only probe aborts at the same thresholds),
  but the entry point that should own the budget is in this region. `catch_unwind` cannot contain it.
- **Silent width truncation at the 16-bit ID boundary** (finding 2). The `INTEGER`/`STRING`/`BIGINT`/
  index families do widen (`size1_step` 5500–5595 checks `> 255`/`> 65535`), and the scoper rejects
  >255 parameters ("too many arguments", scoper.rs:2432–2433; probe confirms), so the ID space is the
  one unguarded boundary.
- **Error model is bimodal.** Parser/scoper errors are `Result`; the coder is "infallible" with a
  first-error side channel (442, 954–956, 992–994); unported constructs are panics; the harness
  flattens panic → `Unsupported`. `ParseErrorKind::Unsupported` exists precisely for "valid but
  unported" (parser.rs:59–63) but the coder never emits it, so a genuine coder bug and a known fold
  are indistinguishable downstream (both become `Halt::Unsupported("eval:compiler-unimplemented")`,
  interp.rs:8010–8011).
- **Hidden state.** Five staged one-shot fields (`pending_name`, `pending_accessor`, `no_value`,
  `tail`, `class_instance_init`) plus three target-stack heads and `chain_target` are mutated as side
  effects of emission; two are hygienically `take`n at dispatch, the rest are save/restore by hand
  (2674/2705, 2703/2707, 2880–2886, 1499/1507).
- **Byte-identity coupling.** The public API has exactly one script shape: the oracle *shim's*
  `mxProgramFlag | mxEvalFlag` eval program (936–952; README.md:770–771, 1324–1325). No code path
  emits a non-eval program header (`XS_CODE_PROGRAM_ENVIRONMENT` is never emitted; grep shows only
  `PROGRAM_REFERENCE` uses at 2388/2499/4505/4700/4865). Production `endor -e ironhorse` therefore
  compiles every script as an eval program. Other couplings: `SYMBOL_MODULO = 1993`, the 58-entry seed
  list, signed-`char` hashing, `ID_SIZE = 2`, opcode contiguity for `id += 1`.
- **Determinism.** Good: no `HashMap`/`HashSet` is iterated in coder.rs (grep for `.iter()`/`.keys()`/
  `.values()` on the maps: none; `assign_ids` walks a `Vec<Vec<usize>>`), no host time/locale, `f64`
  emitted as bits, BigInt limbs canonical. Address-keyed maps are used only for lookup, so ASLR does
  not leak into output. One latent hazard: `Coder.tag` restarts at 0 per compile (471, 493–497)
  whereas XS's `the->tag` is per machine; two scripts compiled for one machine both mint `#0`.
  The VM currently has no `TEMPLATE_CACHE` handler (grep: only opcode.rs names it), so this is latent.
- **Metering doctrine.** The coder emits no meter points and is itself unmetered; parse metering
  (`PARSE_METER_RELEASE = "ironhorse-meter-0"`, meter.rs:22) is not threaded through
  `compile_atoms_with` (934 constructs an unmetered `Parser`). Whether the production path charges for
  compilation at all is outside this region; noted as unverified.
- **GC roots / snapshot coverage.** Not applicable to the coder (no VM state). The only snapshot-
  adjacent artifact is the SYMB atom whose id contract the VM relinks by name.
- **Dead/vestigial state.** `Payload::Index.plus_one` (69) and `Target.index` (335) are never read
  (the two lib build warnings in the census). `stack_level` is accrued on every record and snapshotted
  on every target but never checked or emitted (grep: 322–360, 450, 570–604, 646, 1463–1467, 1759,
  1865 are its only uses).
- **Docs drift.** The 43-line module header describes "child 5/7" scope with a deferred list that is
  now implemented (calls, member access, destructuring, `for-in/of`, `with`, catch bindings).
  `code_super` carries three concatenated doc blocks for `fxFunctionNodeCode`/`fxClassNodeCode`/
  `fxSuperNodeCode` (2617–2634), `code_access`'s doc says resolved access "arrives with the declaration
  slices" while the body resolves (2368–2382), `scope_code_define_nodes` is documented as a no-op but
  asserts (871–877), `code_yield`'s doc defers async/`yield*` which are implemented (2138–2143, 2181).
- **Monolith symptoms.** One 6,048-line file; `impl Coder` spans the entire file; the class coder alone
  (`code_class` + `code_field_init_function`) is ~400 lines with hand-maintained two-pass member
  ordering and a hand-built capture plan mirrored in two places (`fi.is_none()` branch 2907–2967 vs
  the `fi` branch from 2986). Splitting by XS source section (scope coding, statements, expressions,
  classes, serializer) would not change any byte.

## Candidate findings

1. **Untrusted source of a few KB aborts the whole process via stack overflow (not a panic).**
   `coder.rs:934-935` — `let mut parser = crate::parser::Parser::new(source, strict, false)?; let mut
   root = parser.parse_program(strict)?;` with no depth budget anywhere in the crate.
   Claim: a script of ≥4000 nested parentheses (≥1000 on a 2 MiB thread) makes `compile_atoms_with`
   overflow the stack and abort the process; `catch_unwind` cannot contain it.
   Evidence: probe (release, 8 MiB): `deep-parens-2000: OK`, `deep-parens-4000: STACK OVERFLOW ABORT`;
   (2 MiB): `deep-parens-500: OK`, `deep-parens-1000: STACK OVERFLOW ABORT`; `parse-only-parens-4000`
   aborts too (parser is the first overflowing stage). XS guards this with `fxCheckParserStack`.
   Why it matters: the design's safety story is "a panic is a crashed crank, not a compromised daemon"
   (ironhorse-engine.md:614-618); an abort kills every machine in the process (the `shared` platform)
   and is a trivial DoS for any guest that can submit source. Category robustness; **high**
   (critical in shared-process deployments). Confidence: confirmed.

2. **Symbol IDs silently wrap at 65,536 used symbols, producing a corrupt but "successful" compile.**
   `coder.rs:292-298, 307` — `let mut used: u16 = 0; … used = used.wrapping_add(1); … let count =
   used.wrapping_add(1);` and emission `(symbol_id(c, sym_ids) as u16)` at 5787.
   Claim: a program with >65,535 distinct emitted symbols compiles without error to bytecode whose
   symbol operands collide.
   Evidence: probe `70k-symbols: OK bytecode=700004 symbols_atom_len=478894 count_le=[114, 17]`
   (0x1172 = 4466 = 70,002 mod 65,536). `parse_symbols` (symbols.rs:24-26) ignores the count, so the
   VM cannot detect it either.
   Why it matters: AGENTS.md names exactly this anti-pattern ("silently truncates … rather than
   failing"); XS's `txID` is 16-bit and the port should refuse at the boundary. Deterministic, so not
   a consensus split, but a wrong program with no diagnostic. Category robustness; **high**. Confirmed.

3. **Unported constructs are encoded as panics and the harness maps every panic to `Unsupported`,
   erasing the line between a known fold and a coder bug.** `coder.rs:2997` — `panic!("static block
   with lexical declarations deferred");` (also 836, 873, 1201, 2654-2655, 2762, 2797, 2958);
   `ironhorse-262/src/lib.rs:76-78` — `Err(payload) => Err(SourceCompileError::Unsupported(
   panic_message(…)))`.
   Claim: no coder path produces `ParseErrorKind::Unsupported` (parser.rs:63), so a scoper/coder
   invariant failure and a deliberate fold are both reported as a coverage gap.
   Evidence: probe `static-block-let: PANIC static block with lexical declarations deferred` for the
   valid program `class C { static { let x = 1; } }`; grep `Unsupported` in coder.rs: no hits.
   Why it matters: a real miscompile-turned-panic reads as "not yet ported" in the dual-run report,
   and the census's "TODO/FIXME: 0" is true only because the TODOs are runtime asserts. Category
   error-model; **high**. Confirmed.

4. **The compiler exposes exactly one script shape — the dev-only oracle shim's eval program — and
   production rides it.** `coder.rs:941-942, 952` — `n.flags |= crate::ast::flags::EVAL; …
   coder.eval_flag = true;` (comment 936-940: "The oracle shim compiles the Script goal with
   `mxProgramFlag | mxEvalFlag`"); `rust/endo/src/ironhorse_engine.rs:162` calls `compile_atoms_with`.
   Claim: no code path emits XS's non-eval program header (`XS_CODE_PROGRAM_ENVIRONMENT` never
   emitted; `fxScopeCodingProgram` not ported), and the API (`compile_with(source, strict)`) has no
   goal/flag parameter to ask for one.
   Why it matters: program-scope lexicals in the eval shape are frame locals rather than
   program-environment closures (940), so cross-crank visibility of top-level `let`/`const` and every
   free reference (`EVAL_REFERENCE` vs `PROGRAM_REFERENCE`) is dictated by a test-harness choice, not
   by what xsnap does; it cannot be verified here (c/moddable absent). Category api-boundary;
   **medium**. Confidence: the coupling is confirmed; the semantic consequence is plausible.

5. **A CoverInitializedName used as an expression panics instead of reporting XS's SyntaxError.**
   `coder.rs:2401-2404` — `if t.token == Token::Access { panic!("coder: invalid initializer"); }`;
   the parser pushes the `Binding` at parser.rs:1397 without recording the refinement obligation.
   Claim: `({a = 1});` compiles to a panic, not `Err(Syntax "invalid initializer")`.
   Evidence: probe `cover-init-expr: PANIC coder: invalid initializer`, `cover-init-nested: PANIC`.
   Why it matters: under `eval` XS throws a catchable `SyntaxError`; Ironhorse halts the crank with
   `Halt::Unsupported("eval:compiler-unimplemented")` (interp.rs:8010-8011) — a guest-observable
   divergence from one line of input. Category error-model; **medium**. Confirmed.

6. **Tagged-template cache tags are minted per compile, XS mints them per machine.** `coder.rs:471,
   493-497` — `tag: 0` in `Coder::new`; `let s = format!("#{}", self.tag); self.tag += 1;` (doc
   422-427 acknowledges "`the->tag` — the per-machine counter").
   Claim: two scripts compiled separately for one machine each mint `#0` for their first tagged
   template.
   Why it matters: the cache key is a symbol name that relinks machine-wide; once the VM implements
   `TEMPLATE_CACHE` (today only `opcode.rs` names it; no interp handler), distinct call sites across
   cranks would share one frozen template object, and `#0` collides in the persisted KEYS table.
   Category compiler; **medium** (latent). Confidence: mechanism confirmed, impact conditional.

7. **Opcode/payload agreement is by convention; a mismatch emits zero bytes silently.**
   `coder.rs:573-579` — `add_symbol_null` "a plain `Byte` payload on a symbol-operand opcode emits the
   two zero bytes"; readers `branch_tid`/`index_value`/`integer_value`/`symbol_id` default to 0 on any
   other payload (5800-5823); `opcodes.rs:8-253` are bare `i32`.
   Claim: constructing a `Code` with the wrong `Payload` variant for its opcode is not detected and
   produces well-formed but wrong bytecode.
   Why it matters: this is the class of bug byte-identity testing catches only where the oracle
   corpus reaches; an enum-per-opcode or a debug assertion in `add` would make it structural.
   Category compiler; **medium**. Confidence: design fact.

8. **Five staged one-shot flags form hidden coder state with hand-maintained hygiene.**
   `coder.rs:395-415` (`pending_name`, `pending_accessor`, `no_value`, `tail`) and 433
   (`class_instance_init`); `set_pending_name` 2442-2444 returns without clearing.
   Claim: `pending_name`/`pending_accessor` are cleared only by their consumer (`code_function`),
   unlike `no_value`/`tail` which are `mem::take`n at every dispatch (1017, 1021).
   Why it matters: `code_class` already has to save and restore `pending_name` around heritage coding
   (2674, 2705) to avoid a mis-named heritage function — evidence the hazard is live; passing these
   as parameters (as `tail` already is) removes the class. Category modularity; **medium-low**.

9. **Stack-depth accounting is tracked on every record and target but never checked.**
   `coder.rs:601-605` — `self.stack_level += delta; … self.codes.push(Code { id, stack_level, payload })`;
   targets snapshot it at 646, 1759, 1865; no reader (grep) and the serializer ignores it.
   Claim: a wrong `delta` (e.g. the `-count` on `MODULE` at 1370 or any `add_byte(-3, …)`) produces
   no compile-time diagnostic.
   Why it matters: a `debug_assert_eq!(self.stack_level, self.targets[tid].stack_level)` in
   `place_target` would catch an entire bug class for free; today it surfaces as VM stack corruption.
   Category verification; **medium-low**.

10. **`report()` continues coding after a code-time error, so the "infallible coder" contract is
    soft.** `coder.rs:479-487` — records only the first error; callers at 2126-2130, 2476-2477,
    1656/1664 keep emitting.
    Claim: any future report site that leaves state inconsistent will fire a later invariant `expect`
    (e.g. 526) and the SyntaxError is masked as a panic → `Unsupported`.
    Evidence: today's three sites are benign (probe: `invalid-break`, `const-no-init`, `label-dup`
    all return `Err(Syntax)`).
    Category error-model; **low-medium**. Confidence: structural, no live failure found.

11. **Byte identity with the oracle is platform-conditional for non-ASCII identifiers.**
    `coder.rs:218-224` — `sum.wrapping_shl(1).wrapping_add((b as i8 as i32) as u32)` ("C promotes
    `char`, signed on the pin's platform").
    Claim: an XS oracle built where `char` is unsigned (aarch64 Linux default) assigns different
    bucket/IDs to identifiers containing bytes ≥ 0x80, so the dual-run's byte-identity bar depends on
    the CI host architecture. Ironhorse itself stays deterministic (good).
    Category determinism (of the parity claim); **low**. Confidence: the promotion rule is standard C;
    not executable here.

12. **Address-keyed side tables make coder correctness contingent on never cloning the AST.**
    `scoper.rs:361-363` — `n as *const Node as usize`; `coder.rs:389` `defined: HashSet<usize>`;
    `coder.rs:1670-1672` "a clone would miss its registration".
    Claim: any `Node` clone on the coding path yields `expect("scope for node")` (701) or a silently
    duplicated `Define`.
    Why it matters: no determinism leak (maps are never iterated), but it is an unsound seam
    between scoper and coder with a panic as its only guard. Category modularity; **low**.

13. **Documentation describes a superseded slice plan and vestigial fields remain.**
    `coder.rs:8-43` (module header: "deferred to child 6" for constructs now implemented),
    `2617-2634` (three stale doc blocks attached to `code_super`), `2368-2373`, `871-877`,
    `2138-2143`; `Payload::Index.plus_one` (69) and `Target.index` (335) never read.
    Claim: at least five doc comments in the range contradict the code they annotate.
    Why it matters: for an LLM-authored codebase (census) the narrative comments are the primary
    maintenance surface; stale "deferred" notes invite re-implementation or false confidence.
    Category docs-drift; **low**. Confirmed by reading.

14. **The SYMB/ID contract is bound to XS hash-table internals at the pin.** `coder.rs:123`
    `const SYMBOL_MODULO: u32 = 1993;`, `165-174` `SEED_SYMBOLS` ("their position is part of the ID
    contract"), `246-263` bucket-walk ID assignment.
    Claim: a moddable bump that changes `parserTableModulo` or the seed order changes every symbol
    operand byte while leaving Ironhorse's own behaviour unchanged.
    Why it matters: harmless for the VM (it relinks by name) but it means "byte identity" is a
    property of one pin, and snapshot images carry pin-specific IDs. Design-accepted; recorded so the
    coupling is explicit. Category compiler; **low**.

## What is done well

- The three-pass serializer, symbol bucket walk, CESU-8 encoding, and `SYMB` writer are ported as
  algorithms with the XS source names cited at every step; the intent is auditable line-by-line
  against `xsCode.c` without the oracle present.
- Determinism hygiene is genuinely good: no `HashMap` iteration reaches output, `f64` is emitted as
  bits, BigInt limbs are canonicalized, address keys are lookup-only, and nothing touches host time or
  locale.
- Width selection for `INTEGER`/`STRING`/`BIGINT`/`RESERVE`/`UNWIND` families is real (probe:
  `deep-arrays-2000` emitted 49 KB with correct widths), and the scoper rejects >255 parameters with
  XS's own message.
- The code-time SyntaxErrors that XS raises in the coder (`invalid break/continue`, `invalid const/
  using`, duplicate labels) are surfaced as structured `Err(Syntax)` with XS wording rather than
  panics — the right pattern, applied to three of the reachable sites.
- Cross-stage contracts (`no_value`/`tail`) that could leak are `mem::take`n at dispatch, and the
  authors documented *why* for each staged flag.
- `#![forbid(unsafe_code)]` holds (lib.rs:16), and the crate is a pure library with no I/O.
