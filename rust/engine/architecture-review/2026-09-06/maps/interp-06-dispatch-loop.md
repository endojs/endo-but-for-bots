## Purpose and responsibilities

`dispatch_at_inner(code, start_pc, return_depth) -> Halt` is the bytecode interpreter proper:
one `loop` that (a) runs the per-iteration guards (step ceiling, bounded-mode slot ceiling,
id-space poison latch, `pc` bounds, opcode decode, `instruction_len` bounds), (b) ticks the
meter once per dispatched opcode, then (c) `match op` over every XS opcode. It owns:

- the value stack discipline (`self.stack: Vec<Slot>`, `push`/`pop`, XS frame quartet
  `[THIS, FUNCTION, RESULT, FRAME]` laid down by `CALL`/`NEW`/`SUPER`, 13463–13502);
- frame entry/exit (`RUN*` → `enter_call`, `END*` → `leave_call`, 13545–13983, 15213–15260),
  including the eight callee classes the `RUN` arm discriminates (promise resolve fn, native
  ctor, `Function.prototype.call/apply`, native method, bound fn, proxy, cross-segment user fn,
  in-loop user fn);
- exception establishment/unwind (`CATCH`/`UNCATCH`/`EXCEPTION`/`THROW`/`RETHROW`,
  15655–15743) over the `self.jumps: Vec<CatchJump>` chain, and the `Halt::Resume(pc)`
  protocol that carries a catch landing across native re-entry (`dispatch_result!`);
- suspension of generators/async/async-generators (`YIELD`/`AWAIT`/`START_*`, 15278–15645)
  by moving the activation into a `SavedFrame`;
- scope/closure cells (`NEW_LOCAL`/`*_CLOSURE`/`RETRIEVE`/`STORE`, 11633–11710, 14000–14116);
- the property MOP entry points (`GET/SET/NEW/DELETE_PROPERTY[_AT]`, 12001–13194) including
  ~14 inline exotic-object fast paths in `GET_PROPERTY`;
- literals, arithmetic, comparison, branches, `with`/eval environments, private names,
  `using`, class definition, `for-of`/`for-in` iterator acquisition.

`dispatch_at` (11280) is the thin wrapper that counts native re-entry depth against
`DISPATCH_REENTRY_LIMIT = 64` (205) and returns `Halt::StackOverflow` when exceeded.

## Invariants and contracts claimed (doc comments) — and whether the code upholds them

1. **"Every dispatched opcode meters one code unit (mxBreak…)" (11364–11366).** Upheld
   mechanically: one `tick_code` before the `match`. But see Findings 1 and 5 — the weight is
   XS's `1<<16` constant and the *check* points are not uniformly applied.
2. **"ID-operand opcodes have `size == 0`, so they must advance by `ilen`, never by `size`"
   (11373–11378).** Upheld: every ID arm uses `pc += ilen` (e.g. 11561, 11637, 11812, 12680,
   13035, 14008, 14545, 14967); `NEW_PROPERTY` advances 5 with its own guard (12331, 12437),
   `NEW_PRIVATE_*` advances `ilen + 2` with its own guard (12444, 12500).
3. **"Bounds-check the operands before reading" (11389–11398).** Upheld for all arms that read
   within `ilen`; the three arms that read beyond `ilen` (`NEW_PROPERTY` 12331,
   `NEW_PROPERTY_AT` 12073, `NEW_PRIVATE_*` 12444) add explicit checks. `CODE_*` uses
   `code.get(body_start+1)` (13301) and `count_new_locals` clamps (41314). No panic path on
   operand reads was found.
4. **"Never `panic!` … degrade to a host-facing `Halt`" for frame underflow (15233–15248).**
   Upheld at the four return-family sites and at the `YIELD`/`AWAIT` `split_off` sites
   (15340, 15392, 15555, 15607). The remaining panic surface on untrusted bytecode is
   arithmetic: Finding 4 (`DECREMENT` at `i32::MIN`).
5. **`Halt::Resume` ownership: "propagate the resume outward when the catch frame is below
   this dispatch's depth" (3577–3583, 13951–13969).** Upheld consistently across the macro, the
   `THROW`/`RETHROW`/`BRANCH_STATUS` arms (15040, 15706, 15729) and the cross-segment arms
   (13727–13735, 13889–13896, 13959–13967).
6. **"A mxFirstCode meter check fires on resume" at a catch landing (15697–15699).** Partially
   upheld: `THROW`/`RETHROW`/`BRANCH_STATUS` and 11 hand-expanded raise arms check; the
   73 `dispatch_result!` landings and 3 hand-expanded arms (13093–13098, 13168–13173,
   13184–13189) do not. See Finding 5.
7. **"Reading a lexical binding still in its TDZ is a catchable ReferenceError … Mirrors the
   `GET_VARIABLE` unresolved arm" (11674–11686).** Upheld for `GET_LOCAL`; **violated** for
   the closure twin `GET_CLOSURE` (14016–14021) and for `CHECK_INSTANCE` (12318–12320), which
   return `Halt::Throw` directly. See Finding 2.
8. **"XS's exact int-boundary promotion to number (INT_MAX for increment, -(INT_MAX) for
   decrement)" (14742–14748).** The guard `v != -i32::MAX` leaves `v == i32::MIN` unguarded
   and `v - 1` overflows. See Finding 4.
9. **Design § dispatch: "interpreter state … lives in a small register struct threaded through
   the loop".** Not upheld: only `pc` is a local; `stack/locals/id_map/args/this_val/env/
   result/exception/strict/cur_func/cur_target/target_func/resume_status/pending_new_target/
   callback_return_depth/eval_direct` are `Interp` fields mutated from inside the loop and
   from the natives it calls.
10. **Design § dispatch: "same frame geometry as XS (frames are stack slots, arguments below
    the frame …) because the debugger's frame walk, the exception machinery, and several
    opcodes observe that geometry".** Partially upheld: the quartet is laid down on the stack
    at the call site (13463–13502), but `enter_call` copies the args into `self.args: Vec` and
    truncates the stack to `base` (16209, 16252), then emulates XS's footprint with the
    `frame_slots` counter (16243–16254) so the overflow point still brackets XS's. Nothing
    can walk XS geometry on the value stack after entry. See Finding 14.
11. **Design § heap: "NaN canonicalization follows `mxCanonicalNaN`".** Not visible: the
    `NUMBER` literal pushes `Slot::number(f64::from_le_bytes(b))` (14139–14141) and
    `Slot::number` (value.rs 332) is a plain constructor; a grep for `canonical`/`to_bits`
    across `ironhorse-vm/src` finds no NaN canonicalization. See Finding 11.
12. **Design § memory-safety: panics are crashed cranks, never UB.** Upheld: all operand and
    stack access is bounds-checked or `get`-guarded; the crate forbids `unsafe`.

## Architectural observations

**Coupling and monolith shape.** The loop is 4,579 lines with 156 arm groups. Two arms are
themselves mid-sized modules: `GET_PROPERTY` (12687–13036, ~350 lines) inlines Temporal
(`Instant`/`Duration`/`PlainDate*`/`ZonedDateTime` field getters, 12699–12776), Intl `Locale`
getters (12914–12946), `Collator.compare` (12947–12961), RegExp getters (12873–12913),
TypedArray/DataView/ArrayBuffer/collection accessors, `disposed`, and synthesized function
`length`/`name` — each selected by `self.<table>.contains_key(&inst)`; `RUN` (13545–13983,
~440 lines) resolves eight callee classes by six sequential side-table probes
(13583–13616). The exotic-object *type* is therefore "membership in a side table", tested in a
fixed textual order on the hottest opcodes; adding a built-in means editing `GET_PROPERTY`.
The `Payload::Reference(inst) if table.contains_key(&inst)` guards do not check `obj.kind`,
so a `Kind::Symbol` (whose payload is also a `Reference` to its descriptor slot, 12989–12996)
is kept out of the exotic arms only by slot-index uniqueness — a latent kind-confusion seam.

**Duplication.** (a) The `YIELD`/`AWAIT` activation snapshot (`split_off` stack, rebase
`jumps`, build `SavedFrame`, store into the driver's table) appears four times with only the
run-stack/side-table names varying (15343–15378, 15395–15434, 15558–15593, 15610–15644).
(b) The "return the created instance to the caller, mirroring `END`'s boundary split" block
appears four times (15214–15259, 15292–15311, 15448–15467, 15498–15519). (c) The
accessor-merge logic for getter/setter definition is written twice (`NEW_PROPERTY_AT`
12091–12144, `NEW_PROPERTY` 12339–12378). (d) `raise_js` + `match {Ok(target) => {pc =
target; [check_meter]; continue} Err(h) => return h}` is hand-expanded 11 times alongside the
`dispatch_result!` macro that exists for exactly this (and the expansions disagree on
`check_meter`). (e) Each branch family is spelled out per operand width (14975–15000,
15074–15128) instead of one signed-operand reader.

**Hidden state.** Control decisions cross the loop boundary through `Interp` fields:
`callback_return_depth` tells `run_callback` whether a `Halt::Return` is the callback's own
return or the caller's loop having run onward after a throw unwound past the re-entry
(16437–16446); `resume_status` is a one-shot register consumed by `BRANCH_STATUS`;
`pending_new_target` is armed by `SUPER` (13496) and `Reflect.construct` (24008), consumed in
`enter_call` (16291), disarmed in `unwind_to_jump` (34603); `eval_direct` (13530–13532)
scopes one native call; `strict` is reset only by `enter_call` (16270), `BEGIN_SLOPPY` never
clears it (11403–11423).

**Panics / unwraps / indexing on untrusted bytecode.** The decode envelope is sound:
`instruction_len` (opcode.rs 1064–1098) sizes every instruction including variable payloads,
and the loop refuses `pc + ilen > len` before any operand read; arms that read past `ilen`
guard explicitly. Negative branch/catch targets wrap to huge `usize` and are rejected at the
loop top. The 7 `.unwrap()`s are guarded. The remaining hazard is integer arithmetic:
`DECREMENT` at `i32::MIN` (Finding 4). `INCREMENT` is guarded correctly at `i32::MAX`.
`leave_call`'s `expect` is protected by the four underflow checks. One latent index:
`AT` computes `idx` before a re-entrant `to_primitive` and indexes `self.stack[i]` after it
(12012–12031) — safe only while every callee path restores the stack length.

**Determinism.** No host time/locale/env in the region. `HashMap` iteration appears only in
order-insensitive uses (`id_map.retain` 11708; `collator_compare_functions.iter().find_map`
12951–12954 where the match is unique). f64 formatting goes through the custom
`number_to_ecma_string`; `format!("M{:02}")` is integer. Two platform-sensitive points:
`fx_pow` → `f64::powf` (Finding 10) and NaN payloads never canonicalized (Finding 11).

**Metering doctrine.** The loop meters XS's way: a flat `CODE_METERING = 1<<16` per
dispatch plus residual constants that the comments repeatedly describe as "verified against
the pin", "measured against the pin", "bit-exact", "raw-exact against XS" (11962–11973,
12603–12607, 12682–12686, 13050–13055, 14410–14415). The design's "Ironhorse's own
release-versioned cost table, per opcode, derived from calibration instrumentation" does not
exist as a table (Finding 1). Check points are XS's (backward branch 14977, call entry 13975,
return into JS 15257, native return 13636, catch landing 15710) but the catch-landing check
is applied inconsistently (Finding 5). One allocation in the loop is unmetered (Finding 12).

**Error-handling shape.** Three exit species coexist: (i) catchable realm errors via
`raise_js`/`catchable_type_error` → `Halt::Resume` (the correct shape, 36 sites); (ii)
`Halt::Unsupported(&'static str)` "named skips" (69 sites) that halt the crank on ordinary
JS (Finding 6); (iii) legacy uncatchable `Halt::Throw(String)` for two spec-catchable errors
(Finding 2). `Halt::Throw` carries rendered text, not the value; the value survives only in
`self.exception`.

**Re-entrancy.** JS-to-JS calls stay in-loop (`pc = body_start`) and consume value-stack
budget only (`would_overflow`, 16248). Native-driven callbacks, `step_async`, generator
resumes and cross-segment calls recurse on the Rust stack through `dispatch_at`, capped at
64 (Finding 3). The `return_depth` protocol lets a throw unwind through any number of nested
dispatches to the loop that owns the handler frame.

**Performance architecture.** Per `GET_PROPERTY`: up to ~14 hash probes before
`ordinary_get`. Per `RUN`: 6 probes. Per `CATCH`: a `HashMap<u16,usize>` clone (15671). Per
call: a fresh `Vec<Slot>` for args (16209) and a `CallerState` carrying the frame's `HashMap`.
Per `NEW_LOCAL`: a `HashMap` insert (11636). `ARGUMENTS` collects then inserts item-by-item
(11493–11499); `FOR_OF` over a string copies the whole string (12242).

**Snapshot/GC coverage from this region's writes.** All side tables this region inserts into
are named in the snapshot ledger and GC prune (checked for `arguments_objects`,
`collator_compare_functions`, `jumps[*].env`); the `functions.entry(f).or_default()` in
`CODE_*`/`FUNCTION_ENVIRONMENT` (13302, 13334) lets crafted bytecode mark any reference as a
function with a body pointer — semantically odd, not memory-unsafe.

## Candidate findings (most architecturally significant first)

1. **Metering is XS-parity by construction, not a calibrated per-opcode cost table**
   — `interp.rs:11364–11366`. Claim: the dispatch loop charges a single constant
   (`CODE_METERING = 1<<16`, meter.rs:29) per opcode plus XS-measured residuals, so the
   design's "cost-table entry, per opcode … derived from the cost-calibration
   instrumentation" (design 393–411) is not what ships under `COST_TABLE_VERSION =
   "ironhorse-meter-1"` (meter.rs:26). Evidence: `// Every dispatched opcode meters one code
   unit (mxBreak /` / `// the switch-path meterIndex += XS_CODE_METERING).` /
   `self.meter.tick_code();` and e.g. 11966 `Measured against the pin: y = 1 costs one
   create's 65536 raw more`. Why it matters: the consensus meter's provenance is documented as
   one thing and implemented as another; a future recalibration has no table to edit, only
   ~250 scattered constants and inline `tick_raw` calls. Category: metering. Severity: high.
   Confidence: high (docs-vs-code).

2. **Two spec-catchable errors are uncatchable host halts** — `interp.rs:14016–14021`
   (`GET_CLOSURE` TDZ) and `12318–12320` (`CHECK_INSTANCE`). Claim: reading a captured
   `let`/`const` in its TDZ, or an iterator `next()` returning a primitive, returns
   `Halt::Throw` directly instead of `raise_js`, so an enclosing `try/catch` never runs and the
   crank halts; the sibling `GET_LOCAL` arm (11682–11686) was already converted for exactly
   this reason. Evidence: `if s.kind == Kind::Uninitialized { return Halt::Throw("get
   closure: not initialized yet".into()); }` / `return Halt::Throw("iterator result: not an
   object".into());`. Why it matters: result divergence from XS/spec on ordinary programs
   (`try { f() } catch {}` where `f` closes over a TDZ binding). Category: error-model.
   Severity: high. Confidence: high by reading (not executed here).

3. **`DISPATCH_REENTRY_LIMIT = 64` is an undocumented second stack budget that aborts
   legitimate programs** — `interp.rs:11281–11285`, const at 205. Claim: recursion that passes
   through a callback-taking native (`map`/`forEach`/`reduce`/`then`) more than 64 levels deep
   returns `Halt::StackOverflow` even though the value stack is far from XS's `fxOverflow`
   point. Evidence: `if self.dispatch_depth >= DISPATCH_REENTRY_LIMIT { return
   Halt::StackOverflow(self.stack_slots_in_use()); }`. Why it matters: a recursive tree walk
   via `.map` that XS completes halts on Ironhorse — a result divergence the design does not
   list; the 64 was chosen from a fuzz crash, not from measured `dispatch_at_inner` frame
   size. Category: robustness. Severity: medium-high. Confidence: high.

4. **`DECREMENT` overflows at `i32::MIN`** — `interp.rs:14755–14767`. Claim: the boundary
   guard is `-i32::MAX`, so a `Kind::Integer` slot holding `i32::MIN` (from an `INTEGER_4`
   literal 14129–14135, or from `to_int32` value.rs:1739–1747 via `x|0`) executes `v - 1`,
   which panics with overflow checks on (debug/fuzz) and wraps to `i32::MAX` in release.
   Evidence: `let boundary = if inc { i32::MAX } else { -i32::MAX };` / `if v != boundary {
   top.value = Payload::Integer(if inc { v + 1 } else { v - 1 });`. Why it matters: a
   bytecode-reachable panic (fuzz target 2) and a silent wrong value in release; no
   `[profile] overflow-checks` is set in either Cargo.toml. Category: robustness. Severity:
   medium. Confidence: high on the overflow; medium on source-level reachability of an
   `i32::MIN` Integer via `(-2147483648|0)--`.

5. **The meter check at a catch landing depends on which arm raised** —
   `interp.rs:3580–3583` (macro) vs `11800–11809`, `15704–15712`. Claim: `dispatch_result!`'s
   `Resume` arm sets `pc = target; continue` with no `check_meter`, while `THROW`/`RETHROW`
   and 11 hand-expanded arms check after landing, and 3 hand-expanded arms (13093–13098,
   13168–13173, 13184–13189) do not. Evidence: `Err(Halt::Resume(target)) => {
   $program_counter = target; continue; }` vs `pc = target; if self.check_meter() ==
   MeterCheck::Abort { return Halt::MeterAbort; }`. Why it matters: the design fixes "catch"
   as a check point; here the abort point is a function of code shape rather than of a
   principle — deterministic per release, but unprincipled and unreviewable. Category:
   metering. Severity: medium. Confidence: high.

6. **Core operators halt the crank with `Halt::Unsupported` on ordinary JS** —
   `interp.rs:14426–14435` (`+"3"`), `14405–14410` (`-"3"`), `14343–14350` (`~"3"`),
   `14391–14401` + `38692–38697` (`"1" == 1`), `14913–14920` (`0 in arr`, `'toString' in o`),
   `12300–12308` (`for (k in "abc")`), `14807–14820` (`x instanceof nonModeledCtor`),
   `11883` (`with("ab")`). Claim: 69 named-skip sites in the loop turn common expressions into
   uncatchable crank halts. Evidence: `Kind::String => return Halt::Unsupported(op.name()),`
   / `if string_to_index(&s).is_some() { return Halt::Unsupported(op.name()); }`. Why it
   matters: the README's "bit-exact" narrative and the consensus-engine framing sit on a core
   whose scalar operators are incomplete; skips are honest but the surface is the interpreter's
   most basic layer, not a built-in. Category: other. Severity: medium-high. Confidence: high.

7. **Exotic-object dispatch by side-table membership inside the hottest opcodes** —
   `interp.rs:12687–13036` (`GET_PROPERTY`), `13583–13616` (`RUN`). Claim: `GET_PROPERTY`
   performs up to ~14 `HashMap::contains_key` probes in a fixed order before reaching
   `ordinary_get`, and every new built-in (Temporal, Intl, disposables…) has been added as
   another inline arm. Evidence: `Payload::Reference(inst) if self.temporal_instants
   .contains_key(&inst) => {` … `Payload::Reference(inst) if self.locales.contains_key(&inst)
   => {`. Why it matters: O(#exotic kinds) per property read, a 350-line arm that mixes
   Temporal calendar math with the MOP, and no single place that says what an instance *is*;
   the arms' guards also skip `obj.kind`, relying on slot-index uniqueness to keep `Symbol`
   payloads out. Category: modularity. Severity: medium. Confidence: high.

8. **Four-fold and two-fold copy-paste of frame-critical logic** —
   `interp.rs:15343–15378 / 15395–15434 / 15558–15593 / 15610–15644` (suspend snapshot),
   `15214–15259 / 15292–15311 / 15448–15467 / 15498–15519` (boundary return),
   `12091–12144 / 12339–12378` (accessor merge). Claim: the same 30–40 line blocks differ only
   in table names, so a fix to one (e.g. the `stack_base > self.stack.len()` guard added after
   a fuzz crash) must be hand-replicated. Evidence: `let stack_slice =
   self.stack.split_off(stack_base); let jumps = self.jumps.split_off(jumps_base)…` ×4. Why it
   matters: suspend/resume is the seam where prior waves found the most bugs; duplication is
   how the same bug survives in one twin. Category: modularity. Severity: medium. Confidence:
   high.

9. **`CATCH` clones the frame's `HashMap` and calls allocate per invocation** —
   `interp.rs:15667–15678`, `16209`, `11636`. Claim: establishing a handler clones
   `id_map: HashMap<u16, usize>` into the `CatchJump`, and `enter_call` allocates a fresh
   `Vec<Slot>` for args, so `try` in a loop and every call carry heap allocation proportional
   to scope size. Evidence: `id_map: self.id_map.clone(),` / `let args: Vec<Slot> =
   self.stack[base + 4..base + 4 + argc].to_vec();`. Why it matters: XS's `txJump` and frame
   are fixed-size; this is the kind of constant-factor cost that decides the 2.0× envelope and
   it is structural (per-frame name map) rather than local. Category: performance. Severity:
   medium-low. Confidence: high.

10. **`**` goes through the platform libm** — `interp.rs:41930–41935` (called from
    `EXPONENTIATION` 14792). Claim: `fx_pow` lowers to `f64::powf`, whose last-ulp results
    differ between libc implementations and architectures, so `a ** b` can differ across
    validators. Evidence: `/// … Rust's f64::powf lowers to the same libm call, so the result
    is bit-exact with the oracle.` / `x.powf(y)`. Why it matters: the design promises
    identical outcomes "on every host, architecture, and build"; XS has the same exposure but
    the port could have closed it with a correctly-rounded software `pow`. Category:
    determinism. Severity: medium. Confidence: medium-high (libm divergence is well known;
    whether Agoric's fleet is homogeneous is a deployment fact).

11. **No NaN canonicalization at the `f64` → slot boundary** — `interp.rs:14138–14142`
    (`NUMBER`), `14762–14770`, `value.rs:332`. Claim: `Slot::number` stores whatever bits it
    is given, so a crafted `NUMBER` operand or a hardware-produced NaN (x86 default NaN has the
    sign bit set, AArch64 does not) enters the heap uncanonicalized, contradicting design
    336 ("NaN canonicalization follows `mxCanonicalNaN`"). Evidence: `b.copy_from_slice(&code
    [pc + 1..pc + 9]); self.push(Slot::number(f64::from_le_bytes(b)));` and no `canonical`/
    `to_bits` NaN handling anywhere in `ironhorse-vm/src` (grep). Why it matters: NaN bits are
    observable through `Float64Array`/`DataView` and in snapshot bytes, so cross-architecture
    determinism and snapshot identity can depend on the host CPU. Category: determinism.
    Severity: medium. Confidence: medium (the exposure path is in other regions).

12. **`EXTEND`'s prototype allocation and `CLASS`'s two property installs are unmetered**
    — `interp.rs:13362`, `13406–13417`. Claim: the class prototype is allocated with a raw
    `slots.alloc` and `prototype`/`constructor` are installed with
    `set_own_unmetered_with_flag`, unlike every other allocation in the loop which pairs
    `slots.alloc` with `tick_slot_alloc` (14002–14003, 14065–14066, 14082–14083). Evidence:
    `let proto = self.slots.alloc(Slot::instance(parent_proto));`. Why it matters: the loop's
    own rule is "meter at the allocation"; an unmetered slot is invisible to the
    allocation-faithfulness canary. Category: metering. Severity: low-medium. Confidence:
    medium-low (may be folded into a class residual constant elsewhere).

13. **Out-of-band control registers between the loop and its drivers** —
    `interp.rs:15229`, `15296`, `15452`, `15502` ↔ `16443`, `16578`; `15026–15027`; `13496`.
    Claim: whether a nested `dispatch_at` returning `Halt::Return` means "the callback
    returned" or "a throw unwound past me and the caller's loop ran to its end" is decided by
    `self.callback_return_depth == Some(return_depth)`, a field any arm can set. Evidence:
    `self.callback_return_depth = Some(return_depth); return Halt::Return;` / `Halt::Return if
    self.callback_return_depth != Some(return_depth) => Err(Halt::Return),`. Why it matters:
    the `Halt` enum is the loop's return type yet the meaning of `Return` lives in a side
    field; `resume_status`/`pending_new_target`/`eval_direct` follow the same pattern.
    Category: reentrancy. Severity: medium-low. Confidence: high.

14. **Frame geometry differs from the design's stated reason for keeping XS geometry** —
    `interp.rs:16209`, `16252`, `16243–16254`. Claim: after `RUN`, arguments are copied into
    `self.args: Vec<Slot>` and the stack is truncated to the quartet base, with a
    `frame_slots` counter emulating XS's live footprint; the design (355–359) says frames and
    args stay on the value stack "because the debugger's frame walk, the exception machinery,
    and several opcodes observe that geometry". Evidence: `let args: Vec<Slot> = self.stack
    [base + 4..base + 4 + argc].to_vec();` / `self.stack.truncate(base);` /
    `self.frame_slots += caller_footprint;`. Why it matters: the future debugger's frame walk
    cannot be a stack walk; overflow parity is by accounting, not by construction. Category:
    docs-drift. Severity: low-medium. Confidence: high.

## What is done well

- **Decode envelope is genuinely panic-free on untrusted bytecode.** `instruction_len`
  bounds the whole instruction (opcode.rs 1094–1097), the loop re-checks `pc + ilen > len`
  (11390), the three arms that read past `ilen` add explicit guards, negative branch targets
  are caught at the loop top, and every return-family/suspend arm has a frame- or
  stack-underflow guard with the fuzz trophy cited (15233–15248, 15387–15394).
- **The `Halt::Resume` / `return_depth` protocol is applied uniformly** across the macro,
  the throw opcodes, and every cross-segment/bound/apply arm, so a throw can unwind through
  arbitrary native re-entry to the loop that owns the handler; the test
  `nested_run_unwind_floor.rs` pins the XS-agreement cases.
- **Bounded-mode guards are layered thoughtfully**: step ceiling, live-slot ceiling
  (OOM trophy), and the id-space poison latch all fire at the loop top before any
  guest-observable effect (11325–11353), and are documented with the incident that
  motivated each.
- **`GET_VARIABLE`'s `typeof` peek** (11786–11794) reproduces XS's lookahead exactly and
  distinguishes truly-unbound from TDZ names — a subtle spec corner handled correctly and
  explained.
- **Comments are unusually load-bearing**: nearly every arm cites the `xsRun.c` case it
  mirrors, the measured metering residual, and the review wave that changed it, which made
  this audit tractable.
- **GC roots for everything this region creates are present** (`jumps[*].env`, `env`,
  `exception`, `result`, `call_stack` frames) and the side tables it inserts into are in both
  the sweep prune and the snapshot ledger.
