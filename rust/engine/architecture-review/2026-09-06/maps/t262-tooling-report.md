## Purpose and responsibilities

This region is the *instrument* layer of the conformance story: it never executes JS itself
(that is `lib.rs::dual_run` + `xst.rs::run_case`, the neighbouring region); it decides how a
runner verdict becomes a number a maintainer can publish, and how a large sweep is
partitioned, resumed, and gated.

- `report.rs` — per-case record (`CaseRecord`), provenance, hand-emitted JSON read back through
  `yaml-rust2`, the `(outcome, reason) -> Category` classifier, whole-tree discovery into
  100-case batches, identity-bound resume planning and aggregation, static HTML.
- `compile_diff.rs` — the stage-5 byte-identity gate: `ironhorse_compile::compile*` vs
  `xs_oracle::run`/`compile_module` bytes (and the `SYMB` atom), total over coder panics.
- `bin/endot_ih.rs` — the `xst`-analogue CLI: flags -> `xst::Config`, subtree/batch selection,
  YAML/JSON output, the (unwired) expectation-list ratchet, exit codes.
- `bin/ironhorse_262_report.rs` — the oracle-free orchestration verbs (`discover`, `plan`,
  `validate`, `aggregate`, `quarantine`, `batch-size`, ...) that `scripts/full-run.sh` drives.
- `bin/corpus_to_262.rs` — one-shot converter of the retired `corpora/*.js` line corpora into
  the shared `packages/test262-runner/test262/test/ironhorse/` case tree (1,712 files today).
- `bin/compile_diff.rs` — CLI over `compile_diff.rs` for a whole subtree or the curated corpora.
- `scripts/full-run.sh` — the bash orchestrator: vendors test262 at `TEST262_SHA`, verifies
  corpus/engine/oracle identity, computes `run_id`, runs batches under `xargs -P` with a
  watchdog and a 3-attempt quarantine, gates completeness, writes provenance, aggregates.
- `tests/` — 68 files / 484 `#[test]`s: 65 are hand-written XS-differential snippet suites over
  `lib::dual_run`; 3 drive `xst::run_files` over checked-in case trees.

## Architectural observations

**Coupling / duplication.** Three generations of report types coexist: `test262::Report`/`run_files`
(test262.rs 177-247, legacy honest-split), `lib::Summary` (838-856), and `xst::XstReport` (1182);
`report::Verdict` duplicates `xst::Verdict` without payload. `report::aggregate`, `pending_batches`,
`read_batch` are retained "for the unbound case" but their only callers are their own tests
(report.rs 1644, 1691, 837). Sixty-five test files carry a copy-pasted 15-line
`assert_result_agrees`/`agrees` helper (e.g. tests/class_semantics.rs 208-223,
tests/collections.rs 238-251) instead of a shared test-support module.

**Three parallel "expectation" mechanisms.** (a) `expectations.rs` + `endot-ih --expectations`
(Rust, unit-tested, no committed list, never invoked); (b) hardened262 `baseline/` pass.txt/fail.txt
per scenario (JS, committed, wired into PR CI); (c) `report.json` from the whole-tree sweep (no
baseline comparison at all). The fixture-consolidation design names one list set under
`packages/test262-runner/expectations/`, which does not exist.

**Monolith / bash-held logic.** `full-run.sh` (412 lines) owns retry, quarantine, watchdog,
identity fingerprinting (`run_id` at 213, never validated for shape by Rust), and the provenance
heredoc. Rust unit tests pin the wire shapes (`provenance_reads_the_shell_wire_shape`,
`read_provenance_reads_the_typed_fields`) but nothing tests the shell control flow. The
`attempts/` directory is hidden cross-invocation state: a batch already at the cap on entry skips
the loop and is quarantined with the initial `status=0` (284-289, 337).

**Hidden global state.** `compile_diff.rs` sets/restores the process-global panic hook inside three
library functions (323-329, 387-394, 501-542). The crate's own tests that call them
(663, 734, 807) run on parallel test threads by default, so take/set/restore interleaves can leave
the silent hook installed for the rest of the test process.

**Panics / unwraps on untrusted data.** None found on the report/CLI side: batch and provenance
readers return `Err`; `collect_js_batch` uses `checked_mul` (test262.rs 295-297); CLI arguments go
through `fail()`. `corpus_to_262` uses `expect`/`panic!` freely (186, 204, 207, 242) but is a
developer one-shot over a trusted manifest. `compile_diff` is total over coder panics by design.

**Determinism hazards.** No `HashMap`/`HashSet` in the region; all breakdowns are `BTreeMap`;
`read_dir` results are sorted before use (report.rs 832, 871-872, 922-923, 965; test262.rs 256,
282). f64 appears only in `percentage` (display) and `is_numeric_literal` (a parse check). Host
time appears only in `full-run.sh` provenance timestamps (documented as intentionally
non-reproducible). The one genuine hazard is the *verdict* being wall-clock dependent:
`ironhorse-hang` is a bar-forbidden `Fail` decided by a 10 s per-case timer (endot_ih.rs 52,
xst.rs 1427-1430) while `full-run.sh` 309-310 documents 4-8 s/case for the property-escape
batches; a slow runner can mint IronhorseFailure rows.

**Error-model shape.** The honest split is asymmetric: over-acceptance (`IronhorseOnlyComplete`)
is a `Fail` (xst.rs 551-553) but under-acceptance (`OracleOnlyComplete`, i.e. Ironhorse throws
where XS completes) is a non-gating `RunSkip("ironhorse-aborted")` (560). With `met_bar` = zero
`Fail` and no committed per-case list, a fixed divergence that regresses into a throw is green in
`regressions_dual_run` (which permits named skips, 90-97) and in the whole-tree sweep. The report
classifier's default-to-Infrastructure rule (report.rs 211-214) is safe for unknown reasons but
mis-files the known `module:*` family.

**Metering-doctrine drift.** The design says XS-computron equality is never an acceptance gate and
the oracle is result-only. In this region: `corpus_conversion_equivalence` runs 1.7k cases with
`gate_meter_exact: true` in PR CI (tests/corpus_conversion_equivalence.rs 63-66 -> xst.rs 462-466
`Fail("meter-exact violation ...")`); 28 of 31 corpora are tagged `ironhorse-meter-exact`
(corpus_to_262.rs 65-97); 9 test files assert `is_bit_exact`/`computrons_agree` (with_statement,
resource_management, suspend_in_try_metering, detached_native_redispatch, multi_crank_oracle,
await_in_try, intl_numberformat_format_getter, ...). Meanwhile the doctrine's own unconditional
property — determinism across runs — has a gate (`--repeat`, xst.rs 878) that no script or
workflow passes, and the `ironhorse-meter-determinism` tag emitted by the converter has no
consumer in the runner (its only mentions are the xs/node `--features-exclude` lists).

**API-boundary leaks.** hardened262's adapter regex-rewrites the harness
(`Test262Error.prototype.toString`, ironhorse.js 24-30) before handing it to `endot-ih`, so the
ironhorse host does not run byte-identical harness source; the adapter also depends on
`report.cases[0]` of an unstamped (`run_id = ""`) batch. `endot-ih` positional resolution prefers
an existing relative path over subtree resolution (205-206), making results cwd-dependent for a
bare `language` argument when a same-named directory exists.

**Coverage-gate shape.** Gates that can catch a covered->skip regression: `corpus_conversion_equivalence`
(`covered == total`, 107-111), hardened262 baseline. Gates that cannot: `XstReport::met_bar`,
`regressions_dual_run`, `proxy_is_observed_unimplemented_via_oracle_slice` (asserts only
`covered > 0` and `ironhorse_failure == 0`, report.rs 2298-2305), the whole-tree sweep.
Intl/Temporal suites (8 files) gate `IronhorseOnlyComplete` + an exact oracle error string and
then pin Ironhorse's own rendered output (tests/intl_core.rs 787-800): self-referential by
necessity (the pinned XS has no Intl/Temporal) but worth naming as a place with no external
oracle.

**Performance-architecture.** `full-run.sh` spawns the report binary once per batch for
`batch-count` twice (283, 402-405) — thousands of process launches on a whole-tree run; harmless
but avoidable with a `discover --with-counts` verb. Leaked hang threads hold 32 MiB stack
reservations until the batch process exits (xst.rs 1409-1420), bounded by the 100-case cap.

## Candidate findings (most architecturally significant first)

1. **Expectation-list ratchet exists only as code; the whole-tree instrument has no anti-regression
   baseline** — `verification`, high.
   `endot_ih.rs:352` / `xst.rs:1219`. Claim: no committed expectation list exists and no script or
   workflow passes `--expectations`, so the only gate the sweep and `endot-ih` apply is zero-`Fail`,
   under which any covered->skip regression is invisible.
   Evidence: `xst.rs:1219-1221 pub fn met_bar(&self) -> bool { self.total > 0 && self.failures.is_empty() }`;
   `ls packages/test262-runner/expectations` -> "No such file or directory" (the design's stated
   location); repo grep for `--expectations` matches only `src/bin/endot_ih.rs`.
   Why it matters: the design (§ test262) promises "progress toward parity is a monotone, visible
   number"; today a change that turns 10k covered cases into `unsupported-opcode` skips is green
   everywhere except the 1.7k converted-corpus gate and hardened262's separate JS baseline.

2. **One divergence direction is structurally non-gating: Ironhorse-throws-where-XS-completes is a
   skip, not a failure** — `error-model`, high.
   `xst.rs:560` (consumed by report.rs `classify` 192-201 as Unsupported). Claim: `evaluate_positive`
   maps `Agreement::OracleOnlyComplete` to `RunSkip("ironhorse-aborted")` regardless of halt kind,
   so a semantic bug that makes Ironhorse throw where XS returns a value never reddens a
   zero-`Fail` gate.
   Evidence: `xst.rs:560 Agreement::OracleOnlyComplete => Verdict::RunSkip("ironhorse-aborted".into())`;
   `tests/regressions_dual_run.rs:93-97 assert!(rep.met_bar() && rep.failures.is_empty(), ...)`
   with the header stating named skips are permitted; `report.rs:2298-2305` only asserts
   `covered > 0` and `ironhorse_failure == 0`.
   Why it matters: the commonest regression shape of a *fixed* fuzz trophy (the fix un-lands and
   Ironhorse throws again) passes the trophy gate; combined with (1) the fail vector the design
   says "matters as much as the pass vector" is not gated anywhere in the sweep.

3. **`classify` files every `module:*` run-skip under Infrastructure ("explicitly NOT an Ironhorse
   gap"), including a compiler byte divergence, while the lede says modules are excluded** —
   `error-model`, high (confidence high).
   `report.rs:192-214`. Claim: since `run_case` routes `flags: [module]` cases to
   `run_module_case` (xst.rs 803-804), the reasons `module:evaluation`,
   `module:compiler-byte-divergence`, `module:compiler-rejected`, `module:resolution-linking`
   reach `classify`, match no Unsupported prefix, and hit the Infrastructure fallthrough.
   Evidence: `xst.rs:1022 Verdict::RunSkip("module:compiler-byte-divergence".into())` /
   `1024 Verdict::RunSkip("module:evaluation".into())`; `report.rs:211-214 // Unknown run skips
   must not be charged to Ironhorse ... Category::Infrastructure`; `report.rs:1094 "... excluding
   staging, harness support files, and module cases"` and doc `100-104` still describe module as a
   Skipped pre-skip.
   Why it matters: the published headline undercounts the actionable backlog by the whole module
   goal (346 `language/module-code` files in the checked-in subset alone) and hides a real compiler
   defect class as an oracle non-result.

4. **PR CI hard-gates XS computron equality on the converted corpus and 9 suites, contrary to the
   accuracy-over-parity doctrine** — `metering`, medium.
   `tests/corpus_conversion_equivalence.rs:63-66` -> `xst.rs:462-466`. Claim: with
   `gate_meter_exact: true` a computron difference against XS on any of the ~1.7k
   `ironhorse-meter-exact` cases fails the build.
   Evidence: `corpus_conversion_equivalence.rs:63-66 let cfg = Config { gate_meter_exact: true, ..Config::default() };`;

## What is done well

- Fail-closed, identity-bound aggregation: `aggregate_plan` never globs, rejects any batch whose
  `run_id` differs, treats an empty identity as reject-all, derives `completion` from the
  artifact, and the CLI refuses to publish on any warning (report.rs 858-909;
  ironhorse_262_report.rs 241-246) — with tests for every conjunct (2039-2114).
- Authority claims in the HTML come from typed provenance fields, not from operator-controlled
  prose, and the whole-corpus claim requires a verified 40-hex SHA plus completeness
  (report.rs 312-321, tests 1970-2086).
- Determinism discipline in the instrument itself: BTreeMap-only, sorted `read_dir` results,
  byte-identical JSON round-tripped through the same reader (report.rs 1405-1444).
- The partition cap is genuinely single-sourced and the boundary is tested at cap+1
  (report.rs 788-794, 1781-1809; full-run.sh 106).
- `compile_diff` is total over coder panics and names every divergence class with an offset and
  bytes, and the in-crate gate now asserts an empty fold allowlist (663-731).
- Thoughtful hang attribution: on a per-case timeout the runner re-runs Ironhorse alone before
  charging the hang to Ironhorse (xst.rs 1408-1431), and the batch's JSON is still written
  atomically so a resumable sweep never loses a directory to one case.
