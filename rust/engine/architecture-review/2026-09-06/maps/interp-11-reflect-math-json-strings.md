# Region map: interp-11-reflect-math-json-strings

## Purpose and responsibilities

This slice of the ~38k-line `impl Interp` is the "value-producing native" tail
of the built-in dispatcher `call_native_method` (28349–28399 route here). It
implements, as Rust functions returning `Result<Slot, Halt>`:

- `Reflect.*` (ordinary, TypedArray-exotic, and proxy-routed arms) — `call_reflect`,
  `call_reflect_proxy`, `arraylike_to_vec`.
- Map/Set/WeakMap/WeakSet mutators and queries — `call_collection`, plus the
  constructor's dense-array population fast path
  `populate_collection_from_dense_array`.
- `Math.*` — `call_math`, `math_extremum`.
- `Number.*` statics, `Number.prototype.toString`, `parseInt`/`parseFloat`/
  `isNaN`/`isFinite` — `call_number`.
- `JSON.stringify` (no replacer/space) and `JSON.parse` (no reviver) — `call_json`,
  `json_serialize`, `json_parse_*`, `object_own_string_keys`,
  `object_has_unnamed_own_key`.
- The string-allocation seam — `new_string_metered`, `new_string_units`,
  `to_string_units`, `string_this_units`, `string_receiver_units/text`.
- `String.fromCharCode`/`fromCodePoint` — `call_string_static`.
- `String.prototype.*` — `call_string` (charCodeAt … toWellFormed, `[Symbol.iterator]`).
- Iterator instance builders — `make_array_iterator`, `make_string_iterator`,
  `make_collection_iterator`, and the head of `iterator_to_array`.

Every function reads its arguments off the value stack at `stack[base + 4 + i]`
(XS frame geometry), coerces through shared helpers (`to_number`, `to_primitive`,
`to_property_id`), charges the meter with named `*_METERING` constants, and
returns either a `Slot`, a catchable JS error (`catchable_type_error()` →
`Halt::Resume(target)`), a bare `Halt::Throw(String)`, or an "honest skip"
`Halt::Unsupported(&'static str)`.

## Architectural observations

**Error-model split.** Natives raise errors three ways: `catchable_type_error()`
/ `catchable_range_error()` (build a realm error, `raise_js`, return
`Halt::Resume`) — guest-catchable; bare `Halt::Throw("TypeError: …".into())`
(29003, 29017, 29097, 29115, 29124) — falls through `dispatch_result!`'s
`Err(halt) => return halt` (3584) and exits the dispatch loop as an uncaught
throw, bypassing the guest's `try`/`catch`; and `Halt::Unsupported` — a named
abort. The same `call_reflect` mixes the first two for the same spec
condition (`Reflect.apply` non-callable → catchable 29445; `Reflect.isExtensible`
non-object → uncatchable 29003). The pattern recurs outside the region
(25918, 26344, 26369, 26387).

**`Halt::Unsupported` as guest-value-dependent control flow.** About 45 sites in
the region abort on ordinary values rather than on unimplemented opcodes:
`indexOf`/`lastIndexOf` unconditionally (31275–31277); any `Math.*` with a
string or object argument (29861–29863, 30054–30055); string-method position
arguments that are strings/objects (31052–31058); `JSON.parse` of any
`\uD800–\uDFFF` escape or any astral character (30716–30717, 30750, 30826);
`JSON.stringify` with a replacer/space, callable, wrapper, or own `toJSON`
(30267, 30275, 30392, 30397, 30403); `toLowerCase` on non-ASCII (31283);
`repeat` with a negative count (31201, 31209); `Reflect.*` on any non-object
where the spec mandates a catchable TypeError (28948, 28965, 29230, 29312,
29343, 29372, 29417). The harness maps these to `Verdict::RunSkip`
(ironhorse-262/src/xst.rs:450), so they never enter the pass/fail vector; the
production seam maps them to `MachineError::Halt` (rust/endo/src/
ironhorse_engine.rs:91). Deterministic, but a broad class of "abort where XS
completes or throws catchably".

**Determinism hazards.** (a) libm: `acos, acosh, asin, asinh, atan, atanh, cbrt,
cos, cosh, exp, exp_m1, ln, ln_1p, log10, log2, sin, sinh, tan, tanh, atan2,
powf, hypot` (29879–29930) are platform-libm calls; `floor/ceil/trunc/sqrt/
abs`, `as f32`, `+ 0.5` are IEEE-exact and fine. (b) NaN payloads are never
canonicalized (`Slot::number`, value.rs:332); Float64 typed-array stores write
raw bits (40344) and the snapshot codec preserves them by test
(slot_codec.rs:78, 189–200), so an in-region NaN with a platform-specific sign
bit is both guest-observable (`new Uint8Array(new Float64Array([Math.sqrt(-1)]).buffer)`)
and snapshot-observable. (c) Number formatting and parsing are pure Rust
(`format!("{:e}")` in value.rs:1775; `str::parse::<f64>` at 30653 and 41689)
and therefore deterministic — good. (d) `HashMap` with default `RandomState`
is iterated in `populate_collection_from_dense_array` (29746–29749, `functions`),
`string_key_name` (35100–35102), `is_symbol_key_id` (35096), `property_key_slot`
(37905–37916): every use is order-independent today (unique id→name, boolean
`any`, identity not observable) but the pattern is one refactor away from a
leak. (e) No host time/locale in the region.

**Robustness (panics/aborts on guest input).** Unbounded native recursion in
`json_parse_value`↔`json_parse_array/object` (30558–30559 → 30780/30840) and
`json_serialize` (30435, 30474): `DISPATCH_REENTRY_LIMIT` bounds only
`dispatch_at` re-entry (11281), not these. A Rust stack overflow is a process
`SIGABRT`, not a panic — it kills every worker in a shared-platform process.
Unbounded allocation: `repeat` (31219 `Vec::with_capacity(content.len() * count)`,
count ≤ 2^31−1 but the product is unchecked), `padStart/padEnd` (31348–31351
accept any target ≤ `usize::MAX as f64`, then 31367/31372 allocate),
`arraylike_to_vec` (29483 loops to `to_length_u64` ≤ 2^53−1). Meter ticks only
accumulate (meter.rs:183–185, 213–216, 227–229); the limit is consulted only in
the dispatch loop (13750), so none of this is interruptible. `ChunkArena::alloc`
has no size cap and stores `data.len() as u32` (value.rs:1480), a silent header
truncation past 4 GiB. Indexing: `content[pos as usize]` sites (31077, 31097,
31126, 31147) are guarded by `pos < ulen` checks; `json_parse_keyword`'s
`input.len() - *pos` (30592) is safe because callers check `*pos < len`;
`self.typed_arrays[&inst]` (29093) follows a `contains_key`. `unreachable!()`
at 31005 is reachable only by dispatcher bug. `(s.id - 1) as usize` (30508,
30523) is guarded by `s.id != XS_NO_ID` (=0, value.rs:22).

**Correctness (silent divergences).** JSON.stringify key set (no enumerability,
own-only `toJSON`, accessor values dropped via `_ => Ok(None)` at 30492, no
index-first ordering); `JSON.parse` turns lone surrogates into U+FFFD
(30312 `from_utf16_lossy`); `parseInt` radix `NaN`/`Infinity`/≥2^32 → `NaN`
instead of ToInt32→0→10 (30190–30197); `String.fromCharCode(1e300)` → 65535
via saturating `as i64` (30985) where ToUint16 gives 0; `Reflect.defineProperty`
on exotic targets (29113–29134) bypasses the exotic `[[DefineOwnProperty]]`.

**Monolith / duplication.** Own-key ordering exists in at least five variants
with different filters: `own_enumerable_ids` (35593), `own_all_string_ids`
(35635), `Reflect.ownKeys` TA inline (29238–29249), `Reflect.ownKeys` ordinary
inline (29276–29290), `object_own_string_keys` (30517). The id→name reverse
lookup exists as O(1) `symbol_names[id-1]` (30508, 30523) and as two O(N)
scans (`string_key_name` 35099, `property_key_slot` 37912). XS chunk geometry
`(((len+1)+7)&!7)+16` is inlined at 30472, 30564, 30830 and `length*32+16` at
30797 although `meter.tick_chunk_new` (meter.rs:213–216) encapsulates it.
~80 lines of `ReflectDefineProperty` (29140–29221) are dead. Two string
allocators coexist: `alloc_str_text` (unmetered, 10900) used at 29258, 30166,
30180, 30565, 37917, and `new_string_units` (metered, 30899) — callers must
remember which one meters.

**Metering-doctrine drift.** Comments justify weights by XS parity ("measured
against the pin", "fixed 33280-raw host residual" 30159–30164; "No mxMeterSome
and no chunk — the pin's bodies carry neither" 29826); every `Math` function
costs one flat `MATH_FRAME_METERING` (29876) so `sin` = `abs`; JSON strings are
metered by UTF-8 byte length (`bytes.len()` 30564, `key_bytes.len()` 30830,
`key.len()` 30472) while every other string allocation meters by code units
(30905) — inconsistent within one release; proxy-routed `Reflect` charges no
frame cost; `ReflectIsExtensible`/`PreventExtensions` charge nothing (29000–29031).

**Performance-architecture.** `json_parse_string_bytes` re-validates the entire
remaining input per non-ASCII character (`std::str::from_utf8(rest)` 30741) —
O(n²) in one unmetered native. `Reflect.ownKeys` sorts with an O(|symbol_ids|)
key function (29281–29290) → O(k log k · N) unmetered. `json_serialize` clones
each array's whole item map (`a.items().clone()` 30413). `str_units` allocates
a `Vec<u16>` for every receiver access (10876–10878), so "no decode step" from
the design holds for storage but not for the natives, which decode on every call.

**String-encoding seam.** The design stores UTF-16 code units to avoid lossy
round-trips, yet this region round-trips through Rust `String` at 30188, 30206,
30312, 30880, 30890, 30901, 30928 (all `from_utf16_lossy`/`from_utf8_lossy`).
Only 30312 (JSON.parse input) is a confirmed silent corruption; the others are
benign for their inputs today.

## Candidate findings (most architecturally significant first)

1. **Non-canonical NaN from Math built-ins is guest- and snapshot-observable, and differs by CPU architecture** — interp.rs:29873 (`Some(s) => Ok(Slot::number(f(num(s)?)))`), doc 29826–29827 claims canonical; value.rs:332 stores raw bits; 40344 Float64 store `n.to_le_bytes()`; slot_codec.rs:78 + test 189–200 preserve NaN bits. Claim: `Math.sqrt(-1)` (and `acos(2)`, `pow`, etc.) stores a NaN whose sign/payload depends on the host CPU/libm, readable via a Float64Array byte view and persisted verbatim in snapshots, violating design line 336 ("NaN canonicalization follows mxCanonicalNaN"). Severity: high (determinism). Confidence: high on code facts; the x86-64 (0xFFF8…) vs AArch64 (0x7FF8…) default-NaN difference is standard architecture behavior.
2. **Platform libm in 22 `Math` functions contradicts the design's unconditional cross-host determinism** — interp.rs:29829–29843 (decision-of-record), 29879–29916. Claim: results of `Math.sin/exp/pow/…` are not bit-identical across glibc/musl/macOS, so results, guest branches, and therefore computrons can diverge between validators on different platforms; the design (ironhorse-engine.md:373–375) promises identity "on every host, architecture, and build". Known/open (W6-23); still open. Severity: high (determinism).
3. **Bare `Halt::Throw(String)` from `Reflect` arms is uncatchable by guest code** — interp.rs:29003, 29017, 29097, 29115, 29124; `dispatch_result!` 3584 `Err(halt) => return halt`; contrast `catchable_type_error()` 29445 → `Halt::Resume`. Claim: `try { Reflect.isExtensible(1) } catch (e) {}` aborts the crank on Ironhorse while XS throws a catchable TypeError — a result divergence and an inconsistent error model within one function. Severity: high (error-model). Confidence: high.
4. **Unbounded recursion in `JSON.parse`/`JSON.stringify` → Rust stack overflow → process abort** — interp.rs:30558–30559/30780/30840 (parse), 30435/30474 (serialize); `DISPATCH_REENTRY_LIMIT` 205 guards only `dispatch_at` (11281). Claim: `JSON.parse("[".repeat(1e5))` or `let a=[];for(let i=0;i<1e6;i++)a=[a];JSON.stringify(a)` overflows the thread stack, which is `SIGABRT`, not a panic — the design's "a panic is a crashed crank" does not cover it, and a shared-platform process loses every worker. Severity: high (robustness). Confidence: high on code; exact depth threshold untested here.
5. **String natives allocate guest-controlled multi-GiB buffers before any meter check** — interp.rs:31219 (`repeat`), 31348–31372 (`padStart/padEnd`), 29483 (`arraylike_to_vec`); meter.rs:183–185/213–229 accumulate only; check at 13750. Claim: `"abcdefgh".repeat(2**30)` or `"".padStart(2**40)` attempts an 8 GiB–2 TiB `Vec` allocation with no RangeError and no meter abort, ending in an allocation-failure abort. XS bounds chunk sizes; `ChunkArena::alloc` (value.rs:1480) has no cap and truncates `len as u32`. Severity: high (robustness/metering). Confidence: high.
6. **`Halt::Unsupported` used for guest-value-dependent conditions makes common programs abort and hides result-parity gaps as skips** — interp.rs:31275–31277 (`indexOf`/`lastIndexOf` always), 29861–29863, 30716–30717, 30267, 30403, 28948…29417; xst.rs:450 `RunSkip`; ironhorse_engine.rs:91. Claim: `"abc".indexOf("b")`, `Math.max("1", 2)`, `JSON.parse('"\\ud83d\\ude00"')`, `Reflect.get(1, "x")` each abort the crank uncatchably, and the differential harness excludes them from the pass/fail vector, so "pass vector equals the oracle's" can hold while these diverge. Severity: high (api-boundary). Confidence: high.
7. **`JSON.stringify` emits the wrong key set: no enumerability filter, own-only `toJSON` probe, accessors silently dropped, no index ordering** — interp.rs:30517–30531 (no `XS_DONT_ENUM_FLAG`; contrast 35608), 30401–30405 with `find_property` own-only (35570–35584), 30473+30492 (accessor payload → `None`), stale comment 30443–30448 vs `append_name_key` 35020. Claim: `JSON.stringify(Object.defineProperty({}, "x", {value: 1, enumerable: false}))` yields `{"x":1}`, and `class A { toJSON() { return 1 } }; JSON.stringify(new A())` yields `{}`. Severity: medium-high (correctness). Confidence: high (by reading; not executed).
8. **`JSON.parse` is O(n²) on non-ASCII text inside one unmetered native** — interp.rs:30740–30744 (`std::str::from_utf8(rest)` per character). Claim: a 1 MB string of `é` costs ~5×10¹¹ byte validations in a single call the meter cannot interrupt. Severity: medium (performance/DoS). Confidence: high.

## What is done well

- Number formatting and parsing are pure Rust and correctly rounded (`format!("{:e}")` reformatted to the spec's thresholds in value.rs:1759–1812; `str::parse::<f64>` behind explicit ECMAScript grammars at 30604–30668 and 41668–41737), so the dtoa/strtod axis of determinism is sound.
- `IterState` for string iterators is fully rooted (44873–44876) and fully snapshotted with validation on restore (10373–10385, 10411–10415); the `iterators` table is one of the side tables that got the headline bug class right.
- GC is host-driven (no `collect_garbage` call inside `interp.rs`), so the many Rust-local `Vec<Slot>`/`SlotIndex` temporaries these natives hold across allocations are safe by construction rather than by care.
- Bounds discipline on the UTF-16 unit vectors is consistent: every `content[i]` index is preceded by an explicit range check, and JSON keyword/escape reads check `n` before slicing.
- XS's integer-kind fast paths and ±0 tie-breaks (`math_extremum`, `math_to_integer`, JSON number classification "integer iff nonzero and in i32 range") are ported with the reasoning written down next to the code.
- Cycle detection in `json_serialize` (30406–30409, 30489) raises a catchable TypeError rather than looping.
- The libm decision (29829–29843) is honestly recorded as an open determinism scope with a named remedy (vendored pure-Rust `libm` landed together with an oracle built the same way).
