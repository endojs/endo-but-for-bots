## Purpose and responsibilities

`scoper.rs` is the transliteration of XS `xsScope.c`: the two AST passes between parser and
coder.

* **hoist** (`hoist_dispatch`, :918) builds the scope arena (`Program`/`Eval`/`Module`/
  `Function`/`Block`/`With` scopes), hoists `var`/function declarations to the body scope with
  `NoToken` placeholders in intermediate blocks, records lexical (`let`/`const`/`using`)
  declarations plus their duplicate-declaration early errors, injects the synthetic
  `arguments` `Var`, poisons scope chains reached by direct `eval` / `with`, synthesizes class
  member closures (`atAccess`/`symbolAccess`/`valueAccess`, `instanceInit`) and the two
  field-init function scopes, and records module import/export linkage.
* **bind** (`bind_dispatch`, :1774) resolves every identifier to `(scope, declare id)` up the
  chain, creates function-boundary closure aliases, marks captures, computes frame arithmetic
  (`scope_level`/`scope_maximum` → per-function `scope_counts`), and raises the remaining early
  errors (getter/setter arity, `delete` of a private member, unknown export, private name
  resolution).

Its output (`ScopeTree`, :278) is the **byte-identity contract** for the coder: declare order
and counts become frame slot indices embedded in bytecode (module doc :17–24).

## Invariants and contracts claimed (doc comments) — and whether the code visibly upholds each

1. **"The order and count of declare nodes in each scope, the closure flags, and the
   per-function `scopeCount` are a byte-identity contract"** (:17–24). *Upheld as far as this
   region can show*: fixtures pin dumps; `coder_byte_identity.rs` (oracle-backed, CI-only)
   covers many shapes including the `arguments`-named parameter (:318–325) and private
   accessor pairs (:1624–1648). Caveat: XS exposes no scope dump, so the scoper itself is
   never oracle-checked (`corpus_scope_smoke.rs:8–11`); only the coder's bytes are.
2. **"Keys the per-node associations by the node's stable address … valid only while that
   tree is alive, which it is for the whole compile"** (:28–33, :356–360). *Upheld by
   construction in `compile_atoms_with`/`compile_module_atoms`* (coder.rs:934–957, 986–995
   keep `root` and `tree` in one frame) but **not enforced by the type system**: `ScopeTree`
   holds plain `usize`s, `run` returns it without a lifetime, and the public `scope_program`/
   `scope_module` return trees whose keys point into a tree already dropped (:369–380).
3. **"Carries a stable `id` so … can reference it across the index shifts an eval-scope
   prepend or a block placeholder removal cause"** (:124–127). *Upheld*: ids are per-scope
   counters (:681–682) and all cross-references use `(scope, id)`.
4. **`direct_eval` "computed once the node's extras are populated"** (:217–223). *Partially*:
   true for real nodes; for the synthesized field-init scopes all sharing `node_ptr = 0`
   (:641) the flag is read from a shared `node_extra[0]` slot (:771–774), so it leaks across
   every field-init scope in the compile (probe confirmed).
5. **`Scope::node_has_eval` "keys the two-`WITHOUT` teardown … a `with`-poisoned scope leaves
   the node flag clean"** (:227–234). *Upheld*: `hoist_with` sets only scope flags via
   `scope_eval(parent)` (:1574), never `node_extra`.
6. **"XS's `fxCatchNodeBind` pushes (not pops) here too; transliterated faithfully"**
   (:2238–2239). *Upheld as stated*: an acknowledged XS accounting bug is reproduced for byte
   identity (scope_level leaks +4 per `using`-bearing catch body).
7. **"`hoist_class` … The private / computed-key / field declares that populate the body scope
   are deferred; the method-only surface adds none"** (:943–948) and **`bind_class` "The
   class/symbol scopes … are the deferred class-hoisting fold"** (:1812–1817). *Stale*: both
   are implemented (:964–1032, :1821–1938). Same for `class_node` "(Reserved for the deferred
   class-scoping pass.)" (:426–428, used at :1033/:1829/:2087/:2512) and `anon` "(Reserved for
   class computed-key slots.)" (:448–449, used at :980/:1009/:1026).
8. **`hoist_function` "inject here, before the body's own `var arguments`/`arguments`
   parameter is hoisted"** (:1216–1222). *Contradicted by the code*: params are hoisted at
   :1213, injection at :1222, so a parameter named `arguments` precedes the `Var` (probe:
   `d0 ARG arguments closure`, `d1 VAR arguments`). The coder documents and depends on the
   *actual* order (coder.rs:3871–3879), and the oracle test covers it — the comment is wrong,
   the code is right.
9. **Modules-are-strict invariants** (`hoist_import` :1602–1606). *Upheld*: `Parser::new(_,
   true, true)` seeds `STRICT|ASYNC` (parser.rs:141–148).

The design diagram's `CC --> VM` edge (ironhorse-engine.md:284) does not match: neither crate
depends on the other; the seam is the host.

## Architectural observations

* **Two-pass immutable-AST port of a mutating C pass, glued by raw-address maps.** Nine
  `HashMap<usize, …>` tables plus `node_extra` re-create XS's in-place `self->scope` /
  `access->declaration` / `node->flags |=`. A miss in these maps has three different
  behaviours in the coder: `resolutions` → `Option::flatten` to the *symbol path* (coder.rs:502,
  silent semantic downgrade to a global lookup); `scope_counts` → `unwrap_or(&0)` (coder.rs:1194,
  1279, 2999, 3160 — silent under-reservation of the frame); `node_scopes` → `expect`
  (coder.rs:701). Nothing at the type level prevents a coder pass over a cloned or synthesized
  node (the parser already synthesizes nodes, stmt.rs:1702–1716) from silently missing.
* **Production always runs the `Eval` root path.** `compile_atoms_with` ORs `flags::EVAL` onto
  the root (coder.rs:936–943) to mirror the oracle shim's `fxParseScript(mxProgramFlag |
  mxEvalFlag)` (xs_shim.c:376, 561, 623). Consequences: `hoist_program` chooses `Token::Eval`
  (:1145); every top-level declaration is *prepended* (:703–704); the `Program` branches at
  :790–796, :882–893 and :1756–1759 are dead in production; a strict script's top-level `var`
  is a frame local, not a global property. **All 24 fixtures in `tests.rs` use
  `scope_program(_, false)` or `scope_module` and therefore never build an `Eval` root** (the
  `s0 PROGRAM eval` in `direct_eval_poisons_scopes` is a poisoned `Program`, not an `Eval`).
* **Hidden shared state via a sentinel address.** Both synthesized field-init scopes of every
  class use `node_ptr = 0` (:641). `hoist_call` writes `ARGUMENTS|EVAL` into `node_extra[0]`
  when a direct eval sits in a field initializer (:1250–1253), and every later
  `fx_scope_hoisted(fi)` reads it back (:771–774). Probe: `class A { static x = eval('1'); }
  class B { y = 2; }` gives B's field-init scope `direct_eval=true` with `flags=0x10` (not
  poisoned). Latent today because the coder keys the field-init eval prelude on scope `flags`
  (coder.rs:3018–3026), not `direct_eval`. In the same construct `environment_node` is never
  re-pointed while hoisting inside a field-init scope (:635–664), so the enclosing body/program
  receives the direct-eval extra (probe: `function f(){ var a; class C { x = eval('a'); } }`
  → f's body scope `direct_eval=true`), which makes `code_body` take the two-`with` variant
  for `f` (coder.rs:3970–3978). Whether XS marks the enclosing body identically could not be
  verified (submodule absent).
* **Panics/unwraps on the public API.** `run(&Item)` accepts any root (:383–387); `hoist_declare`
  / `hoist_define` / `hoist_import` / `hoist_export` / `bind_*` `unwrap()` `scope`,
  `function_scope`, `body_scope` (:1338–1339, 1353, 1374, 1437–1439, 1608, 1659, 2111, 2152,
  2169, 2184, 2515, 2542); `declare_ref`/`declare_mut` `expect` (:731, 734); `scope_of`
  `expect` (:2030). Unreachable from the parser's well-formed output as far as I could trace,
  but the API contract is "panic on misuse", and the crate's `ParseErrorKind::Unsupported`
  (ironhorse-262 lib.rs:148–154) is never produced by the scoper.
* **Recursion is unbounded** (`hoist_item`/`hoist_dispatch` :1130–1141, `bind_item`/
  `bind_dispatch` :2016–2027). The parser is co-equal (probe at 32 MiB stack, debug: 4,000
  nested blocks OK, 8,000 abort in *parse* already; 2,000 nested functions OK, 4,000 abort).
  A stack overflow is an **abort**, not a panic — outside the design's "panic = crashed crank"
  model (§ Memory-safety) and uncatchable by the harness's `catch_unwind`
  (compile_diff.rs:153). The VM bounds runtime re-entry (`DISPATCH_REENTRY_LIMIT`,
  interp.rs:3741–3743); the compiler has no analogue.
* **Determinism**: no `HashMap` iteration anywhere in the region (all `get`/`insert`; `dump`
  iterates `Vec`s); `Sym::Anon` counter and declare ids are sequential; no host time, no
  floats. Address-keyed maps affect only lookup, never order. Determinism looks sound.
* **Metering**: the scoper does no metering; the parse meter charges per token only
  (`meter.rs:26`, `charge_token` :46). Scoper cost is super-linear in adversarial shapes:
  `scope_get_declare` is a linear scan (:725–728) invoked per declaration and per access;
  `declare_ref`/`declare_mut` are linear by id (:730–735); `Eval`-scope prepend is `Vec::insert(0)`
  (:703–704) — the production path for *every* top-level declaration; `hoist_catch` cross-checks
  are O(n·m) (:1288–1299); `export_links.contains` is O(n²) (:1692, :1708). XS has the same
  linked-list asymptotics, but under "accuracy over parity" the compile meter should track
  real cost and does not.
* **Byte-identity vs. correctness policy** is visible: an XS accounting bug is reproduced on
  purpose (:2237–2241); spec deviations that XS *may* share are therefore not "bugs" under
  Design Decision 4 but remain spec deviations for consumers.
* **Doc drift** is pervasive: "deferred"/"reserved" comments describing implemented features
  (:426–428, :448–449, :943–948, :1812–1817), an `arguments` injection comment contradicting
  the code (:1216–1222), `#[allow(dead_code)]` on live fields. Consistent with the census's
  LLM-authored accretion signal.
* **Performance nits**: `record_access` allocates an `AccessRecord` + `String` per identifier
  (:1769–1771) for a dump the coder never reads; `Sym::Named(String)` is cloned on every
  lookup (:2112, :2153, :2170, :2185); `declares_of` in the coder clones symbol strings per
  scope (coder.rs:733–739).

## Candidate findings

Ordered most architecturally significant first. Confidence noted per item.

1. **The scoper→coder contract is nine raw-address `HashMap<usize,…>` tables with inconsistent
   miss handling** — `scoper.rs:290–339, 361–363`; `coder.rs:502, 701, 1194`.
   Claim: a node the coder visits without a scoper entry is silently downgraded (`resolutions`
   → symbol path; `scope_counts` → 0 frame slots) or panics (`node_scopes`), and nothing ties
   `ScopeTree`'s keys to the tree's lifetime.
   Evidence: `pub fn node_key(n: &Node) -> usize { n as *const Node as usize }` (:361–363);
   `self.tree.resolutions.get(&node_key(node)).copied().flatten()` (coder.rs:502);
   `*self.tree.scope_counts.get(&scope).unwrap_or(&0)` (coder.rs:1194).
   Why: this is the seam where a silent wrong-bytecode bug (wrong slot / global lookup /
   under-reserved frame) can enter without a panic; `scope_program`/`scope_module` already
   return trees keyed into dropped nodes (:369–380). Confidence: high on structure; no
   concrete miss found in production paths.

2. **Production compiles every Script as an XS eval program; the scoper's `Program` branch and
   the entire fixture suite exercise a path production never runs** — `coder.rs:936–943`,
   `scoper.rs:1145, 703–704, 797–806`, `tests.rs:14–16`.
   Claim: no scoper fixture builds an `Eval` root, so the prepend ordering and the sloppy/strict
   `Eval` discount rules that every `Machine::evaluate` depends on are pinned only indirectly
   by coder byte-identity tests that cannot run in PR CI.
   Evidence: `n.flags |= crate::ast::flags::EVAL;` (coder.rs:942); `if sc.token == Token::Eval {
   sc.declares.insert(0, decl); }` (:703–704); `scope_program(src, false).expect("scopes").dump()`
   (tests.rs:15).
   Why: verification gap on the load-bearing path; also a semantic inheritance from the oracle
   *shim* (strict-script top-level `var` becomes a frame local) that is nowhere documented as a
   product decision. Confidence: high.

3. **Any declaration inside a class `static { … }` block panics the compiler on valid JS** —
   `scoper.rs:650–659`; `coder.rs:2992–2997` (and vacuous guard `2957–2961`).
   Claim: `class C { static { let x = 1; } }` (also `var`, `function`) compiles to a `panic!`,
   not a `SyntaxError`/`Unsupported`, and is reachable from `Machine::evaluate`.
   Evidence: `if is_static && m.token == Token::Body { if let Some(body) = m.children.first() {
   self.hoist_item(body)?; } }` (:651–655) hoists statements directly into the field-init
   scope with no `Block`; `panic!("static block with lexical declarations deferred")`
   (coder.rs:2997). Probe: all three shapes panic.
   Why: a guest can kill a worker with syntactically valid code; the crate has
   `ParseErrorKind::Unsupported` for exactly this class but the path panics; the coder's own
   check at 2957 looks up a `Body` scope the scoper never records. Confidence: high (probe).

4. **Unbounded recursion in hoist/bind (and parser/coder) aborts the process on deeply nested
   source** — `scoper.rs:1130–1141, 2016–2027`; parser co-equal.
   Claim: ~8,000 nested `{}` or ~4,000 nested functions overflow a 32 MiB stack (debug) and
   abort — not panic — the process; the design's "panic = crashed crank" model does not cover
   this, and `catch_unwind` cannot.
   Evidence: `fn hoist_item(&mut self, item: &Item) … Item::Node(n) => self.hoist_dispatch(n)`
   (:1130–1132) with no depth counter; VM has `DISPATCH_REENTRY_LIMIT` (interp.rs:3741–3743);
   endo runner threads are 32 MiB (endo.rs:885). Probe at 32 MiB: `blocks n=8000 | parse:
   stack overflow`.
   Why: JS source is an untrusted input; an abort takes down the daemon worker, not one crank.
   Cross-region: the parser overflows first, but a scoper guard alone would not help.
   Confidence: high (probe); release thresholds are higher but finite.

5. **Compile-time cost is metered per token while the scoper is quadratic in adversarial
   shapes** — `scoper.rs:703–704, 725–735, 1288–1299, 1692, 1708`; `meter.rs:26, 46`.
   Claim: the parse meter (`ironhorse-meter-0`) cannot reflect scoper cost, so a source with
   many top-level declarations (Eval-root prepend), many same-scope names, or many exports
   costs O(n²) real time for O(n) computrons.
   Evidence: `sc.declares.insert(0, decl)` (:704); `sc.declares.iter().find(|d| d.symbol…)`
   (:727); `pub const PARSE_TOKEN_METERING: u64 = 1 << 16;` (meter.rs:26).
   Why: "accuracy over parity" makes the meter a proxy for real cost; compile is a
   guest-triggerable phase (`eval`, `Function`, bundle evaluate). XS shares the asymptotics,
   which is exactly what the doctrine says not to inherit. Confidence: medium (no benchmark).

6. **Annex B.3.4 `catch (e) { var e; }` is rejected as "duplicate variable"** —
   `scoper.rs:1390–1399`; parser `stmt.rs:611`.
   Claim: `hoist_var`'s intermediate-scope walk treats the catch parameter's `Let` as a
   conflict, rejecting a spec-legal program.
   Evidence: `if matches!(dtok, Token::Const | Token::Let | Token::Using | Token::Define) {
   conflict = Some(id); break; }` (:1393–1395); `self.binding(Token::Let, 1)?;` (stmt.rs:611).
   Probe: `try {} catch (e) { var e; }` → `EARLY ERROR … duplicate variable`.
   Why: real-world sloppy code does this; no corpus/262 case covers it (grep). XS parity
   unverified (submodule absent) — if XS accepts, this is a result divergence the oracle would
   flag once the annexB tree is run. Confidence: high on spec; medium on XS divergence.

7. **Field-init scopes share `node_ptr = 0`, leaking hoist extras across classes, and
   `environment_node` is not re-pointed inside them** — `scoper.rs:641, 771–774, 612–615,
   1250–1256, 635–664`.
   Claim: after any direct `eval` in a field initializer, every later field-init scope in the
   compile reports `direct_eval = true`, and the *enclosing* body/program (not the field
   function) receives the direct-eval node extra.
   Evidence: `let mut sc = Scope::new(parent, Token::Function, 0, SCOPE_STRICT);` (:641);
   `if self.node_extra.get(&ptr).copied().unwrap_or(0) & SCOPE_EVAL != 0 { … direct_eval =
   true; }` (:771–774); `if let Some(env) = self.environment_node { self.add_extra(env,
   SCOPE_EVAL); }` (:1254–1256). Probe: B's fi `direct_eval=true flags=0x10`; f's body
   `direct_eval=true`.
   Why: the first half is latent (coder keys fi on scope flags, coder.rs:3018–3026) but is a
   landmine for any future reader of `direct_eval`/`scope_node_flags`; the second half changes
   the enclosing function's bytecode shape and is unverified against XS. Confidence: high on
   behaviour; medium on consequence.

8. **Private-name duplicate check consults only the first declare, so `get #m; set #m; set #m`
   is accepted** — `scoper.rs:993–1003`.
   Claim: the XOR test against the first-found `#m` declare passes for every additional
   setter (or getter), missing the spec early error.
   Evidence: `if let Some(existing_id) = self.scope_get_declare(si, sym_ref) { … if existing ^
   current != (flags::GETTER | flags::SETTER) { return Err(…"duplicate") } }` (:994–1001).
   Probe: three `CONST #m closure` declares, no error.
   Why: spec early error missed; probably XS-inherited (the pair model is oracle-checked,
   coder_byte_identity.rs:1624–1648), so under DD4 it is "faithful", but it is still a
   SyntaxError the engine fails to raise. Confidence: high (probe) / XS unverified.

9. **An XS frame-accounting bug is transliterated on purpose (`bind_catch` pushes twice, never
   pops)** — `scoper.rs:2230–2241, 2247–2256`.
   Claim: a `using` inside a catch body leaks `scope_level += 4` for the rest of the function,
   inflating every later `scopeCount`.
   Evidence: `if disp { // NOTE: XS's fxCatchNodeBind pushes (not pops) here too; …
   self.push_variables(2); }` (:2237–2241).
   Why: deterministic and byte-identical, so not a consensus risk, but it documents the policy
   that byte identity outranks correctness in the compiler; any future XS fix forces a
   coordinated bytecode/meter bump. Confidence: high (self-documented).

10. **Runtime direct-eval private-name resolution is knowingly wrong and only masked by the VM
    refusing function-frame eval** — `scoper.rs:838–851`, `interp.rs:7994–7996`.
    Claim: `compile("this.#x")` yields `SyntaxError: invalid private identifier`, so a future
    direct eval inside a class method referencing a private name would be a result divergence.
    Evidence: `// A future direct-eval implementation must resolve a private name against the
    *real* enclosing private environment` (:848–850); `return Err(Halt::Unsupported("eval:direct-scope"))`
    (interp.rs:7995). Probe confirms the error.
    Why: documented gap, but the coupling (scoper assumes shim-mode eval) will bite whoever wires
    real direct eval. Confidence: high.

11. **The public `run(&Item)` API panics on any non-`Program`/`Module` root that contains a
    declaration** — `scoper.rs:383–408, 1338–1339, 1353, 1374, 1437–1439, 1608, 1659`.
    Claim: `run` validates only that the root is a `Node`; a `Function`/`Block` root reaches
    `self.body_scope.unwrap()` / `self.function_scope.unwrap()`.
    Evidence: `_ => return Err(err(1, "invalid root"))` (:386) is the only root check;
    `let function_scope = self.function_scope.unwrap();` (:1338).
    Why: API-boundary robustness; the fuzz/262 harnesses and any future embedder go through
    `compile*`, so low exposure, but "panic on misuse" is not the crate's stated error model.
    Confidence: high (by reading).

12. **Doc comments describe implemented features as "deferred"/"reserved" and contradict the
    code on `arguments` injection order** — `scoper.rs:426–428, 448–449, 943–948, 1216–1222,
    1812–1817`.
    Claim: `class_node`/`anon` are live yet `#[allow(dead_code)]`/"reserved"; `hoist_class`/
    `bind_class` docs say class scoping is deferred; the `arguments` comment says "before the
    parameter is hoisted" while injection follows the params (:1213 vs :1222) as the coder
    requires (coder.rs:3875–3879).
    Evidence: `/// (Reserved for the deferred class-scoping pass.) #[allow(dead_code)]
    class_node` (:426–428); `self.class_node = Some(node_ptr(node));` (:1033).
    Why: maintainers reading the doc will make the wrong change; the census flags LLM accretion
    and this is a concrete instance. Confidence: high.

13. **Flag words are overloaded across node kinds and between node and declare flag spaces with
    no type separation** — `scoper.rs:55–78, 1005–1006`; `ast.rs:37, 44, 65–73`.
    Claim: `SCOPE_EVAL == flags::STRING_LEGACY == 1<<2`, and `dflags` 12–16 alias
    `flags::NATIVE/HOST/DEFAULT/FIELD/FUNCTION`; `hoist_class` ORs node bits into a declare
    word, correct only because bits 22/25/28 happen not to collide.
    Evidence: `pub const SCOPE_EVAL: u32 = flags::EVAL;` (:76); `pub const EVAL: u32 = 1 << 2;`
    / `pub const STRING_LEGACY: u32 = 1 << 2;` (ast.rs:37, 44); `d.flags |= dflags::CLOSURE |
    (m.flags & (flags::STATIC | flags::GETTER | flags::SETTER));` (:1005–1006).
    Why: faithful to XS's C enum but a latent aliasing hazard in a language that could make it
    unrepresentable; no collision found today. Confidence: high (no bug), low severity.

14. **A per-identifier `AccessRecord` (with a `String` clone) is built on every production
    compile for a dump the coder never reads** — `scoper.rs:1769–1771, 2113, 2176, 2189`.
    Claim: `accesses` is dead weight outside tests (no `.accesses` reads in coder.rs).
    Evidence: `self.accesses.push(AccessRecord { symbol: symbol.to_string(), line, resolved });`
    (:1770).
    Why: minor allocation overhead in a guest-triggerable phase; trivially gated behind a flag.
    Confidence: high.

## What is done well

* The scope arena + `(scope, id)` addressing is a clean, index-based replacement for XS's
  pointer graph; ids survive the `Eval` prepend and `Block` placeholder removal without
  remapping (:124–127, :681–682, :777–789), and the whole state is `Default`-fresh per compile
  (:388) — no hidden globals.
* Determinism is sound in this region: hash maps are used only for keyed lookup, the dump and
  every order-bearing structure are `Vec`s, and there is no host time, float, or locale use.
* The fixture dump (`ScopeTree::dump`, :2602–2661) is a genuinely readable, stable contract
  and the fixtures document *why* each count is what it is (tests.rs:37–41, 110–114, 158–164).
* Early-error coverage is broad and spec-referenced: duplicate lexical/arg, coalesce mixing,
  legacy-octal-in-strict deferral to hoist (:1582–1600 explains the ordering subtlety),
  getter/setter arity, `delete` of private members, `super.#x`, unknown/duplicate export.
* Faithfulness notes are explicit where the port *chooses* to reproduce XS behaviour
  (:2237–2241) or deliberately defers (:838–851), so a reader can distinguish design from
  accident.
* `corpus_scope_smoke.rs` gives the scoper a totality bar over the corpus, and the 262 harness
  classifies compiler panics as coverage gaps rather than verdicts (lib.rs:155–161), which is
  the right epistemics for a port in progress.
