## Purpose and responsibilities

This slice of the `impl Interp` monolith holds four unrelated clusters that happen to be adjacent:

1. **Intl option plumbing and constructors** (18638–19903): locale-argument coercion
   (`intl_locale_argument`, `intl_first_locale`, `intl_locale_list`), the ECMA-402 abstract ops
   `GetOptionsObject` / `GetOption` / `GetNumberOption` / `GetStringOrBooleanOption`, the
   `Intl.Locale` option applier, the `Intl.Collator` option applier, `CreateDateTimeFormat`
   (`build_date_time_format`), the DateTimeFormat prototype dispatcher and `resolvedOptions`,
   `StringListFromIterable`, `SetNumberFormatDigitOptions`, `InitializeNumberFormat`
   (`build_number_format`), the `NumberFormatData → intl_number::NfResolved` adapter, and three
   `formatToParts` array builders.
2. **Promise allocation cluster** (19926–20042): `new_promise_instance`, `make_resolving_functions`,
   `new_promise_capability` — the object model for a pending promise + its resolving pair.
3. **RegExp surface** (20044–21030): `build_regexp`, the match drive, `exec`/`test`, the four
   `String.prototype.{search,match,replace,split}` workers over the matcher, `GetSubstitution`,
   `toString`/`source`.
4. **Date**: not in the range itself, but the focus asked for `Date.now` (method index 2 registered
   at 6981): it is dispatched at 25243 → `date_method` 25148, and `2 => Ok(Slot::number(0.0))`
   (25163) — **`Date.now()` is the constant 0**; `new Date()` therefore is the epoch
   (`[probe] Date.now() → "0"`, `new Date().getTime() → "0"`).

## Architectural observations

- **Monolith accretion.** Four unrelated subsystems interleave in 2,400 lines of one `impl`; the
  Intl helpers appear in two spec-fidelity tiers (`intl_option_*` raw reads vs `intl_get_*`
  spec reads) that constructors mix per key, and three parts-array builders repeat the same
  `arrays.get_mut(&arr).unwrap().insert_item(i, item, &mut self.side_refs)` + `item.id = 0;
  item.next = NULL` incantation (19291–19296, 19310–19315, 19917–19922).
- **Un-oracled surface in a consensus engine.** The XS oracle lacks Intl; ironhorse-262's Intl
  tests assert `Agreement::IronhorseOnlyComplete` against hand-written expectations
  (`intl_datetime_segmenter.rs:14–27`). Those tests live in `ironhorse-262`, which hard-depends on
  `xs-oracle` (Cargo.toml:15), so they run only in the oracle CI job — never in the PR job
  (`cargo test -p ironhorse-vm -p ironhorse-snapshot`). The design doc says this surface does not
  exist.
- **Determinism (good).** No host clock (`Date.now` = 0; `Temporal.Now` is another region), no
  host locale (4420–4421), ICU4X pinned exactly (`=2.2.0`) with compiled data, `LocaleData.unicode`
  is a `BTreeMap`, `civil_fields` is integer arithmetic after one `floor` (39554–39576),
  `INTL_DATA_VERSION` names the data profile. No `HashMap` iteration feeds any observable in
  this range. Hazard: the ICU crate version is a consensus input with no explicit link to
  `INTL_DATA_VERSION` or a meter version.
- **Metering-doctrine drift.** The promise cluster hard-codes XS slot counts as ticks
  (6/13/8 phantom `tick_slot_alloc`s) plus `PROMISE_FUNCTIONS_METERING`/`PROMISE_CAPABILITY_METERING`
  residuals "raw-exact" to the pin; `build_regexp` reconstructs XS's C struct sizes (8/4/16/12) to
  meter chunk bytes (20119–20123). This is parity, not the release-versioned accuracy model.
  Conversely, the per-capability empty-name chunk (19978) and `split`'s limit coercion are unmetered.
- **Wrong values instead of honest skips.** The regexp surface's ASCII assumption is enforced only
  for `g`/`y` subjects and for `split`; `exec`/`test`/`search`/`match`/`replace` silently return
  byte offsets / mis-sliced text on non-ASCII input. `String.prototype.split`'s limit is not
  `ToUint32`.
- **Hidden state.** `regexp_last_names` (global scratch) couples `exec` to a later
  `GetSubstitution` (20301 → 20753). Safe today only because function replacements are
  unsupported (20564–20568), so no guest code can run in between; it becomes a reentrancy bug the
  day that skip is lifted.
- **Error-handling shape.** Catchable errors are uniform (`catchable_{type,range,syntax}_error`);
  `Halt::Unsupported(name)` is used consistently for named skips; `unreachable!` at 19223 is
  guarded by the caller's match. Indexing on side tables (`self.segments[&inst]`,
  `self.regexps[&inst]`, `self.date_time_formats[&inst]`) follows a `contains_key` brand check in
  every caller I traced (25745, 25767, 19183, 28739, 28746, 28832–28882).
- **Panics on untrusted data.** `regexp_exec_inner` trusts matcher output: `captures[0]`
  (20201, 20312) and `&subject[from as usize..to as usize]` (20324) would panic on a malformed
  `MatchOutcome`; regexp patterns are untrusted input, so a matcher bug is a crashed crank (within
  doctrine, but there is no `MatchOutcome` invariant check at the seam).
- **GC / snapshot.** No omission found in this range: all slot-bearing tables reached here are
  GC edges and ledger rows; `promise_guards` growth is bounded by `compact_reaction_arenas`
  (locked by `reaction_arena_pruning.rs`). The snapshot decoder maps DTF component key strings back
  to statics and refuses others (4570–4594) — good — but the stringly-typed enum fields
  (`rounding_mode: String`, etc.) are re-parsed with silent defaults in `nf_resolved` (19895–19896),
  so a corrupt persisted string degrades behavior instead of failing validation (unverified whether
  the snapshot validator checks these strings; flagged with low confidence).
- **API boundary.** `Date.now()` returning 0 (rather than a host power the supervisor injects, or
  a SES-style throw) is an engine-level policy decision that neither the design nor README states.

## Candidate findings (most architecturally significant first)

1. **RegExp surface returns byte offsets and mis-sliced text for non-ASCII subjects — wrong values, not honest skips.**
   `interp.rs:20169` (guard only for `advance && !subject.is_ascii()`), `:20311–20312` (`index` = byte
   offset − NUL pairs), `:20606–20607` (`former = pos + match_len`, byte + code-unit).
   Claim: `/b/.exec("éb").index` is 2 (spec 1) and `"aéb".replace(/é/,"X")` yields `"aX\u{FFFD}b"`.
   Evidence: `if advance && !subject.is_ascii() { return Err(Halt::Unsupported(...)) }` /
   `let match_start = captures[0].0 - Self::regexp_nul_pairs_before(...)` / lib.rs:69 "`(from, to)` byte offsets".
   `[probe]` confirmed all four (`exec`, `search`, `match`, `replace`). Why: silent result
   divergence on any non-ASCII text, violating the codebase's own "never a wrong value" rule
   (README 1225) and the oracle's result-parity bar. **High; confirmed.**

2. **A full ECMA-402 surface ships without a design, un-oracled, contradicting design decision 10.**
   `interp.rs:4420–4422`, `:18909–18913`; design 1181–1185; Cargo.toml:19–20. Claim: the design says
   "Intl is omitted … no seam is reserved" and requires a meter bump for any ICU4X Intl, yet
   Locale/Collator/ListFormat/PluralRules/Segmenter/DateTimeFormat/NumberFormat exist with
   `INTL_DATA_VERSION = "ironhorse-intl-2026a"` and no `ironhorse-meter-N` bump; tests are
   `IronhorseOnlyComplete` in the oracle-only job. Why: consensus-critical code whose correctness
   rests solely on LLM-authored expectations, invisible to PR CI and to the design record.
   **High (docs-drift / verification); confirmed.**

3. **Intl option reads bypass `[[Get]]` for half the keys and read `dateStyle`/`timeStyle` out of spec order, despite the doc's parity claim.**
   `interp.rs:18720–18744` (`instance_get`), `:38125–38141`, `:18984–18987`, `:19051–19067`.
   Claim: getters on `calendar`/`numberingSystem`/`hour12`/`timeZone`/`currency`/`unit` never run
   and accessor-valued options read as `undefined`. Evidence: `let value = self.instance_get(options,
   id);` / "Order of reads mirrors the spec". `[probe]` getter log and swallowed throw confirmed.
   Why: two helper families with different MOP semantics inside one constructor is an unsound
   seam; observable behaviour diverges from ECMA-402. **Medium; confirmed.**

4. **`String.prototype.split` limit is not `ToUint32`.** `interp.rs:20852–20861`. Claim:
   `"abc".split(/b/,-1).length` is 0 (spec 2) and `split(/b/,Infinity).length` is 2 (spec 0).
   Evidence: `if n.is_nan() || n < 0.0 { 0 } else { (n as u64) & 0xFFFF_FFFF }`. Also `to_number`
   (41810) has no ToPrimitive for object limits and the coercion is unmetered. Why: a saturating
   `as u64` is exactly the numeric-domain anti-pattern AGENTS.md warns about; result divergence
   the oracle would flag. **Medium; confirmed.**

5. **Promise allocation meters XS's phantom slots and hides an unmetered per-promise chunk with a false "boot" justification.**
   `interp.rs:19933–19935`, `:19963–19966`, `:20035–20038`, `:19974–19978`. Claim: 27 slot ticks are
   charged for 3 real slots per capability, and every capability appends an unmetered empty-name
   chunk. Evidence: `for _ in 0..13 { self.meter.tick_slot_alloc(); }` / "Unmetered (the boot chunk
   allocation is outside the guest meter)" / value.rs:1470 `alloc` always appends a header.
   Why: contradicts "accuracy over parity" (design 363–411) and lets heap growth escape the meter;
   deterministic but inaccurate. **Medium (metering); confirmed.**

6. **`Date.now()` / `new Date()` are the constant 0, undocumented in the design.** `interp.rs:25163`,
   `:6971–6974`; README:952. Claim: the engine hard-codes epoch time rather than a host power or a
   SES-style refusal, and no design text records it. Evidence: `2 => Ok(Slot::number(0.0)),`.
   `[probe]` confirmed. Why: deterministic (good) but a silent wrong value versus the oracle and a
   policy decision that belongs in the design's host-powers seam. **Low–medium (api-boundary / docs-drift); confirmed.**

7. **`regexp_last_names` is cross-call hidden state that will become a reentrancy bug.**
   `interp.rs:20297–20301`, `:20753`. Claim: `$<name>` substitution reads a global scratch written
   by the previous `exec`, correct only because function replacements are `Unsupported` (20564–20568).
   Evidence: `self.regexp_last_names = names.clone();` / `let cidx = self.regexp_last_names.get(slot)`.
   Why: the README plans function replacement; a callback running its own `exec` would clobber the
   scratch. **Low–medium (reentrancy, latent); confirmed by reading.**

8. **`GetOptionsObject` used where ECMA-402 specifies `CoerceOptionsToObject` (NumberFormat, DateTimeFormat).**
   `interp.rs:18837–18849`, `:19002`, `:19616`. Claim: `new Intl.NumberFormat("en","x")` throws
   TypeError; spec coerces. Evidence: `_ => Err(self.catchable_type_error())`. `[probe]` confirmed
   the throw; spec reading is my recollection (medium confidence). **Low.**

9. **`StringListFromIterable` imposes a hidden 1,000,000-element cap that surfaces as RangeError.**
   `interp.rs:19425–19453`. Claim: a guest iterable of >10^6 strings gets a non-spec RangeError
   instead of meter exhaustion. Evidence: `for _ in 0..1_000_000 {` … `Err(self.catchable_range_error())`.
   Why: ad-hoc constants in a consensus engine are observable policy; the meter is the sanctioned
   bound. **Low (error-model); confirmed by reading.**

10. **`SetNumberFormatDigitOptions` omits the `roundingIncrement ≠ 1` consistency errors.**
    `interp.rs:19503–19512`, `:19537–19540`. Claim: `roundingIncrement:5, minimumFractionDigits:1,
    maximumFractionDigits:2` formats `"1.25"` instead of throwing RangeError (and a non-fraction
    rounding type should TypeError). Evidence: `if rounding_increment != 1 { mxfd_default = mnfd_default; }`
    with no subsequent check. `[probe]` confirmed. **Low; confirmed.**

11. **Locale resolution reports the requested tag, not the data locale used; list handling is array-only.**
    `interp.rs:18658–18702`, `:18914–18928`. Claim: `resolvedOptions().locale` for `xx-YY` is `xx-YY`
    although only `en`/`es` data exist, and an array-like `{length:1,0:"es"}` is coerced as a single
    tag (probe: `Halt::Unsupported("to_primitive:…")`). Evidence: `Ok(locale_base_name(&locale))` /
    `if let Some(array) = self.arrays.get(&r) { … } else { vec![value] }`. **Low (docs-drift); confirmed.**

12. **Matcher output is trusted at the `exec` seam (slice/index panics on a malformed `MatchOutcome`).**
    `interp.rs:20201`, `:20312`, `:20324`. Claim: a matcher bug on an untrusted pattern panics rather
    than erroring. Evidence: `let end = outcome.captures[0].1 as f64;` /
    `&subject[from as usize..to as usize]`. Within the "crashed crank" doctrine; no memory-safety
    issue. **Low (robustness); by reading.**

13. **Stringly-typed Intl records re-parsed with silent defaults at the value-engine boundary.**

## What is done well

- Determinism hygiene is real: no host clock or locale reaches this code; ICU4X is pinned to an
  exact version; the one data-bearing map (`LocaleData.unicode`) is a `BTreeMap`; date math is
  integer after a single `floor`.
- Every side table touched here is both a GC edge (43857, 43866, 43934–43969) and a snapshot ledger
  row (sidetable.rs 694–710), and the ledger is reconciled mechanically against the struct; the
  formerly append-only `promise_guards` arena is compacted from live holders (44441–44512).
- Brand checks precede every side-table index in the traced callers; catchable errors use one
  uniform helper family; named skips (`Halt::Unsupported`) are the norm where a path is not modeled.
- The promise object model is small and explicit (`PromiseData`/`PromiseFnData`/shared guard index),
  with the two-level `[[AlreadyResolved]]` structure documented at 2778–2785.
- Metering intent is documented at every tick site, and `build_regexp` models XS's pattern-scaled
  chunk sizes rather than fitting a constant.
- The DTF snapshot decoder maps component keys back onto a closed static set and refuses others.
