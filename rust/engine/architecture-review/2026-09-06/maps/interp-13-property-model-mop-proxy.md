## Purpose and responsibilities

This region is the engine's **property model and meta-object protocol**:

1. **Key interning** — the program-local `u16` property-id space. String keys
   append upward (`symbol_names`/`symbol_ids`, `append_name_key` 35006), symbol
   keys are minted downward from `next_symbol_key_id` (`intern_symbol_key`
   35056); the two meet at the `id_space_exhausted` poison latch (35008–35018,
   35060–35068; the dispatch loop halts at 11352).
2. **Computed-key resolution** — `resolve_at_key` 35155 turns an `AT` key into
   `Payload::At(id, index)` (index keys use `XS_NO_ID`); `property_at_get` 35242
   / `property_at_set` 35313 dispatch by receiver shape (string primitive,
   proxy, typed array, array, ordinary).
3. **Ordinary object internals** — the `next`-linked property chain
   (`find_property` 35570, `own_property_slots` 35688, flag byte
   `XS_DONT_ENUM/DELETE/SET/PATCH`, `XS_GETTER/SETTER`), accessor callables in
   the `accessors` side table (4229), `ordinary_get_own_descriptor` 35911,
   `ordinary_define_own_property` 35977 (ValidateAndApply), `ordinary_get`
   36195, `ordinary_set` 36224, `delete_own_property` 38046.
4. **Exotic own-state synthesis** — function `length`/`name` from `FuncInfo`
   (`function_meta_own_descriptor` 35883, tombstones in `deleted_fn_meta`),
   array `length`/items (`array_own_descriptor` 36959), constructor
   `prototype` from `ctor_prototype` (`exotic_own_descriptor` 36914).
5. **Hardened JS** — `do_harden` 35718 (`harden_enqueue` 35746,
   `harden_freeze_and_traverse` 35766) and `do_petrify` 35826. No `lockdown`
   exists (6836–6853: only `harden`/`petrify` are installed).
6. **Proxy (ECMA-262 10.5)** — `make_proxy` 36356, `proxy_trap` 36393
   (GetMethod), `invoke_value` 36415 / `construct_value` 36463 /
   `run_callback_construct` 36497, the `mop_*` dispatchers 36591–37093 and the
   thirteen `proxy_*` traps 37098–37554, `object_static_proxy` 37559,
   `is_compatible_descriptor` 37780, `descriptor_from_object` 37829,
   `to_property_id` 37882, `property_key_slot` 37904, `descriptor_object` 37967.
7. **Primitive-string and environment access** — `string_property_get` 38097,
   `string_index_get` 38113, `instance_get` 38125, `instance_has` 38153,
   `with`/eval environments (`new_environment_instance` 38180,
   `is_scopable_slot` 38215, `environment_get/set` 38281/38297,
   `resolve_env_reference` 38340), frame/global name resolution (`resolve_get`
   38448, `resolve_set` 38482), `truthy` 38511.

## Architectural observations

**Coupling / duplication (the "one seam or several?" question).** There are at least four layered read paths — `instance_get` (chain only), `ordinary_get` (+accessors, +proxy-in-chain), `mop_get` (+exotic side-table descriptors, +proxy receiver), `property_at_get` (+arrays/TA/strings by receiver shape) — three presence paths (`instance_has`, `chain_has_descriptor`, `mop_has`/`object_own_property_present`), five own-property insertion primitives (`instance_put`, `define_descriptor_field`, `define_descriptor_field_slot`, `set_own_unmetered_with_flag`, `ordinary_define_own_property`), two key-enumeration families (`own_enumerable_ids`/`own_all_string_ids` vs `ordered_own_key_ids`/`mop_own_keys`), and two ValidateAndApply implementations. Which layer a caller picked is a historical accident of the "increment" it was written in, and the layers give different answers for the same object: [probe M3] `Reflect.ownKeys(f)` → `prototype,caller,x` but `Reflect.ownKeys(new Proxy(f,{}))` → `length,name,caller,x,prototype`. Every bypass is a spot where a proxy trap or an accessor is silently skipped.

**Integrity flags model only chain slots.** `is_ordinary_object` (35673) is the gate for `harden`/`petrify`/`freeze`/`seal`/`isFrozen`; anything with side-table own state either halts (`Unsupported`) or, for functions (which pass the gate), leaves its synthesized/side-table own properties unfrozen while the query paths report frozen. This is the structural reason harden is not yet SES-adequate (arrays cannot be hardened at all, 35776).

**Hidden state / side tables** in this region: `accessors` ((inst,id)→callables; GC edge is an O(|accessors|) filtered scan per marked owner, 43871–43885), `deleted_fn_meta` (tombstones), `symbol_key_ids` + `next_symbol_key_id`, `proxies`/`proxy_revokers`, `ctor_prototype`, `global_props` (must stay 1:1 with the global chain — maintained at 36028–36034, 38013–38024, 38081–38083, but `resolve_set` bypasses its flags). All are GC-visited/swept and in the snapshot ledger.

**Panics/unwraps on untrusted data.** `current.unwrap()` 36039, `.value.unwrap()` 36062, `.get/.set.unwrap()` 36070/36073, `find_property(..).unwrap()` 36080, `method.unwrap()` 36450, `unreachable!()` 37873 — all guarded by construction (materialize-then-lookup; descriptor shape invariants); I found no input-reachable panic in the region. `find_property` and the prototype walks assume acyclic `next`/proto links; a corrupt snapshot with a cyclic chain would hang (snapshot reader's responsibility, not this region's). The real robustness hole is not a panic but **unbounded Rust recursion** through the MOP (no depth counter anywhere in 35006–38520; `run_callback` 16308 has none either) → process abort [probe M6]; 3000 nested proxies still succeed on an 8 MiB main-thread stack [probe M7], so the abort threshold is a host stack-size property, not an engine property.

**Determinism.** HashMap iteration appears only as equality searches (`string_key_name`, `property_key_slot`, `is_symbol_key_id`) whose result is order-independent while `symbol_ids` is injective; the poisoned (`id_space_exhausted`) state breaks injectivity but is discarded. Sorts are stable with (rank,index) keys → creation order preserved. No f64 formatting except `number_to_ecma_string` for numeric keys (shared helper). No host time/locale. Determinism hazard: the recursion-depth abort above.

**Metering-doctrine drift.** Between 36339 and 38005 exactly one `meter.tick_*` exists (36736, `hasOwnProperty`). Trap `GetMethod`, trap invocation glue, invariant checks (`mop_get_own_property`/`mop_is_extensible` on the target per trap), `descriptor_object` (5 slot allocs per defineProperty/GOPD trap), `property_key_slot` (a fresh string chunk per trap call), `array_from_slots` (args array per `apply`/`construct` trap and per `Object.keys/values/entries` result) all allocate and compute unmetered. [probe N5/N6]: 1000× `p.x` through a `get` trap = 41,578 computrons vs 1000× the equivalent plain call = 48,565. Under "accuracy over parity" (meter = deterministic proxy for wall cost) this is a systematic under-charge with unaccounted heap growth. Likewise the O(|symbol_ids|) scans and the O(n²) `seen.contains`/`unchecked.remove` in `proxy_own_keys` 37468/37489–37505 cost wall time invisible to the meter.

**Error-handling shape.** Two shapes coexist: `catchable_type_error()` (realm-local, unwinds to the guest handler, returns `Halt::Resume`) used by all traps and `make_proxy`; and `Err(Halt::Throw(String))` (uncatchable host escape) used by `descriptor_from_object`, `to_property_id`, `define_properties_from_object`. A third, `Halt::Unsupported`, self-names coverage gaps.

**API-boundary leaks.** `to_length_u32`'s `_ => 0` and `as i32` length reads leak the internal `u32` representation as wrong guest-visible values; `run_callback_construct` drops `new_target`.

**Performance architecture.** Reverse id→name is O(n) though `symbol_names` is the O(1) inverse; `own_property_slots` materializes a `Vec` per integrity op; `array_own_descriptor`/`exotic_own_descriptor` are consulted on every `mop_*` call for arrays; `accessors` GC edge is quadratic in accessor count.

## Candidate findings (most architecturally significant first)

1. **Several property seams, not one; each bypass skips proxies/accessors.** `interp.rs:38125` (`instance_get`), `:38153` (`instance_has`), `:38005` (`instance_put`), `:38448/38482` (`resolve_get/set`), `:37847–37851`, `:38216–38233`, `:38105`. Claim: the doc's "all … operations route through the same `mop_*` seam so a trap cannot be bypassed" (36348–36350) is false — `with(proxy)`, proxy descriptor objects, `String.prototype` accessors and `@@unscopables` getters all bypass traps/getters. Evidence: `let v = self.ordinary_get(code, descriptor, id, receiver)?;` after `if !self.instance_has(descriptor, id).0 { continue; }` (37847–37851); probes H (`caught:ReferenceError` vs 42), J (`undefined` vs 7), G (`undefined` vs `'G'`), M3 (two ownKeys answers). Why: the MOP is the security boundary for SES membranes; every bypass is a place where a proxy is transparent to the guest. Severity high, confidence high.
2. **`descriptor_object` doubles as FromPropertyDescriptor and always completes the descriptor, so `defineProperty` traps receive fields the spec omits.** `interp.rs:37277` + `:37967–38003`, callers 36290–36298, 37692–37709. Claim: a forwarding `defineProperty` trap turns `p.x = 2` into a freeze of `t.x` and turns `Object.freeze/seal(proxy)` into `t.a = undefined`. Evidence: `let desc_obj = self.descriptor_object(desc);` (37277); `self.define_descriptor_field(object, "value", descriptor.value.unwrap_or_else(Slot::undefined))` (37981–37985) with no "present" check; probe A → `value,writable,enumerable,configurable|2:false:false:false`, B → `undefined`, M9 → `undefined:false:false`. Why: the canonical SES membrane trap is `Reflect.defineProperty(t,k,d)`; this corrupts targets through the most common proxy idiom. Severity high, confidence high.
3. **Integrity flags cover only chain slots: hardened/frozen functions keep `length`/`name` redefinable and deletable; arrays cannot be hardened at all.** `interp.rs:35897–35907` (`configurable: Some(true)` hard-coded), `:35780–35788` (stamps `own_property_slots` only), `:35775–35777`. Claim: `harden(f)` reports `Object.isFrozen(f) === true` while `Object.defineProperty(f,'name',{value:'evil'})` succeeds and `delete f.name` returns true; `harden([1])`/`Object.freeze([])` halt with `Unsupported`. Evidence: `configurable: Some(true),` (35906); `return Err(Halt::Unsupported("harden:exotic-object"));` (35776); probes E2 `true:true`, M1 `no-throw:evil`, M2 `true:undefined`. Why: harden is the SES primitive; the design's acceptance bar is the endo boot running identically. Severity high, confidence high.
4. **No recursion bound in the MOP: a prototype cycle through a proxy (spec-legal) or a deep proxy chain aborts the process with a native stack overflow.** `interp.rs:36206–36207` (`ordinary_get` → `proxy_get`), `:36623–36625` (cycle check stops at a proxy), no depth counter in 35006–38520 or `run_callback` 16308. Claim: guest code can terminate the worker process (not a `Halt`, not a panic) and the finite-depth threshold depends on host thread stack size. Evidence: `if owner != inst && self.proxies.contains_key(&owner) { return self.proxy_get(code, owner, id, receiver); }`; probe M6 → `fatal runtime error: stack overflow, aborting`; probe M7 (3000 nested proxies) succeeds. Why: design § Memory-safety promises logic bugs surface as deterministic panics; a stack abort is neither deterministic across hosts nor a crashed-crank `Halt`. Severity high, confidence high.
5. **The proxy/MOP seam is unmetered (one tick in ~1,700 lines).** `interp.rs:36339–38005` (only 36736 ticks), `:37968` + 4× `define_descriptor_field`, `:37917` `alloc_str_text` per trap key, `:37765–37773` `array_from_slots`. Claim: trap dispatch, invariant checks and their allocations cost zero computrons, so a proxied read meters less than an equivalent plain call. Evidence: awk over the range finds only `self.meter.tick_raw(METHOD_HAS_OWN_PROPERTY_METERING);`; probe N5 41,578 vs N6 48,565 computrons for 1000 iterations. Why: metering doctrine requires the meter to track real cost; unmetered allocation is also unmetered GC pressure. Severity high (consensus/DoS), confidence high.
6. **Bare-identifier assignment ignores non-writable/accessor global properties; bare reads ignore global getters.** `interp.rs:38498–38501` (`resolve_set` writes `p.kind/p.value` with no `XS_DONT_SET_FLAG`/`XS_GETTER_FLAG` check), `:38471–38473` (`resolve_get` raw read), caller 11975 with no flag check in 11953–11974. Claim: after `Object.freeze(globalThis)`, `g = 2` succeeds in sloppy and strict code. Evidence: `let p = self.slots.get_mut(idx); p.kind = value.kind; p.value = value.value;`; probes F1 `"2"`, F2 `no-throw:2`. Why: frozen globals are the first thing a hardened realm relies on; `Object.defineProperty(globalThis, …)` is already an honest `Unsupported` (26433) but `freeze` is not gated. Severity high, confidence high.
7. **Integer-index keys on non-array objects are interned as permanent `u16` names, so ordinary dictionary code exhausts the id space and kills the machine.** `interp.rs:35297`, `:35392`, `:36584`, `:37030` (`self.intern_key(&index.to_string())`), `:35007–35017` (exhaustion latch). Claim: `for (i<70000) o[i]=i` halts with `Unsupported("property-key:id-space-exhausted")`. Evidence: `let id = self.intern_key(&index.to_string()); self.ordinary_get(code, inst, id, obj)` (35297–35298); probe I → `completed=false halt=Unsupported("property-key:id-space-exhausted")`. Why: a legitimate program pattern (numeric-id caches, `Object.keys` over a large array through a proxy) is a machine-fatal event; XS (to my recollection — not verifiable here, submodule absent) keeps ordinary-object index properties in an internal array slot rather than the key table. Severity high/medium, confidence high on the ironhorse behavior, medium on the XS comparison.
8. **`arr.length = v` silently truncates the array to 0 for any non-integral/negative/string `v`, and lengths ≥ 2^31 read back negative.** `interp.rs:35513–35519`, `:35491–35507`, `:35302`, `:36562`, `:36967`. Claim: `a.length = 1.5` drops every item without throwing; `a.length = '2'` → 0; `a.length = 2147483648` → `-2147483648`. Evidence: `_ => 0,` (35517) while `checked_array_length` (35524) exists unused; `Ok(Slot::integer(self.arrays[&inst].length as i32))` (35302); probes C1/C2 `no-throw:0:undefined`, C3 `0:undefined:undefined`, D/N7 `-2147483648`, `-1`. Why: a documented "later increment" that yields wrong results instead of self-naming — a result divergence the oracle would flag on any test touching it. Severity medium, confidence high.
9. **Two error shapes: descriptor helpers throw uncatchable `Halt::Throw(String)` while traps throw catchable realm errors.** `interp.rs:37861`, `:37869`, `:37877`, `:37886/37893/37899`, `:37952–37955` vs `catchable_type_error` 34654 and its doc 34633–34636. Claim: `try { Object.defineProperty({}, 'x', {get: 1}) } catch (e) {}` does not catch; the crank ends `completed=false`. Evidence: `return Err(Halt::Throw("TypeError: getter is not callable".into()));`; probe M4 `completed=false halt=Throw(...)`. Why: guest-visible error semantics differ by which helper a path happens to use; test262 `assert.throws(TypeError, …)` cases over descriptors fail as crashes rather than passes. Severity medium, confidence high.
10. **O(n) reverse id→name scans and O(n²) key checks on hot MOP paths, invisible to the meter, though an O(1) inverse exists.** `interp.rs:35099–35103` (`string_key_name`), `:37904–37916` (`property_key_slot`), `:35095–35097` (`is_symbol_key_id`), used in comparators 35617/37082, per `hasOwnProperty` 36778, per array `mop_*` 36974; `:37468`, `:37489–37505`. Claim: every `hasOwnProperty` and every proxy-forwarded array operation scans the whole `symbol_ids` HashMap and clones strings, while `symbol_names[id-1]` (7250, 35019–35020) is the O(1) answer. Evidence: `self.symbol_ids.iter().find_map(|(name, property_id)| (*property_id == id).then(|| name.clone()))`. Why: wall cost grows with the number of interned names (up to ~65k) while the meter charges a constant — doctrine drift and a cheap DoS lever. Severity medium, confidence high.
11. **`descriptor_from_object` uses the chunk-blind `to_boolean` and a `functions`-membership test for callability.** `interp.rs:37853–37856`, `:37858–37870`, `to_boolean` 41376 ("stage-1 strings are results only"). Claim: `{enumerable:'', writable:''}` yields `enumerable:true, writable:true`; a callable proxy getter is rejected as "not callable". Evidence: `"enumerable" => out.enumerable = Some(to_boolean(&value)),`; `Payload::String(_) => true, // non-empty; stage-1 strings are results only`; probe N2 `1:true:true`. Why: a stale stage-1 assumption surviving into the MOP; `truthy` (38511) already exists for exactly this. Severity low/medium, confidence high.
12. **`run_callback_construct` discards `new_target`, so `Reflect.construct(F, args, G)` and trap-absent proxy `[[Construct]]` build the wrong prototype.** `interp.rs:36515` (`let _ = new_target;`), `:36490`, `:37544`. Claim: `Object.getPrototypeOf(Reflect.construct(F, [], G)) === F.prototype` instead of `G.prototype`. Evidence: `let _ = new_target;`; probe N1 `false:true`. Why: subclassing through proxies/Reflect (common in membranes) is silently wrong. Severity medium/low, confidence high.
13. **ValidateAndApply is implemented twice (inline in `ordinary_define_own_property` and as `is_compatible_descriptor`), with the ordinary path relying on materialize-by-construction `unwrap()`s.** `interp.rs:36040–36078` vs `:37780–37827`; `:36039`, `:36062`, `:36070`, `:36073`, `:36080`. Claim: the two copies agree today by inspection but nothing ties them together, and the ordinary copy panics rather than fails if `materialize_function_meta_slot` and `ordinary_get_own_descriptor` ever disagree. Evidence: `let property = self.find_property(inst, id).unwrap();` (36080). Why: a spec algorithm with two implementations is where proxy-vs-ordinary compatibility drifts. Severity low, confidence high.
14. **String wrapper objects have no exotic index/`length` in `property_at_get`.** `interp.rs:35286–35299` (no `wrapper_data` branch; index interned and looked up as an ordinary slot). Claim: `new String('ab')[0]` and `[k]` read `undefined`. Evidence: `let id = self.intern_key(&index.to_string()); self.ordinary_get(code, inst, id, obj)` (35297–35298); probe N3 `undefined:undefined:undefined`; contrast `object_own_property_present` 36818–36824 which does model it for `hasOwnProperty`. Why: another instance of finding 1 — per-path exotic modeling. Severity low, confidence high.

## What is done well

- The thirteen proxy traps are complete and spec-faithful: revocation check, `GetMethod`, trap-absent forwarding through `mop_*` (so proxy-over-proxy composes), and every 10.5.x invariant check present with realm-local catchable errors and correct `SameValue` semantics (`same_value` 35948 handles NaN and signed zero).
- `harden` is an iterative worklist with a visited mark set at enqueue: terminates on cyclic graphs, walks prototypes and accessor getters/setters, and `do_petrify` is correctly non-transitive.
- Every side table this region introduces (`accessors`, `proxies`, `proxy_revokers`, `ctor_prototype`, `deleted_fn_meta`, `symbol_key_ids`) has a GC edge or sweep (43821–43885, 44374, 44608–44643) and a snapshot ledger row (`sidetable.rs`); GC roots are sorted and deduplicated so HashMap order never reaches the trace.
- Where behavior is not modeled, the code mostly self-names with `Halt::Unsupported` (`harden:exotic-object`, `defineProperty:global-object`, `Object-static:unexpected-proxy`) rather than guessing — the exceptions are the ones listed above.
- Doc comments cite the spec section and the XS function for nearly every method, and record the metering rationale (`array_item_grow_metering` 35463–35484 even documents its known −8-raw residual), which made this review tractable.
- The `global_props` fast index is kept in lockstep with the global chain at every ordinary create/delete site (36028–36034, 38013–38024, 38081–38083) and the `id_space_exhausted` latch design is sound at crank granularity.
