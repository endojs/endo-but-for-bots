## Purpose and responsibilities

This region is the native-method back half for the built-in iteration and collection surface,
plus the raw-byte view surface:

- **Intrinsic iterators**: `Iterator.prototype.toArray` over native iterators; Map/Set
  iterator `next`; string iterator `next` (UTF-16 code-point stepping); for-in enumerator
  construction and `next`; array iterator `next` (values/keys/entries). All share one
  `IterState` record keyed by iterator instance in `Interp::iterators`.
- **Collections**: `Map/Set.prototype.forEach`; the ES2025 Set methods (union, intersection,
  difference, symmetricDifference, isSubsetOf, isSupersetOf, isDisjointFrom) with a faithful
  `GetSetRecord`; the upsert proposal (`getOrInsert`, `getOrInsertComputed` for Map/WeakMap);
  `Map.groupBy`/`Object.groupBy`; key canonicalisation (`-0`→`+0`), SameValueZero lookup
  (`collection_find`), entry-slot metering, and XS's `fxResizeEntries` table-geometry
  metering (`collection_table_resize`).
- **Array exotic generic path**: `array_generic_readonly` — the spec-order MOP-driven fallback
  for the read-only `Array.prototype` methods over sparse arrays, array-likes and Proxies,
  with `array_generic_index_id` interning each visited index as a property name.
- **TypedArray / ArrayBuffer / DataView / Atomics**: `ValidateTypedArray`, the four in-place
  mutators (`copyWithin`, `fill`, `reverse`, `set`), element codecs (`typed_array_element_*`),
  the integer-indexed exotic MOP pieces (`ta_valid_index`, `ta_indexed_element_get/set`,
  `ta_index_own_descriptor`, `ta_index_define`, `set_data_on_receiver`), `ToBigInt` low-64
  reduction, single-agent `Atomics` RMW (numeric + BigInt), DataView read/encode/store,
  `ToIndex`/byte-length coercions and `alloc_array_buffer`.
- **Tail of the range (not in FOCUS, read anyway)**: `end_completion`, `leave_call`,
  `unwind_to_jump`, `raise_js`, `catchable_{type,syntax}_error`, meter host-escape
  adjustment, closure scope helpers (`closure_index`, `retrieve_closures`, `store_closure`),
  `bind_program_this`, `run_constructor`, `bind_this_sloppy`, `new_array[_unmetered]`,
  `flat_into`, `intern_key`, and the start of `append_name_key` (the u16 key-id allocator).

## Invariants and contracts claimed (from doc comments) — and whether the code visibly upholds each

1. **"the stage-2 no-mid-run-GC contract"** (bulk.rs 235) — Upheld: `collect_garbage` has no
   call site in interp.rs (only tests and the snapshot resume path, machine.rs 1723/1759), so
   the many `self.arrays.get_mut(&fresh).unwrap()` / `self.collections.get_mut(&inst).unwrap()`
   on freshly allocated, unrooted instances (31561–31567, 32433–32441, 32498–32502) are safe.
   Consequence: within a crank, memory is bounded only by the meter (see finding 2).
2. **"Entries are addressed by index into the live `entries` Vec … deleted tombstones"**
   (31580–31583, bulk.rs 240–248) — Upheld for cursors; `remove_entry` tombstones Map/Set and
   physically removes for Weak kinds (bulk.rs 332–340). But the bulk.rs comment that iterator
   cursors are "an honest `Pending` ledger row that does not round-trip" is **stale**:
   `iterators_snapshot` (10354–10386) emits an `ITER` row and translates the physical index to
   a live-entry ordinal to match the compacted `COLL` row. Docs drift, code consistent.
3. **"A `clear()` since this cursor was created retires it for good"** (31587–31589) — Upheld:
   generation latch at 31590–31598, folded into `done` at the snapshot boundary (10364–10369).
4. **"`has` may mutate THIS, so re-check the element is still present"** (31970–31971) — The
   re-check is implemented, but it is **not in the specification** (intersection appends `e`
   when `inOther` is true regardless of whether `has` removed `e` from `O`); see finding 12.
5. **"The write routes through the counted accessor so the side-ref page counts move with
   it"** (31558–31560) — Upheld throughout the region: every insert/push goes through
   `insert_item`/`push_entry`/`set_entry_value` with `&mut self.side_refs`.
6. **"`index` must be in bounds (the caller checks)"** (33577–33578, 33653) — Upheld at every
   in-region caller (loop bounds derived from `ta.length`, `ta_valid_index`, constructor
   checks at 18297–18316); but the write primitive `slice_mut` is not chunk-bounded (finding 7),
   so the contract is enforced only by caller discipline, never by the arena.
7. **"Buffer detach is a host-only concern the XS oracle build does not model (it exposes no
   `$262`), so it is not checked here"** (33689–33691) — Contradicted by the engine itself:
   `NativeMethod::Test262DetachArrayBuffer` exists (26951–26963). Detach is checked in
   `validate_typed_array`, `TypedArraySet`'s array-like loop and both DataView paths, but not
   in `ta_valid_index`/`ta_indexed_element_get/set`/`ta_index_own_descriptor`/`atomics_dispatch`
   (finding 10).
8. **"A defensive bound against a pathological non-terminating guest iterator; the tested
   iterables are short"** (32370–32371) — The bound exists but exits the loop *normally*, so a
   1,000,001-element iterable yields a silently truncated group result (finding 4).
9. **"Exceeding the bound returns the method's ORIGINAL named skip … never a new failure"**
   (32954–32957) — Upheld as stated; but the "skip" is `Halt::Unsupported`, an uncatchable
   crank halt for a spec-valid program (finding 5).
10. **"`fxResizeEntries` … charge the `fxNewChunk(currentLength * 8)` — the rehash's only
    allocation"** (34454–34457) — Upheld as metering; but there is no hash table: `table_length`
    is a metering fiction and lookups are linear (finding 1). Determinism is trivially fine
    (no hashing at all), performance is not.
11. **"Raw-exact against the pin"** (34488) and the XS `txSlot`/`txChunk` size arithmetic
    (33270–33281) — Upheld as XS parity, which is exactly what the design's 2026-07-04 doctrine
    declared a non-goal (finding 13).
12. **`ToIndex` ceiling `0x7FFFFFFF`** (34376–34380, 34397) — Upheld; every constructor path
    checks `length <= 0x7FFFFFFF >> shift` with checked shifts/adds (18297–18307, 18375, 18439,
    18452, 18458).

## Architectural observations

**Coupling / monolith.** The region is ~3,500 lines of one `impl Interp`, mixing four
unrelated built-in families with the exception/call plumbing (`end_completion`,
`unwind_to_jump`, `raise_js`) and the key allocator (`intern_key`). Argument access is by raw
stack arithmetic (`self.stack.get(base + 4 + i)`) repeated ~20 times with the same
`unwrap_or_else(Slot::undefined)` idiom. Iterator kinds are magic numbers (0–7) matched in
`array_iterator_next`; the string iterator is chained to `%ArrayIteratorPrototype%` "in
ironhorse's model" (31459–31461), which is observably wrong (`Object.getPrototypeOf(""[Symbol.iterator]())`)
though outside this region's scope to fix.

**Hidden state / metering fictions.** `CollectionData.table_length` models XS's address array
purely to charge rehash chunks; there is no hash table. `collection_find` is
`entries().iter().position(...)` with SameValueZero (34435–34440); `collection_live_len` is a
filtered count (31752–31757); tombstones from `delete` persist until `clear` for Map/Set
(bulk.rs 332–340). A Map used as a queue/LRU is O(ever-inserted) per op and never reclaims
tombstone memory while it lives.

**Panics / unwraps / indexing on untrusted data.** In-region `.unwrap()`s are on entries the
same function just created (31563, 31567, 31632, 32441, 32500, 32698) or on options the
control flow already excluded (33514 non-BigInt kinds, 33626/34297 BigInt|Boolean payloads,
33945 `expect`) — sound under the no-mid-run-GC contract. `unreachable!` at 33571/33642/
33791/34234/34944 are internal. Indexing `self.iterators[&iter]`, `self.collections[&inst]`,
`self.array_buffers[&ta.buffer]`, `TYPED_ARRAY_TYPES[kind as usize]` all follow membership
checks or restored-row validation (9061–9070, 10398–10428). `code[pc+1]`/`code[pc+2]` in
`closure_index` (34719–34725) trusts the decoder's validity envelope (a panic, not UB, on a
truncated operand). Slicing `payload(...)[base..base+size]` would panic on an
`ArrayBufferData.length` larger than the chunk's stored length; the restore at 9038–9044
checks only `data + length <= arena size`, not `length <= len_of(data)` (finding 7).

**Index arithmetic.** u32/usize casts are consistently guarded: `checked_shl`/`checked_add` in
constructors, `saturating_sub` for counts, `i128` for signed relative indices
(33160, 33197–33201, 33256–33260), `as u64` on non-negative finite f64 (saturating is the
right behaviour there), `rem_euclid` in `encode_element_le` (40330–40338) rather than
saturating `as` casts. `to_wrapped` uses `2f64.powi(bits)` — exact for base 2. The one
unguarded narrowing found is cross-region: `ChunkArena::alloc` does `let off = v.len() as u32`
(value.rs 1481) with no cap, so an arena past 4 GiB wraps offsets (finding 2).

**Determinism.** No HashMap/HashSet iteration reaches an observable result in this region:
`enumerable_keys` uses a `HashSet` only for dedup and sorts array indices (32608–32614);
`ArrayData.items` is a BTreeMap; `gc_roots` sorts (43692–43693); snapshot exporters sort by
owner. f64 use is IEEE-deterministic (`trunc`, `rem_euclid`, `round`, `floor`, `ceil`,
`f32 as f64`, `from_le_bytes`); `number_to_ecma_string` is the engine's own formatter.
`String::from_utf16_lossy` is deterministic but *lossy* (finding 8). No host time/locale.
The iteration caps (1,000,000 and 1<<24) are deterministic behaviour cliffs not present in
the specification or in XS.

**GC roots and side tables.** All side tables this region writes are edges in
`extra_edges` (arrays 43903, collections 43908 with weak kinds via ephemerons, typed_arrays→
buffer 43928, data_views→buffer 43931, iterators→iterable/result 43934) and are pruned in
`swept` (44009+). `IterState.enum_keys` holds only string-key ids (symbol keys are filtered at
32634), so no missing edge there. `detached_buffers` is a set of owners; nothing in the region
frees or zeroes a detached chunk.

**Snapshot coverage.** Collections (COLL, tombstones compacted), iterators (ITER with ordinal
translation and `str_bytes`/`enum_keys`), buffers (ABUF with detached/shared flags), typed
arrays (TARR), data views (DVIW) all travel; `generation` deliberately does not (folded into
`done`). One stale doc comment in bulk.rs (finding 14). `str_bytes` duplicates the iterated
string outside the chunk arena and is serialised per iterator — a live string iterator over a
large string doubles that string's footprint in every checkpoint.

**Metering doctrine.** The region's constants are XS raw-exact calibrations (34486–34491,
33275–33281, 31569, 32636, 32702), and several O(n) host costs are metered O(1) or not at
all: linear `collection_find` behind a hash-table price; `IterState` clone per `next`
(32513, 32730, 31585/31599); per-element `TypedArrayFill`/`Reverse`/`CopyWithin` writes
(33439–33461) with no per-element tick; `Vec` snapshots (`collection_live_keys`, `to_vec()` of
buffer spans) unmetered. Memory is priced at 1 raw unit per byte (`CHUNK_ALLOCATION_METERING
= 1`, meter.rs 49) = 2^-16 computron/byte and no allocation ceiling exists in the VM (grep for
allocation/heap limits in `ironhorse-vm/src` found none).

**Error-handling shape.** Spec errors are realm-local and catchable via
`catchable_*_error` → `raise_js` (good). Coverage gaps are expressed as `Halt::Unsupported`
(uncatchable): generic `Iterator.toArray`, `Atomics` with object/undefined operands or a
`Uint8Clamped`/float view, `wait/notify`, resizable buffers, `ArrayBuffer.prototype.transfer`
/`concat`, generic-path over-cap, non-dense receivers for allocating methods, and any native
callback via `run_callback`. In production these are guest-triggerable, deterministic, but
unrecoverable crank deaths.

**Performance architecture.** Beyond the two quadratic hot paths (collections, iterator
clone), `is_symbol_key_id` scans all symbol keys per call (35095–35097; called per property in
`enumerable_keys` 32634), `string_key_name` is a linear `find_map` over all interned names
(35099–35103; called per typed-array named-key access via `ta_numeric_index_at` 33732), and
`store_closure` walks to the environment tail per captured variable (34821–34829).

## Candidate findings (most architecturally significant first)

1. **Map/Set lookups are O(n) linear scans priced as O(1) hash operations; tombstones make them O(ever-inserted).** — `interp.rs:34435-34440` (also 31752–31757, 32017, bulk.rs 250–255, 332–340).
   Claim: every `get/set/has/delete` on a Map/Set walks the whole physical entry list with SameValueZero, so a Map of n entries costs O(n²) host time to build while the meter charges only entry slots plus XS's power-of-two rehash chunk.
   Evidence: `data.entries().iter().position(|entry| entry.is_some_and(|(k, _)| self.same_value_zero(&k, key)))`; bulk.rs: "`table_length` tracks XS's power-of-two address-array length … to charge the `fxNewChunk(length * 8)`"; bulk.rs 329–331 concedes weak kinds remove physically "keeping `collection_find` O(live) instead of O(ever-inserted)" — Map/Set do not.
   Why it matters: the design's meter is "the best available deterministic proxy for real (wall-clock) execution cost"; here a guest buys O(n) host work for O(1) computrons, a DoS amplifier against validators and a 2.0× performance-envelope breaker for any collection-heavy contract. Severity high, confidence high.

2. **Memory is effectively unmetered and uncapped: 2 GiB of ArrayBuffer costs 32,768 computrons, no allocation ceiling exists, and the chunk arena's `u32` offset silently wraps past 4 GiB.** — `interp.rs:34410-34412`, `value.rs:1481`, `meter.rs:49`.
   Claim: `new ArrayBuffer(0x7FFFFFFF)` zero-fills 2 GiB after ticking `(2^31+16)` raw units (≈32,768 computrons), nothing refuses the allocation, and a third such buffer makes `ChunkArena::alloc` compute `let off = v.len() as u32` past 2^32, aliasing chunk offsets.
   Evidence: `self.meter.tick_chunk_new(byte_length as u64); let data = self.chunks.alloc(&vec![0u8; byte_length as usize]);` / `let off = v.len() as u32;` / `pub const CHUNK_ALLOCATION_METERING: u64 = 1;`
   Why it matters: XS bounds this with an allocation limit that fails the crank; IronHorse has none (grep for allocation/heap limits in `ironhorse-vm/src` is empty), so the only bound is host RAM — OOM-kill of the worker (or, with enough RAM, deterministic heap-offset aliasing). Severity high; confidence high on the mechanism, medium on the >4 GiB reachability (host-dependent).

3. **The generic Array path interns one permanent property name per visited index, so a spec-valid `Array.prototype.forEach.call({length: 70000}, f)` exhausts the u16 key space and poisons the machine for life.** — `interp.rs:32809-32812`, `35006-35017`, `11351-11353`.
   Claim: `array_generic_index_id(k)` calls `intern_key(&k.to_string())`, `append_name_key` saturates when `symbol_names.len()+1 >= next_symbol_key_id` and sets `id_space_exhausted`, after which every crank halts with `Unsupported("property-key:id-space-exhausted")` and `is_quiescent` is false forever.
   Evidence: `let name = k.to_string(); self.intern_key(&name)`; `if next >= self.next_symbol_key_id as usize { … self.id_space_exhausted = true; …}`; `if self.id_space_exhausted { return Halt::Unsupported("property-key:id-space-exhausted"); }`
   Why it matters: a guest can kill a vat permanently (and un-persistably) with ~65k iterations costing ~256 computrons; short of that, every index visited becomes a NAME-row entry in every future snapshot. The 1<<24 cap at 32958 is 256× larger than the id space it consumes, so the cap can never fire first. `to_property_id` (37896–37901) has the same root cause for ordinary objects. Severity high, confidence high.

4. **`Map.groupBy`/`Object.groupBy` over a generic iterator silently truncate after 1,000,000 elements and return a wrong result.** — `interp.rs:32372-32380`.
   Claim: the `for _ in 0..1_000_000` loop exits normally when the cap is hit, so the remaining elements are dropped and a partial grouping is returned without error.
   Evidence: `// A defensive bound against a pathological non-terminating guest iterator; the tested iterables are short.` `for _ in 0..1_000_000 { … if self.truthy(&done) { break; } … record!(value); }`
   Why it matters: a deterministic wrong answer (not a halt) for a spec-valid program; the metering limit, not a magic loop count, is supposed to bound long computations. Severity medium-high, confidence high.

5. **Native loops over guest-controlled lengths never run a meter check and substitute ad-hoc caps or none: `iterator_to_array` is unbounded, `array_generic_readonly` halts with `Unsupported` at 1<<24, typed-array `fill/reverse/copyWithin` tick nothing per element.** — `interp.rs:31542-31566`, `32958-32960`, `33439-33443`.
   Claim: `Meter::check` fires only in the dispatch loop, so `Iterator.prototype.toArray` on `[].values()` of a sparse array with `length = 2**32-1` performs ~4×10⁹ `insert_item`s (BTreeMap OOM) with no abort point, while `forEach.call({length: 2**25})` dies with an uncatchable `Halt::Unsupported`.
   Evidence: `loop { let result = self.array_iterator_next(iter)?; … .insert_item(length, value, &mut self.side_refs); length += 1; }`; `const GENERIC_ITER_CAP: u64 = 1 << 24; let over_cap = Halt::Unsupported(Self::array_generic_skip_reason(m));`; `for i in start..end { … out[pos..pos + size].copy_from_slice(&bytes); }`
   Why it matters: the design says checks at XS's loop-closing points suffice because XS also bounds memory; without that, a native call is an unabortable unit of work sized by the guest. Severity medium, confidence high.

6. **Every iterator `next()` clones the whole `IterState`, including the iterated string's bytes and the for-in key list, making `for..of` over a string and `for..in` over an object O(n²) while metered O(1) per step.** — `interp.rs:32513`, `32730`, `31585` and `31599`, `3086-3090`.
   Claim: `let st = self.iterators[&iter].clone();` copies `str_bytes: Vec<u8>` (the full UTF-16 text) on every string-iterator step and `enum_keys: Vec<(u16,u32)>` on every enumerator step; `collection_iterator_next` clones twice.
   Evidence: `#[derive(Clone, Debug)] struct IterState { … enum_keys: Vec<(u16, u32)>, … str_bytes: Vec<u8>, }`; `let st = self.iterators[&iter].clone();` (32513); `let st = self.iterators[&iter].clone();` (32730).
   Why it matters: a 1 MiB string iterated by `for..of` moves ~250 GB of memory for a few hundred thousand computrons — a metering-accuracy inversion and a practical hang; `make_string_iterator(self.str_content(off).to_vec())` also duplicates the string outside the metered arena. Severity medium, confidence high.

7. **`ChunkArena::slice_mut` bounds against the arena, not the chunk, so every typed-array/DataView write depends on caller arithmetic; the buffer restore checks `data+length ≤ arena` but not `length ≤ len_of(data)`, so a crafted image makes reads panic and writes silently overwrite neighbouring chunks.** — `value.rs:1529-1534`, `interp.rs:9038-9044`, `33417`, `33441`, `33665`, `34252`.
   Claim: `slice_mut(off, len)` returns `&mut bytes[start..start+len]` with no comparison to the chunk header length, and the ABUF restore only requires `data.0 + length <= chunk_len`.
   Evidence: `&mut self.bytes_mut()[start..start + len]`; `|| data.0 as u64 + *length as u64 > chunk_len` (the only length check); `let out = self.chunks.slice_mut(buffer.data, dst + byte_count);`
   Why it matters: the design promises a stale index is "a logic bug caught by kind checks, not undefined behavior" — here a length bug or a crafted snapshot (an untrusted input) becomes deterministic cross-chunk corruption rather than a caught panic; a `debug_assert!(len <= self.len_of(off))` or a checked variant would restore the property. Severity medium; confidence medium (I did not read whether the chunk-arena restore validates the header chain independently).

8. **Property keys and group-by bucket identity go through `String::from_utf16_lossy`, so strings differing only in lone surrogates alias to one key.** — `interp.rs:32409-32421`, `32471-32479`, `10891-10893`, `37896-37901`.
   Claim: `property_key_repr` and `new_group_object_from_buckets` use `str_text` (lossy) to identify and intern keys, so `Object.groupBy(xs, () => "\uD800")` and `() => "\uDC00"` (and `"�"`) share a bucket and a property; `to_property_id` has the same shape for every string property key in the engine.
   Evidence: `fn str_text(&self, off) -> String { String::from_utf16_lossy(&self.str_units(off)) }`; `Kind::String => match key.value { Payload::String(off) => self.str_text(off), …}`; `let name = … self.str_text(offset) …; Ok(self.intern_key(&name))`.
   Why it matters: deterministic but spec-wrong property identity (`o["\uD800"] = 1; o["\uDC00"]` reads 1), a result divergence the oracle would flag on any lone-surrogate key test. Severity medium, confidence high on mechanism.

9. **Every callback-taking method in this region inherits `run_callback`'s refusal of native callbacks, so `map.forEach(console.log)`, `Map.groupBy(xs, String)`, `set.union` over a Set-like whose `has` is a bound/native function, etc., halt the crank uncatchably.** — `interp.rs:16305-16306` (contract), call sites `31724`, `32202`, `32281`, `32976`.
   Claim: `run_callback` "A non-user-function callback (a native, or a non-callable) self-names an honest skip", i.e. `Halt::Unsupported`, and no in-region caller special-cases a native callee.
   Evidence: `self.run_callback(code, callback, this_arg, &cb_args)?;` (31724); doc: "A non-user-function callback (a native, or a non-callable) self-names an honest skip."
   Why it matters: an API-boundary hole reachable from ordinary SES boot code and contracts (`arr.map(String)`, `harden` passed as a callback), deterministic but fatal. Severity medium, confidence high (cross-region contract, in-region exposure).

10. **The detach model is partial and its justification is stale: integer-indexed element get/set/define and `Atomics` ignore `detached_buffers` "because the oracle exposes no `$262`", yet the engine binds `$262.detachArrayBuffer`; detach never releases the backing chunk.** — `interp.rs:33689-33705`, `33740-33754`, `33974-34012`, `26951-26963`.
   Claim: after `$262.detachArrayBuffer(buf)`, `ta[0]` returns the stored element (spec: `undefined`), `ta[0] = v` stores into the detached buffer's still-live bytes, and `Atomics.load(ta, 0)` succeeds.
   Evidence: "Buffer detach is a host-only concern the XS oracle build does not model (it exposes no `$262`), so it is not checked here."; `NativeMethod::Test262DetachArrayBuffer => { … self.detached_buffers.insert(buffer); Slot::undefined() }`; `ta_valid_index` tests only finiteness, integrality, sign and `n >= ta.length as f64`.
   Why it matters: inconsistent semantics inside one engine (DataView and the mutators check detach in spec order; the MOP does not) and a wrong-answer class in the test262 harness; production impact is nil today only because `transfer` is `Unsupported` (28497). Severity low-medium, confidence high.

11. **Key-table helpers are linear scans on hot paths: `is_symbol_key_id` scans all symbol keys per property during for-in key collection, and `string_key_name` scans all interned names per typed-array named-key access.** — `interp.rs:35095-35103`, `32634`, `33732`.
   Claim: `enumerable_keys` is O(properties × symbol-keys) and `ta_numeric_index_at` is O(interned names) per access.
   Evidence: `self.symbol_key_ids.values().any(|&v| v == id)`; `self.symbol_ids.iter().find_map(|(name, property_id)| (*property_id == id).then(|| name.clone()))`.
   Why it matters: unmetered host cost that grows with unrelated program state (how many names/symbols the machine has ever interned) — a metering-accuracy leak and a performance-envelope risk for large programs. Severity low-medium, confidence high.

12. **Set-method reentrancy handling deviates from the specification's live-list algorithm: `intersection` adds a "still in THIS" re-check the spec lacks, and `difference` walks a snapshot of THIS instead of the live list.** — `interp.rs:31984-31990`, `32008-32021`.
   Claim: if `otherRec.has(e)` deletes `e` from the receiver, spec `intersection` still appends `e` to the result; IronHorse drops it. If `has` appends to the receiver during `difference`, spec visits the appended entries; IronHorse does not.
   Evidence: `if self.truthy(&in_other) && self.collection_find(inst, &k).is_some() && !self.key_list_contains(&result, &k)`; `let mut result = self.collection_live_keys(inst); … while i < result.len() { … result.retain(…) }`.
   Why it matters: result divergences (observable via a Set-like with a mutating `has`) that a differential test262 run would attribute to the wrong side; the comment's rationale ("`has` may mutate THIS, so re-check") documents the deviation as intended. Severity low, confidence medium (spec recollection, not re-read here).

13. **In-region metering is XS raw-exact parity, contradicting the approved "accuracy over parity" doctrine.** — `interp.rs:34486-34491`, `33270-33281`, `31568-31570`, `32636`.
   Claim: weights model XS's `sizeof(txSlot)*n + sizeof(txChunk)`, a measured one-time `+8` raw on the first table grow, and a single final chunk charge for `toArray` rather than costs derived from the calibration instrumentation the design mandates.
   Evidence: `// … Raw-exact against the pin. if former == MAP_MIN_TABLE_LENGTH && current > former { self.meter.tick_raw(8); }`; `(slots as u64) * 32 + 16`; `if length != 0 { self.meter.tick_raw(self.array_chunk_size_metering(length)); }`.
   Why it matters: confirms the census-level drift at the code level; every such constant is a frozen `ironhorse-meter-1` weight whose provenance is the oracle, not measurement, so "accuracy" recalibration has no baseline to start from. Severity low (documented theme), confidence high.

14. **Stale doc contract in `bulk.rs`: iterator cursors are described as "an honest `Pending` ledger row that does not round-trip", but the ITER row exists and round-trips with ordinal translation.** — `bulk.rs:245-248` vs `interp.rs:10345-10386`.
   Claim: the tombstone-compaction soundness argument in `CollectionData`'s doc rests on a premise the code no longer has; the actual soundness argument (ordinal translation at 10365–10368) lives elsewhere.
   Evidence: "iterator cursors live in the `iterators` side table, an honest `Pending` ledger row that does not round-trip."; `let ordinal = c.entries()[..(st.index as usize).min(c.entries().len())].iter().filter(|e| e.is_some()).count() as u32;`
   Why it matters: the next maintainer who changes compaction will read the wrong invariant. Severity low, confidence high.

## What is done well

- **Spec observation order is taken seriously**: `GetSetRecord` (size → ToNumber → NaN/negative → has → keys), `SetViewValue` coercion before detach/range checks, `TypedArray.prototype.set` offset coercion before source dispatch, `IntegerIndexedElementSet` coercion before validity, and `IteratorClose` on early exit in `isSupersetOf`/`isDisjointFrom` — each with a comment naming the spec step or the test262 case that pins it.
- **Integer-width discipline in the codecs**: `encode_element_le` uses `rem_euclid` explicitly because "A Rust `f64 as iN` cast SATURATES … which is NOT the spec's modular reduction"; `round_half_even` for `Uint8ClampedArray`; constructor length checks use `checked_shl`/`checked_add` against the `0x7FFFFFFF` ceiling; signed relative indices are computed in `i128`.
- **Reentrancy robustness in collection loops**: `call_collection_foreach`, `intersection`, `isSubsetOf`, `isDisjointFrom` re-fetch the collection through `.get()` on every iteration and check the clear-generation, so a callback that deletes, appends, or clears never indexes out of bounds.
- **GC edge and snapshot coverage for this region's tables is complete**: arrays, collections (with weak kinds via ephemerons), typed arrays, data views and iterators are all edges in `extra_edges` and pruned in `swept`; the ITER row translates physical cursor positions to live ordinals to match COLL compaction, and folds clear-staleness into `done`.
- **Determinism hygiene**: no HashMap iteration order reaches an observable; array items are a BTreeMap; `gc_roots` sorts and dedups; snapshot exporters sort by owner.
- **Aliasing-safe byte moves**: `copyWithin`, `reverse`, same-kind `set` and cross-kind `set` snapshot the source bytes/values before writing, so overlapping views behave as if cloned.
