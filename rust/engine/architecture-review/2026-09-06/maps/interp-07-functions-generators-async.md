## Purpose and responsibilities

This region is the call/suspend/resume substrate of the interpreter:

- **Function definition** (`new_function`, `new_generator_function`, `new_async_function`,
  `new_async_generator_function`, `install_own_function_prototype`, `new_environment`): allocate the
  function instance, its `FuncInfo` side-table row, its default `.prototype` object (`ctor_prototype`),
  and re-chain prototypes per kind.
- **Instance creation for suspendable bodies** (`new_generator_instance`, `new_async_generator_instance`,
  `new_async_instance`): allocate the instance object and clone the freshly-entered activation into a
  `SavedFrame` stored in the `generators` / `async_generators` / `async_instances` side tables.
- **Call entry / nested dispatch** (`enter_call`, `run_callback`, `call_cross_segment`,
  `dispatch_entered_cross_segment`, `resume_segment_buffer`, `segment_buffer`,
  `ensure_active_code_segment`, `callee_segment`, `cross_segment_callee`, `run_callback_catching_throw`).
- **Resume protocol** (`resume_generator`, `step_async`, `step_async_generator`,
  `enqueue_async_generator`, `kick_async_generator`, `finish_async_generator_request`,
  `await_schedule`, `schedule_native_await`, `settle_via_function`, `new_generator_result`,
  `generator_done_result`).
- **`call_native`** (17487–18636): the plain-call dispatcher for intrinsic constructors (eval, the
  dynamic-Function family, Intl constructors, Temporal, Date, Boolean/Number/String/Object/Symbol,
  Error hierarchy, Array/Map/Set/WeakMap/WeakSet, ArrayBuffer/SharedArrayBuffer/TypedArray/DataView,
  Promise, RegExp, DisposableStack). ~1,150 lines of one `match` inside a 38k-line `impl`.

## Architectural observations

- **Monolith symptoms.** Four near-identical copies of the "suspend the driver, install the saved frame,
  rebase handlers, nested dispatch, unwind by arm" sequence (`resume_generator`, `step_async`,
  `step_async_generator`, plus the YIELD/AWAIT arms' four copies of the snapshot code). The fence exists
  in two of the three resume paths and in none of the callback paths. `call_native` is a 1,150-line
  `match` with the Intl constructors inlined.
- **Two-meaning success channel.** `enter_call -> Result<usize, Halt>` returns either a body pc or a
  catch-handler pc (16222). Three of four consumers pre-screen `functions.contains_key`, so only the
  cross-segment consumer is live — and it is wrong (finding 1). `catchable_type_error` (34654) shows the
  intended shape (`Halt::Resume(target)`), which `enter_call` predates.
- **Code buffer as a parameter.** `code: &[u8]` is threaded through every native and every resume;
  segment routing (`resume_segment_buffer`) is a retrofit whose `None => code` fallback (16789, 17076,
  17299) is silent. Today `run()` always sets `top_level_code` (11162) so the fallback is dormant.
- **Hidden global registers.** `resume_status`, `pending_new_target`, `callback_return_depth`,
  `eval_direct`, `frame_slots` are machine-global and hand-saved at each nesting seam; `eval_source`
  saves 14 of them (8048–8064). Each new seam must remember the full list.
- **Error model.** `Halt::Throw(String)` carries a lossy render computed eagerly at every host escape
  (34646), while the real value lives in `self.exception`, which every native catcher must clear by hand
  (16607, 17129, 17373). Native "mxTry" boundaries are implemented three different ways (fence +
  `Halt::Throw` arm; no fence + `Halt::Throw` only; `Halt::Resume` pass-through).
- **Panics/unwraps on untrusted input.** None found reachable from bytecode in this region: the
  `unwrap()`s in `kick_async_generator`/`step_async_generator` follow a `contains_key`/`get_mut` on the
  same key in the same synchronous path; `symbol_names.get(name - 1)` is guarded by `name != 0`;
  `promise_guards[data.guard]` follows a successful `get`. `unreachable!()` at 16934 is guarded by the
  match guard. The `expect` in `leave_call` (34568) is guarded by the frame-underflow checks at the
  START_* arms.
- **Robustness (native recursion).** `dispatch_at` counts re-entry depth (11281), but
  `kick_async_generator` → `finish_async_generator_request` → `kick_async_generator` recurses without
  passing through it (16914/16919/16932 → 16971), one level per queued request. Reproduced: process
  abort at 20k queued requests (debug, 2 MiB test thread) and 200k (release).
- **Determinism.** No HashMap iteration, no `f64` formatting, no host time in the suspend/resume paths.
  `id_map: HashMap<u16, usize>` is cloned, never iterated, here. (Snapshot export of `id_map` as
  `Vec<(u16,u64)>` must sort — other region.)
- **GC roots / side tables.** Verified complete for `generators`, `async_instances`, `async_generators`
  (incl. `requests`/`active`), run stacks, and reaction kinds. The internal async instance object
  (`Slot::instance(NULL)` 16113) is reachable only through `ReactionKind` payloads and run stacks — four
  separate sites (43610–43618, 43641–43644, 43953–43956, 43988–43995) must stay in sync.
- **Snapshot coverage.** `async_instances` and `async_generators` remain `Pending`; the persist gate
  refuses honestly (8656–8686). Operationally: a worker with any in-flight `await` or any live async
  generator cannot be suspended.
- **Metering doctrine drift.** Region constants are XS-raw calibrations with negative credits;
  frame-size-proportional work (cloning `locals`/`args`/`id_map` at instance creation and every
  suspend) is charged as a constant (`GENERATOR_START_METERING`, `ASYNC_INSTANCE_METERING`,
  `GENERATOR_YIELD_METERING`).
- **Performance architecture.** Every JS call heap-allocates `args: Vec<Slot>` (16209) and a
  `CallerState` carrying a `HashMap`; every suspend `mem::take`s and every resume re-installs `Vec`s and a
  `HashMap`; `run_callback` and the cross-segment path clone an `Rc<Vec<u8>>` per call.
- **Stack-budget accounting asymmetry.** `enter_call` checks `would_overflow` before opening a frame
  (16248); the three resume paths add `driver_footprint` (16712, 16991, 17212) and reinstall a saved
  frame of arbitrary size with no `would_overflow` check.
- **Docs drift (minor).** `unmeter_host_escape` carries `#[allow(dead_code)] // consumed by the deferred
  promise handler-throw increment` (34710) but is live at 16608. `enter_call`'s doc (16196–16199) still
  says non-callables produce `Halt::Throw`.

## Candidate findings (most architecturally significant first)

1. **Non-callable object call inside a function frame is misrouted through the cross-segment path and
   corrupts control flow (confirmed).** `interp.rs:16530-16535` (`cross_segment_callee`) treats any
   `Payload::Reference` — a plain object, array, … — as a callee with segment `None`, so once any segment
   exists (`ensure_active_code_segment` runs at the first CODE opcode, 13312) the RUN arm (13936) takes
   `call_cross_segment` → `enter_call`, whose non-callable branch returns `raise_js`'s catch pc through
   the `Ok(body_start)` channel (16220–16223); `dispatch_entered_cross_segment` (16564–16572) then runs
   that handler in a nested loop over `top_level_code`, and on the handler's function END returns
   `Ok(pop())` to the RUN arm, which sets `pc = ret_pc` of the dead frame's call site (13944–13949).
   Evidence (repro, scratchpad/repro07): `function f(){ try { ({})(); } catch(e){ return 1; } return 2; } f()`
   → `Throw("ReferenceError")`; `function assertThrows(fn){ try { fn(); } catch(e){ return e instanceof
   TypeError; } return false; } var o={}; assertThrows(function(){ o(); })` → `"undefined"`. Control cases
   (primitive callee, handler in caller frame, top level) are correct. Why it matters: silent wrong result on
   legal JS in the exact `assert.throws(TypeError, () => obj())` shape test262 uses. Severity high.
   Confidence: high (reproduced).

2. **Guest-controlled unbounded native recursion in the async-generator request drain aborts the process
   (confirmed).** `interp.rs:16971` (`finish_async_generator_request` → `kick_async_generator`) and
   `16914/16919/16932` (`kick` → `finish`) recurse once per queued request with no `dispatch_at` between
   them, so `DISPATCH_REENTRY_LIMIT` (11281) never applies. Evidence:
   `async function* ag(){} var g = ag(); for (var i=0;i<20000;i++) g.next(); 1` → `thread … has overflowed
   its stack / fatal runtime error: stack overflow, aborting (SIGABRT)` in debug; 200k aborts in release.
   Why it matters: a Rust stack overflow is a process abort no `catch_unwind` contains — daemon death, not
   a crashed crank; the design's memory-safety section promises only the latter. Severity high.
   Confidence: high (reproduced; the exact threshold depends on thread stack size).

3. **`run_callback_catching_throw` does not fence the caller's handler chain, so a `new Promise(executor)`
   throw is caught by the caller's `try/catch` instead of rejecting the promise (confirmed).**
   `interp.rs:16588-16612` records `jump_depth` but leaves `self.jumps` live (compare the fence
   `std::mem::take(&mut self.jumps)` at 17238 and 17017). Evidence (repro):
   `var r=0; var p; try { p = new Promise(function(){ throw 1; }); } catch(e){ r='caught:'+e; } r` →
   `"caught:1"` (spec/XS: `0`, `p` rejected); same inside a function frame. Reactions/thenable jobs are
   unaffected because the drain runs with an empty chain. Why it matters: silent result divergence and a
   promise that never settles; the doc comment (16584–16587) claims the opposite. Severity high.
   Confidence: high (reproduced).

4. **`async_instances` and `async_generators` still do not persist; a worker with any in-flight `await`
   or live async generator cannot be suspended.** `interp.rs:8656-8686` refuses by reaction kind and by
   row; `sidetable.rs:558,568` mark both `Pending`. Already recorded open in
   `designs/ironhorse-snapshot-store-seam.md:1469-1474` — reported here as *still open*, not new.
   Why it matters: for an Endo worker whose steady state is "awaiting a message", suspend is refused
   every time. Severity medium (honest refusal, not silent loss).

5. **Re-entrant `.next()` on an executing generator is an uncatchable named skip instead of the spec's
   catchable TypeError.** `interp.rs:16681-16685`: `GeneratorState::Executing =>
   return Err(Halt::Unsupported("generator:already-running"))`. Why it matters: XS completes
   `function* g(){ try { it.next(); } catch(e){ yield e; } }` with a TypeError; ironhorse aborts the crank
   — a result divergence on legal JS, in the one path the `Executing` state exists to guard.
   Severity medium.

6. **`enter_call`'s `Ok(usize)` conflates "callee body start" and "catch-handler resume target".**
   `interp.rs:16220-16223` `_ => { let error = …; return self.raise_js(error); }` returns the handler pc
   through the success channel; consumers at 16408, 16553, 36524 and 13971 all treat it as a body pc.
   Three pre-screen `functions.contains_key` so only 16553 is live today (finding 1), but the seam is the
   same loaded gun `FuncInfo::body_start: Option` was introduced to defuse (1729–1744). The fix shape
   already exists (`catchable_type_error` → `Halt::Resume`, 34654). Severity medium (structural cause of 1).

7. **Native `mxTry` boundaries are implemented three different ways.** Fenced + `Halt::Throw` arm
   (`step_async` 17238–17387, `step_async_generator` 17017–17134); unfenced, catches `Halt::Throw` only
   and passes `Halt::Resume` through (`run_callback_catching_throw` 16588–16612); unfenced by design for
   sync generators (16668–16859). There is no single "run guest code under a native try" primitive, which is
   how finding 3 arose after finding-3's twin was fixed for async. Severity medium (class of bug).

8. **Resume paths bypass the stack-overflow budget.** `enter_call` checks `would_overflow` before
   opening a frame (16248); `resume_generator`/`step_async`/`step_async_generator` add `driver_footprint`
   (16712, 16991, 17212) and reinstall `saved.locals`/`saved.args`/`saved.stack_slice` (16728–16738 etc.)
   with no check. Why it matters: `Halt::StackOverflow` is an abort observable the design wants to track
   XS's `fxOverflow`; the resume side can exceed the fixed budget without aborting. Severity low–medium.
   Confidence: medium (I did not consult XS's resume-side overflow check).

9. **The region's meter is XS-parity-calibrated with negative credits, contrary to the design
   doctrine.** `interp.rs:15870-15874` ("exactly `2 * XS_BUILTIN_METERING` = 32768 raw");
   `16079 self.meter.untick_raw(ASYNC_FUNCTION_DEFINE_DELTA)`; `17444
   self.meter.untick_raw(ASYNC_AWAIT_FASTPATH_CREDIT)`. Design § Metering: "XS-computron parity is an
   explicit non-goal… weights are entries in Ironhorse's own release-versioned cost table". Census notes
   this globally; these are the region's instances. Severity medium (docs/doctrine drift; determinism is
   unaffected).

10. **Frame-size-proportional suspend/resume work is metered as a constant.** `interp.rs:15991-16011`
    (`GENERATOR_START_METERING` then `locals.clone()`, `id_map.clone()` (a `HashMap`), `args.clone()`),
    same at 16027–16043 and 16107–16134; YIELD/AWAIT charge `GENERATOR_YIELD_METERING` while moving
    `stack_slice`/`jumps` (15358, 15414, 15573, 15625). Why it matters: the doctrine's stated purpose is
    a "deterministic proxy for real (wall-clock) execution cost"; a generator with 200 locals costs the
    same as one with none. Severity low.

11. **`Halt::Throw(String)` is a lossy duplicate of the `exception` register that every native catcher
    must clear by hand.** `interp.rs:3541-3543`; `34646 Err(Halt::Throw(self.render(&value)))` renders
    eagerly on every host escape even when a native catcher discards it (16600–16607, 17122–17129,
    17360–17373). Why it matters: error identity lives in a side register with manual hygiene; the
    string is dead weight on the hot rejection path. Severity low.

12. **Fence invariant is release-silent.** `interp.rs:17155` and `17412`
    `debug_assert!(self.jumps.is_empty(), "async body left handlers behind")` then
    `self.jumps = fenced_jumps` — in release a violation would silently discard live handlers. All arms
    truncate today, so upheld; the guard should be a real assertion or the overwrite an `extend`.
    Severity low (verification).

13. **Silent wrong-buffer fallback in segment routing.** `interp.rs:16787-16790`, `17074-17077`,
    `17297-17300`: `None => code` uses the *driver's* buffer when `segment_buffer(callee_seg)` is `None`;
    `segment_buffer(None)` is `top_level_code` (16477), which only `run()` sets (11162). Dormant today;
    becomes wrong-code execution if any entry point (a restored machine, a compartment evaluator) reaches
    a resume with `top_level_code == None`. Severity low. Confidence: medium (restore path not read).

14. **`new_function` allocates a `.prototype` object and `constructor` back-reference for every
    function; non-constructor kinds must undo it.** `interp.rs:15906-15921` (unconditional alloc + insert),
    `16073 self.ctor_prototype.remove(&f)` in `new_async_function` (object left in the arena until GC).
    Why it matters: unmetered heap footprint divergence (design § Performance: "slot accounting is
    identical by construction") and a hazard for any caller that forgets the undo. Severity low.
    Confidence: medium (arrow/method definers are outside this region).

## What is done well

- The suspend/resume protocol is genuinely symmetric where it matters: `frame_slots` accrual in the
  resume paths (16712/16991/17212) matches `leave_call`'s release (34571–34573); saved handlers are stored
  frame-relative and rebased on resume (15344–15357 → 16760–16772), with the `rebased` flag feeding a
  deliberate metering delta.
- GC coverage of suspended state is complete and cross-checked: `saved_frame_slots` visits every
  reference-bearing field including `jumps[].env`; async-generator `requests`/`active` are edges;
  run stacks and reaction kinds are roots (43610–43618, 43641–43644, 43847–43856, 43953–43995).
- Hostile-bytecode shapes found by fuzzing are refused by name rather than panicking: `yield:stack-underflow`,
  `await:stack-underflow` (15340, 15392, 15555, 15607), the `START_ASYNC, RETURN` frame-leak twins in all
  three resume paths (16819–16830, 17103–17113, 17333–17344), `start_async:frame-underflow`.
- The persist gate refuses unpersistable async state by name (8656–8686) instead of dropping it, and the
  design ledger records the gap honestly.
- Nested re-entry depth is centrally bounded in `dispatch_at` (11280–11290), so callback/async/generator
  nesting cannot overflow the native stack — the one uncounted cycle (finding 2) is the exception, not the
  rule.
- Doc comments cite the XS source function (`fxStepAsync`, `fx_Generator_prototype_aux`, `fxRunID`) and
  the review wave that motivated each guard, which made this region auditable.
