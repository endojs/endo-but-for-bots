## Description

Note: Claude prepared this issue for me; i discovered the failures by upgrading ses to v2 in es-abstract.

## Summary

In `ses@2.0.0`, `DataView.prototype.setFloat32(offset, NaN, …)` and `setFloat16(offset, NaN, …)` silently write all-zero bytes instead of a canonical NaN bit pattern. `setFloat64(offset, NaN, …)` is unaffected. This is a regression introduced by the new unconditional `tameNaNSideChannel` in `lockdown()` (there is no config option to disable it).

## Reproducer

```js
require('ses');
lockdown({ errorTaming: 'unsafe' });
const dv = new DataView(new ArrayBuffer(8));
dv.setFloat32(0, NaN, true);
console.log(Array.from(new Uint8Array(dv.buffer, 0, 4))); // [0, 0, 0, 0] — should be a NaN pattern, e.g. [0, 0, 192, 127]
console.log(dv.getFloat32(0, true));                       // 0 — should be NaN
```

Observed output with `ses@2.0.0` on Node:

```
Float32 NaN bytes: [ 0, 0, 0, 0 ]
Float32 readback: 0
Float64 NaN bytes: [ 0, 0, 0, 0, 0, 0, 248, 127 ]
Float64 readback: NaN
```

`setFloat64` produces the correct canonical NaN bytes `[0,0,0,0,0,0,248,127]` and reads back as `NaN`.

## Root cause

`packages/ses/src/tame-nan-sidechannel.js` defines:

```js
const canonicalNaN = 0x7ff8000000000000n; // 64-bit pattern
```

and the `setFloat32` wrapper does:

```js
return apply(setUint32, this, [byteOffset, Number(canonicalNaN), littleEndian]);
```

`Number(0x7ff8000000000000n)` is `9221120237041091000`, which is far outside the Uint32 range. `ToUint32(9221120237041091000)` is `0`, so four zero bytes get written. The same bug applies to the `setFloat16` branch via `setUint16`.

```
Number(0x7ff8000000000000n) === 9221120237041091000
Number(0x7ff8000000000000n) >>> 0 === 0            // setUint32 result
Number(0x7ff8000000000000n) & 0xffff === 0         // setUint16 result
```

`setFloat64` is unaffected because it passes the BigInt directly to `setBigUint64`.

## Expected fix

Use the appropriately-sized canonical NaN bit pattern for each precision rather than `Number`-coercing the 64-bit pattern:

- Float32 canonical quiet NaN: `0x7fc00000` → pass to `setUint32`
- Float16 canonical quiet NaN: `0x7e00` → pass to `setUint16`

## Impact

Any code that relies on `setFloat16` / `setFloat32` preserving NaN (round-tripping, writing canonical NaN bytes, etc.) silently produces zero values after `lockdown()`. Discovered while upgrading `es-abstract` from `ses@1` to `ses@2`; 107 tests in its `test:ses` suite fail for this single root cause.

## Workaround

None via configuration — `tameNaNSideChannel()` is called unconditionally from `lockdown.js`. Users must pin `ses@^1`.
