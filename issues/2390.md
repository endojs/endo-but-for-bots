## Description

_(Originally posted by @gibson042 in https://github.com/endojs/endo/pull/2387#discussion_r1695807510 )_

Non-comprehensive list:
* `export const { propName: exportName } = objWithPropName` (_**`prop.key.name`** of `propName: exportName` pulls propName, whereas we should pull **`prop.value.name`** to  ensure the presence of `harden(exportName)`_) and
* `export const { name, ...rest } = obj` (object rest) and
* `export const { name, parent: { subName } }` (nested patterns) and
* `export const [ exportName1, … ] = array` (_`declaration.id.type === 'ArrayPattern'` is just skipped entirely_)

The linked comment proposes a fix in the form of a `pushDeclaredNames` helper that handles default assignment and arbitrarily nested destructuring patterns, to be used in combination with post hoc verification of the style already employed for "_should be followed by a call to 'harden'_" complaints (i.e., collect all declarations in one phase and validate their conformance in a second phase).
