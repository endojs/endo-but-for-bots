## Description

Per exploration in the XS engine, Patrick Soquet suggests that we could extend the type signature of the values in a moduleMap and the return values of a moduleMapHook to include the static module types. This is both possible and valuable, since some compartments consist entirely of pre-compiled sources.

The insight that makes this possible is that we can distinguish module namespaces by brand check instead of structural type. The static module types are all distinguishable amongst themselves by structural type.

An implication of this is that the `load` method would need to allow progress on module loading even in the case where a `loadHook` is absent. The default `loadHook` would instead throw an error. We would either give `resolveHook` similar treatment or need to allow for a platform-dependent default.
