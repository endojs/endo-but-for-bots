## Description

I wrote a tool that uses `makeArchive` to deduce the full set of imported source files from a given entry point (to help answer the question "if I change file X, how many bundles/deployed things do I have to upgrade/re-deploy?"). It works fine on everything in agoric-sdk that we're currently bundling, of course, but I also want to ask about non-bundled things, like https://github.com/Agoric/agoric-sdk/blob/master/packages/cosmic-swingset/src/entrypoint.js (the starting point for the JS portion of the Agoric chain executable). I hacked around this code's desire to import e.g. Node.js builtin modules, by adding a fake `modules: { fs: null, process: null, .. }` record, to provide exits for those non-source modules. That works pretty well.

But, for at least two source modules, I got an error during `makeArchive`. One was when pointed at https://github.com/Agoric/agoric-sdk/blob/master/packages/SwingSet/src/index.js , which ends with some type-related imports:
```js
// eslint-disable-next-line import/export
export * from './types-external.js';

export * as shape from './typeGuards.js';
```

If I comment those out, or if I point `makeArchive` directly at `types-external.js` or `typeGuards.js`, it's fine. But if I point it at `index.js`, I get:
```
err (TypeError#1)
TypeError#1: Failed to load module "./src/index.js" in package "file:///home/node/trees/agoric-sdk/packages/SwingSet/" (1 underlying failures: Error transforming source in <unknown>: Cannot read properties of undefined (reading 'name')
```

Likewise, I have problems with https://github.com/Agoric/agoric-sdk/blob/master/packages/cosmic-swingset/src/anylogger-agoric.js , which gives me:
```
err (TypeError#1)
TypeError#1: Failed to load module "./src/anylogger-agoric.js" in package "file:///home/node/trees/agoric-sdk/packages/cosmic-swingset/" (1 underlying failures: Error transforming source in <unknown>: Cannot read properties of undefined (reading 'buildError')
```

I know this error is coming from https://github.com/endojs/endo/blob/master/packages/static-module-record/src/transform-analyze.js#L38 , which means it's coming from a call to the transformer created by `const transformSource = makeTransformSource(makeModulePlugins, babel);`, but I don't know how to investigate further.

The core of my tool looks like:
```js
const builtinsToIgnore = [
  'buffer',
  ..
];
async function findContents(entryfn) {
  const moduleLocation = url.pathToFileURL(path.resolve(entryfn));
  const modules = {};
  builtinsToIgnore.forEach(name => modules[name] = null); // value is unused
  const options = { modules };
  const archiveBytes = await makeArchive(readPowers, moduleLocation, options);
  return extractMemberNames(archiveBytes);
}
```
