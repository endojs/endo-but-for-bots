## Description

## What is the Problem Being Solved?

Clean up CI tech debt to [avoiding duplication](https://docs.github.com/en/actions/sharing-automations/avoiding-duplication), finishing what we started 4y ago
- https://github.com/endojs/endo/pull/37

https://github.com/endojs/endo/blob/df5a0e8677432afc12255bfcb67903045d1597c1/.github/workflows/ci.yml#L11-L14

so replace all our begin/end macro comments with a GH [composite action](https://docs.github.com/en/actions/sharing-automations/creating-actions/creating-a-composite-action)

spotted [earlier](https://github.com/endojs/endo/pull/2334#discussion_r1761818686) by @boneskull

## Description of the Design

e.g. `uses: endojs/setup@1.0.0` (or mvp via filepath)

the alternative is a [reusable workflow](https://docs.github.com/en/actions/sharing-automations/reusing-workflows)

## Security Considerations

- [gha security hardening](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions#understanding-the-risk-of-script-injections)
- [using a commit's sha for release management](https://docs.github.com/en/actions/sharing-automations/creating-actions/about-custom-actions#using-a-commits-sha-for-release-management)

## Scaling Considerations

this improves scaling CI jobs

## Test Plan

[Testing out your action in a workflow](https://docs.github.com/en/actions/sharing-automations/creating-actions/creating-a-composite-action#testing-out-your-action-in-a-workflow)

local testing works well with [nektos/act](https://github.com/nektos/act)

## Compatibility Considerations

consider: linux / windows / macOS

## Upgrade Considerations

upgrading this composite actions to e.g. `uses: endojs/setup@1.0.1` involves pushing a new tag (unless using commit sha)
