## Description

## Describe the bug

Calling `hardenIntrinsics()` twice unknowingly, emits [SES_ALREADY_LOCKED_DOWN](https://github.com/endojs/endo/blob/master/packages/ses/error-codes/SES_ALREADY_LOCKED_DOWN.md)

which isn't immediately clear it's because we're repairing twice

https://github.com/endojs/endo/blob/bd964898215adfd4ba46311f0d1fd374c289cba6/packages/ses/src/lockdown-shim.js#L24

(also depending on the React Native version the stack trace may not be clear)

- https://github.com/LavaMoat/LavaMoat/pull/1438#discussion_r2027323267

ideally we should emit either

1 SES_ALREADY_REPAIRED or SES_ALREADY_HARDENED (similar original behaviour)
2 ignore subsequent calls to `hardenIntrinsics()`

## Steps to reproduce

Call `hardenIntrinsics()` more than once
