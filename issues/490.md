## Description

At https://github.com/Agoric/SES-shim/pull/447/files/b24a650a1bebec1c8a0b9abfad7690becb4f8d50#diff-03e7a59379df2f84382dd5a0b76e3d76 we have an example where we need a stronger `assert`, that immediately terminates the [unit of preemptive termination](https://github.com/tc39/proposal-oom-fails-fast), which for our usage is almost certainly the vat.

At https://github.com/Agoric/SES-shim/blob/b24a650a1bebec1c8a0b9abfad7690becb4f8d50/packages/ses/src/error/assert.js#L378-L387 is a commented out implementation of `insist` which, if made from a capability for terminating this unit, is such a more powerful `assert`.

On SwingSet we can wire up a capability for sudden vat termination. However, what is a host-neutral mechanism?

Btw, the contrasting terms `assert` vs `insist` don't work as the labels for their respective sides of the distinction. If one didn't know other JS `assert` libraries, then from the two names, once would guess they had the swapped meanings: That `insist` is doing input validation, in which case throwing on failure makes sense. The first widespread use of `assert` in a programming language that I am aware of is C's stdlib, where failure terminates the process. But we cannot swap the names, because entrenched JS expectations are that `assert` throws on failure. So we need at least a new name for `insist`.
