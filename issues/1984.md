## Description

## Describe the bug

As observed in #1982, many if not all XS string operations are O(n), affecting in particular code that performs successive random access like e.g. `for (let i = 0; i < string.length; i += 1) { const ch = string[i]; … }`. We should therefore avoid such patterns in favor of iterators in any potentially performance-sensitive code:
* [encodePassable.js `decodeArray`](https://github.com/endojs/endo/blob/98d6ebed7d8f202458ed11041d16a6b4a8f71a20/packages/marshal/src/encodePassable.js#L246)
* [compartment-map.js `pathCompare`](https://github.com/endojs/endo/blob/98d6ebed7d8f202458ed11041d16a6b4a8f71a20/packages/compartment-mapper/src/compartment-map.js#L63)
* [maybe?] [nested-evaluate-and-get-exports.js `longestCommonPrefix`](https://github.com/endojs/endo/blob/98d6ebed7d8f202458ed11041d16a6b4a8f71a20/packages/bundle-source/src/nested-evaluate-and-get-exports.js#L23)
* [cjs-module-analyzer `parseSource`](https://github.com/endojs/endo/blob/98d6ebed7d8f202458ed11041d16a6b4a8f71a20/packages/cjs-module-analyzer/index.js#L102)

Also `substring` and `slice` on strings as seen in e.g. [packages/marshal](https://github.com/endojs/endo/blob/8f93653d077c37fbd1735c7d66a4b6277b12c1b0/packages/marshal), `endsWith` if used anywhere, and `length` if used redundantly/unnecessarily.

----

We should also evaluate successive `replace` calls vs. a single call with a replacer function:
* [evasive-transform `transformComment`](https://github.com/endojs/endo/blob/98d6ebed7d8f202458ed11041d16a6b4a8f71a20/packages/evasive-transform/src/transform-comment.js#L31)

Analysis suggests that for short strings, XS favors a single `.replace(pattern, fn)` over a `.replace(pattern, str).…` chain while V8 favors the reverse, and for long strings, other factors come to dominate in both.
