## Description

## What is the Problem Being Solved?

Node.js supports `package.json` in for directories that are not themselves published packages for the purpose of reading the `"type"` property, which informs the decision of whether to interpret `.js` files as `.cjs` or `.mjs`, and `.ts` as `.cts` or `.mts`.

## Description of the Design

We will need to reveal the `package.json` cache that is already present for `mapNodeModules` and thread it forward to the `importHook` so that it can check for the module type in the context of a package subdirectory without duplicating reads.

## Security Considerations

None.

## Scaling Considerations

We must have a shared cache for package.json reads.

## Test Plan

Add a test fixture that exploits a floating `package.json` with `"type"` of alternately `"module"`, `"commonjs"`, or unspecified (defaults to `"commonjs").

## Compatibility Considerations

This will increase ecosystem compatibility, and will in particular improve our support for the latest versions of `@noble/hashes`.

## Upgrade Considerations

None.
