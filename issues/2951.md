## Description

At 
https://github.com/endojs/endo/blob/5885418223025cb6c8d67edfe953a2175be9ce2a/packages/ses/src/error/tame-error-constructor.js#L41-L42
we see that the ses error taming detects if it is on v8 by sniffing the existing of only `captureStackTrace`. That was accurate at the time, but since then other platforms have implemented `captureStackTrace` without `prepareStackTrace`, and so will be tamed as if it were v8. But if they don't implement `prepareStackTrace`, then we need to tame them as not-v8.

We cannot simply fix the sniff test to check for the existence of `prepareStackTrace` too, because it does not exist on the initial state of the v8 error constructor. We need some more elaborate sniff test that might involve setting a `prepareStackTrace` and seeing if it gets called.

This issue is now urgent, not simply because other platforms have implemented `captureStackTrace`, but because https://github.com/tc39/proposal-error-capturestacktrace is a live standards track proposal that looks good.
