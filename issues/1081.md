## Description

Import-bundle does not currently freeze module exports namespaces. It should not be necessary to do so, since module exports namespaces are not writable or configurable anyway, but it should be possible to freeze one in principle. However, the SES compartment-shim (in module-proxy) implements the defineProperty trap as an unconditional throw. This should be changed such that defining a property of the module proxy can make it non-writable and non-configurable if it is not already. This should be done in a way that does not interfere with the underlying module’s initialization, which is to say, we should be certain that the module exports namespace exotic object has a target that is not identical to the module environment record. The module namespace should be an indirect read-only partial view of the module environment record.

Making this change might depend on implementing module environment records that match the interpretation of the specification proposal in XS https://github.com/endojs/endo/issues/1066
