## Description


If scope proxy allowed setting `Symbol.unscopables` on it, poking a hole in the with(proxy) scope guard would be possible.
Currently proxy protects against it, but a unit test ensuring this property is maintained (eg. while quadruple backflip is introduced) would be nice.

### @kriskowal (MEMBER) — 2024-01-11T20:05:43Z

We’ve missed our window of opportunity to add tests for this before changing the mechanism to four with blocks instead of just one scope proxy, so this might ring differently now. I’m not sure whether the invariant we seek is testable.

If one managed to get a hold on each of the four scope objects, setting `Scope.unscopables` on that object would allow you to force the scope chain to pass through a property on that layer. Getting a handle on a scope object and what you can cause to fall through varies:

1. The eval scope has one property: `eval`. If you added `Scope.unscopables`, you could cause `eval` to fall through to an arbitrary value on a higher scope, but you could not force it to reveal the unsafe/feral/original/intrinsic `eval`. I know of no mechanism that would allow guest code to obtain the eval scope object.
2. The module lexicals object does leak to guest code and guest code does define properties on the object. A module could cause some properties to be transparent to their own lexical scope. This is perhaps a hazard. But, the global lexicals are generally frozen.
3. The global object is expressly available and mutable to guest code. Adding an unscopable list would allow the guest to fall through to the opaque scope.
4. Adding an unscopables property to the opaque scope would cause lexical lookup to fall through to the true intrinsic global. However, the opaque scope proxy is empty and frozen, denying access to any property above it. I also know of no mechanism that would allow guest code to obtain a handle.

The fourth case might be testable in isolation. Assuming that a guest does get access to one of the opaque scope proxy or the sloppy globals scope proxy, they should still be unable to add a property, especially not `Symbol.unscopables`. Also: check my reasoning on any of the above including the inability to get a direct reference to the scope proxy.
