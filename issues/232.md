## Description

While working on #230, @erights and I noticed that `packages/test262-runner` has a lovely configuration mechanism to skip tests, but doesn't really have a way to express that a given test is known to fail.  When we fixed the RegExp problem, I had to re-enable the 50-ish excluded tests one at a time, to find out which ones were now fixed (and could be removed from the exclusion list). If we ran all the tests, but disregarded failures from the marked ones (logging them as "unexpected success"), it would be easier to trim the now-working ones.

I found 8 excluded tests that were working before our RegExp fix. So I suspect there are other tests that don't really need to be excluded which we might re-enable more easily with tooling like this.

(mind you, some of the RegExp tests cause a hang if you try to run them, so we probably need to retain the `excludePaths` option.. we just want to move most of it to a new `expectedFailingPaths` section)
