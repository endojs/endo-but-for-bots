## Description

## What is the Problem Being Solved?

Avoid multiple invocations of Babel's parser when using `@endo/evasive-transform` with `ses` (via a module transform within `@endo/compartment-mapper`). This is a performance concern

## Description of the Design

- Core parsing & transformation extracted into its own module
  - Whether or not to perform evasive transforms should be an _opt-in_ flag; if not provided, it doesn't do much more than parse (or whatever `@endo/module-source` does now)
  - The API should return a Babel AST
  - Therefore it cannot purport to be parser-agnostic and the package naming should reflect this
- `@endo/evasive-transform` retains string-based API and mostly just wraps the new module and regenerates source maps
- `@endo/module-source` invokes new module instead of directly invoking Babel's parser
  - The new flag (mentioned above) should be exposed to the end-user of `@endo/compartment-mapper` (**note:** this may be an incorrect assumption)
