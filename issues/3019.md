## Description

## What is the Problem Being Solved?

The growth of AI-written code is accelerating and inevitable. Endo is a comprehensive object-capability (ocap) fabric, used in production, to enable mutually suspicious software components to richly cooperate when things work out, and to minimize the damage when they do not. 

We propose to add bridges from Endo into some modern AI code-writing tools, and show that practical AI-written code with vulnerabilities can run with a surprising degree of safety without loss of functionality.

## Description of the Design

This will be a plugin for the Endo Pet Dæmon (`@endo/daemon`, `@endo/cli`) that upon installation enables the user to to chat with an AI agent. The AI agent request an OpenAI API server URL and optional authentication. This server may be remote or local. The AI agent will present a system prompt and a code execution tool. When the AI agent gets a tool request to execute JavaScript code from the LLM, it will use its CapTP connection to the Pet Dæmon to request that the user evaluate some code in a disposable Compartment on a Worker, in the presence of the AI agent’s powerbox.

The AI agent will initially have only the capability to request capabilities from the user. Each capability may be a gateway to further capability or amplified by combination of capabilities. The agent may use pet names to carry capabilities between tool calls.

We will establish a convention that each capability may implement a `help` method that returns a human- and LLM-readable description of its usage, in addition to the existing methods for introspecting the usage patterns of that AI.

The tool prompt will instruct the LLM in how to propose code that can harness capabilities in the Endo execution environment, and how to discover further capabilities by inspecting their interfaces.

The AI agent will monitor the AI agent’s Pet Dæmon message inbox, manage a transcript, and propose requests to the LLM, ferry responses to the user, and trampoline tool calls.

The user interface will be the existing Familiar Chat demo interface at `@endo/cli/demo/cat`, which we will make more straight-forward to use. We expect that the user interface will greatly benefit from polish but otherwise is ready to enable the user to chat with an AI agent in the same way as a peer.

I’m tentatively using a llama.cpp server for the Qwen3 model, running on a Linux desktop, since this obviates payment and rate limit concerns.
