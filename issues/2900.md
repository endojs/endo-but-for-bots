## Description

## What is the Problem Being Solved?

Endo should support import attributes https://github.com/tc39/proposal-import-attributes, specifically for the types "json", "bytes", and maybe even "text" and "url" as experiments. It already supports text and bytes through module extension mappings, which is non-standard.

## Description of the Design

`module-source` will need to grow additional properties to express import with attributes. These will need to overshadow existing import properties as a progressive enhancement that new versions of `ses` may take into account, but fall back to the current behavior (falling back to hoping that there is a coïncident package.json mapping from the extension for the same type.)

`ses` will need to account for import attributes, threading them from new properties on our first-party module source convention into a second argument of `importHook` and `importNowHook`, and also integrate all import attributes into the memo key in a normalized order.

## Test Plan

We will need tests that exercise import type with the support types as unit tests of `ses` and `@endo/module-source` but also in integration with `@endo/compartment-mapper`, taking into account the migration path from using package.json extensions.

## Compatibility Considerations

As mentioned, we will want a migration path from out-of-band type to in-band-type. We will need to ensure that existing bundles continue to work with the new runtime, and ideally old runtimes gracefully ignoring the import attributes.
