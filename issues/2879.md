## What is the Problem Being Solved?

We should have tests for compartment code importing from `@endo/env-options`. The compartment set up should set the compartment's `process.env.<env var name> = <env var setting>` as the existing tests at https://github.com/endojs/endo/blob/master/packages/ses-ava/test/env-options.test.js do. But rather than use a `makeEnvironmentCaptor` evaluated in the root compartment, it should run code within the compartment that (directly or indirectly) imports from `@endo/env-options`.

See https://github.com/endojs/endo/pull/2873/files#r2191085939 for more

After #2873 , in `@endo/marshal` we should add a corresponding test that sets the `process.env.ENDO_RANK_STRINGS` only for the new compartment and then run string ranking tests in that compartment without reference to these setting in the root compartment. Or even after ensuring the that root compartment has different settings.

See https://github.com/endojs/endo/pull/2873#issuecomment-3028112548 for more.
