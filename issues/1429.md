## Description

At https://github.com/endojs/endo/tree/master/packages/ses/error-codes is the directory of the current SES error code explanations, where the name of each file in the directory is the error code it explains.

I had initially proposed that the rendering of the error include a URL to the page explaining the error. This could be by manually writing the url as the error code where the error is defined, or by keeping the current conventions of error codes as identifiers, but then rendering the error by prepending a fixed URL base. Both of these were rejected on the theory that we did not want the source code to privilege a given host as the definitive explanation of the errors. By this theory, it would be better for users to do a web search for the error code identifier, to see all those providing explanations.

Empirically, this theory has failed. That directory and most of the files in it are now over a year old. I just did a Google search on each of these identifiers. Not one of these Google searches provided a useful result. In particular, not one produced a URL to the error explanation page itself. (Attn @dtribble )

@turadg just had an interesting observation: when investigating an error, after looking at the message, the next thing we generally look at are the source code positions captured in the error stack. A comma placed into the source code where the error is thrown from is thereby more naturally discoverable than are anything based on websearching error codes.
