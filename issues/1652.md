## Description

Here is a step-by-step plan for `eventual-send` in order to improve its feature set and factoring (cf. tc39/proposal-eventual-send#31):

- [ ] Make `E.get(x)` unnecessary
  - [ ] thenables have an "thenable identity" of themselves
  - [ ] `E(x)[prop]` returns a function `(...args) => HandlePromise.applyMethod(x, prop, args)`, whose "thenable identity" is `HandledPromise.get(x, prop)`
  - [ ] all other values do have a "thenable identity" that always rejects
  - [ ] `E(x).then(...args)` operates on the thenable identity of `x` (ht: @mhofman)
- [ ] enable the use of wrapped promises in the shim to detect shortening without platform support (ht: @mhofman)
  - [ ] direct `await` or `Promise.resolve(p).then` cannot pierce wrapped promises in the resolution chain because they do not have a `.then` method
  - [ ] create `type WrappedPromise<T> = RemotableBrand<{}, T & PromiseLike<T>>`.  post-standard: same as `Promise<T>`
  - [ ] extend definition of `ERef<T>` to include `WrappedPromise<T>`
  - [ ] create `type UnwrapAwaited<T>` extending `Awaited<T>` by being able to unwrap `WrappedPromise<T>` to `T`
  - [ ] `<T>Promise._wrap(x: T): WrappedPromise<UnwrapAwaited<T>>` to create a WrappedPromise for any value `x`.  post-standard: deprecated identity function
  - [ ] `<T>Promise.settle(wp: T): Promise<UnwrapAwaited<T>>` to return the final fully-shortened settlement of `wp` as an object that quacks like a platform promise.  post-standard: same as `Promise.resolve(wp)`
  - [ ] `<T>Promise.shorten(wp: T): Promise<UnwrapAwaited<T>> | Promise<WrappedPromise<UnwrapAwaited<T>>>` to return the next resolution of `wp`, not necessarily the final settlement. post-standard: exposed by platform promise
  - [ ] `promise-wrap.js` shim
- [ ] `Promise.eventual` is similar in spirit to `E`
  - [ ] handler implementation is either `HandledPromise` or (soon) `EventualHandler`
  - [ ] `Promise.eventual(x).then(...args)` bottoms out in `Promise.settle(x).then(...args)` (ht: @mhofman)
  - [ ] `Promise.eventual[trapName]` methods correspond to the "eventual traps" (such as `get`, `send`, etc. below)
    - [ ] the result of each is wrapped with `Promise._wrap(resultP)` (ht: @mhofman)
- [ ] `globalThis.EventualHandler` class
  - [ ] `new EventualHandler(defaultBehavior: any, traps?: Partial<EventualTraps>)`
  - [ ] the `traps` object's methods can override any of the "eventual traps":
    - [ ] `delete(x: any, prop: PropertyKey): ERef<boolean>`
    - [ ] `get(x: any, prop: PropertyKey, opts: EventualOptions): ERef<any>`
    - [ ] `invoke(x: any, args: unknown[], opts: EventualOptions): ERef<any>` (function call)
    - [ ] `send(x: any, prop: PropertyKey, args: unknown[], opts: EventualOptions): ERef<any>` (atomic method call)
    - [ ] `set(x: any, prop: PropertyKey, value: any): ERef<boolean>`
  - [ ] if `traps` does not implement an eventual trap, the handler uses Reflect protocol on the `defaultBehavior` object (ht: @dead-claudia)
  - [ ] an `EventualHandler` has methods to create fresh objects associated with it:
    - [ ] `newProxy(target: any, handler: ProxyHandler): any`
    - [ ] `proxyRevocable(target: any, handler: ProxyHandler): { revoke: () => void, proxy: any }`
    - [ ] `<T>promiseResolve(x: T): WrappedPromise<UnwrapAwaited<T>>` (ht: @dead-claudia, @mhofman)
    - [ ] `objectCreate(proto: object, ownProperties?: PropertyDescriptors): object`
    - [ ] `<T extends (...args: any[]) => any>functionClone(fn: T) => (...args: Parameters<T>) => ReturnType<T>`
  - [ ] `Promise.eventual[trapName]` static methods use the `EventualHandler` internally associated with its created objects instead of `HandledPromise`
