# #3190: compartment-mapper: parses happen once per module specifier instead of once per module

- **State:** OPEN
- **Author:** @boneskull
- **Created:** 2026-04-18T00:42:09Z
- **Updated:** 2026-04-18T01:37:15Z
- **Labels:** `bug`

## Description

Presume this `foo.js` exists. If a package contains source code that does something like:

```js
// module A
const foo = require('./foo');
```

and also this

```js
// module B
const foo = require('./foo.js');
```

`@endo/compartment-mapper` will end up parsing `foo.js` _twice_, duplicating work for no good reason.  Once module resolution occurs here:

https://github.com/endojs/endo/blob/8d92961bab8bc6fd6eac06a233346295b967d890/packages/compartment-mapper/src/import-hook.js#L404

it's already too late to back out; we need to provide a module record. No module record is retained anywhere, so we just have to go ahead and re-create one. The same code will overwrite the module source object in `packageSources` for the file at `moduleLocation`. Hope the bytes on disk don't change between the first and second parses!

How to fix this—and more importantly if it is even worth fixing—is TBD.

## Notes

- This doesn't seem to happen often.  In a sample, this happened thirteen (13) times for a compartment map containing 2604 modules.
- I don't know if this problem crosses compartment boundaries; e.g., if package `cows` required `pigs/sheep.js` and package `ducks` required `pigs/sheep` instead.
- I don't know if this is unique to CJS, but I suspect it is not.
- I also expect that a module containing both `require('./foo')` and `require('./foo.js')` (for whatever reason) would also exhibit the same behavior.
